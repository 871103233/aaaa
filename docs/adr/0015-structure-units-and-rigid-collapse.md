# ADR 0015：结构单元与刚体化倒塌（"规定哪些元素是一个整体"）

- **状态**：已采纳（2026-09-27）
- **相关**：[ADR 0004](0004-hybrid-layered-world-representation.md)（分层混合世界）、[ADR 0012](0012-collision-takeover-by-volumes.md)（碰撞接管与体积内塌落）、[ADR 0013](0013-destructible-elements.md)（可破坏元素）、[ADR 0014](0014-voxel-material-index.md)（体素级材质）、`docs/game-design.md`（能力清单·结构整体性）、`docs/world-setting.md`

## 背景

项目所有者 2026-09-27（人工实测第 7 轮）：

> "当前两个高塔，最早的细塔不会掉落，后来建的粗大高塔我在破坏底部时虽然不会每次都塌陷但是也不是整体塌陷，**我希望引擎能规定哪些元素是一个整体**，将这两个塔设计为各自独立的整体，**要求整体坠落并具备倾斜旋转等效果**。"

现状（[ADR 0012](0012-collision-takeover-by-volumes.md) 第二节）的塌落是**逐列独立**的：失去支撑的实心体沿**本列**下落到腔底。它**在原理上**只能产生两种结果：

- **原地垂直下沉**（细塔被打断后每列落到同一高度 ⇒ 塔只是"垂直变矮"，看起来没倒）；
- **局部陷落**（粗塔因球半径 6 格 < 21 格宽而打不穿整个截面 ⇒ 侧壁仍接地 ⇒ 有时根本不塌）。

⇒ 要"整体倾倒 + 倾斜 + 旋转"，必须把"失去支撑的一部分"**整体刚体化**。

## 决策

### 一、引入「结构单元（Structure）」

- 体积体素新增 **`structureId`**（`std::int32_t`；**`0` = 普通地形**，未归属任何单元）。**同一 ID 的实心体素属于同一个整体**。
- 存储：与密度 / 材质（[ADR 0014](0014-voxel-material-index.md)）同布局的 33³ 数组，**+140 KB/块**（`int32`）；首期**只对"被打标的块"分配**（普通地形块不分配），避免 441 块 × 140 KB ≈ 62 MB 的无谓开销。
- 用户可见的语义：**"整体"= 同一 ID 的体素在倒塌时一起动**（同生共死），而不是各自下落。

### 二、标记来源

| 阶段 | 标记方式 |
| --- | --- |
| **首期（本次）** | **地图预设声明**：`assets/maps/<name>.toml` 新增 `[[structure]]` 段（`name` / `min` / `max`，世界列与高度范围），装载后把该范围内的实心体素打上该单元的 ID ⇒ **测试地图的两塔各自声明为一个单元** |
| 后续 | 建造 / 器物层落地后，由**建造行为**自动打标；编辑器提供可视化标记 |

### 三、倒塌触发与流程

**触发**：单元内**已无任何"接地"体素** —— 按 [ADR 0012](0012-collision-takeover-by-volumes.md) 的「载荷通路 + 悬挑容差」逐列判定，**按单元聚合**：只要仍有任一列接地 ⇒ **不动作**（保守，避免误倒）；**全部**失支撑 ⇒ 整个单元倒塌（首期口径，简单且符合"整体坍塌"的直觉）。

**流程**（全部在固定步内、确定性，红线 7 / 11）：

1. **抽出**：按单元的体素集合生成几何，并**立即从体积中清空这些体素**（密度 + 材质 + structureId）⇒ 随即重网格 + 同步碰撞体（复用 T30 的分段计时链路），避免"幽灵地形"与刚体同时存在；
2. **刚体化**：生成 Jolt **动态刚体**——首期形状用 **`ConvexHullShape`（凸包）**，位置取单元质心；初速为零（由重力接管）；
3. **模拟**：交给 Jolt 求解 ⇒ **倾斜、旋转、与地形/其它刚体碰撞**；
4. **落定**：判定静止（速度阈值持续若干固定步）后**体素化回写**（按刚体最终姿态把体素写回密度 + 材质）并销毁刚体 ⇒ **残骸成为可继续挖掘的地形**（保证"洞仍能走进去、倒下的东西能站上去"）；
5. **限流**：回写**分帧**（每帧最多 1 个单元），复用 T30 已做的"重网格 + 碰撞体重建 + GPU 上传"链路。

**预算（首期建议值，可调）**：活跃倒塌单元 ≤ **4**；单单元体素 ≤ **20000**（超出则拒绝并记日志）；回写每帧 ≤ **1** 个单元。

### 四、未打标区域保持现状

`structureId == 0` 的体素**继续走 T29 的逐列塌落**（[ADR 0012](0012-collision-takeover-by-volumes.md)）—— 本 ADR **不改**普通地形的行为，只给"被声明为整体"的结构换一条路径。

## 备选方案（已评估）

| 备选 | 未采纳的理由 |
| --- | --- |
| **纯隐式连通分量**（不做显式标记） | 能自动把"被挖断的部分"整体化，但**无法表达"哪些元素属于同一个整体"**（元素尚未完全断开时无能为力），而项目所有者明确要的是**可规定**的能力 ⇒ 保留为**辅助判据**（可用于单元内部的进一步分裂），不作唯一方案 |
| **预制碎块 + 接合**（Chaos / Blast 路线：美术预切块 + bond 断裂） | 倒塌效果与性能最好，但需要美术资产与独立的资产管线，且"塔是程序化地形"没有预制件 ⇒ 记为后续（器物 / 建造层落地后） |
| **逐列下落**（现状） | 原理上无法倾斜 / 旋转（见「背景」），已被本次需求否决 |
| 把塔改成**器物**（几何不可变） | 整体性天然且最省，但**塔不能再被挖穿** ⇒ 与项目所有者选定的路线不符（他选了"显式结构单元"，即塔仍可被挖穿） |

## 后果

- **正面**："整体"成为**引擎可表达的概念**；塔被挖断后**整体倾倒并翻滚**，落定后残骸回到地形（可继续挖、可站上去）。
- **代价与已知限制**：
  1. **凸包形状会填平凹形**（首期用 `ConvexHullShape`）⇒ 门形 / L 形结构的碰撞与外观会偏"实"，须在后续用复合盒或凸分解改进；
  2. **Jolt 的 `MeshShape` 不能做动态体**（`MustBeStatic()` 为真）⇒ 动态倒塌体必须用凸 / 复合形状；
  3. 需要**体素 ↔ 刚体双向转换**（新增子系统）与**体积存档**——本项目体积**当前无存档**（所有者 2026-09-27 明确"暂时不要求"）⇒ **倒塌结果不跨会话**是已知限制；若要跨会话须先做存档；
  4. 性能（形状构建 + 物理步 + 回写）须实测，并按预算限流；T30 已把"重网格 + 碰撞体重建"链路压到可接受量级，回写复用该链路；
  5. **确定性**：形状构建用 `FavorBuildSpeed`（沿用 T30），倒塌与回写全部在固定步内、禁止随机。
- **后续 / 切换条件**：
  - 需要**更准的形状** ⇒ 复合盒 / 凸分解（V-HACD 类工具）；
  - 需要**碎裂成多块**（撞碎而不是整体倒） ⇒ 需新的断裂判据（应力 / 损伤），另开 ADR；
  - 需要**跨会话保留倒塌结果** ⇒ 先做体积存档（已登记的前置项）。
