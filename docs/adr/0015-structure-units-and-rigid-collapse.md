# ADR 0015：结构单元与刚体化倒塌（"规定哪些元素是一个整体"）

- **状态**：已采纳（2026-09-27）；**2026-09-27 修订**（项目所有者二次指示：**删除逐列下落**，统一走刚体化；见「修订记录」）；**阶段 1 已落地并实测**（同日，见「修订记录」末条：地标塔整体倾倒、落定倾角 88°）
- **相关**：[ADR 0004](0004-hybrid-layered-world-representation.md)（分层混合世界）、[ADR 0012](0012-collision-takeover-by-volumes.md)（碰撞接管与体积内塌落）、[ADR 0013](0013-destructible-elements.md)（可破坏元素）、[ADR 0014](0014-voxel-material-index.md)（体素级材质）、[ADR 0016](0016-collapse-realism-impulse-material-debris.md)（倒塌真实感）、[ADR 0017](0017-landing-by-material-rigid-vs-granular.md)（落地表示按材质分流）、[ADR 0018](0018-structural-support-and-representation-preserving-destruction.md)（**修订本 ADR 的支撑检查 scope**：由"被改动采样 ± (悬挑 + 1) 格的固定窗口、只做一次"改为**连通域洪泛至结构边界**，修"长条中段悬空不落"）、`docs/game-design.md`（能力清单·结构整体性）、`docs/world-setting.md`

## 背景

项目所有者 2026-09-27（人工实测第 7 轮）：

> "当前两个高塔，最早的细塔不会掉落，后来建的粗大高塔我在破坏底部时虽然不会每次都塌陷但是也不是整体塌陷，**我希望引擎能规定哪些元素是一个整体**，将这两个塔设计为各自独立的整体，**要求整体坠落并具备倾斜旋转等效果**。"

现状（[ADR 0012](0012-collision-takeover-by-volumes.md) 第二节）的塌落是**逐列独立**的：失去支撑的实心体沿**本列**下落到腔底。它**在原理上**只能产生两种结果：

- **原地垂直下沉**（细塔被打断后每列落到同一高度 ⇒ 塔只是"垂直变矮"，看起来没倒）；
- **局部陷落**（粗塔因球半径 6 格 < 21 格宽而打不穿整个截面 ⇒ 侧壁仍接地 ⇒ 有时根本不塌）。

⇒ 要"整体倾倒 + 倾斜 + 旋转"，必须把"失去支撑的一部分"**整体刚体化**。

**2026-09-27 二次指示（本次修订的触发）**：

> "逐列独立 + 悬挑容差明显不符合真实世界，按照登记的开发方向做整体刚体化，**严禁**现在这样逐列独立的不符合真实世界的效果"

并明确两点（同一日问答确认）：
1. **覆盖范围 = 统一**：所有"失去支撑的实心体"都按**连通分量**整体刚体化，**逐列下落路径删除**；
2. **不设分量体素上限**：一律刚体化（含超大片），不做"超限退回逐列"或"拒绝刚体化"。

## 决策

### 一、统一刚体化（**取代** T29 的逐列下落）

- **判定**（沿用 [ADR 0012](0012-collision-takeover-by-volumes.md) 的判据，不改）：在**被改动采样的邻域**内，按「**载荷通路**（自邻域底面起连续实心）+ **悬挑容差**（同层实心横向连通 ≤ `max_cantilever_blocks` 步）」标记「支撑体素」；**实心但不在其中 = 失去支撑**。
- **分组**：失去支撑的实心体素按 **6 邻域连通分量**分组 —— **每个分量 = 一个整体**（同一分量在倒塌时一起动，同生共死）。
- **删除** T29 的"按连续段逐列下落 + 堆顶摊开"路径（连同 `pile_spread_blocks` 参数）。**禁止**保留两套并存。

### 二、「结构单元」= 对连通分量的**强制合并**（阶段 2）

- `structureId`（`std::int32_t`，**`0` = 普通地形**）仍需**用于"规定哪些元素是一个整体"**：**同一非零 ID 的体素即使体素连通性上不相邻，也视为同一个整体**（合并进同一分量）。
- **存储**：与密度同布局的 33³ 数组、**仅对被打标的块分配**（普通块不分配，避免 441 块 × 140 KB ≈ 62 MB 的无谓开销）。
- **标记来源**：地图预设 `assets/maps/<name>.toml` 的 `[[structure]]`（`name` / `min` / `max`）。
- **分期**：**阶段 2 实现**。**首期不实现**的理由与切换条件：首期的两塔在体素连通性上**本就各自独立**（细塔 x∈[52,54] / 粗塔 x∈[6,26]，相隔 26 格以上）⇒ 连通分量已经让它们"各自成为一个整体"，**用户可见的"整体倾倒"不依赖显式标记**；显式标记要解决的是"**局部已断开、但仍应算一个整体**"与"**建造层打标**"，属独立的一小块（新数据通道 + 地图格式 + 校验 + 测试）。
  **切换条件**：需要"同一结构被挖成两半仍整体倒"或建造层落地后自动打标时，立即实现（已登记在阶段计划 T33 的阶段 2）。

### 三、倒塌触发与流程

**触发**：某个（连通分量 / 结构单元）**已无任何"接地"体素** ⇒ 该整体倒塌。保守口径：**只要仍有任一列接地 ⇒ 不动作**（避免误倒）。

**流程**（全部在固定步内、确定性，红线 7 / 11）：

1. **抽出**：按分量生成几何，并**立即从体积中清空这些体素**（密度）⇒ 随即重网格 + 同步碰撞体（复用 T37 的延后队列），避免"幽灵地形"与刚体同时存在；
2. **刚体化**：生成 Jolt **动态刚体**——首期形状用 **`ConvexHullShape`（凸包）**，顶点取该分量的**逐列最低 / 最高实心角点**（降点集规模，保证形状构建有上界）；刚体局部原点取分量质心，位置与初始姿态取实际位置 / 单位旋转；线初速为零（由重力接管）+ 一个**确定性初始角速度**（`initial_tilt_speed`，方向与正负由分量包围盒坐标哈希决定 —— 真实失稳总是"一侧先屈服"，若初速恒为零，细长的塔只会原地垂直落下）；质量 = 体素数 × `mass_per_voxel`；
3. **模拟**：交给 Jolt 求解 ⇒ **倾斜、旋转、与地形 / 其它刚体 / 角色碰撞**；
4. **可见**：启动时预建**退化网格池**（`max_active_units` 个槽位，每槽定长顶点 + 固定索引模式，退化三角形不可见）；`Spawn` 把该整体的**外表面**顶点写一次（**局部坐标**，保留 ADR 0014 的材质槽位），之后每帧只推 **`mat4 modelToRender`（平移 × 旋转，64 B / 网格）** ⇒ **CPU 零重烘焙、GPU 零重传**（T41 的「每网格自带原点」泛化为带旋转的模型矩阵；顶点只承载局部坐标，法线用 `mat3` 变换）；
5. **落定**：线速度 / 角速度**持续 `settle_steps` 个固定步**低于阈值 ⇒ 判定静止，**体素化回写**（按刚体最终姿态把体素写回密度）并销毁刚体；
6. **限流**：回写后的**重网格 / 碰撞体重建 / GPU 上传**复用 T37 的延后破坏队列（每帧预算推进），避免"一次倒塌把一帧拉爆"。

**预算（配置项，`collapse.toml`，`schema_version = 2`）**：活跃倒塌单元 ≤ `max_active_units`（默认 **4**，超出则本次**不抽出**该分量、保持原状并打日志）；落定阈值 `settle_linear_speed = 0.6` / `settle_angular_speed = 0.7` / `settle_steps = 12`；初始不对称 `initial_tilt_speed = 0.9`；质量 `mass_per_voxel = 2.4` / 摩擦 `friction = 0.6`；**不设**单分量体素上限（项目所有者明确）。

## 备选方案（已评估）

| 备选 | 未采纳的理由 |
| --- | --- |
| **纯隐式连通分量**（不做显式标记） | **已采纳为首期主体**（修订后）；显式 `structureId` 保留为阶段 2 的"强制合并"。 |
| **逐列下落**（T29 现状） | **原理上无法倾斜 / 旋转**（见「背景」）；项目所有者 2026-09-27 明确**严禁**，**已删除**。 |
| **预制碎块 + 接合**（Chaos / Blast 路线：美术预切块 + bond 断裂） | 倒塌效果与性能最好，但需要美术资产与独立的资产管线，且"塔是程序化地形"没有预制件 ⇒ 记为后续（器物 / 建造层落地后）。 |
| 把塔改成**器物**（几何不可变） | 整体性天然且最省，但**塔不能再被挖穿** ⇒ 与项目所有者选定的路线不符。 |
| **超限分量退回逐列 / 拒绝刚体化** | 项目所有者 2026-09-27 明确**不设上限** ⇒ **不采纳**（代价见「后果」第 6 条）。 |

## 后果

- **正面**："整体"成为**引擎可表达的概念**；塔被挖断后**整体倾倒并翻滚**，落定后残骸回到地形（可继续挖、可站上去）；**不再有"逐列垂直变矮"的非物理表现**。
- **代价与已知限制**：
  1. **凸包形状会填平凹形**（首期用 `ConvexHullShape`）⇒ 门形 / L 形结构的碰撞与外观会偏"实"，须在后续用复合盒或凸分解改进。**已实测到的具体表现**：若被抽出的是**凹形**整体（例："塔 + 高台板"在体素上连成一体），其凸包**大于**被挖空的体积 ⇒ 抽出处即与周围地形重叠、Jolt 顶出后容易被**卡住**，落定倾角可能只有 **1~5°**（"干净切在塔基"时同一座塔实测 **88°**）；
  2. **Jolt 的 `MeshShape` 不能做动态体**（`MustBeStatic()` 为真）⇒ 动态倒塌体必须用凸 / 复合形状；
  3. **回写不保证严格质量守恒**：按最终姿态把体素**落位到最近格**，重叠 / 越界时按固定顺序找邻近空格，仍可能少量丢失（实测一次 1815 体素的塔回写**丢弃 0 个**，也有丢弃 37 / 144 个的实例；与 T29 的"严格守恒"口径不同，**这是本修订的一处已登记放松**）；
  4. 需要**体素 ↔ 刚体双向转换**（新增子系统）与**体积存档**——本项目体积**当前无存档**（所有者 2026-09-27 明确"暂时不要求"）⇒ **倒塌结果不跨会话**是已知限制；
  5. **性能实测（Debug，真实操作）**：「倒塌」段（支撑检查 + 分组 + 抽出 + 刚体化 + 网格写入，**全部在当帧主线程**）= **5.9~25.2 ms**（随邻域采样数 4.7~16.4 万规模变化；其中与体素数**无关**的固定部分 ≈ 8 ms 来自"每槽按整容量补齐顶点并上传 2.62 MB/槽"）；整帧最坏 **46.0 ms**（< 50 ms 判据，但已越过 33 ms 的帧尖峰阈值 ⇒ 仍须优化）。**回写后的重建全部走 T37 队列**；
  6. **不设分量上限的直接后果（项目所有者已确认接受）**：一次爆炸若在薄壳下产生超大片失支撑体，会生成**很大的凸包与很大的渲染网格**，形状构建 / 上传可能超过一帧预算（表现为一次明显顿卡）。**缓解**：邻域本身仍限制在"被改动采样 ± (悬挑 + 1) 格"内，实际分量通常远小于世界尺度；**实测**：主动抽出的最大分量 = 1815 体素（地标塔），未出现 > 50 ms 单帧。日志已逐次打出体素数 / 各段耗时以便继续实测。
  7. **确定性**：形状构建（凸包）与物理求解在固定步内、禁止随机；但物理求解的**浮点结果**取决于步序 ⇒ 只要固定步与步序一致（本工程已如此），结果可复现。
- **后续 / 切换条件**：
  - 需要**更准的形状** ⇒ 复合盒 / 凸分解（V-HACD 类工具）；
  - 需要**碎裂成多块**（撞碎而不是整体倒） ⇒ 需新的断裂判据（应力 / 损伤），另开 ADR；
  - 需要**跨会话保留倒塌结果** ⇒ 先做体积存档（已登记的前置项）；
  - 需要**显式规定整体**（阶段 2）⇒ 见「决策 二」的切换条件。

- **2026-09-27（阶段 1 落地实测，回填本 ADR）**：`cmake --build --preset debug` 零警告 + `ctest --preset debug` **260/260**。**真实操作冒烟**：向测试地图**地标塔**（3×5 列、高出高台 130 格）基座发射光球 ⇒ 日志 `失去支撑 1815 体素、整体 1 个、已刚体化 1 个` ⇒ `倒塌落定（T33）：回写体素 1815 个（丢弃 0 个）；倾角 88°、落点 (51.7, 132.9, 4.3)`（同批另有 82° / 90° / 77° 的整体）⇒ **整座塔作为一个刚体倾倒 / 翻滚后横躺，残骸回写为地形**。精度回填：决策三·4 的"逐帧重烘焙"已改为"**只推 `mat4`（64 B）不重烘焙**"、决策三·2 的"初速为零"已补**确定性初始角速度**、预算项的默认值以 `collapse.toml` 为准（`max_active_units = 4`）。

  [ADR 0017](0017-landing-by-material-rigid-vs-granular.md)。
- **2026-09-27（T46 同日修订）**：分流判据由"全体体素的多数材质"改为"**碎块露出来的表面材质**"
