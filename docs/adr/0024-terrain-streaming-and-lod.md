# ADR 0024：地形流式加载与 LOD 分环

- **状态**：已采纳（2026-10-05）；**收敛 `SKILL.md` 待收敛项 4（地表 LOD 方案与接缝策略）**
- **日期**：2026-10-05
- **相关**：ADR [0008](0008-sizes-precision-budget.md)（其 §7.3"Draw Call 与视距内存只记录、不验收"由本 ADR **转为有预算**）、[0020](0020-dig-volume-vertical-band-and-dynamic-residency.md)（常驻调度形态，本 ADR 复用）、[0022](0022-volume-build-worker-pipeline.md)（worker 形态，本 ADR 复用）、[0023](0023-world-representation-v2-hybrid-shell.md) / [0026](0026-premade-map-format-and-bake-tool.md)
- **来源**：项目所有者 2026-10-05 裁定（架构路线 A；10km 大世界；预制地图；流式加载性能好；近场环取"加大"档）

## 背景

ADR 0008 §7.3 规定"地表 LOD 未收敛前，**Draw Call 与视距内存只记录、不验收**"。10km 世界若全量常驻：

| 指标 | 1km（289 tile） | 10km（≈25,300 tile） |
| --- | --- | --- |
| 地表网格显存（0.19 MB/tile） | ≈ 55 MB | ≈ **4.8 GB** |
| 地表高度数据（8 KB/tile） | ≈ 2.3 MB | ≈ **200 MB** |
| 启动（生成 + 网格化，debug 实测 15.3 s） | 15.3 s | 同比例 **数分钟** |

⇒ 全量常驻在预算（VRAM ≤ 300 MB / CPU ≤ 150 MB，ADR 0008）下**不成立**。必须引入"以玩家为中心、只常驻窗口、远景降级"的流式 + LOD。

本仓库**已有**两套可复用的形态：ADR 0020 的"玩家窗口 + 预取环 + 分帧建卸"，与 ADR 0022 的"块构建下沉 worker"。本 ADR 把这两者从"可挖体积"推广到"地形与体积壳"，并确定分环参数。

## 决策

### 一、常驻集合 = 玩家窗口 + 预取环（不变量：每帧成本 O(窗口)）

- 常驻集合由**玩家所在 tile ± R** 决定，**与世界总大小无关**；
- 预取环宽 ≥ 1 tile（复用 `kResidencyPrefetchTiles` 口径），且**预取必须在玩家看到之前完成**；
- 建 / 卸一律**下沉 worker + 分帧**（复用 ADR 0022 的"快照式纯函数 + 主线程收包上传"），**禁止**在渲染帧内同步建卸（SKILL 第四节）。

### 二、LOD 分环（所有者选定"加大近场环"档）

| 环 | 距离 | 表示 | 说明 |
| --- | --- | --- | --- |
| **Ring 0** | 0 – **512 m** | **体积壳全细节**（含洞穴 / 悬垂 / 河床） | 真三维仅在此环成立 |
| **Ring 1** | 512 – 1024 m | 高度场**高模** | 洞口 / 悬垂在此环**淡出**（已知限制） |
| **Ring 2** | 1024 – **2048 m** | 高度场**低模**（CDLOD 顶点 morph 消接缝） | — |
| 雾 | 覆盖 **2048 m** 外 | 遮住流式窗口边界 | **硬要求**：视距 < 常驻半径 |

- 接缝策略：**顶点过渡 morph**（CDLOD 形态）；相邻环的边界必须在**远处**完成切换（SKILL：LOD 切换在远处完成）。
- Ring 0→1 的"体积淡出"是本 ADR 的主要观感风险点，须在实现期目视验收；若不可接受，切换条件见"何时重新审视"。

### 三、预制数据按块流式读取

预制地图（[ADR 0026](0026-premade-map-format-and-bake-tool.md)）必须支持**按块随机访问**（块坐标 → 偏移 + 长度），使"只加载窗口"成立；不允许"整份读入再切窗口"。

### 四、预算口径（收敛待收敛项 4）

- 从本 ADR 起，ADR 0008 §7.3 的"只记录"**改为有预算**：
  - 常驻 VRAM **≤ 640 MB**、常驻 CPU（进程工作集）**≤ 512 MB**（**2026-10-06 修订**，见下）；
  - 帧时间：1080p / GTX 1660 级 **≥ 60 FPS**，**P99 ≤ 2× 帧预算**，**无 > 50 ms 单帧**（SKILL 第四节 hitch-free）；
  - Draw Call：**记录并纳入验收**（分环后应有界；实测上界回填见下方修订）。
- **不变量**：每帧成本只与窗口有关，**不得**随世界总量增长（禁止每帧 O(总量) 扫描；物理宽相只含窗口内刚体）。

#### 修订（2026-10-06）：常驻预算按 10 km 尺度重算

**原值 `VRAM ≤ 300 MB / CPU ≤ 150 MB` 是 ADR 0008 的"V0.1 小场景"口径**（该节原文即写明"小场景：1~9 个地表 tile"），
本 ADR 起草时**沿用而未重算**。S3b 的 10 km 实测证明它**不成立**，据项目所有者 2026-10-06 裁定（"如过预算给得过低可适当增加"）按下表重算：

| 项 | 原值 | 实测（10 km / Ring 2 = 2048 m / 4489 常驻 tile） | 新值 | 余量 |
| --- | --- | --- | --- | --- |
| CPU 常驻（进程工作集） | 150 MB | **388 MB 稳态**（1 km 基线 293 MB；4200 个额外 tile ≈ +95 MB ≈ 23 KB/tile） | **≤ 512 MB** | ≈ 32% |
| VRAM 常驻 | 300 MB | 纹理记账 **262 MB** + 地形网格估算 ≈ **161 MB** ⇒ ≈ **423 MB** | **≤ 640 MB** | ≈ 51% |
| Draw Call | 只记录 | 首帧提交 **1383** 个网格 / **≈5.3k** 次 draw（含 3 级级联阴影各一遍） | **≤ 6000 次/帧**（实测上界回填） | — |

- **口径说明**：CPU 一律取**进程工作集**（`WorkingSet64`），不再用含义含糊的"常驻"；VRAM 为
  "纹理记账 + 网格缓冲按上传字节记账"之和。**注意**：`MeshRenderer` 的 `textureBytes` **目前只统计纹理**，
  网格缓冲未入账 ⇒ 上表的 VRAM 是**估算**，须补"网格字节记账"后才算实测（列为待办）。
- **切换条件**：本表**只对"10 km 世界 + Ring 2 = 2048 m + tile 64 m"成立**；改环半径 / 世界尺度 / tile 尺寸须重算。
- **实测的当前瓶颈**：帧尖峰来自**渲染提交**（20~33 ms/帧，≈5.3k draw）与**视锥剔除**（5~28 ms），
  主因是 4489 常驻网格中约 1300 个进入提交、且**阴影通道对每个网格各画一遍（3 级级联）** ⇒ 属本节"Draw Call 纳入验收"的范围，
  收敛手段（按级联正交盒剔除投射体 / 合并远景网格）留待 W7-S4 与遮挡剔除（待收敛项 6）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **窗口流式 + CDLOD 分环**（采纳） | 常驻有界；成熟；与既有调度/worker 形态一致 | 需处理环间接缝与体积淡出 | **采纳** |
| Geometry Clipmaps | 内存极省、适合超远 | 与动态改变的地形/洞穴契合差 | 不采纳（备选） |
| 无 LOD，仅窗口流式（视距锁 ~1.5 km） | 实现最简 | 悬垂/洞穴只能在很近处出现，远景无层次 | 备选（最小可交付形态，先于分环落地） |
| 全量常驻 | 零复杂度 | 4.8 GB，直接超预算 | 不采纳 |

## 后果

### 正面

- 10km 世界的**帧预算与内存**与 1km 同级（O(窗口)）；待收敛项 4 关闭。
- 复用 ADR 0020/0022 的调度与 worker，新增工作集中在"环参数 + 接缝 + 预制读取"。

### 负面 / 必须承受的代价

- **Ring 1 起无真三维细节**（洞口/悬垂淡出）—— 已知限制，须在文档登记。
- 流式跨界仍需预取纪律；否则重演 T72/T73 的成串尖峰。
- 需要"雾盖住窗口边界"的联合调参（雾太淡 ⇒ 看到世界尽头；太浓 ⇒ 观感受损）。

## 何时需要重新审视

1. **Ring 0→1 体积淡出观感不可接受** ⇒ 扩大 Ring 0（代价 = 显存/流式上升，需实测是否超 300 MB）；或改为"体积壳只在有洞穴/悬垂处存在"的稀疏实例。
2. **跨界实测守不住 hitch-free** ⇒ 加大预取环宽或引入按行进方向的非对称预取（Minecraft 形态，ADR 0020 已登记为可选切换项）。
3. **CDLOD 接缝长期不收敛** ⇒ 改 Geometry Clipmaps 或用裙边（需另开 ADR）。

## 修订（2026-10-06）：体积壳的**覆盖半径**降为 ±4 tile（所有者裁定）

- **改了什么**：本节决策二把 **Ring 0（0..8 tile ≈ 512 m）划为"体积壳"**；W7-S3b① 实测该口径**超预算**
  （目标 **4085** 个壳块；首次规划主线程冻结 **1.05 s**；逐块 `JPH::MeshShape` 构建 ≈16 ms/块 ⇒ 23 s；
  运行期尖峰 176–261 ms）⇒ 所有者裁定：**体积壳只覆盖玩家 tile ± 4（256 m）**，其余仍由高度场 LOD 承担。
- **不变的**：**LOD 分环（8/16/32）本身不变**（Ring 1/2 仍按本 ADR 决策二）；变的只是"**哪一段用体积壳**"。
  已实现：粗采样 + 高度余量的 Y 范围（消除规划冻结）、`MeshShape` BVH **下沉 worker**（主线程只加体）、
  分帧建 / 卸 + 接管翻转（见 `docs/plans/v0.4.md` §1.13）。
- **降级三点（按 SKILL「降级必须先问」）**：① **降到什么程度** = 真三维（洞穴 / 悬垂）的近场半径 512 m → **256 m**；
  ② **为什么** = ±8 的块数（4085）与逐块碰撞体成本守不住 hitch-free / 内存预算（实测见上）；
  ③ **何时补回 / 切换条件** = 当"壳块 GPU 缓冲池化 + 帧级安装限流 + draw call 收敛"落地并实测守住预算，
  或改为"体积壳只在有洞穴 / 悬垂处存在"的**稀疏实例**（见上「何时需要重新审视」第 1 条）时，可评估回到 ±8。
- **仍待收口（不影响本修订）**：安装 ≈10 ms/块（GPU 缓冲未池化）与壳块带来的 draw call 上升（渲染提交 ~50 ms/帧）
  尚未达标 —— 属 **S4 性能收口**，见 `plans/v0.4.md` §3。
