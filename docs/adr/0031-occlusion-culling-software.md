# ADR 0031：遮挡剔除 —— **CPU 软件遮挡**（地形高度场 + 低分辨率深度图 + 保守层级 Z 测试）

- **状态**：已采纳（2026-10-06）；**收敛 `SKILL.md` 待收敛项 6（遮挡剔除：硬件遮挡查询 vs 软件分层）**。
  **能力已实现但默认休眠**（实测零收益，见「实测结果」）—— 代码 / 单测 / 本 ADR 全部保留，`--occlusion=on` 可启用
- **日期**：2026-10-06
- **相关**：ADR [0024](0024-terrain-streaming-and-lod.md)（视距 / Draw Call 预算：≤ 6000 次/帧）、[0010](0010-render-quality-pipeline.md)（渲染质量线）、[0001](0001-render-backend-sdl3-gpu.md)（渲染后端 SDL3_gpu —— 本 ADR 的**约束来源**）、[0004](0004-hybrid-layered-world-representation.md)（地形 = 高度场 ⇒ 天然是主要遮挡体）
- **来源**：项目所有者 2026-10-06 指定"继续完成 2.3 档"→ P3 = 遮挡剔除；并在可行性核实后（本 ADR 背景 §2/§3）**选择路线 C = CPU 软件遮挡**
- **施工细则**：`docs/plans/v0.5.md` §1.15（P3）

## 背景

### 1. 为什么现在要收敛「遮挡剔除」

SKILL 待收敛项 6 的时限是"**V0.5 开工前**"，**已逾期**；规范（`references/meshing-and-render.md` §5）明文
「方案**尚未收敛**……收敛前**禁止实现，也禁止写候选方案**」。本 ADR 即该逾期项的收敛动作。

### 2. 为什么**不能**用业界标准做法（硬件遮挡查询 HOQ）

**实测（本仓库 vcpkg 依赖）**：`SDL3_gpu.h` **没有遮挡查询 API** —— 全文只有 `SDL_QueryGPUFence`（栅栏查询），
没有 "occlusion query / `SDL_GPUBeginOcclusionQuery`" 之类的设施。业界标准（UE5 **Hardware Occlusion Queries**、
DirectX/Vulkan 的 `D3D12_QUERY_TYPE_BINARY_OCCLUSION` / `vkCmdBeginQuery`）**在本项目的渲染后端约束下不可用**。

### 3. 为什么也**不用**「上一帧深度回读 → HZB」

同样实测：**默认 `MSAA = 2×`**（`engine/platform/settings.hpp`，所有者 2026-09-29 的显存取舍），
⇒ 主深度目标是**多采样**纹理；而 SDL_gpu **不支持深度 / 模板的多采样解析**（`SDL_gpu.h`："depth/stencil targets
do not support multisample resolves"）⇒ **无法下载**。要回读就得**再加一条 1× 深度预通道**（多一趟几何）——
代价大于收益，且这是"为了绕开后端限制而新增的一整条通道"，不属最小实现。

### 4. 性能现状（决定本项**不是当前瓶颈**，但仍按所有者指示收敛）

P1（阴影按级联剔除）+ P2（剔除相位）落地后，A 世界 10 km 实测：draw call p50 **5853 → 1404**、
渲染提交 p50 **27.6 → 7.8 ms**，**只用到 ADR 0024 上限（6000/帧）的约 23%**；余下帧尖峰的主导项是
**既有逻辑 / 流式相位**（非渲染）。故本 ADR **不承诺**性能收益，只承诺"**提供该能力且不破坏正确性**"。

## 决策

### 一、形态：CPU 软件遮挡（Intel MOC 的最小版），遮挡体 = **地形高度场**

1. 每帧在 **CPU** 侧把相机附近的**地形高度场**按列投影进一张**低分辨率 NDC 深度图**（`OcclusionDepthGrid`，如 160×90）：
   每格记录"落进该格的遮挡面深度的**最远值**"（`max` 聚合）。
2. 对每个**静态**网格的（渲染相对）AABB 做层级 Z 测试：把 8 个角点投影到 NDC ⇒ 屏幕格矩形 + 候选的**最近** NDC 深度；
   **当且仅当矩形内每一格都有遮挡面、且候选最近深度更远（含偏置）**时判为被遮挡。
3. **纯函数 + 固定顺序 ⇒ 确定性**（红线 7），可单测。

### 二、**保守性优先**（硬约束，违反即缺陷）

| 规则 | 理由 |
| --- | --- |
| **只剔主通道提交**；阴影列表**一律不动** | 被相机遮住的**投射体**仍可能把影子投进画面（B6 / B8 契约） |
| 任一格**无遮挡面 / 候选未完全落在 NDC 盒内 / 矩形越界** ⇒ **不剔** | 宁可多提交，绝不误剔可见物 |
| 每格取**最远**遮挡面深度；比较加**深度偏置** | 让判定偏"保守侧"，吸收浮点与高度场采样误差 |
| 屏幕矩形面积过大（近处网格）⇒ **不做**遮挡判定 | 既省 CPU，也避免"近处大网格被稀疏遮挡面误判" |

### 三、能力**可关闭**（符合 SKILL 第五节硬规则）

启动参数 **`--occlusion=on|off`**。**缺省 `off`（休眠）** —— 理由见下方「实测结果」：
这条最小路线在本场景**零收益**，故按 SKILL「已实现能力只允许用配置项关闭、不删代码」**保留能力、默认关闭**；
`on` 时启用，`off` 时逐位回退到"不剔"（与引入前一致）。

### 四、明确不做（登记为已知限制）

- **物体之间的遮挡不做**（只有地形当遮挡体）——物体的遮挡率低、且需要更贵的遮挡体管理；
- 不做多帧延迟 / 时间重投影（**不做**）；
- 不做 GPU 侧 HZB / 预通道（见背景 §3）。

## 备选对比

| 方案 | 结论 | 依据 |
| --- | --- | --- |
| **A. 硬件遮挡查询（HOQ）** —— UE5 标准做法 | **不可用** | SDL3_gpu 无遮挡查询 API（背景 §2） |
| **B. 上一帧深度回读 → HZB** | **不采用**（本阶段） | 默认 MSAA=2 + 无深度 resolve ⇒ 需新增 1× 深度预通道，代价 > 收益（背景 §3） |
| **C. CPU 软件遮挡（地形高度场遮挡体）** | **采纳** | 与 MSAA 无关、默认可用、确定性、可单测；高度场世界里地形即主要遮挡体 |
| **D. 不做**（保持"无遮挡剔除"） | 备选（所有者未选） | 当前渲染有预算余量；但该项已逾期，所有者选择先做最小版以收敛 |

## 后果

### 实测结果（2026-10-06，A 世界 10 km，`--world=world_a --auto-test --autofly=40`；`on` / `off` 各一次）

| 指标（hitch 帧内 p50） | `--occlusion=off` | `--occlusion=on` |
| --- | --- | --- |
| draw call | **1414** | **1413**（**无变化**） |
| 遮挡深度图覆盖 | — | **293 / 14400 格 = 2%**（1089 个采样点全命中） |
| 剔除相位 | 5.74 ms | **26.78 ms**（+21 ms） |
| 帧尖峰条数 | 27 | 20 |

⇒ **零剔除 + 显著 CPU 成本**。机制：逐点投影覆盖极稀（近处一个采样点的屏幕足迹可达几十列，却只写 1 格），
而保守判定要求"候选矩形内**每格**都有更近的遮挡面"⇒ 条件几乎永不成立。
**结论：这条最小路线在本场景不可用**，故**缺省关闭（休眠）**。

### 后果

- **正**：待收敛项 6 关闭（有结论、有实现、有单测、有实测）；能力与正确性由 8 项单测钉住；默认行为**无回归**（逐位回退）。
- **负 / 已知限制**：默认**不启用**（= 实际上没有遮挡剔除）；CPU 软件遮挡的**覆盖度**是决定性瓶颈
  （要修就得上"逐格射线 / 精确填充"，属更大改动）；**只挡地形**；
- **目视风险**：默认关闭 ⇒ 无假剔除风险；启用时由"保守性硬约束"（决策二）+ 单测兜住。
- **记账**：深度图为**纯 CPU 内存**（160×90×4 B ≈ 57 KB），不进 VRAM。

## 何时重新审视（切换条件）

1. **渲染后端换为自研 Vulkan / 直接使用 Vulkan 查询**（SKILL 第五节把它列为 **V1.0 之后**的暂缓项）⇒ **改回 HOQ**（业界标准）；
2. **draw call 再逼近 ADR 0024 的 6000/帧上限** ⇒ 升级为"完整 MOC / 物体互挡 / HZB";
3. **进入表现阶段或要求 release 达标** ⇒ 复核本项收益并调参（网格分辨率 / 采样间距 / 偏置）。
