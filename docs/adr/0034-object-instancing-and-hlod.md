# ADR 0034：物件**GPU 实例化**与**远景 LOD 链**（+ 物理共享 Shape）

- **状态**：已采纳（2026-10-07）
- **日期**：2026-10-07
- **相关**：ADR [0024](0024-terrain-streaming-and-lod.md)（draw call 预算与 CDLOD 分环）、
  [0029](0029-a-world-asset-enrichment-model-and-scatter.md)（素材与 `Model` 形态；其**决策四.2** 已登记"无实例化 ⇒ 数量受限"）、
  [0033](0033-world-content-placement-and-streaming.md)（流式散布）、
  [0004](0004-hybrid-layered-world-representation.md) 层③（几何绝不写进地形场）、
  [0028](0028-world-families-and-static-asset-first.md)（静态资产优先）
- **来源**：项目所有者 2026-10-07 指示"接下来考虑物件实例化 / HLOD"，并四答冻结：
  ① 做到 **"实例化 + 远景 LOD 链"**（**不做** impostor）；② 物理侧 **共享 Shape + 半径裁剪**；
  ③ **新建阶段 `docs/plans/v0.7.md`**；④ 本次即视为**解冻 P4**（原 2026-10-06 冻结：不启动、不删代码）。
- **施工细则**：`docs/plans/v0.7.md`

## 背景

1. **现状**：每个物件 = **1 次 `SDL_DrawGPUIndexedPrimitives` + 1 次 80 B 顶点 uniform 推送**（`MeshTransformUniform`，带去重）；
   阴影通道**再各一遍**（并逐级联各一份列表）⇒ 单物件最多 `1 + 级数` 次绘制。A 世界 draw call **p50 1386**（地形 tile 主导），
   但物件量**随内容上量线性增长** ⇒ 与"内容越做越多"的主线直接冲突。
   [ADR 0029](0029-a-world-asset-enrichment-model-and-scatter.md) 决策四.2 早已登记："无实例化 / HLOD ⇒ 数量必须受控、不能全图铺开"。
2. **P4 冻结已解除**（所有者 2026-10-07）：原冻结条件之一是"draw call 再逼近 6000/帧 或进入表现阶段"，
   现因**内容规模化主线**主动启动；本 ADR 即解冻的决策载体。
3. **平台能力（已核实 `SDL3/SDL_gpu.h`，非推测）**：顶点阶段可绑 **只读 storage buffer**（相机已在用）；
   `SDL_DrawGPUIndexedPrimitives` 带 `instanceCount` / `firstInstance`；另有 **indirect draw** 与 **compute pipeline**（本期不用）。
   ⇒ 实例化**不需要**更底层后端，SDL3_gpu 足够。

## 决策

### 一、渲染 = **GPU 实例化**（每个"原型"一次绘制）

- **原型** = 一个 `ObjectType` 的局部网格（已由 `object_mesh.hpp` / `BuildObjectMeshFromModel` 产出，**渲染与碰撞同源**）。
- **每实例变换**（世界原点 + 旋转，可选不透明度）放进**顶点阶段的只读 storage buffer**；顶点着色器按
  `firstInstance + gl_InstanceIndex` 取自己的变换，替代原先的逐网格 uniform 推送。
- 绘制 = `SDL_DrawGPUIndexedPrimitives(indexCount, instanceCount, 0, 0, firstInstance)` ⇒ **每原型 1 次**（主通道 + 阴影通道各一次）。
- **旧逐网格路径保留不动**（SKILL「已实现能力只允许用配置项关闭，不得删除代码」）：地表 tile / 动态网格 / 倒塌残骸继续走它；
  实例化是**新增路径**，不是替换。
- **阴影一致**：主通道与阴影通道**共用同一块实例缓冲** ⇒ 阴影与几何不可能错位（与既有"两通道推同一份变换"同源）。

### 二、实例数据**每帧一次上传**（硬约束）

- 每帧的可见实例列表 = **复用既有视锥剔除结果**（`RenderFrame` 前端打包进常驻暂存缓冲 → 一次 copy pass）。
- **禁止逐实例 push / 上传**（SKILL 第四节硬规则 3）：上传次数必须与"每帧一次"解耦，而不是与实例数成正比。
- 实例缓冲**容量在创建时定死**（满足 SKILL 硬规则 4：资源创建不得发生在渲染热路径）；超容量 ⇒ **WARN 并截断**（不静默）。

### 三、物理 = **共享 `Shape` + 半径裁剪**

- 相同几何（同一原型）的物件**共用一个 Jolt `Shape`**（引用计数，`Shape` 生命周期由 `PhysicsWorld` 统一管理）
  ⇒ 静态网体的**形状内存与构建成本**与实例数解耦（当前是每物件一个 `MeshShape`）。
- 物理体**只建在碰撞半径内**（内容已在 512 m 内，进一步收敛到"玩家能碰到"的范围）⇒ 体数与世界内容量解耦。

### 四、远景 = **原型 LOD 链**（**不做** impostor）

- 每个原型可有**低模代理**（由 `ObjectType` 的配置声明，或离线生成），按**到相机的距离**切换（切换在**远处**完成，避免 pop）。
- **不做** impostor / billboard 代理（登记为后续，见「何时重新审视」）。

### 五、边界不变

- 层③几何**绝不写进地形场**（ADR 0004 硬约束 1）；人工可进入空间仍用静态资产（ADR 0028）；
  本 ADR 只改"**怎么把同一份几何画很多次**"，不改"内容归属哪一层"。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **GPU 实例化 + storage buffer 实例变换**（采纳） | 每原型 1 次绘制；阴影同源；SDL3_gpu 原生支持；与既有"相机 storage buffer"同机制 | 需新增实例化管线变体与两个 Shader，随 MSAA 档位重建 | **采纳** |
| CPU 静态合并网格（把 N 个实例烘成一个大网格） | 零 Shader 改动 | 任一实例变化（放下 / 删除 / 流式增删）就要**重建整块**；与流式增删冲突 | 不采纳 |
| 只做更好的剔除（不实例化） | 改动最小 | draw call 仍与物件数成正比 ⇒ 不解主线问题 | 不采纳 |
| **impostor（八面体 billboard）** | 远景近乎零成本 | 观感与美术长尾；需离线烘焙多视角 | 备选（**切换条件见下**） |
| **合并式 HLOD proxy**（UE5 式，把一片内容合一个代理） | 远景 draw call 更低 | 与"流式增删 + 玩家可摆放"耦合复杂；地形已有 CDLOD | 备选（**切换条件见下**） |
| GPU-driven 全剔除（indirect + compute） | 上限最高 | 复杂度大；本阶段收益不明 | 备选（**切换条件见下**） |

## 后果

### 正面

- **draw call 与物件数解耦**：同类型 N 个物件从 N 次降到 **1 次**（主 + 阴影各 1）；
- **物理内存/构建成本与实例数解耦**（共享 `Shape`）⇒ 内容上量不再线性抬高成本；
- 复用既有剔除与"渲染 / 碰撞同源"口径，**不引入第二条几何通路**。

### 负面 / 必须承受的代价

- 新增**实例化管线变体 + 2 个 Shader**（`mesh_instanced.vert` / `shadow_instanced.vert`），须按 **SPIR-V + DXIL 双格式**编译，
  并**随 MSAA 档位重建**（同 `CreateMainPipeline` 现有做法）；
- 实例缓冲是**新增显存**（每实例 ≈ 64~80 B × 容量）——**须计入 VRAM 记账**（ADR 0010 的记账义务，当前网格缓冲尚未入账，一并补）；
- **LOD 切换**要保证在远处完成（否则可见 pop）；低模代理的来源需在配置里声明（数据驱动）；
- 若某原型实例数很少（1~2 个），实例化路径**不划算** ⇒ 需要一个**阈值**（低于阈值走旧路径），阈值进配置。

## 落地记录（V0.7 H1~H4，2026-10-07）

- **决策四的"低模代理来源"已定**：**由本工程自动生成**（`world/object/object_mesh.hpp` 的 `BuildLowPolyProxy`，
  **顶点聚类**，加载期 / 离线生成）—— 不依赖美术额外产出；将来若美术提供针对性代理，可改为**配置声明**覆盖（数据驱动）。
  聚类会轻微改变轮廓 ⇒ **只在远处切换**（切换距离 200 格，像素占有率 < 1%）；退化保护：代理顶点 < 8 或索引为空 ⇒ 回退原网格。
- **落地取值**（均为具名常量 + CLI 开关，可实测微调，不动结构）：
  - 每类型实例缓冲容量 **1024**（超容量截断 + WARN）；实例化阈值 **4** 个可见实例（`--object-instancing=on|off` 总开关）；
  - 静态物件物理体碰撞半径 **128 格**（`--object-collision-radius=<格>`，`0` = 关闭裁剪）；
  - 远景 LOD 切换距离 **200 格**、聚类格距 **0.5 格**（`--object-lod-distance=<格>`，`0` = 关闭）。
- **实测（world_a，debug，2026-10-07）**：draw call **2800 → 2219**（物件 **132 → 201** 而 draw call 增量 **0**）；
  共享 `MeshShape` **14/14 类型**、体数 **704 → 643**；低模代理 **11 类型**、远景顶点 **−83%**；
  网格缓冲 **231.84 → 233.51 MB**（**+1.67 MB**，无下降 —— 见下）。
- **已知缺口（未做，登记切换条件）**：**逐物件 GPU 网格未移除** ⇒ 没有"实例化省下的显存"（+1.67 MB 是净增）。
  为什么：旧逐网格路径必须保留（阈值以下 / 动态物件回落），而"物件转动态时再上传网格"会**在渲染帧创建资源**
  （违反 SKILL 硬规则 4）。切换条件 = 把该上传做成**加载 / 非热路径**（例如闲置帧预算）之后，再让静态物件不建逐物件网格。
  另：实例化物件**未做逐级联阴影过滤**（每级都画全部实例，冗余但不漏投影）⇒ 需要再压 draw call 时补。

## 何时需要重新审视

1. **远景顶点量 / 带宽成为瓶颈**，或需要更远视距 ⇒ 上 **impostor**（切换条件：LOD 链最粗一级仍占显著顶点/带宽）；
2. **内容不再"离散摆放"而变成大片成规模**（如整片森林用同一原型数千个）⇒ 上 **合并式 HLOD proxy**；
3. **CPU 侧剔除成为瓶颈**（实例数上万）⇒ 上 **GPU-driven 剔除（indirect + compute）**（SDL3_gpu 已具备能力）；
4. **Jolt `Shape` 共享的引用计数 / 生命周期**在动态破坏场景下出现悬垂 ⇒ 回到"每体一 Shape"，并把该退化登记进本节。
