# ADR 0040：输入上下文栈与动作归属表（按键隔离的单一权威）

- 状态：**有效**（2026-10-08）
- 相关：[ADR 0032](0032-object-palette-and-placement-mode.md)（物件选择器与摆放模式；本 ADR **收敛**其决策四"模式内输入让位"的**实现方式**）、
  [ADR 0039](0039-three-interaction-modes-and-input-isolation.md)（三种交互模式与输入隔离；本 ADR **实现**其硬规则 2「三模式互斥」与硬规则 3「按键功能隔离」）、
  [ADR 0038](0038-construction-editor-and-runtime-separation.md)（编辑器分期；本项属 A 组"建造交互完善"后的**输入层收敛**）
- 落实：所有者 2026-10-08 —— "当前按键功能是怎么隔离的，要做好**统筹**（不同**面板状态**、不同**模式状态**下按键功能的隔离），
  该**复用**的地方也要**复用提高性能**（比如走动和飞行在三种模式下都是一样的逻辑），结合**业界规范和 3A 标准**，给出方案"；
  随后下令"**写入 SKILL 规范** + **一次性完成 S1~S4**"。
- 前置：V0.11 的 A5（三模式契约）已落地。本 ADR **不改变** A5 定义的交互形态，只改变"**判定写在哪里**"。

## 一、背景与真伪判定（**确认架构缺陷**，非功能缺陷）

**现象**：按键隔离规则**散落在 ≥ 5 处**，没有单一权威处：

| # | 散落点 | 位置 |
| --- | --- | --- |
| 1 | 发射判据**手写布尔** `!placementMode && !modifyMode` | `game/main.cpp` 的 `fireHeld` |
| 2 | 相机不转**手写布尔** `!gizmoDragging` | `game/main.cpp` 视角段 |
| 3 | 各模式分支**逐个** `ConsumePressed(...)` "让位" | `game/main.cpp` 建造 / 修改 / 其它三分支 |
| 4 | `Esc` 的 **5 级 `if/else` 链**（选择器 → 修改 → 建造 → 传送门 → 系统面板） | `game/main.cpp` |
| 5 | `suppression` 的**独立布尔**（与模式判定各判各的） | `game/gameplay_input.hpp` + `game/main.cpp` |

**判定 = 确认缺陷**（契约 = SKILL《三种模式与输入隔离》硬规则 2/3；机制 = 缺少单一归属权威）：
- **A5 已因此漏过一处** —— `fireHeld` 少排除 `modifyMode`（修改模式内一度仍会发光球）。这不是"看走了眼"，而是**结构使然**：
  新增一种模式 / 一个键，必须记得改**多处**，漏一处就静默出错。
- **"移动 / 飞行三模式同源"是隐式成立的**（靠"没有任何地方去 gate 它"），**不是显式声明** ⇒ 未来谁加一个 gate 就可能悄悄破掉。

## 二、决策

1. **引入「输入上下文栈」（`game/input_context.hpp`，纯函数、header-only）**，形态 = **分层 + 优先级 + 消费 / 穿透**：
   - **层（`InputContext`）**，优先级由低到高：**自由活动（base）** < **建造 / 修改** < **模态面板**；
     修改模式在"正在拖动 gizmo"时细分为 **`ModifyDrag`**（唯一差别：鼠标位移归 gizmo、不转相机）。
   - **状态（`InputContextState`）**：`build` / `modify` / `gizmoDragging` + 三个面板布尔（`objectPaletteOpen` / `portalMenuOpen` / `systemPanelOpen`）；
     `ModalPanelOpen(state)` = 三个面板布尔之或。
   - **`CurrentContext(state)`**：`Modal > ModifyDrag/Modify > Build > FreeRoam`（**玩法模式互斥由结构保证**）。
2. **动作归属表（单一权威）**：`OwnerOf(state, action) -> InputOwner`，取值语义：

   | `InputOwner` | 含义 | 谁处理 |
   | --- | --- | --- |
   | `Free` | 归**自由活动（base）** | 光球 / 传送门交互 / 相机 / 移动 / 飞行…… |
   | `Build` | 归**建造模式** | 放下 / 旋转 / 落点模式 / 室内变暗 / 右键删除 |
   | `Modify` | 归**修改模式** | 选中 / 拖动 gizmo（`ModifyDrag` 时另含鼠标位移） |
   | `Inactive` | 当前上下文**无效果**（**消费边沿**、不做事） | 防残余 / 防同键误触发 |
   | `Blocked` | 被**模态面板阻断**（玩法输入绝不泄漏到世界） | 无 |
   | `AlwaysOn` | **面板级热键**：任何上下文（含模态）都生效 | `F1` / `F2` / `F5` / `Ctrl+Z`·`Ctrl+Y` / `Z`·`X`·`B` / `Esc` |

   表的构造口径：**默认 = `Free`**（"新增动作默认归 base"是最安全的默认），再按上下文**覆写例外项**。
   完整矩阵（含"表 ↔ `ui-inventory` 逐格一致"的核对义务）写在 [`docs/ui-inventory.md`](../ui-inventory.md)。
3. **穿透 = 复用**：**未被子上下文 claim 的动作自动落到 base** —— 移动 / 跳跃 / 冲刺 / 飞行 / 视角是**表里均为 `Free` 的通用项**，
   三种模式下**逐位同源**；`command` 仍**每帧只算一次**供全部固定步复用 ⇒ **复用是显式的、性能不退化**。
4. **光球屏蔽 = 结构的后果，不是判据**：建造 / 修改上下文里 `Attack` 归 `Build` / `Modify` ⇒ 自由活动的发射路径**拿不到该动作**。
   **A5 那类遗漏在结构上不可能复现**。（SKILL 硬规则 1 由表保证。）
5. **`Esc` = 栈顶弹出**：`EscPopTarget(state)`（纯函数）—— 物件选择器 → 修改模式 → 建造模式 → 传送门菜单 → 系统面板，
   替换手写 `if/else` 链。任意"面板 × 模式"组合都弹出正确的一级。
6. **`suppression` 走上下文**：`DecideInputSuppression(InputContext)` —— **`Modal` ⇒ 三类全量抑制，其余 ⇒ 全放行**。
   去掉"面板布尔"与"模式布尔"各判各的（`F1` / HUD 等**只读叠加层**不进 `Modal` ⇒ **不抑制**，V0.9 回归不变）。
7. **边界（不合并）**：`MouseCapture`（`mouseCaptured` / `fireSuppressUntilRelease` / `captureBeforePanel`）是**物理层**（光标是否锁定），
   本栈是**逻辑层**（动作归谁）—— 两者**正交**，本 ADR **不合并**（合并会把既有的纯函数捕获状态机弄脏）。
8. **面板内部按键不走表**：`PaletteConfirm`（`Enter`）与各面板按钮是**面板自身**的确认 / 控件语义（由 `ObjectPaletteOpen()` 自门控），
   不属于"玩法 / 模式"的隔离契约。

## 三、备选方案与切换条件

| 备选 | 为什么不用（当前） | 何时改用 |
| --- | --- | --- |
| **维持散落手写判断** | 已出过一次漏（A5）、且新增模式 / 键要改多处 ⇒ 违反"可检查、单一权威" | 不再改用 |
| **把动作重绑定做成运行期可配置**（键位一键一键地改） | 超出本次范围（属"运行期可修改"的**输入重绑定**，工作量与 UI 都另算）；本次只收敛**归属**，不动**绑定** | 所有者提出"要能改键位"时（须另开 ADR：绑定表 + 冲突检测 + 落盘） |
| **模态面板拆成三个独立上下文** | 三个模态面板**当前**对玩法输入的隔离行为**完全相同**（全量抑制）⇒ 拆开无增量语义 | 某个面板需要"只抑制一部分"时（`InputContextState` 已保留三个独立布尔，成本低） |
| **把栈做进 `engine/input/`（引擎层复用）** | 三种模式是**本款游戏**的玩法契约；SKILL 明确"**不为未来的第二款游戏提前抽象**" | 出现第二款游戏且确实共用同一套模式契约时 |
| **运行期字符串匹配（按动作名查表）** | 热路径引入字符串比较与分配，违反"本项零开销"目标 | 不再改用 |
| **让路由层直接调用玩法函数（回调总线）** | 隐藏了"谁在处理这个动作"的调用点，可读性与可测性都下降 | 不再改用 |

## 四、后果与已知取舍

- **正面**：① "光球仅自由活动"由**结构**保证（不再依赖记得写 `!modifyMode`）；② 新增模式 / 键 = **加一行或一列**，diff 一眼可读；
  ③ 移动 / 飞行**显式**三模式同源（复用有出处）；④ `Esc` 逐级退出对任意组合自动正确；⑤ 归属矩阵**可单测**（面板 × 模式 × 动作），
  取代"靠人读 `main.cpp`"；⑥ 路由 = **O(1) 查表**，编译期常量、零分配、无字符串 ⇒ **热路径不退化**。
- **代价**：多一层间接（一个 header + 一次查表）。判断：**值得** —— 边界不在"模式数是 3"，而在**散落点 ≥ 5 且已出过一次漏**。
- **不做 / 不影响**：**不改键位绑定**（`InputMap::BindKey` 一行不动）、不改世界表示 / 破坏分级 / 存档字节布局、
  不改 `MouseCapture` 捕获状态机、不引入"动作重绑定"、**不删除任何能力代码**（SKILL §五）。
- **已登记取舍**：`ModifyDrag` 单列一个上下文值（为表达"拖动期间鼠标位移归 gizmo"）；`PaletteConfirm` 与面板按钮不走表。

## 五、验证（可检查判据）

1. **自动侧**：`tests/input_context_test.cpp` 覆盖**面板 × 模式 × 动作**矩阵（含：光球仅 `Free`、移动 / 飞行三模式均 `Free`、
   模态 ⇒ 玩法 `Blocked` 且热键 `AlwaysOn`、`Esc` 栈顶顺序）；`ctest` 全绿；`check-banned-identifiers.ps1` 通过；构建零警告。
2. **行为逐位不变**：引入前后的游戏行为一致（本次为**纯架构收敛**，不改变任何交互形态）——
   人工复验 A5 的四项（自由活动连发 / 建造·修改内不发光球 / `E` 不传送 / `Esc` 逐级）与 `F2`/`F5`/`Ctrl+Z` 等热键。
3. **表 ↔ 文档一致**（DoD 勾选项）：`OwnerOf` 的矩阵与 [`docs/ui-inventory.md`](../ui-inventory.md) §2.5 的「三种模式与按键隔离 —— 权威矩阵」**逐格一致**。

## 六、何时重新审视

- 出现**第四种玩法模式**，或某个模态面板需要**部分抑制**（⇒ 拆分 `Modal`）。
- 所有者要求**运行期改键位**（⇒ 另开 ADR：绑定表 + 冲突检测 + 落盘）。
- 出现**手柄 / 触摸**等非键鼠输入（⇒ 动作层不变，新增绑定源即可，本 ADR 的归属表无需改动）。
