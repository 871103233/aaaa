# ADR 0009：地表材质采用「逐像素权重 + 分层贴图（splat + 法线）」

- **状态**：已采纳
- **日期**：2026-09-25
- **相关**：`docs/plans/v0.1.md` T19；`references/meshing-and-render.md`（材质段）；`tech-plan-v2.0.md` §4；ADR 0008（尺寸 / 精度 / 预算）
- **取代**：`tech-plan-v1.3.md` / v2.0 §4 中"多纹理权重混合（splat）"的**笼统表述**——本 ADR 明确"权重在哪算""外观从哪来""采样怎么裁"

## 背景

人工实测指出：**地表在大型棱角处出现大片"过渡色"**。诊断结论（已核实）：

1. 现在材质权重（草 / 土 / 岩 / 沙 4 槽）在**顶点上**按"高度 × 坡度"算好写入顶点属性，由 GPU 在三角形内**线性插值**
   ⇒ 棱角处坡度在一个三角形内从缓变陡，整段变化被摊在 **约 1 格宽（≈ 一个人高）** 里，形成明显色带。
2. 这 4 个槽是**占位纯色**（无纹理、无法线、无细节）⇒ 插值结果只能"糊成一片"。
3. 顶点间距 1 格是**放大器而非根因**：即使加密到 1/4 格，只要仍是"平色 + 线性插值"，过渡依然存在，只是变窄。

同时需要纠正一个方向性误解：**贴图不是"省性能"的手段，恰恰是带宽开销的主要来源**。
逐像素重算权重很便宜（几次点乘 + `smoothstep`）；昂贵的是**每层贴图的采样次数**（4 层 × albedo+法线 = 8 次带各向异性过滤的采样）。
因此性能要靠**减少采样层数 / 分辨率 / 视距**来控制，而不是"少用贴图"。

## 决策

**权重用算的，外观用贴的。**

1. **权重逐像素计算**：顶点不再承载材质权重，片元着色器按**世界高度与坡度**（坡度由法线求得）重算各层权重，
   过渡带使用**窄带 `smoothstep`**（而非全域线性）。⇒ **过渡带宽由几何局部曲率决定，不再受顶点间距限制**，不加顶点、显存不涨。
2. **外观用分层贴图**：每层提供 **albedo + 法线（normal）** 两张贴图；**每层各自的 UV 尺度**；叠加**高频细节噪声**
   打散平铺重复与"机器般等距"的边界。**法线贴图是棱角立体感的主要来源**（靠它而非靠几何）。
3. **只对权重最高的 3~4 层采样**：这是控制带宽的关键手段，也是后续提性能的第一旋钮。
4. **占位贴图为程序生成**：运行时用已有噪声生成 albedo，并用高度噪声的梯度生成 normal ⇒ **不引入二进制资产、可复现、确定性**；
   后续可直接替换为美术 PBR 资源而**不改管线**。
5. **不在本次范围**（列为后续）：陡壁的**三平面映射（triplanar）**、大世界阶段的**运行时虚拟纹理（RVT）/ 虚拟纹理**把采样压到 1~2 次、
   以及**光照相关**的方向光 + 级联阴影 + AO —— 后者属独立渲染质量线（v2.0 §4）。

## 备选方案与取舍

| 方案 | 视觉 | 性能 | 工程成本 | 结论 |
| --- | --- | --- | --- | --- |
| 逐顶点权重 + 占位纯色（现状） | 差（宽色带 + 糊色） | 极低 | 已完成 | **不可交付**（已按 SKILL 第七节登记为品质未达标） |
| 逐像素权重 + 纯色 | 中（边界利落，但仍"平色"） | 低 | 低 | 仅作过渡，不单独立项 |
| **逐像素权重 + 分层贴图（albedo + 法线）** | 好~很好 | 中（靠层数裁剪控制） | 中 | **采纳**（3A 主流基础做法） |
| 上述 + RVT / 虚拟纹理 | 很好（大视距稳定） | 中高（需额外 pass 与页表） | 高 | 后续（大世界阶段评估） |
| 上述 + triplanar + 视差 + 宏微变化 | 极好 | 高 | 高 | 后续（局部顶配） |

**切换条件**：若纹理带宽成为主瓶颈（实测帧时间随层数陡增）⇒ 提优先级到 **RVT/虚拟纹理**；
若近景岩壁出现明显 UV 拉伸 ⇒ 局部先上 **triplanar**。

## 后果

### 正面

- 棱角边界变利落（与网格颗粒度**解耦**），且**不增加顶点与网格内存**。
- 外观具备材质感（纹理 + 法线），是走向"3A 观感"的必要基础；法线贴图带来的立体感收益最大。
- 程序生成占位贴图 ⇒ 管线可先行打通，美术资源可后接，**不阻塞**。

### 负面 / 必须承受的代价

- **新增显存与带宽开销**：4 层 × (albedo + normal) 的纹理数组 + mipmap。ADR 0008 的"VRAM ≤ 300 MB（V0.1）"仍有效，
  但**纹理部分需要单独记账**（本轮实现后须在 `engine-capabilities.md` 与预算里补登记）。
- **纹理缓存命中率成为新瓶颈**：性能调优的第一旋钮从"顶点数"变成"采样层数 / 分辨率 / 各向异性等级"。
- 材质参数（高度带、坡度带、UV 尺度、层数上限）现在**同时被 CPU（配置表）与 GPU（uniform）消费**，
  两边必须来自**同一份 `assets/config/materials.toml`**，否则会出现"配置改了但画面没变"的漂移。

## 何时需要重新审视

1. **LOD 与视距方案收敛后**（SKILL 待收敛项 4）⇒ 评估是否上 RVT/虚拟纹理（它同时解决视距与采样数）。
2. **纹理带宽成为主瓶颈**时（Tracy/RenderDoc 显示采样相关耗时占比第一）。
3. 需要**电影级近景**（视差遮蔽 / 置换）时 —— 属另一条线，须重新评估。
