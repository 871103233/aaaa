## 背景

1. **现状缺口**：层③（物件 / 建造）已有的形态是**土堆 / 石块 / 木箱 / 传送门 / 外部模型（GLB）**，
   它们都是**不可进入的实体**。ADR 0028 决策二要求"人工可进入空间（建筑 / 地宫 / 洞府 / 房间 / 城镇 / 塔）
   **一律用静态资产（模块化 kit）**"，但**没有任何 kit 构件、也没有把多件拼成一座空间的数据形态** ⇒
   "世界成立"这条链上的「**人能进去**」一直缺环（本 ADR 是补这一环）。
2. **判定归属（SKILL §五 三分类）**：① 地形 = 地面与大尺度形体（高度场）；② **人工规则空间 = 静态资产** ← **本次**；
   ③ 要挖的 = 体素 + 标记区域。⇒ 本 ADR **不碰地形**，只扩层③。
3. **业界参照（点名）**：
   - **UE5 Modular Building Kit + Grid Snapping**（模块化构件按**统一模数**吸附拼接）、
   - **Unity ProBuilder** / **Godot GridMap**（同"模数网格 + 构件库"形态），
   - **UE5 Level Instance / Skyrim·Elden Ring 的 load door 独立室内**（超大室内 = 独立空间/实例）。
4. **可判定判据（动手前立的 3A 基线）**：① **可进入**（门洞净高 ≥ 角色总高 + 余量，且洞里**真的没有几何**）；
   ② **无缝嵌入**（构件按模数对齐 ⇒ 接缝错位 = 0）；③ **室内变暗**（同材质在室内的屏上亮度比室外低 ≥ 30%）；
   ④ **性能**（构件走既有实例化 / 剔除 / LOD 路径，draw call 增量 ≤ 类型数）；⑤ **持久化**（配置可加载、可校验）；
   ⑥ **确定性**（同配置 ⇒ 逐位同结果，红线 7）。

## 决策

### 一、建筑 = **模块化 kit 构件** + **成套建筑声明**（新增两种数据形态）

- **构件**（`[[type]]`，`kind = "kit"`）：一个**带角色的模块化建筑构件**。角色（`kit_role`）取
  `floor` / `wall` / `wall_door` / `roof`；每类构件**必须**给出模数（`module_blocks`）。
  几何由 `BuildKitPieceMesh` 生成（**程序化代理体**，见决策二）：地板 / 屋顶 = 有厚度的板（顶面 = 可站面），
  墙 = 占满模数格的中间薄板，**门洞墙 = 两侧墙垛 + 门楣，洞口区域没有任何几何**。
- **成套建筑**（`[[building]]`）：`锚点（position + yaw_deg） + 构件清单（type + 相对偏移 + 附加 yaw）`。
  **这是"竖直堆叠"的唯一来源**：逐件 `[[placement]]` 的 `y` 一律按地表高度求解，因此"墙压在地板上、
  屋顶压在墙上"**只能**由成套声明的相对偏移给出。锚点的地表高度在**加载期解算一次**，全部构件共用同一基准。
- **展开在游戏层**（`game/main.cpp`）：构件复用**同一条装配路径**（`objectLayer.Place` + `addObjectSlot`）
  ⇒ 渲染 / 碰撞 / 视锥剔除 / GPU 实例化 / 远景 LOD **零分叉**（不引入第二条几何通路）。
- **不得引用传送门**：构件项没有 `target_world` 字段 ⇒ 引用传送门必然是"写了不生效"的静默配置，解析期**一律拒绝**。

### 二、美术资源 = **程序化代理体先行**（CC0 近风格 kit 记为备选）

- 首期**不引入外部美术资产**：构件几何由程序化代理体提供，保证"可进入性 / 模数对齐 / 室内变暗"三条判据
  **现在就成立**，且**零美术依赖**（不阻塞阶段闭环）。
- **CC0 公共库近风格 kit 作为备选登记**（切换条件见「何时需要重新审视」）：等进入**表现与深度**阶段、
  或业主认定代理体观感不达标时，按 ADR 0029 的既有流程（`NOTICE.md` 台账 + `Model` 形态）引入。
- **程序化代理体不等于"临时丢弃"**：它同时是**几何保证**（门洞净高的可判定来源）与**碰撞体来源**，即使将来接入
  美术 kit，也仍需保留为"无资产时的回退形态"（SKILL「已实现能力只允许用配置项关闭，不得删除代码」）。

### 三、**模数与可进入性 = 解析期强制的不变量**（非法即抛，ADR 0005 口径）

- **模数整除占地**：`2*half_extent.x` 与 `2*half_extent.z` 都必须是 `module_blocks` 的整数倍（容差 `1e-4`）。
  这是"拼起来不出现错缝"的**可判定不变量**（判据②）。
- **门洞净高**：门洞墙必须 `2*half_extent.y > kKitDoorClearanceBlocks`（**留得下门楣**），
  且 `kKitDoorWidthBlocks < 2*half_extent.x`（**留得下两侧墙垛**）。角色总高 1.80 格 ⇒ 净高下限取 **2.2 格**（余量 0.4）。
  这是"人能走进去"的**可判定不变量**（判据①）—— 几何侧由 `BuildKitPieceMesh` 保证洞口区域**没有三角形**（单测锁定）。
- **字段只允许出现在该出现的地方**：`kit_role` / `module_blocks` **仅 `kind = "kit"` 可给**，否则抛
  （与 `model_file` / `material_slot` / `target_world` 同一口径：写了却不生效 = 静默配置）。

### 四、室内变暗 = **逐实例的「围合体」解析式代理**（首期最小实现）

- **做法**：由建筑的**屋顶构件并集**求一个方盒代理（世界 XZ 包围盒 + 屋檐下沿高度，`ComputeBuildingEnclosure` 纯函数），
  整座建筑的每个构件带**同一份**；经**实例缓冲**送进 GPU（新增 2 个 `vec4`，见下），
  片元 `computeSkyVisibility` 判定"该片元是否室内" ⇒ 是则把**环境项（天空光 / IBL）**乘 `kInteriorSkyVisibility = 0.45`（**暗 55%**）。
- **判据**：① 片元 XZ 落在围合体内；② 且是"室内的面" —— **竖直面**法线的水平分量指向围合体中心（朝内的墙），
  **水平面**高度 ≤ 屋檐下沿 + `0.05`（地板 / 天花板）。**直接光不受影响** —— 它由级联阴影负责遮挡；
  本项补的是"**天空光不被阴影遮挡**"这个缺口。
- **为什么不用逐顶点烘焙 AO**（业界标准做法的轻量替代）：本阶段 kit 构件是**共享原型**（同一原型被多座建筑复用），
  逐原型烘焙**无法区分墙的内侧与外侧**；而业界标准（**UE5 Lightmass / Volumetric Lightmap**、
  **Unity Lightmap + Light Probes**）需要**离线烘焙管线** —— 本阶段尚未具备 ⇒ 按「降级必须先问」取**最接近的替代**：
  **解析式围合体 + 逐实例数据**（无烘焙、无新 GPU 资源、零运行期几何、成本 = 十几次 ALU）。
- **实例缓冲记录随之扩展**：`mat4`(64) + 围合体 `vec4`×2(32) = **96 B**（`kInstancePoseBytes`，
  与 `mesh_instanced.vert` / `shadow_instanced.vert` 的 std430 结构体逐字节一致；记账已同步）。
- **配套例外**：含围合体的实例组**不受实例化阈值（4）限制** —— 围合体**只能**经实例缓冲送到 GPU，
  若因构件数少而回落旧逐网格路径，室内变暗会**整段失效**。

### 五、与地形的结合 = **首期只放地形之上**（其余方案登记留痕）

- 首期：建筑**整体放在地表之上**（锚点解算地表高度，构件按相对偏移堆叠）。**不裁地形、不留通道、不嵌入**。
- **已知代价**：台地 / 斜坡上会出现"地板悬空 / 半埋"（与既有 `[[placement]]` 的同一限制，不是本 ADR 引入的）；
  需要**嵌入地形**时按备选表切换（**离线裁地形 + 留通道**，见下）。

### 六、边界不变

- 层③几何**绝不写进地形场**（ADR 0004 硬约束 1）；本 ADR 只**新增数据形态与装配路径**，
  不改"内容归属哪一层"，也不改地形的任何生成参数（可判定不变量：世界指纹不变）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **程序化代理体 kit + 成套建筑 + 放地形之上 + 解析式室内变暗**（采纳） | 零美术依赖；三条判据现在即成立；复用既有渲染 / 碰撞 / 实例化路径 | 观感是"白模级"；斜坡上会悬空 / 半埋 | **采纳** |
| **引入 CC0 近风格 kit**（如 Kenney / Quaternius 的建筑套件） | 立刻有像样的外观 | 需比对风格、建立 `NOTICE.md` 台账、处理逐模型贴图 / UV（**尚未做**，见 ADR 0034 / 0029 的同一前置） | 备选（**切换条件见下**） |
| **纯体素挖空**（把建筑当"要挖的区域"，用体积网格做出房间） | 无需 kit；天然可破坏 | 撞 ADR 0028 决策二（人工空间**不用**体素）；运行期不能生成几何；房间形状不可控 | 不采纳 |
| **嵌入地形**：离线裁地形 + 留通道（地宫 / 洞府 / 半地穴） | 空间感强；真正"陷进山体" | 需**离线工具**改地形并重烘相关 tile；与流式地形（ADR 0024）的接缝要额外处理 | 备选（**切换条件见下**） |
| **超大室内 = 独立空间 / 实例**（load door，Skyrim / Elden Ring 式） | 室内可任意大、与自己世界解耦 | 需门 + 切换 + 实例持久化（ADR 0030 已有单槽存档可复用） | 备选（**切换条件见下**） |
| **逐顶点烘焙 AO / lightmap**（UE5 Lightmass 式） | 业界标准的室内明暗，质量最高 | 需离线烘焙管线 + 逐实例烘焙数据；共享原型**无法区分内外侧** | 备选（**切换条件见下**） |
| **不做室内变暗**（室内与室外同亮） | 零成本 | 与"AAA 品质"目标冲突；且天空光不遮挡会让室内发假 | 不采纳 |
| **合并式 HLOD proxy**（把一座建筑合成一个代理） | 建筑成规模时 draw call 更低 | 与实例化路径重叠；当前建筑规模不需要 | 备选（沿用 ADR 0034 的登记） |
| **建筑持久化**（把 `[[building]]` 写进可编辑层 / 存档） | 玩家可自己建 | ADR 0032 的可编辑层目前只放 `[[placement]]` / `[[remove]]` | 备选（**切换条件见下**） |

## 后果

### 正面

- **补上「人能进去」这一环**：成套建筑 + 门洞净高保证 ⇒ 可进入性从"配置里写着"变成**几何上可验证**（单测锁定洞口无三角形）；
- **零分叉**：构件走既有装配路径 ⇒ 渲染 / 碰撞 / 剔除 / 实例化 / 远景 LOD **自动生效**，不引入第二套几何通路；
- **零美术依赖**：三条判据（可进入 / 模数对齐 / 室内变暗）现在即成立，不被"等资产"阻塞；
- **可判定可单测**：模数整除、门洞净高、围合体求法都是**纯函数 / 解析期校验**（22 个新单测）。

### 负面 / 必须承受的代价

- **观感是白模级**（程序化代理体），正式美术 kit 未接入；
- **实例缓冲每实例 +32 B**（64 → 96 B；当前容量 1024/类型 ⇒ 每类型 **+32 KB**，已计入 `meshStats` 记账）；
- **室内变暗是解析式近似**：屋檐下沿那一层、非轴对齐朝向的包围盒、门洞侧壁的两面，判定都不是逐面精确的
  （见「何时需要重新审视」第 1 条）；
- **斜坡上悬空 / 半埋**（首期只放地形之上）；
- **成套建筑目前只能来自发布清单 / 可编辑层**（玩家不能在运行时"盖房子"）。

## 落地记录（V0.8，2026-10-07）

- **数据**：`ObjectAssetKind::Kit` + `ObjectKitRole` + `ObjectType::kitRole / moduleBlocks` +
  `ObjectBuilding / ObjectBuildingPiece` + `ObjectTable::buildings`；解析 `[[type]] kind="kit"` 与 `[[building]]`。
- **几何**：`object_mesh.hpp` 的 `AppendBoxCentered` + `BuildKitPieceMesh`（门洞墙 = 墙垛 ×2 + 门楣）。
- **内容**：`assets/maps/world_a_objects.toml` 增 4 个 kit 类型（`kit_floor` / `kit_wall` / `kit_wall_door` / `kit_roof`，
  `module_blocks = 4.0`）+ 1 座可进入小屋 `spawn_hut`（4×4、门洞朝 +X、屋檐下沿 +3.3 格）。
- **室内变暗**：`ObjectEnclosure` + `ComputeBuildingEnclosure`（纯函数）+ `InstancePose` 围合字段 +
  `kInstancePoseBytes = 96` + `mesh.frag` 的 `computeSkyVisibility` + 两个实例化 vert / `mesh.vert` / `mesh_skinned.vert` 的 varyings。
- **实测（world_a，debug，2026-10-07，`build/v08_enclosure.log`）**：
  成套建筑 **1 座、展开 6 个构件（跳过 0）、其中 1 座带围合体代理**；
  物件实例化 **10 类型 / 132 物件 → 14 类型 / 138 物件**（多出的 4 个类型 = 4 个 kit 构件类，因"围合体例外"进入实例化）；
  draw call **2240 → 2235**（首帧）/ **2249 → 2243**（流式对账后）⇒ **零回归**（构件数少，实例化反而略降）。
- **验证**：构建**零警告**（`/W4 /WX`）；`ctest` **714/714**（较 V0.7 基线 689 增 **25**：
  `object_kit_test` 22 + `instance_batch_test` 3）；门禁 **220 文件 0 违规**。
- **已知缺口（未做，登记切换条件）**：**室内变暗的目视验收（P99 / 亮度比 ≥30%）需人工** ——
  本环境无法向前台窗口注入输入 / 截图；机制与判据已落到 shader 与单测，端到端观感由所有者目视确认。

## 修订（V0.9，2026-10-07 —— 见 [ADR 0036](0036-interior-darkening-param-and-building-placement.md)）

- **决策四的写死常量被取代**：`kInteriorSkyVisibility = 0.45` 由**全局可调值 + 逐建筑覆盖**取代 ——
  全局走 `--interior-darkening=<0~1>`（缺省 0.45，`1.0` = 关闭），逐建筑走 `[[building]].interior_darkening`
  （经实例缓冲的空闲分量 `enclosureB.y` 承载）。**机制（解析式围合体 + 逐实例数据）不变**，只把常量参数化。
- **决策五仍是现行口径（"首期只放地形之上、不裁地形"）**：ADR 0036 的落点模式 **①（压平地形）/③（填充地形）不放行**，
  与决策五一致；②（向下半埋）/④（落地必须平整）**不改地形**，属决策五允许的范围。
- **决策三 / 六不变**：构件仍复用同一条装配路径（零分叉）；层③几何仍绝不写进地形场。
- **「何时需要重新审视」第 6 条（玩家自建 + 持久化）已部分落地**：成套建筑的**运行期摆放 / 删除**与
  **可编辑层落盘**已由 ADR 0036 实现（仍**不触发**世界状态存档 —— 那是 V0.3 的范围）。

## 修订（V0.10，2026-10-07 —— 见 [ADR 0037](0037-world-state-save-v2-and-terrain-persistence.md)）

- **决策五（"首期只放地形之上、不裁地形"）被解除**：该限制的**唯一硬理由**是"改地形无持久化"；
  ADR 0037 使地形改动**可持久** ⇒ **放行落点模式 ①（压平地形）/ ③（悬空处填充）**。
- **决策六（层③几何绝不写进地形场）不变**；"**嵌入地形（离线裁地形 + 留通道）**"仍是**备选**
  （离线烘焙路线，与 ADR 0037 的"运行期改地形"是两件事），切换条件见本 ADR「何时需要重新审视」第 2 条。

## 何时需要重新审视

1. **室内明暗的观感不达标**（明暗边界生硬 / 屋檐那一层被误判 / 朝向非 90° 倍数时包围盒外扩可见）
   ⇒ 切到**逐顶点烘焙 AO**（或轻量 lightmap），切换条件：需要"逐面精确"而非"逐实例近似"；
2. **需要真正嵌进山体的地宫 / 洞府 / 半地穴** ⇒ 切到**离线裁地形 + 留通道**，切换条件：出现"建筑必须陷进地形"的需求，
   且能接受**离线工具 + 重烘 tile** 的成本；
3. **单座建筑内部规模超过"一间房"**（多层 / 大厅 / 院落）⇒ 切到**独立空间 / 实例**（load door），
   并复用 ADR 0030 的单槽实例存档；
4. **接入正式美术 kit**（CC0 或自制）⇒ 走 ADR 0029 的素材流程 + `NOTICE.md` 台账；**前置** = 逐模型贴图 / UV（ADR 0034 已登记的同一缺口）；
5. **建筑成规模**（几十座同时可见）⇒ 上 ADR 0034 已登记的**合并式 HLOD proxy**；
6. **玩家需要在运行时建造并保存** ⇒ 把 `[[building]]` 纳入 ADR 0032 的可编辑层与保存器，切换条件：出现"自建 + 持久化"的需求。
