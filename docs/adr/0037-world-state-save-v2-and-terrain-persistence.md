## 背景

1. **缺口**：世界状态**整块未落盘** —— 挖坑 / 挖洞 / 塌落 / 地形平整**重启即丢**。按 SKILL 的防走偏标尺
   （**世界成立 → 玩法成立 → 表现与深度**），"**能持久**"是"世界成立"链上**唯一还缺的一环**；
   不补它，后续任何改动都只活一次运行（破坏、建筑、建造全部白做）。
2. **它同时是 §5.6 的前置**：落点模式 ① 压平地形 / ③ 悬空处填充会**改地形**，此前**不放行**的唯一硬理由就是
   "地形改动没有持久化（重启即丢）"。持久化一旦就位，该理由消失 ⇒ 所有者已裁定**放行 ①/③**。
3. **业界参照（点名）**：
   - **容器 / 分块 + 索引**：**Minecraft Anvil（区域文件 + 位置表）**、本项目既有的 **ADR 0026 预制地图容器**（同一形态，已实测）；
   - **只存差量**：**Unreal World Partition / 关卡差异**、**Unity Terrain `TerrainData` 只写改动层**、**Godot 的 `PackedScene` 局部覆盖**；
   - **原子替换 + 版本纪律**：Minecraft `level.dat` 的临时文件替换、本项目 **ADR 0030**（TOML + `schema_version` + 临时文件 + `rename`）。
4. **可判定判据（动手前立的 3A 基线）**：① **往返逐字段一致**（写 → 读 → 与内存状态逐值相同）；
   ② **只存脏数据**（未改动的 tile / 块**不出现在文件里**，可用文件内 chunk 计数断言）；③ **确定性**
   （同一状态两次写盘**逐字节相同**，红线 7）；④ **版本纪律**（未知版本**拒绝**；布局变更**必须**配迁移函数 + 迁移测试）；
   ⑤ **主线程不阻塞磁盘**（读写走 worker；退出前强制 flush）；⑥ **世界定义一致性**（区域表 / 生成参数哈希不匹配 ⇒ **提示**，**禁止**静默迁移）。

## 决策

### 一、存档范围与**载体划分**（避免双份事实源）

| 脏数据类别（`references/save-and-serialization.md` §2） | 载体 | 本 ADR |
| --- | --- | --- |
| **高度场脏列**（挖坑 / 堆土 / 平整） | **`.voxr` v2** | **新增** |
| **脏体积块**（可挖区域内被改动的 32³ 密度 / 材质） | **`.voxr` v2** | **新增** |
| **物件与建造** | **仍是可编辑层 TOML**（[ADR 0032](0032-object-palette-and-placement-mode.md) `objects_edit_file`） | **不重复存** |
| **实体状态**（动态实体） | —— | **本阶段不做**（当前没有需要持久化的动态实体；登记为后续） |

- **为什么物件不搬进 `.voxr`**：物件已经是**可编辑层**（TOML，人可读、手可改、按世界清单绑定）⇒ 再存一份二进制就是
  **双份事实源**（"哪个说了算？"）。**不变量**：**同一条数据只有**一个**落盘处**。
- **为什么实体状态不做**：当前动态实体（光球 / 倒塌碎块）都是**瞬时**的，落盘没有语义；等出现"会留在世界里的动态实体"再按 §6.2 补
  （届时**必须**提升 `version` + 迁移）。

### 二、`.voxr` v2 **精确字节布局（冻结，本节即权威）**

> 冻结依据：`references/save-and-serialization.md` §3 要求"**首次存档实现前**定稿"；本 ADR 定稿并回填该文件。

**文件 = 头部（64 B 定长）+ 索引（`chunkCount × 32 B`，按 key 升序）+ 数据段（逐块 zstd）**，全部**小端**。

**头部（64 字节）**

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `char[8]` | `magic` | `"VXSAVE2\0"`（**读取器逐字节比对，不符即抛**） |
| 8 | `u32` | `version` | 存档布局版本 = **2** |
| 12 | `u32` | `flags` | bit0 = 含高度场脏列；bit1 = 含脏体积块；其余位**必须为 0**（否则抛） |
| 16 | `u64` | `generatorVersion` | **地形生成参数的内容哈希**（FNV-1a 64；决定"未改动数据重建后是否仍与原档一致"，与 `version` **分离**） |
| 24 | `i32` | `tileRadiusX` | 世界 tile 半径（两轴） |
| 28 | `i32` | `tileRadiusZ` | |
| 32 | `i64` | `worldSeed` | 世界种子（**十进制无损**；`i64` 以容纳负值） |
| 40 | `i32` | `digRegionSchemaVersion` | 可挖区域表 `schema_version`（[ADR 0006](0006-diggable-region-marking.md) §5） |
| 44 | `u64` | `digRegionContentHash` | 可挖区域表**内容哈希**（FNV-1a 64） |
| 52 | `u32` | `chunkCount` | 索引项数 |
| 56 | `u32` | `reserved` | 保留（**写 0**；读取器不校验，留作将来扩展而不升版本） |
| 60 | `u32` | `headerChecksum` | 头部前 60 字节的 **CRC32**（IEEE 反射多项式 `0xEDB88320`；**自写约 15 行实现**，本仓库此前无 CRC 工具，**不新增依赖**） |

**索引项（32 字节，按 `(kind, x, y, z)` 升序 ⇒ 写盘确定性）**

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u8` | `kind`（1 = `HeightDirtyTile`，2 = `VolumeDirtyBlock`） |
| 1 | `u8[3]` | `pad`（**写 0**） |
| 4 | `i32` `i32` `i32` | `x` / `y` / `z`（含义随 `kind`：高度场用 `(tileX, 0, tileZ)`；体积块用块坐标） |
| 16 | `u64` | `offset`（该块**压缩数据**的绝对文件偏移） |
| 24 | `u32` | `compressedSize` |
| 28 | `u32` | `rawSize`（解压后长度，用于分配与**越界校验**） |

**数据段（逐块）**：`zstd(raw)`；`rawSize` 为解压后长度。

**块内 `raw` 格式**（**一律紧凑小端、无填充** —— 逐字节顺序写，不落任何结构体对齐）

- `HeightDirtyTile`（**只存脏列**，与 §2 "粒度 = 列" 一致）：
  `u32 entryCount` + `entryCount × { u16 columnIndex（0..4095，行主序）; i16 heightDelta }`（每条 **4 B**，顺序写）
  —— `heightDelta` = **相对生成结果的高度差**（1/16 格单位，[ADR 0008](0008-sizes-precision-budget.md)）。
  **必须存差值而非绝对值**（生成算法升级后仍可叠加，§2）。
- `VolumeDirtyBlock`：
  `u8 materialPresent` + `u8[3] pad` + `int8 density[32³]` + （`materialPresent == 1` 时）`u8 material[32³]`
  —— 与 `VolumeBlock` 的内存布局一致（[ADR 0014](0014-voxel-material-index.md) 的"懒分配材质"）；
  `materialPresent == 0` 时材质仍按列派生（`0xFF` 语义不变）。
  **「32³」的精确含义（S3 落地补充，2026-10-07）**：= 该块**拥有的**采样（局部 `[0, 32)`），**不含**共享边界层 ——
  体积块的采样数组是 **33³** 且相邻块**重叠一格**（A 的局部 32 == B 的局部 0，同一个世界采样）⇒
  每块只存**自有**那一格，**每个世界采样在档里恰好出现一次**（与地表脏列"只导出本 tile 拥有的列"同一口径）。
  读回时**自有 32³ 直接写入**；那多出的一格（网格会读它）由 **`SampleDensity` 重算**（常驻 ⇒ 读块数据 /
  非常驻 ⇒ 回退高度场推导）⇒ 结果**与恢复顺序无关**，不需要把边界层也写进档（写进去等于重复存邻块的数据，
  且会改冻结布局）。材质**边界层不参与**采样解析（`SampleMaterialSlot` 只读**拥有**该采样的块）⇒ 无需重算。

### 三、加载顺序（**禁止颠倒**，§5）

`区域标记 → 生成初始密度/高度 → 叠加 `.voxr` 差量`。差量**只作用于已生成/已常驻的单元**；
未常驻单元不加载差量，等它被流式建出时**再叠加**（见决策四）。

### 四、与流式的耦合（本 ADR 的关键落地约束）

- **脏单元在流式窗口翻转时"存下再卸"**：一个 tile / 体积块被卸载前，若它是脏的 ⇒ **必须先完成差量落盘**
  （`references/save-and-serialization.md` §9）。**未写的脏单元不得卸载**（否则静默丢改动）。
- **常驻时不写**（避免每帧 IO）：脏数据在内存累积，按"**延迟批量 flush**（5~10 s）+ **退出前强制 flush**"写盘（§6）。
- 差量的**内存表示**由世界层持有（复用现有脏标记：地表脏 tile / 体积脏块），**不新开第二条记账**。
- **口径澄清（S4 落地补充，2026-10-07）**：上一条"必须先完成差量落盘"若按**字面**读（卸载前同步写完整个档），
  会与**决策五**"主线程**绝不**阻塞在磁盘"直接冲突。落地口径 = 取两条的**交集**：
  卸载前**先完成"差量已离开该单元"这一步**（采集进**内存会话** ⇒ 会话已持有该差量，卸载**不会丢改动**），
  真正的序列化 / 压缩 / 写盘仍由 **worker 异步**完成（主线程只提交快照 + 收包）。
  即：**决策四的"不静默丢改动"是目的，决策五的"不阻塞主线程"是硬边界**；两者冲突时以"不冻结渲染帧"为准
  （SKILL 第四节）。落地见 `game/main.cpp` 的 `WorldStatePersistence`（`RecordTile` → 会话 → `Flush` 异步）。

### 五、IO 与写盘安全

- **原子替换**：写 `<path>.tmp` → `flush` → `std::filesystem::rename` 覆盖（口径同 [ADR 0030](0030-instance-save-slot.md)）。
- **异步**：序列化 + 压缩 + 写盘全部走 **worker**（`engine/core/task_scheduler.*`，[ADR 0003](0003-task-scheduler-and-ecs.md)）；
  主线程只在**收包点**做"换指针 + 日志"，**绝不阻塞在磁盘**（红线 2）。
- **失败必须上报**并保留上一份好档（失败**不**覆盖，临时文件清理），不静默。

### 六、版本与迁移纪律（红线 8）

- 文件头 `version` 与 `generatorVersion` **分离**（布局版本 vs 生成算法版本）。
- **读取到未知 `version` ⇒ 拒绝并明确报错**（不静默迁移，口径同 ADR 0030）。
- 任何字段 / 布局变更**必须**同时给出：迁移函数 + 迁移测试（"旧档能被新版本正确读出"）。

### 七、**解除 ADR 0035 决策五**（放行落点模式 ①/③）

- 决策五原文"**首期只放地形之上、不裁地形**"的**唯一硬理由**是"改地形无持久化"；本 ADR 使地形改动**可持久** ⇒
  **解除该限制**：落点模式 **① 顺手压平地形 / ③ 悬空处填充** 由"解析报错"改为**放行并实现**。
- **保留**：ADR 0035 决策六（层③几何**绝不写进地形场**）**不变**；"嵌入地形（离线裁地形 + 留通道）"仍属**备选**
  （那是**离线烘焙**路线，与本 ADR 的"运行期改地形"是两件事，切换条件见 ADR 0035 重审第 2 条）。

### 八、落点模式 ①/③ 的语义（放行后的口径）

| 模式 | 配置串 | 做法 | 记账 |
| --- | --- | --- | --- |
| ① 顺手压平地形 | `flatten` | 放下时把建筑 **footprint 内**的地表压平到**锚点高度**（`ApplyTerrainLevelRect`：**矩形内精确 + 矩形外 3 格边缘过渡带**平滑收敛，见下注） | 触发该 tile 的**高度场脏列**记录 → 随 `.voxr` 落盘 |
| ③ 悬空处填充 | `fill` | 把 footprint 内**低于锚点高度**的空隙**填到锚点高度**（同一条笔刷、反向） | 同上 |

> **注（2026-10-07 落地补充）**：**边缘过渡带是必须的**，不是可选项 —— 无衰减的硬边会在斜坡上留下**近垂直台阶**，
> 而地表是**单面网格**（主通道 `CULLMODE_BACK`）⇒ 画面会出现"看穿 / 破口"。这与本节原本写的"**边界平滑收敛**"一致；
> 过渡带宽度 = `kBuildingLandingFalloffBlocks = 3` 格（footprint 内仍精确压平，故"地基平"不受影响）。

> **注（2026-10-07 缺陷修复第二批 / S8，所有者裁定）**：①/③ **只改高度场**，而**体积接管区**
> （[ADR 0011](0011-layer-transition-volume-takeover.md)：地表四边形被跳过、表面由可挖体积绘制）内**画面上看不到
> 高度场**，且会在接管**边界**处让两套表面错开 ⇒ **破洞**。故本阶段的处理是：
> **① footprint 覆盖到常驻体积块 ⇒ 拒放 ①/③**（判据与 `ResidentQuadFilter::SkipQuad` 同源）；
> **② "不可放置"以逐网格 tint 把幽灵染红提示**（幽灵**始终显示**，不再整块隐藏）；
> **③ "把可挖体积表面也按 footprint 改平"（体积平整）登记为后续阶段的明确目标** ——
> 前置 = "可挖体积的几何编辑（密度场平面切割）"能力落地时。见 [plans/v0.10.md](../plans/v0.10.md) §2（S8）与
> `docs/adr/README.md` §五。

- **共用前提**：改地形**必须**走既有通路（脏标记 → 重网格 → 碰撞重扫 → **差量记账**），
  **不得**新开"只改渲染不改碰撞"的捷径（[ADR 0011](0011-layer-transition-volume-takeover.md) / [0012](0012-collision-takeover-by-volumes.md) 的"谁画谁挡同源"）。
- **成本**：每次放置触发一次局部重网格 + 局部碰撞重扫 ⇒ **分帧**推进（[第四节「不冻结画面」](../../.trae/skills/voxel-engine-dev-standards/SKILL.md)），
  且**不并入逐帧热路径**（它只在"放下"这一用户动作时发生，属一次性）。
- **交互摆放缺省模式**：**仍为 ② 向下半埋**（ADR 0036 决策四的暂定值，所有者本次未改判）。

### 九、边界不变

- **不启动暂缓项**：场景编辑器 / 脚本系统 / 多后端 / 自研 ECS 不变。
- **不动世界表示**：不引入新层；地形改动仍只落"高度场脏列 / 脏体积块"。
- **不把可挖区域标记写进存档**（它是世界定义输入，只记 hash）。
- **不把物件搬进 `.voxr`**（决策一）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **单容器 + 位置表 + 逐块 zstd**（采纳） | 与既有 ADR 0026 容器同源（**已实测**）、随机读、实现风险低 | 单文件随脏数据增长（脏数据量小 ⇒ 可接受） | **采纳** |
| 按 tile 分**区域文件**（Minecraft `region/` 目录） | 单文件有界、天然分片 | 需要目录 + 每文件头 + 跨文件索引；世界目录管理成本高 | 备选（切换条件：脏数据量增长到单文件 > 数百 MB 时） |
| 存**整列绝对值**而非差值 | 实现最简 | 生成算法升级后**无法叠加**（§2 明令禁止） | 不采纳 |
| 用 **SQLite / 现成 KV 库** | 事务、查询 | 引入重依赖、与"自定义二进制 + zstd"的既定格式原则冲突 | 不采纳 |
| **物件也搬进 `.voxr`** | "一个存档文件" | 与可编辑层**双份事实源**；且发布清单是**只读世界定义输入** | 不采纳 |
| **不放行 ①/③**（维持 ADR 0035 决策五） | 零地形副作用 | 所有者已裁定放行；且地形持久化到位后该限制无理由 | 不采纳（所有者裁定） |

## 后果

### 正面

- **补上"能持久"这一环**：挖坑 / 挖洞 / 塌落 / 平整**重启仍在**；
- **解开 §5.6**：落点 ①/③ 放行 ⇒ 斜坡上能"压平地形再放建筑"；
- **格式冻结**：`references/save-and-serialization.md` §3 从"待定"变为"已定稿"，后续实现有唯一权威；
- **零重复事实源**：物件仍在可编辑层，存档只补地形/体积差量。

### 负面 / 必须承受的代价

- **首次实现前无兼容基准**：格式一经冻结，**任何**变更都要迁移函数 + 迁移测试（红线 8）；
- **卸载路径多一个前置**：脏单元卸载前必须先落盘 ⇒ 流式调度要接这一条（否则静默丢改动）；
- **性能预算新增两处记账**：flush 的 CPU（zstd）+ worker 占用（须在准场景下实测，见 §7.4 固定基准）；
- **`generatorVersion` 是内容哈希**：地形参数一改，旧档**必然**报"生成不一致"（这是**正确的**——本来就不一致）。

## 何时需要重新审视

1. **脏数据量增长**（长期游戏后单文件过大） ⇒ 切到"按 tile 分区域文件"（备选表第 2 行）；
2. **出现"必须持久化的动态实体"** ⇒ 按 §6.2 第 4 类补 `EntityState` 块（**升 `version` + 迁移**）；
3. **多存档槽 / 玩家状态** ⇒ 另有 ADR（当前只有秘境绑定的单槽 TOML，ADR 0030）；
4. **地形改动量级远超预期** ⇒ 复核 flush 预算与固定基准（`tech-plan-v2.0.md` §7.4）。
