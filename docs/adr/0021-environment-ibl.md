# ADR 0021：环境贴图与 IBL（天空盒 + 漫反射 irradiance + 预过滤高光 + BRDF LUT）

- **状态**：已采纳（2026-09-29）
- **日期**：2026-09-29
- **相关**：[ADR 0010](0010-render-quality-pipeline.md)（**本 ADR 超出其"半球天空光"质量线，属其"切换条件"之一**）、[ADR 0009](0009-terrain-material-pipeline.md)（材质与 PBR 口径）、[ADR 0008](0008-sizes-precision-budget.md)（**VRAM ≤ 300 MB**）、ADR 0002（Shader 双格式）、T57（纹理加载能力，HDR 部分）、`docs/game-design.md` §2.4、`docs/plans/v0.3.md` T67
- **来源**：项目所有者 2026-09-29 裁定 —— 在"折中 / **完整三件套（GPU 多 pass）** / 最小"三档中选 **完整三件套**

## 背景

当前环境光 = **半球天空光**（`lighting.toml` 的天顶色 / 地平色 / 地面反弹色按法线 `y` 插值，见 ADR 0010 P1）。
它是**无方向性的近似**，有三个可观察的缺陷：

1. **天空不可见**：画面上方是清屏色 / 纯色，不是天空；远景与天空的交界不自然。
2. **环境光与"看到的天空"不同源**：环境色是一组常量，与画面里的天光无关 ⇒ 调了天空亮度，物体的环境光并不会跟着变。
3. **高光没有环境来源**：粗糙度低的表面只在**直射太阳**方向有高光；阴影里 / 背光面的低粗糙表面几乎全黑（现实里它们会反射天空与地面）。

这三条都属于"**看起来不好看**"（ⓒ 表现与深度的目标），且**只有环境贴图能表达方向性** —— 任何"再调几个常量"的做法都做不到
（这正是 ADR 0010 把 IBL 列为"超出质量线、须另开 ADR"的原因）。

## 决策

**引入环境贴图（HDRI）并落地标准 IBL 三件套**，全部在**加载期烘焙、运行期只采样**：

### 一、天空（Sky）
- 全屏三角 + 逐像素由**逆视图投影**求出视线方向 → 按**等距柱状投影**采样 HDRI → 写入 HDR 目标。
- 绘制时机：**主通道（HDR）内、网格之前**，深度测试关闭、深度写入关闭 ⇒ 网格照常覆盖天空，无需第二条颜色目标。
- 天空**不参与雾**（雾只作用于几何），但**参与色调映射**（与其它 HDR 内容同一通路）。

### 二、漫反射 irradiance（环境漫反射）
- 由 HDRI 做**余弦卷积**到 **32×16** 等距柱状（RGBA16F）：`E(N) = ∫ L(ω)·max(N·ω,0) dω / π`（数值积分，固定采样序 ⇒ 确定性）。
- 片元里 `环境漫反射 = albedo · E(N) · ao`，**替换**原来的"半球颜色按 `y` 插值"。

### 三、预过滤高光（Prefiltered specular）
- 由 HDRI 做 **GGX 重要性采样**，按**粗糙度分 mip**：mip `i` ⇒ `roughness = i / (mipCount − 1)`，共 **6 级**（128×64 起）。
- 片元里 `环境高光 = prefiltered(R, roughness) · (F0 · A + B)`，其中 `(A, B)` 来自 BRDF LUT。

### 四、BRDF LUT
- **256×256、RG16F**：split-sum 的第二项 `∫ f·(1−F0) + F0·... `，用 **Karis 解析拟合**（无采样、无纹理依赖、确定性）。

### 五、运行期口径
- `mesh.frag` 的**环境项**从"半球颜色混合"换成 `irradiance` + `prefiltered × BRDF`；
  **直接光路径（方向光 + 级联阴影 + Cook-Torrance）逐字不变** ⇒ 与 ADR 0010 P2 的观感可比。
- 环境项仍**只乘 ao**（AO 不作用于直接光，口径不变）。
- **资源**：Poly Haven **CC0** HDRI（2K 等距柱状 `.hdr`），由 `tools/fetch_assets.ps1` 取回、**不入库**（许可台账见 `NOTICE.md`）。
- **缺失 / 烘焙失败 ⇒ 回落**到现有半球天空光 + `WARN`（与 T66 的贴图回落同口径：**不静默、不崩**）。

## 备选方案（未采纳，留档；出现对应切换条件时经 ADR 修订切换）

| # | 备选 | 不采纳的理由 | 何时改用 |
| --- | --- | --- | --- |
| A | **继续半球天空光**（现状，ADR 0010 P1） | 无法表达方向性（背景三缺陷），且"环境光与天空同源"做不到 | 若 IBL 在实测里成为显存 / 帧时间瓶颈，且质量线允许回退 ⇒ 回退到本项 |
| B | 天空盒 + **CPU 端烘焙**（复用 `R8G8B8A8_UNORM` 纹理数组上传） | 8 位 UNORM **装不下 HDR**（天空亮度 > 1）⇒ 天空与高光出现**色带 / 过曝**失真；要修就得引入浮点纹理 API，等于回到本决策 | 不再采用 |
| C | 天空盒 + **只用 HDRI 的 mip 链近似高光**（不预过滤） | split-sum 的 `A/B` 项与粗糙度分级的能量不守恒 ⇒ 掠射角与低粗糙表面亮度明显偏亮 / 偏暗 | 若烘焙耗时或显存成为硬约束，可先降到本项（**须先经所有者确认**） |
| D | 用 **compute shader** 烘焙（而非图形 pass） | 本轮**不引入**：渲染管线已按图形 pass 组织（阴影 / 主通道 / 色调映射），compute 是另一套绑定与同步模型，收益（更自由的 GATHER）不抵风险 | 烘焙耗时成为实测瓶颈时经 ADR 修订 |

## 后果

1. **显存增量（2026-09-29 实测回填）**：天空 HDRI 2048×1024 RGBA16F（**不含 mip**）**16.78 MB** + irradiance 32×16 0.004 MB +
   预过滤 6 级 128×64 0.083 MB + BRDF LUT 256² RGBA16F 0.5 MB ⇒ **实测 16.59 MB**（与预估 ≈23 MB 同量级；
   差值来自"天空不带 mip 链"与"LUT 用 RGBA16F 而非 RG16F"两处实现取舍）。
   实测总量 **214.67 MB**（加载期）→ **262.42 MB**（阴影 3 级 2048² 建成后）**≤ 300 MB**（ADR 0008）✓。
   **若实测超预算**：按「何时重新审视」第 1 条把 HDRI 降到 1K（≈ −9 MB）。
2. **启动耗时（2026-09-29 实测回填）**：三条烘焙 pass（irradiance 32×16×2048 采样、预过滤 6 mip × 256 采样、LUT 解析）
   + HDRI 半精度转换与上传，**实测 165 ms**（2K HDRI、2560×1440 交换链）—— 远低于"1 s"的重审阈值，
   故维持**加载期阻塞式一次性提交**（与 `CreateTextureArray` 同模式）；`game/` 侧把它拆成
   "解码 → 烘焙"两步并各出一帧加载画面（SKILL「不冻结画面」：画面不停，且进度可见）。
3. **Shader 与 uniform 扩面**：`mesh.frag` 新增 3 个采样器（irradiance / prefiltered / BRDF LUT，set 2 binding 6..8，
   总采样器 9 ≤ 16 ✓）；新增天空管线与 3 条烘焙管线（各自 `.vert`/`.frag`，走既有 glslc → SDL_shadercross 双格式）。
4. **确定性（红线 7）**：烘焙的采样序（Hammersley 序列）与 LUT 的解析公式**固定** ⇒ 同一 HDRI 每次启动得到**同一张** irradiance / 预过滤 / LUT。
5. **太阳与 HDRI 的关系**：`lighting.toml` 的太阳方向**暂不**从 HDRI 推导（两者可能不一致，属**已知限制**，登记为待办：
   "可由 HDRI 最亮方向推导太阳"）。切换条件：目视发现"天空里的太阳位置与阴影方向不一致"。
6. **与 `indestructible` / 地形无关**：本 ADR 只改"环境光怎么来"，**不改**任何世界层语义与破坏规则。
7. **雾色仍取 `lighting.toml [sky].horizon_color`（已知限制，2026-09-29 实现期登记）**：雾的远端颜色是一个**常量**，
   而天空换成了 HDRI ⇒ 地平线附近"远景融入天空"可能不再完全吻合（HDRI 的地平带亮度与该常量不必然一致）。
   **未一并实现的原因**：从 HDRI 推导雾色需要 CPU 侧统计地平带的平均辐照度，且要定义它与显式 `fog.color` 的优先级
   —— 属独立的小决策；当前先按"改一处只动一处"落地，避免把两个量绑死。
   **切换条件**：目视发现地平线处有可见色带 / 硬边 ⇒ 增加"由 HDRI 地平带推导雾色"（仅在 `fog.color` 缺失时生效）。

## 何时重新审视

1. **实测显存超 300 MB** ⇒ 先降 HDRI 分辨率（2K → 1K），再考虑把 irradiance 与预过滤合并 / 降 mip 数。
2. **实测烘焙耗时 > 1 s** 或成为可感知的启动卡顿 ⇒ 按备选 **D** 改 compute，或把烘焙下沉工作线程。
3. **目视发现"天空的太阳位置 ≠ 阴影方向"** ⇒ 增加"由 HDRI 最亮方向推导太阳方向"（后果 5）。
4. **PvP / 联机阶段**（`tech-plan-v2.0.md` §8 V1.0）：环境贴图属**纯客户端视觉**，不需同步；本 ADR 无需改动。
