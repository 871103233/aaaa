## 背景

1. **实测**（T72 / T61）：可挖体积"按需建块"是**主线程同步**的，单块 = `FillBlockDensity` + `MeshBlock`
   ≈ **22 ms**（debug 构建），而窗口挪一格要建一整圈（实测 **63 块**）⇒ 成串 33~175 ms 帧尖峰。
   T73 的滞回、T80 的预取把"何时建"摊平了，但**单块 22 ms 仍然整块落在渲染帧里**
   （违反 SKILL 第四节「所有重活都必须离开渲染帧」：单次 > 3 ms 必须按帧切分或**下沉 worker**）。
2. **业界标准做法（T77 清单第 4 条已点名）**：**Sodium 的 chunk builder**（worker 池 + 主线程只收包上传）、
   **UE5 Task Graph**（任务化 + 依赖）、**Unity Job System + `MeshDataArray`**（job 产数据、主线程一次性 apply）、
   **Horizon / id Tech 的 streaming budget**（构建必须在可见之前完成）。
   四者的共同形态都是：**worker 独占一个块的构建，主线程只做"收包 + 有上界的上传"**。
3. **本项目已具备的前置**：enkits 已由 [ADR 0003](0003-task-scheduler-and-ecs.md) 选型（端口 `enkits`，
   本地 vcpkg 注册表有 1.12），但**从未真正链接使用**（`docs/engine-capabilities.md` 记为"已引入未使用"）。

## 决策

### 一、形态：**快照式纯函数构建 + enkits worker 池**

- **worker 只做纯计算**：输入是一个**不可变快照** `DigVolumeWorld::BlockBuildInput`（在**主线程**一次性采齐），
  输出是 `VolumeBlock` 的密度 / 网格 / 填充分类。worker **不读世界对象、不碰任何图形 API、不加锁**。
- **主线程只做两件事**：① 采快照 + 提交（`BeginCreateBlock`）；② 收结果并**安装**（`InstallBuiltBlock`）——
  安装是**单写者**写入 `DigVolumeWorld::m_blocks`，随后照旧走既有的"GPU 上传 + 三角网碰撞体 + tile 重网格"延后队列。
- **一次"块构建"= 一个任务**：不引入跨帧的依赖图（本阶段建块之间**没有**依赖：见下"为什么不需要邻居依赖"）。
  任务由 `VolumeBuildPipeline` 管理（`enkits::TaskScheduler`）；结果通过**只保护结果队列**的小互斥量移交主线程。

### 二、确定性（红线 7）：**同一块"worker 构建" == "主线程构建" 逐位一致**

- 快照包含**全部外部输入**：① 列表面高度补丁（35×35，供"地表推导密度"）；② 列派生材质槽位补丁（35×35）；
  ③ "壳层"采样（局部坐标 `-1` 那一圈，34³ 减去自家 33³ = **3367** 个：邻块已写入的密度 / 材质，
  邻块不存在时**按同一公式**推导）。
- 密度的**算术与同步路径共用同一个函数**（`TerrainDerivedDensity` 抽出的纯函数），
  网格化共用同一个 `BuildVolumeMesh`，分类共用同一个 `ClassifyFill`
  ⇒ 结果只由快照决定，与"在哪个线程算"无关。**这条由单测逐位钉住**
  （`DigVolumeWorker.PipelineBuildMatchesMainThreadBuildBitForBit`）。
- **不需要邻居依赖**：同步路径 `CreateBlock` 只填**自己**的块并网格化自己（不重网格邻居），
  而网格化读取的越界采样由 `BlockSampler` 按"邻块已存在则读它、否则按高度场推导"回答 ——
  这**正是快照所捕获的东西**。因此"把块 A 与块 B 的构建并行"与"顺序构建"结果相同（各自的壳层取自
  采集时刻的世界状态，与同步路径同一时刻的状态一致）。

### 三、并发契约（`references/concurrency.md` 逐条落地）

| 契约 | 本方案的落地 |
| --- | --- |
| 主 / 渲染线程：窗口、输入、GPU 提交 | 只做"采快照 + 提交 + 收结果 + GPU 上传" |
| Worker：计算 | `FillBlockDensity` + `MeshBlock` 的**纯函数化**部分；**不触碰图形 API** |
| 单写者 + 不可变快照 | worker 独占自己的 `BlockBuildInput`/输出；主线程独占 `m_blocks`；**发布 = 结果队列移交** |
| 禁止对区块加粗粒度锁 | 唯一互斥量只保护**结果队列的进出**（几行 push/pop），**不保护任何世界数据** |
| 版本号 / 陈旧结果 | 提交时记录 `BlockCoord`；**安装时校验该块仍不存在**（窗口又移动过则会话内不再需要它 ⇒ 直接丢弃，不静默使用陈旧数据） |

### 四、失败与降级

- **worker 不可用**（线程创建失败 / enkits 未初始化）⇒ **回落同步路径** `CreateBlock`，
  并 **WARN 一次**（不静默）：功能不变，只是尖峰回到引入本 ADR 之前的样子。
- **不做**（登记为后续可选切换项）：跨帧依赖图（邻居就绪 → 网格化）、按帧预算的工作窃取配额、
  生成 / 光照 / IO 的全面线程化 —— 本阶段只把"建块"下沉，其余仍走既有的**分帧队列**（够用，且风险最低）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **快照 + enkits worker 池**（采纳） | 计算完全纯函数（红线 7 好证）；worker 无锁、不碰世界；主线程成本 = 采快照（≈1~2 ms）+ 收包 | 需要一次 78 KB 级的快照拷贝 | **采纳** |
| 让 worker 直接读 `DigVolumeWorld` | 零拷贝、代码少 | **数据竞争**：主线程可能正在雕刻 / 增删块（TEARDOWN 顺序、邻居中途卸载）；需粗粒度锁（违反红线 9） | 不采纳 |
| 只用"按帧切分"（不引入线程） | 零并发风险；T37 的延后队列已具备 | 单块仍是 22 ms 的**一次**投入（切分只能摊薄，不能消除）；T72 结论：这是尖峰的直接来源 | 不采纳（保留为**降级兜底**） |
| 自研线程池 | 无第三方依赖 | 依赖图与唤醒逻辑易出竞态，须 TSan 验证；ADR 0003 已排除 | 不采纳 |

## 后果

### 正面

- 单块构建（当前 ≈22 ms）从**渲染帧**移到 worker：主线程只剩"采快照 + 收包 + 上传"，尖峰的**主要来源**消除。
- 计算变成**纯函数**（快照进、数据出）⇒ 可单测、可重放、与线程数无关（红线 7 的直接收益）。
- enkits 由"已引入未使用"变为**真正启用**，为后续（生成 / 光照 / 存档 IO 下沉）铺好唯一一条线程池。

### 负面 / 必须承受的代价

1. **结果晚 1~N 帧可见**：与 ADR 0020 决策四已登记的语义一致（"新挖出的洞 / 塌落可在 1~N 帧内补齐"）；
   建块方向同理 —— 块在**安装**后才进常驻集合与接管判据，因此不会出现"地表已跳过、体积还没画"的破洞
   （安装与上传在**同一帧**里按既有顺序完成）。
2. **快照是冗余拷贝**（每块约 78 KB × 2 缓冲）⇒ 常驻内存增加约 0.2 MB（可忽略，且可打印）。
3. **确定性依赖"快照采齐"**：将来若新增"块构建会读到的世界数据"，必须**同步扩充 `BlockBuildInput`**，
   否则两条路径会漂移 —— 由单测（逐位一致）守住。
4. 并发正确性只能用 **ASAN**（本机）验证；**TSan 需 Linux/Clang 配置**（`references/concurrency.md` §6），本轮未跑。

## 何时需要重新审视

1. **快照成本超过收益**（实测采快照 ≥ 单块构建的一半）⇒ 改为"按列 / 按块分级快照"或"预取时批量采快照"。
2. **出现需要跨块依赖的构建**（例如邻居就绪才网格化、或块间一致性的等值面缝合）⇒ 需要 enkits 的任务前置图，
   本 ADR 的"一任务一块"不再够用。
3. **TSan 可用**（Linux/Clang CI 落地）⇒ 必须补跑一次竞争检测。
