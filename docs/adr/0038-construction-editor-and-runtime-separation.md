# ADR 0038：建造能力升级为**独立场景 / 关卡编辑器**（编辑器与运行时分离）

## 背景

1. **现状**：建造能力目前是**运行时工具** —— `F2` 选择器 + 摆放模式（幽灵预览 / `Q`,`E` 旋转 / 左键放下 / 右键删除 /
   `F3` 重复 / `F5` 保存）+ **独立可编辑层 TOML**（[ADR 0032](0032-object-palette-and-placement-mode.md)）。
   它原本是 SKILL §五「**场景编辑器**」暂缓项对应的"当前阶段改用 = Dear ImGui 调试面板 + 配置文件"。
2. **缺口（为什么现在升级）**：该形态是"**逐件手工摆**"的最小工具，做**游戏地图**时效率不足：
   没有**吸附 / 对齐**（构件靠人眼对不齐）、没有**合法性检测**（重叠 / 悬空靠事后发现）、没有**撤销重做**（试错成本高）、
   没有**规模化手段**（几十座建筑同时可见时提交量线性增长）。业界做地图的标准形态是**编辑器**。
3. **所有者的用途口径（两条，缺一不可）**：
   - ① **作为引擎能力，用于开发游戏地图**（制作时使用）；
   - ② **后续可开放给玩家建造部分内容**（运行期使用）。
   ⇒ 二者**共用同一套建造核心**（吸附 / 合法性 / 撤销 / 序列化），差异只在 **UI 与权限**。
4. **判定归属（SKILL §五）**：本条属**解除暂缓项**（场景编辑器）⇒ 必须按《暂缓项启停纪律》执行：
   **过所有者确认 → 同一次提交内改文档（暂缓表 + ADR + 阶段计划 + 同步清单 + devlog）→ 才动手**。本 ADR 即该"确认 + 落盘"的产物。
5. **业界参照（点名）**：
   - **UE5 Editor**：World Partition（大世界分区加载）+ **Place Actors / Level Instance / Packed Level Actor**（多物件组合）
     + **Grid / Socket / Vertex snapping** + **Transaction（撤销重做）** + **HLOD**；地图在编辑器内制作、运行期只读烘焙/数据；
   - **Unity Editor**：**ProGrids / ProBuilder**（网格吸附）+ **Prefab**（多物件组合）+ **Undo 系统** + **LOD Group / Static Batching**；
   - **Godot Editor**：**GridMap**（网格化摆放）；
   - **玩家建造侧**：**Valheim / Rust / 7 Days to Die** 的**吸附 + 结构支撑/稳定性**规则（与编辑器共用吸附与校验核心）。
   - **通例**：**编辑器与运行时分离**（制作时工具与运行期构建分开，运行期不携带编辑器 UI）。
6. **可判定判据（动手前立的 3A 基线）**：
   - **吸附**：落点 / 旋转可被吸附到**模数**（读数 = 模数的整数倍），同一次拖动读数稳定；
   - **合法性**：**重叠 / 悬空** ⇒ **拒绝放置 + 可见提示**（复用 V0.10 / S8 的**逐网格 tint 变红**）；
   - **撤销重做**：`Ctrl+Z` / `Ctrl+Y` 至少 **32 步**一致回退（编辑层状态逐字段一致）；
   - **编辑器本身**：可装载 / 保存大世界（10 km）、**分帧推进、不冻结画面**（SKILL §四）；
   - **规模化**：几十座建筑同时可见时 **draw call 有界**（不随建筑数线性增长）；
   - **确定性**：同一编辑结果 ⇒ 数据文件**逐字节可复现**（红线 7）。

## 决策

### 一、形态 = **独立编辑器**（编辑器与运行时分离）

- **编辑器是制作时工具**：读入世界定义（地图预设 / 世界清单 / 物件清单）与世界数据，产出**数据文件**；
  **运行时（`voxel_game`）不携带编辑 UI**。
- **编辑器与运行时共用同一套"建造核心"**：吸附、合法性检测、撤销栈、蓝图展开、序列化 —— 全部是**与 UI / GPU 无关的纯逻辑**，
  置于可复用位置（见决策二）。编辑器与（未来的）玩家建造都调用它。

### 二、分层与目录

- 新增顶层目录 **`editor/`**（[file-index](../file-index.md) 已预登记为"规划中"）：
  **依赖方向 = `platform → engine → world → game → editor`（`editor/` 在最上层）**；
  **`engine/` / `world/` / `game/` 一律不得 include `editor/`**（SKILL §二 分层硬规则）。
- 建造核心的**纯逻辑**（吸附 / 合法性 / 撤销栈 / 蓝图）从 `game/` 抽到**可复用位置**：优先 **`world/object/`**
  （它已是层③的门面，纯函数、header-only 先例充分，如 `object_palette.hpp` / `object_preview.hpp` / `ground_pick.hpp`）；
  编辑器外壳（窗口 / 面板 / 交互循环）留在 `editor/`。
- **构建**：编辑器为**独立可执行目标**（新增 `editor/CMakeLists.txt`，在根 `CMakeLists.txt` 登记）；运行时构建**不链接**编辑器目标。

### 三、与现有运行时工具的关系（**不删除**）

- 现有 `F2` 选择器 + 摆放模式 + 可编辑层**全部保留**（SKILL《已实现能力：只允许用配置项关闭，不得删除代码》）：
  它是"**游戏内建造 / 调试**"的**活路径**，也是"**开放给玩家建造**"的落地形态；编辑器是它的**升级形态**，**不是替代删除**。
- 二者**写同一份数据**（发布清单只读 / 可编辑层为增量），互相**逐位可读回**。

### 四、首期范围与顺序（所有者 2026-10-07 选定）

**首期 = 建造交互完善**（顺序）：**吸附 / 对齐 → 重叠与悬空合法性检测 → 撤销重做 → gizmo**。

后续顺序（同阶段或后续阶段）：**建筑与地形结合**（嵌入地形＝离线裁地形 + 留通道；体积平整）→
**内容扩展**（多套 kit + 院落级蓝图 + 地宫 / 洞府）→ **规模化 / HLOD**（合并式 HLOD proxy）。

### 五、数据与持久化口径

- 编辑器产物 = **数据文件**（发布清单 / 可编辑层 TOML；未来若改二进制须按 [ADR 0037](0037-world-state-save-v2-and-terrain-persistence.md) 的版本纪律）；
- **发布清单只读、编辑结果写增量层**（[ADR 0032](0032-object-palette-and-placement-mode.md) 决策五 / [ADR 0028](0028-world-families-and-static-asset-first.md) 的"A 不入库"）口径**不变**；
- 编辑器的写入与运行时的读回必须**逐位一致**（同一份解析 / 序列化实现，不新开第二条通路）。

### 六、边界（**不做 / 仍暂缓**）

- **不引入**脚本系统（Lua / sol2，仍属 SKILL §五 暂缓项）、多渲染后端、自研 ECS；
- 编辑器**不改变**世界表示（[ADR 0004](0004-hybrid-layered-world-representation.md) / [ADR 0023](0023-world-representation-v2-hybrid-shell.md)）、
  破坏分级（[ADR 0013](0013-destructible-elements.md)）、发布清单只读口径与 `.voxr` 字节布局。

## 备选方案与取舍

| 备选 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- |
| **继续运行时最小工具**（现状） | 与 SKILL §五 现行口径一致、零新增子系统 | 地图制作效率低（无吸附 / 合法性 / 撤销 / 规模化） | **不采纳**（所有者 2026-10-07 选编辑器）；原工具**保留**为运行时活路径 |
| **独立编辑器 + 与运行时共用核心**（本决策） | 与业界一致；工具与运行时职责清晰；核心可复用给玩家建造 | 新增顶层子系统；需维护 editor ↔ world 边界与独立构建 | **采纳** |
| **编辑器 = 游戏的"编辑模式"（同进程 ImGui）** | 省一套构建与外壳；复用现有渲染 / 面板 | "分离"不彻底（编辑 UI 进运行时构建） | 备选（切换条件见「何时需要重新审视」第 1 条） |
| **用第三方引擎做地图**（UE / Unity） | 现成编辑器 | 与"自研引擎 + 数据管线"冲突；美术 / 资产管线不兼容 | 不采纳 |
| **一次性做完整编辑器** | 一步到位 | 代价过大、风险集中 | 不采纳（**分期**：首期 = 交互完善） |

## 后果

- **正面**：地图制作效率提升（吸附 / 合法性 / 撤销 / 规模化）；建造核心与 UI / 平台解耦 ⇒ 编辑器与玩家建造**共用**，
  符合"产物是引擎、引擎层与游戏层分开"的总调（SKILL「产品方向与防走偏标尺」）。
- **代价 / 必须承受**：
  - 新增一个**顶层子系统**（`editor/`）与**独立构建目标**；
  - 需要维护 **editor ↔ world/engine 的边界**（依赖只能向上，编辑器不得被下层引用）；
  - 编辑 UI **不得**进入运行时构建；
  - **必须登记阶段计划**（`docs/plans/v0.11.md`）并同步 §五 暂缓表 / `adr/README` / 内容基线文档 / `file-index`。
- **不改变**：分层与依赖方向、世界表示、破坏分级、发布清单只读口径、`.voxr` 字节布局、渲染质量线。

## 何时需要重新审视

1. **编辑器与运行时共进程（ImGui 编辑模式）更划算**（外壳成本过高 / 复用现有面板收益更大）⇒ 评估过渡；
2. 地图规模 / 对象数使编辑器需要**增量加载 / 分区（World Partition 式）与 HLOD 预生成** ⇒ 评估分区与合并式 HLOD；
3. 需要**多人协作编辑 / 版本控制友好**⇒ 评估"文本格式 + 稳定 id" vs 二进制（并考虑 [ADR 0032](0032-object-palette-and-placement-mode.md) 的 `[[remove]]` 匹配口径）；
4. **开放给玩家建造**时 ⇒ 复用建造核心；PvP 下的**可破坏范围**按 [ADR 0028](0028-world-families-and-static-asset-first.md)「高风险点 1」单独定；
5. 需要**脚本 / 数据驱动的地图逻辑**（触发器 / 任务）⇒ 属 SKILL §五「脚本系统」暂缓项，**须另行下令 + 确认**。
