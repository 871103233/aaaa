# ADR 0012：碰撞接管 = 体积绘制的地表由**体积**提供碰撞；破坏后**失去支撑的实心体塌落**

- **状态**：已采纳
- **日期**：2026-09-27
- **相关**：ADR 0004（分层混合世界：硬约束 2「标记区域外不可挖掘」、硬约束 3「层间过渡由体积接管」）；ADR 0011（**渲染**上的层间过渡 = 区域足迹内由体积接管地表网格）；ADR 0007（Surface Nets）；ADR 0008（尺寸与精度）；`docs/plans/v0.1.md` 的 T28 / T29；`docs/game-design.md` §2.3「进入可挖体积」「结构塌陷」两条连带必做项
- **落地**：`engine/physics/physics_world.*`（三角网静态碰撞体）、`world/dig/volume_collision.*`、`world/dig/volume_collapse.*`、`assets/config/collapse.toml`、`game/main.cpp`

## 背景

ADR 0011 只解决了**渲染**问题：区域内由体积等值面画出可见表面，地表网格不再发射那些四边形。
但**碰撞**没有跟着走 —— 角色的地面碰撞仍是**每个地表 tile 一个 Jolt `HeightFieldShape`**，
它是"规则网格 + 每格一个高度"的**整体形状**，`UpdateHeightField` 只能整体换高度，**无法局部开洞、也无法局部失效**。

后果（人工实测，2026-09-27）：**洞口看得见、走不进去** —— 表面上"洞"已经存在，
但原地表高度场的隐形斜面仍把角色挡在洞口外。这在任何世界的常识里都说不通
（真实世界与修仙世界都一样：**洞是通道**），因此被 [SKILL](../../.trae/skills/voxel-engine-dev-standards/SKILL.md)
的「世界内一致性」审查判定为"不做则世界明显不自洽"的**连带必做项**。

同一审查还识别出第二个连带后果：**支撑物被破坏后，上方的结构不应悬空不动**，而应塌陷 / 倒塌
（用户原话举例："一个大楼应该倒塌"；并明确"具体的倒塌逻辑可以后续再完善"）。

## 决策

### 一、碰撞接管（T28）

**凡是"可见地表已由可挖体积绘制"的地方，地表高度场不再提供碰撞。**

判定口径与 ADR 0011 **同源**（同一份 `DigRegionTable`），但粒度是 **tile** 而不是四边形 ——
因为 Jolt 的高度场形状是**整块 tile 一个形状**，无法只关掉它的一部分：

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | **tile 的四角列在该 tile 的最低与最高地表高度处都可挖** ⇒ 该 tile **不建**地表高度场碰撞体 | 保守判据：只有"这块地表的可见面全归体积"时才能撤掉高度场；只要有角落在区域外，就保留（宁可保留，也不能让角色脚下没有碰撞） |
| 2 | 体积侧为**每个有网格的体积块**建一个**静态三角网碰撞体**（Jolt `MeshShape`），形状直接用 Surface Nets 的顶点 / 索引 | 体积已经是三角网，不需要另做一套碰撞几何，也不会有"渲染面与碰撞面不一致"的经典坑 |
| 3 | 挖除 / 塌落之后，**同步重建**受影响块的碰撞体（`SetShape`；网格变空则移除该体） | Jolt 的 shape 不可变；不复建就会出现"看得见的新洞、走不进去" |

**为什么不是"按爆炸球在洞口打洞"**：与 ADR 0011 同因 —— 高度场无法开洞，这一方向在 Jolt 的
`HeightFieldShape` 上根本不存在可用的操作。

**已知限制（本轮明确登记）**：① **部分覆盖**的 tile（区域边界横穿它）仍保留高度场 ⇒ 该 tile 内
挖出的洞进不去（本项目的可挖区域已铺满整张地图，故实际不出现；收窄区域时会碰到）；
② **区域必须覆盖世界边缘的共享边界列**（tile 覆盖 `[-64, 128]`，含两端；区域止于 `127` 时每块 tile
最外一圈四边形仍由地表绘制 ⇒ 该 tile 保留高度场碰撞 ⇒ "洞口可见但走不进去"重现）；
③ **体积无存档**：重进游戏洞与碰撞体会一起消失（用户 2026-09-27 明确"暂时不要求"）。

### 二、体积内塌落（T29）

**爆炸挖除后，在受影响块的**有限邻域**内做一次"支撑检查"，失去支撑的实心体下落。**

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | **支撑判定 = 载荷通路 + 悬挑容差**：实心体素若"从区域底面起沿本列连续实心"（**纵向**，载荷能一路传到地底）即算**接地**；再把"接地"沿**同一高度层的实心连通**横向传播 `max_cantilever_blocks` 步。两者都不满足的实心体素 ⇒ **失去支撑** | 真实世界里"上部结构靠下部承重"——承重的柱被炸掉，上面的楼板就没有载荷通路；而岩石能靠**拱 / 悬臂**跨过有限跨度，故给一个可调的跨度上限。两条合起来是**首期能做到"可感知自洽"的最小模型** |
| 2 | 失去支撑的实心体**按连续段逐列下落**：沿该列向下落到"腔底"，**质量守恒**（下落多少个体素，就在落点堆起多少个体素）；落点必须落在**体积块覆盖范围**内，否则本段不塌 | 塌落应当**堆积在腔底**而不是填满整个空腔 —— 这样洞**仍然能走进去**（这也是"洞口可通行"与"会塌"两条要求能同时成立的唯一办法）。落点越界就"不塌"而不是"消失"，是为了让质量守恒成为**不变量**而不是近似 |
| 3 | 落点堆面加**确定性起伏**（把堆顶体素按整数哈希推给相邻列） | 让堆积看起来像**碎石堆**而不是机械的平板；确定性是红线 7 的要求 |
| 4 | **单次判定、不迭代** | 若迭代到稳定，山体里挖一条 12 格宽的隧道会把整座山连锁塌掉（与真实不符）。代价是"本次判定的结果不再复核"（例如下落了一层之后，上面新露出的悬空不再处理），已登记为后续项 |
| 5 | 邻域：**水平** = 被改动采样的世界范围外扩 (悬挑 + 摊开 + 1) 格；**竖直** = 自种子块向下到"**最低的非全实心块**"、向上到"**最高的非全空块**"（T30 收紧；`neighborhood_margin_blocks` 仍可再额外外扩块数，默认 0） | 悬挑判定最多跨 `max_cantilever_blocks` 步、摊开最远推 `pile_spread_blocks` 列，再远的列不可能被本次挖除影响；竖直侧**整块实心**的块里既没有空腔可落、也不会有实心失去支撑，**整块空**的块里没有实心 —— 两类都能整块排除，且被排除段紧邻邻域底 / 顶面（"底面之下全实心 ⇒ 底面等价于地面""顶面之上全空 ⇒ 不可能有实心"），故结论与原判据**逐体素相同**。实测邻域 271.9 万 → **1.75 万**采样（一次爆炸），真实连射场景 374 万 → 5.5 万，塌落 177 → **4 ms**（debug） |
| 6 | **邻域底面视作地面** | 把"接地"定义成"连到地面"需要一个起点。规则 5 保证"**邻域底面之下全是整块实心**"，故这个起点与原判据（连到区域底面、即世界 `y = 0`）**等价**；换区域布局或改规则 5 时必须保住这一条（否则会把整片地形判成悬空） |

**为什么不借用 Jolt 做这件事**：Jolt 只管**刚体**，而体积的密度场不是刚体；把"悬空判定"交给物理引擎需要把塌落区整体切成刚体碎块，那是"完整倒塌模拟"的范畴（用户已同意后续再做）。

**为什么不是"只看向下一格是否实心"**（更简单的替代，实现过且被否决）：那条规则下**只有悬空结构的最底一层**会被判定为失支撑，一层之下的第二层立刻"站在刚掉下去的那一层上" —— 结果是"薄板只掉一半、厚岩只掉表皮"，既不符合"上部整体塌落"的直觉，也让功能几乎不可见。

## 后果

- **正面**：洞真的能走进去、能站在腔底（世界内一致性成立）；破坏有"后果"——失去支撑的体会垮下来。
- **代价（实测，1280×720 / debug）**：① 角色碰撞从"一张高度场"变成**每块一个三角网体** —— 本测试地图
  实测 **137 个**静态体（原 9 个地表高度场 → **0 个**），仍在 Jolt 的 `kMaxBodies = 4096` 内；
  ② 启动期变慢：可挖体积从 360 块提到 **441 块**（世界边缘共享列必须计入区域，见下"已知限制"），
  SDF 初始化 0.43 s → 3.62 s、加碰撞体后到主循环约 **8.2 s**（debug；release 会显著更快）；
  ③ 每次爆炸多一次性开销（塌落邻域的体素扫描 + 重网格 + 重建受影响的碰撞体）。**T30 已把这条压到可接受**：
  单次爆炸的 CPU 分解（debug）：**最坏情形（一次爆炸波及 8 块）从 281 ms 降到 71 ms**，其中塌落
  **177 → 4 ms**（邻域 374 万 → 5.5 万采样，见规则 5）；单块三角网碰撞体重建 16.0 → 7.8 ms
  （`MeshShapeSettings::FavorBuildSpeed`，理由见 `engine/physics/physics_world.cpp`）。**当前最大项已变成
  "每脏块"的三件事**：三角网碰撞体重建 ≈ 9 ms/块、Surface Nets 网格化 ≈ 5 ms/块、GPU 网格上传 ≈ 2 ms/块
  （都是 debug 数字）。运行期另有 `VX_LOG_INFO` 的"爆炸耗时分解"逐次打印各阶段毫秒数（T30 交付项）。
- **后续 / 切换条件**：① 体积存档（洞与碰撞体才能跨会话保留）；② 塌落的**连锁**（迭代复核）与
  **安息角 / 碎块刚体**；③ 建造层建立后，把"载荷通路 + 悬挑"判据换成"结构受力 / 连接性"模型，
  并在 `collapse.toml` 里区分材质强度；④ 启动开销与体数量的优化（按需分块建碰撞体、只建玩家附近的）。

## 与 ADR 0011 的关系

两条 ADR 是**同一件事的两半**：0011 决定"谁来**画**"，0012 决定"谁来**挡**"。
两者必须使用**同一份判据来源**（`DigRegionTable`），否则又会出现"看得见却走不进去"的不一致 ——
这正是本次缺陷的成因，写在这里作为后续改动的约束。
