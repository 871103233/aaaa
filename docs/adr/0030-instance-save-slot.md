# ADR 0030：秘境实例的持久化 —— **单槽元数据存档**

- **状态**：已采纳（2026-10-06）
- **日期**：2026-10-06
- **相关**：ADR [0028](0028-world-families-and-static-asset-first.md)（世界族与实例切换）/ [0005](0005-config-parsing.md)（配置解析：非法即抛）/ [0026](0026-premade-map-format-and-bake-tool.md)（预制格式：`schema_version` 与版本纪律）/ [0004](0004-hybrid-layered-world-representation.md)（红线 4「只存脏数据」）/ [0013](0013-destructible-elements.md)（破坏分级——世界改动存档的前置）
- **来源**：项目所有者 2026-10-06 裁定"**继续向下开发 v9 v10**"，并按三问给出**存档槽口径**：① 存档槽 = **单槽自动**；② 存什么 = **仅秘境绑定**（秘境实例的**种子 + 已重置次数**）；③ 放哪 = **`%APPDATA%\voxel-engine\voxel_game\saves\`**（与 `settings.toml` 同根）。
- **施工细则**：`docs/plans/v0.5.md` §1.13.1
- **执行手册**：`.trae/skills/voxel-engine-dev-standards/references/save-and-serialization.md`

## 背景

V5 建立了**秘境实例账本**（`WorldManager`：`EnsureInstance` 首次建 / 之后复用、`ResetInstance` 销毁换种子），
V9 加了**传送门交互菜单**（走近按 `E` ⇒ 进入 / 重置）。两者合起来让所有者口径里的
"**C 地图生成后与玩家绑定、可以反复进入、同一个玩家反复进入后是一样的，直到被销毁**"**在同一次运行内成立**。

但它**跨启动不成立**：进程退出后账本随内存消失，下次启动 `RandomizeSeedOnEntry` 会 **roll 一个全新种子**
⇒ 同一玩家重启后看到的是**另一个**秘境。所有者裁定"C 的绑定载体 = **存档槽**"，V10 即补这一环。

同时有两条**硬约束**决定了本项不能"照常规存档做"：

1. **`.voxr` v2 的精确字节布局尚未冻结**（`references/save-and-serialization.md` §3；`tech-plan-v2.0.md` §0.3 待定项 3，
   时限 = "**首次存档实现前**"）。若把"秘境绑定"当作"首次存档实现"，就会**反过来变成它的阻塞项** ——
   而世界状态存档（高度场脏列 / 脏体积块 / 物件与建造 / 实体状态）的真实需求**尚未到**（破坏与建造都还在早期）。
2. **红线 8**（存档必须带 `version` + 迁移函数 + 迁移测试）与 **红线 2**（主线程不得阻塞在磁盘 IO）对**任何**落盘项都成立。

## 决策

### 一、单槽自动（无槽位选择 UI）

只有一个存档槽：**启动即读、变更即写**，玩家无需管理。不做多槽 / 存档选择界面（登记为后续阶段项）。

### 二、**只存元数据**（秘境绑定），因此用 TOML —— 不触发 `.voxr` v2 冻结

1. 存档内容 = 每个 `instance_roguelike` 世界的 **`world_id` + `seed` + `generation`**（已重置次数），
   **不含任何世界状态**（不含玩家位置 / 地形改动 / 物件 / 实体）。
2. 依据：`references/save-and-serialization.md` §1 明确 **"文本格式（TOML / JSON）仅用于 `level.dat` 这类人可读的元数据；
   世界状态一律用二进制"**。世界种子 / 生成次数正属"**元数据**"（同 §8「元数据」列出的 `level.dat` 内容），
   且**未修改的世界靠种子确定性重建、本就不落盘**（红线 4）⇒ 本项**不是**世界状态存档，
   **不构成 `.voxr` v2 的"首次实现"** ⇒ 不冻结其字节布局、不阻塞之。
3. 落盘为 **TOML（UTF-8 / LF）+ `schema_version`**，与 `settings.toml` / `LevelManifest` **同一套 IO 口径**。

### 三、路径 = `SDL_GetPrefPath` + `saves/instances.toml`

`%APPDATA%\voxel-engine\voxel_game\saves\instances.toml`（与 `settings.toml` 同根；`saves/` 子目录由游戏补建）。
**不进仓库、不被 git 跟踪**（沿用"资源 / 存档不入库"口径）。

### 四、格式与版本（红线 8）

- `schema_version = 1`；读取按版本**分派**（`ParseByVersion`）——v1 直接读，**未知版本一律抛**
  （**不静默误读**，这正是红线 8 要防的"存档静默损坏"）；未来任何字段 / 布局变更 ⇒ 在该处分派里加**迁移函数** + **迁移测试**。
- **`seed` 写十进制字符串**：TOML 的整数是**有符号 64 位**，而实例种子是 `u64`（`RollInstanceSeed()` 实测产生过
  `17925097746213602324` > `INT64_MAX`）⇒ 只有字符串才能**无损**往返。读取侧**同时接受整数**（兼容手改 / 旧档）。
- 空档合法：`[[instance]]` 段可缺省；**文件不存在 ⇒ 空档、不报错**（首次运行正常 roll 新种子）。

### 五、写入安全：临时文件 + `rename` 原子替换

先写 `instances.toml.tmp` 再 `rename` 覆盖 ⇒ 崩溃不会留下半个存档（`save-and-serialization.md` §6）。
属**极低频非热路径**写入（**首次进入**与**重置**两处），与 `settings.toml` 同口径；
**不是**在流式 / 渲染热路径上做同步盘 IO（红线 2 的适用面是运行期区块 IO）。

### 六、读档装回用**独立入口** `RestoreInstance`

`WorldManager::RestoreInstance(id, seed, generation)` —— **有则覆盖、无则新建**，只由**启动读档**调用。
**为什么不复用 `EnsureInstance`**：后者是运行期语义（"无则建、**有则复用**、绝不覆盖"）；
若为读档给它开一个"覆盖已有种子"的口子，运行期也就可能误改种子（绑定被悄悄换掉）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **TOML 元数据存档**（采纳） | 与 `settings.toml` 同口径（toml++ 已在用）；人可读 / 可手改；**不触发 `.voxr` v2 冻结**；改动面最小 | 非二进制 ⇒ 比固定布局略大（本项 < 200 B，可忽略） | **采纳** |
| 自定义二进制 + zstd（`.voxr` 风格） | 与"世界状态存档"最终口径一致 | 本项**无世界状态**，压缩无收益；且会被当成 `.voxr` v2 的"首次实现" ⇒ **反过来阻塞本项** | 不采纳（留给世界状态存档） |
| 多存档槽（3~5 个 + 槽位 UI） | 玩家可建多个存档 | 需新增槽位选择界面与管理语义，工作量明显更大；当前只有 1 个肉鸽秘境，收益为 0 | 不采纳（所有者为"当前阶段"选单槽；**登记待后续**） |
| 一次把玩家状态 / 世界改动也存了 | "刷新即回到原样"体验最完整 | 世界改动持久化 = 高度场脏列 + 脏体积块 + 物件 + 实体（ADR 0004 层①②③④），须先冻结 `.voxr` v2、并与物理 / 流式重建顺序耦合 ⇒ **属独立大项** | 不采纳（所有者本次明确"仅秘境绑定"；**登记待后续**） |
| 存**绝对**世界（把整张地形落盘） | 无需种子确定性 | 直接违背红线 4「只存脏数据」；且与"种子决定世界"的确定性口径冲突 | 不采纳 |
| 把绑定写进 `settings.toml` | 少一个文件 | 语义混淆（设置 ≠ 存档）；设置面板"恢复默认"会连带清掉绑定 | 不采纳 |
| 读不到档时删档 / 静默重置 | 启动永不失败 | 玩家存档静默丢失 = 红线 8 的反面 | 不采纳（**未知版本 ⇒ 抛**） |

## 后果

### 正面

- 所有者口径闭环：**"与玩家绑定"跨启动成立** —— 重启后仍进入**同一个** C；「重置」后的新种子也会被持久化
  （否则重启会"回到旧绑定"，表现为"重置无效"）。
- **零新依赖**：复用 toml++（ADR 0005 已引入）；**不改**任何世界状态路径，不触碰流式 / 物理 / 渲染。
- **`.voxr` v2 仍未被"提前冻结"**：世界状态存档可以按自己的节奏、在有真实需求（破坏 / 建造持久化）时再定布局。
- **可判定**：同档两次启动 ⇒ 世界指纹逐位相同（复用 V2c 的指纹判据）；单测覆盖往返 / 非法字段 / 未知版本。

### 负面 / 必须承受的代价

- **只存秘境绑定**：玩家位置 / 朝向 / 飞行、世界改动（挖洞 / 塌落 / 物件）**都不持久化** ⇒ 重启回出生点、地形改动丢失。
  这是所有者本次选定范围的**直接后果**，已在 `docs/game-design.md`「存档 / 读档」行与 `docs/ui-inventory.md` §2.4 如实登记。
- **单槽**：无槽位管理；"换新地图时替换"（所有者列的销毁条件之一）在**多秘境实例**落地前无场景。
- **元数据同步写**：与 `settings.toml` 同口径（同步、原子替换、极低频）。若将来写入频率升高（例如每次切换世界都写），
  需按红线 2 改走后台线程 —— **切换条件见下**。

### 实测证据

- 删档后两次**独立进程** `--world=world_c`：第 1 次 `恢复 0 个实例绑定` → 新建种子 `17925097746213602324` 并写档；
  第 2 次 `恢复 [world_c] 的绑定 —— 实例种子 17925097746213602324` ⇒ 同一秘境 ✓；世界指纹 `851fb4cfe5e9319e`。
- 落盘内容：`schema_version = 1` + `[[instance]]`（`seed` 为十进制字符串，**u64 无损**）。
- `ctest` 587/587（含 `+7` `WorldInstanceSave.*` 与 `+1` `WorldManager.RestoreInstance*`）；门禁 0 违规。

## 何时需要重新审视

1. **要做世界状态存档**（挖洞 / 塌落 / 物件 / 实体状态）⇒ 那是 `.voxr` v2 的**首次实现**，
   **必须先在 `references/save-and-serialization.md` §3 冻结字节布局**，并配套版本迁移函数与迁移测试（红线 8）。
   **本 ADR 的 TOML 元数据档可作为 `level.dat` 角色继续存在**，两者不冲突。
2. **要开多存档槽（或"每个秘境一个档"）** ⇒ 升级为多槽 / 多文件；`schema_version` 已就位，按红线 8 加迁移函数。
3. **写入频率升高**（例：每次世界切换都写）⇒ 改走后台线程 / 延迟批量写（红线 2），并把"原子替换"保留。
4. **C 的销毁条件"通关 / 完成目标后"** ⇒ 待**目标 / 任务系统**；届时"销毁"要**同一次提交内**清掉该槽里的绑定。
5. **`.voxr` v2 布局冻结后** ⇒ 复核本 ADR 决策二（"元数据用文本"）是否仍与执行手册口径一致。
