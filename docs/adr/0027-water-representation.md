# ADR 0027：水体表示 —— 样条河流 + 静态水位 + 流动着色（不做流体模拟）

- **状态**：已采纳（2026-10-05）
- **日期**：2026-10-05
- **相关**：ADR [0004](0004-hybrid-layered-world-representation.md)（层划分）/ [0010](0010-render-quality-pipeline.md)（渲染质量线）/ [0023](0023-world-representation-v2-hybrid-shell.md)（体积壳，河床刻蚀在此）/ [0026](0026-premade-map-format-and-bake-tool.md)（预制）/ `docs/world-setting.md`（水系设定）
- **来源**：项目所有者 2026-10-05 要求"河流 + 水体"，并对设定口径裁定"**仿照现实世界的水和洞窟做即可**"

## 背景

需求包含"河流 + 水体"。当前仓库**没有任何水体实现**：`world/`、`game/`、`assets/shaders/` 均无水面、水位或水流代码。世界设定中"水系（河 / 湖 / 海）"此前为 `待补`，所有者 2026-10-05 给出方向：**按现实世界的形态**。

关键取舍是"水要不要被**模拟**"。业界开放世界普遍**不做流体模拟**：

- **UE5 Water Body**（River / Lake / Ocean + Water Zone）：河流是**样条**定义的体积与水面，靠**流动贴图 / 法线滚动**表现流动；
- **Unity HDRP Water System**：样条河流 + 固定水位，模拟只用于局部交互（波纹）；
- **《荒野大镖客 2》**：河流用 **flow map** 驱动流向，非实时求解。

真正的流体求解（浅水方程 / FLIP / SPH）只出现在小范围或专门玩法（如《From Dust》），成本与确定性代价都不适合本项目当前阶段。

## 决策

### 一、河流 = 样条路径 + 静态水位 + 流动着色

1. **路径生成**（离线，[ADR 0026](0026-premade-map-format-and-bake-tool.md)）：样条从高处沿**下坡方向 + 确定性抖动**（域扭曲）行进，遇盆地形成湖泊；
2. **河床刻蚀**：沿样条把河道刻进**地表体积壳**（[ADR 0023](0023-world-representation-v2-hybrid-shell.md) 层②）与宏高度场，保证"水在低处、河岸连续"（世界内一致性）；
3. **水面**：按**静态水位**生成水面网格（河段可分级水位），不做逐帧流体；
4. **流动表现**：水面材质用 **flow map / 法线滚动 + 折射近似**（业界标准），不含真实流速求解；
5. **碰撞**：水面与河床提供碰撞（角色可走到/落入水中；游泳与溺水规则属玩法层，见下"本阶段不做"）。

### 二、湖泊 / 海

- **湖泊**：以**水平水面 + 地形包围**表示；
- **海**：本阶段**不做**（无设定与需求）⇒ 登记为待补。

### 三、本阶段明确不做（防蔓延）

- **不做**流体模拟（浅水方程 / FLIP / SPH）；
- **不做**游泳 / 溺水 / 流体与破坏的耦合（破坏已休眠）；
- **不做**动态水位 / 潮汐 / 洪水；
- **不做**水面随时间的地形侵蚀。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **样条河 + 静态水位 + flow 着色**（采纳） | 业界标准；成本低；确定性好；与预制地图契合 | 无真实水流（水位固定） | **采纳** |
| 浅水方程（局部） | 局部真实流动 | 成本与确定性代价大；与预制只读地图冲突 | 不采纳（备选） |
| FLIP / SPH 粒子流体 | 视觉真实 | 极贵、不确定、不适合开放世界 | 不采纳 |
| UE Water 全套（含水下后处理 / 泡沫 / 交互） | 效果最好 | 属"子系统长尾"，超出当前阶段（SKILL 范围控制） | 备选（后续表现阶段） |

## 后果

### 正面

- 以可控成本满足"河流 + 水体"需求；与预制地图、体积壳、LOD 分环均兼容。
- 河床刻蚀与水面同源 ⇒ 水位与地形自洽（"水在低处"）。

### 负面 / 必须承受的代价

- **无动态水流**：水位固定、河流不会因玩家行为改变；登记为已知限制。
- 需要新的渲染通道与着色器（水面）、新的数据块（水位 / 样条）与碰撞体。
- 游泳等玩法未做 ⇒ 玩家入水后的行为需在玩法阶段定义（`game-design.md` / `npc-behavior.md` 相关项标 `待补`）。

## 何时需要重新审视

1. **玩家行为要改变水位**（挖开河岸 / 决堤）⇒ 需引入局部流体或脚本化水位（另开 ADR）。
2. **需要水下视觉 / 游泳玩法** ⇒ 引入水下后处理与角色状态（表现阶段）。
3. **需要海 / 潮汐** ⇒ 扩展水位模型（须先有世界观设定）。
