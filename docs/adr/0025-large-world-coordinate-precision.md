# ADR 0025：大世界坐标精度 —— 物理原点重定基

- **状态**：已采纳（2026-10-05）；**收敛 `SKILL.md` 待收敛项 7（物理层的世界坐标精度方案）**
- **日期**：2026-10-05
- **相关**：红线 6（世界坐标用 int / `double`）、ADR [0008](0008-sizes-precision-budget.md)（尺寸精度）、[0023](0023-world-representation-v2-hybrid-shell.md) / [0024](0024-terrain-streaming-and-lod.md)（10km 世界）、`engine/physics/physics_world.*`
- **来源**：项目所有者 2026-10-05 要求"10km 下物理与渲染精度都要做好"

## 背景

- **渲染**：本项目自始即用**相机相对渲染**（红线 6）：世界定位由 `int` / `double` 承担，提交前减去相机基准，顶点保持小数值 ⇒ 渲染侧在 10km 量级**本就成立**，只需补验证。
- **物理**：`vcpkg` 的 `joltphysics` 端口**未开** `JPH_DOUBLE_PRECISION`，其 `RVec3` 实际是 `float`（见 `physics_world.hpp` 的精度说明）。把世界坐标直接送进 Jolt：
  - `float32` 在 10,000 格处的可表示间隔约 **0.6 mm**（本身尚可），但 Jolt 的**宽相 AABB**、凸包/网格局部坐标与**约束求解条件数**在大坐标下会显著退化 ⇒ 抖动、穿透、落定判定不稳；
  - 待收敛项 7 的**触发条件**（"坐标量级超出 `float32` 精度时"）**在本需求下被触发**（世界 10km = 10,000 格）。
- 现状 ADR 0020 曾判定"1km 内不触发本项"，本需求把世界扩大到 10km ⇒ 必须处理。

## 决策

### 一、渲染：沿用相机相对（已验证口径）

不新增机制；在 10km 处补**验证项**（见验收判据）。世界定位继续用 `double` / `int`（红线 6 不变）。

### 二、物理：**原点重定基（origin rebasing）**

`PhysicsWorld` 引入一个**世界原点** `m_origin`（`glm::dvec3`，**量化到 512 格**的挡位），并保证：

1. **所有进入 Jolt 的位置 = 世界坐标 − m_origin**，且该差值保证落在"原点附近的小数值"区间（|Δ| ≤ 约 1 km ⇒ `float32` 精度充裕）；
2. **所有离开 Jolt 的位置 = Jolt 位置 + m_origin**（对外仍是世界坐标 `double`，调用方无感）；
3. **重定基（rebase）**：当玩家到 `m_origin` 的距离超过阈值（取 512 格的整数倍）时，把 `m_origin` 跳一档，并**平移全部刚体与角色**（静态 + 动态；`bodyInterface.SetPosition` / `CharacterVirtual::SetPosition`），位移量为 `旧原点 − 新原点`；
4. **默认 `m_origin = (0,0,0)` ⇒ 与引入前逐位等价**（既有单测不得改动）。
5. rebase 必须在**固定步之外**或在步首、以**确定性**方式完成；同一输入序列 ⇒ 同一结果（红线 7 / 11）。

### 三、查询与角色的口径转换

- `RayCastDynamic` 的 `from` / `to`：世界 → 局部再查询，命中点局部 → 世界再返回；
- `CreateCharacter` / `SetCharacterPosition` / `GetCharacterState`：入参世界 → 局部，出参局部 → 世界；
- `HeightFieldDesc` / `MeshDesc` / `BoxDesc` / `ConvexHullDesc` 的 `origin*`：世界 → 局部。

### 四、落地口径修正（W1，2026-10-05）

实现时收敛为**只对水平方向（X / Z）重定基，Y 保持世界值**，理由：

1. 世界垂直范围仅 `0 ~ 512` 格，`float32` 精度绰绰有余，**Y 本就不需要重定基**；
2. 地表**高度场采样是绝对高度**（`HeightFieldShape` 的采样值即世界高度、刚体位置 y 恒为 0）——
   若对 Y 做偏移，会把"绝对高度采样"整体平移而**改变地形形状**。

因此 `SetWorldOrigin` 忽略 `origin.y`；本 ADR 上述决策中的 `m_origin` 以"水平原点"为准
（`glm::dvec3` 的 y 恒为 `0`）。这是**实现细化**，不改变"由世界原点消除大坐标精度退化"的决策本身。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **原点重定基**（采纳） | 现有单精度 Jolt 即可；业界成熟（Unity Origin Shifting / UE Large World Coordinates 的局部化思路）；默认原点下与现状逐位等价 | 需维护"全部体平移"，且平移有一次性成本 | **采纳** |
| 双精度 Jolt 构建 | 一劳永逸、无需平移 | 需要**自建 / 改 vcpkg 端口**（当前端口未开 `JPH_DOUBLE_PRECISION`），且 `RVec3=double` 会改变全工程 ABI 与内存；超出本阶段范围 | 不采纳（登记为备选） |
| 分区物理世界（每区一个 `PhysicsSystem`） | 天然局部坐标 | 多系统边界耦合、跨区查询复杂 | 不采纳（备选） |
| 不处理（依赖 float32 够用） | 零改动 | ~10km 处 Jolt 宽相/求解退化，不可接受 | 不采纳 |

## 后果

### 正面

- 10km（乃至更远）下物理稳定，且**不改变对外接口语义**（对外仍是世界坐标 `double`）。
- 待收敛项 7 关闭；与既有测试兼容（默认原点 = 旧行为）。

### 负面 / 必须承受的代价

- 每次 rebase 需要平移全部活跃刚体/角色（一次性成本，须保证不在帧内产生尖峰；按量级很小、可接受，但须实测）。
- 需专门回归测试：跨原点阈值时**位置连续、速度不丢、接触不抖**。
- 若将来世界扩展到"单精度连局部都吃紧"（> 约 16 km 且需高精度局部）⇒ 回到本 ADR 重审。

## 何时需要重新审视

1. **rebase 平移在实测中产生尖峰** ⇒ 改为"分帧平移"或"分区 + 预建"。
2. **世界扩展到 > 16 km / 需要跨区域高精度** ⇒ 重新评估双精度 Jolt 构建。
3. **Jolt 端口开启 `JPH_DOUBLE_PRECISION` 的成本变得可接受** ⇒ 重新评估（可去掉 rebase 复杂度）。
