# ADR 0003：并发任务调度收敛为 enkits、ECS 收敛为 EnTT

- **状态**：已采纳
- **日期**：2026-09-25
- **相关**：`docs/tech-plan-v1.3.md` §3.2 架构与内存管理 / §4.3 流式加载 / §5 第三方清单 / §8 V0.3；
  技能规范 `references/concurrency.md`、`references/build-and-tests.md`
- **背景缘起**：本 ADR 属**选型收敛**，不是推翻既有方案。原因是原文档在这两项上长期写成
  「A 或 B」的并列形式，属于**未决策**状态，会在施工时产生歧义。

## 背景

技术方案里有两处一直以斜杠并列书写，从未真正拍板：

1. **任务调度**：`tech-plan` §4.3 / §5 / §8 与 `references/concurrency.md` 都写「enkiTS **或** Taskflow」。
2. **ECS**：`tech-plan` §3.2 的「选型」列写**自研稀疏集**，但同一份文档的 §5 与 §9.2 目录说明、
   以及技能规范的「范围控制」表都写 **EnTT** —— 属文档内部矛盾。

两者的共同问题是：**读者无法据此开工**。若要表达"尚未决定"，应显式登记为待收敛项，
而不是留下一串并列候选；否则不同章节会被不同角度解读，最终各自实现一套。

## 决策

### 1. 并发任务调度：**enkits**（vcpkg 端口名 `enkits`，当前 1.12）

- 用途：表达异步区块管线的依赖图（生成 → 邻居就绪 → 光照 → 网格化 → 上传）。
- 采用理由：单 `.cpp` + `.h`，无 header-only 的重复解析开销；依赖用 `TaskSet` 的 prerequisites
  显式表达，与"自身生成完成 + 4 邻居光照完成 → 网格化"这一依赖计数语义直接对应；
  zlib 许可；引擎界成熟用例多。
- **以 vcpkg 端口名 `enkits` 为准**（无连字符），不是 `enki-ts`，也不是通称 `enkiTS`。

### 2. ECS：**EnTT**（vcpkg 端口名 `entt`，当前 3.16.0），**V0.4 再评估**

- 用途：**仅服务动态实体**（玩家、怪物、掉落物、弹射物、粒子）。方块**绝不是** Entity，
  区块也不进 ECS —— 方块是 Section 内数组元素。
- 采用理由：header-only、MIT、工业级，省掉自研 ECS 的全部工期；让 V0.4 的精力留给生成与玩法。
- **V0.4 时评估是否切换到自研**：届时已能看清实际用到 EnTT 的百分之几功能。切换须另开 ADR。

## 备选方案（默认不启用，仅在下列条件出现并经确认后采用）

### 任务调度的备选

| 方案 | 优点 | 缺点 | 切换条件 |
| --- | --- | --- | --- |
| **Taskflow**（端口 `taskflow` 4.1.0） | DAG API 更直观（`precede` / `succeed` / subflow）；header-only 免构建 | 模板代码重，编译时间与错误信息质量明显变差；每次编译都要解析 | 出现 enkits 表达不了的图语义（条件任务、动态 subflow），且实测手工前置管理已开始出错 |
| **自研无锁线程池 + 工作窃取** | 约 300 行，学习价值高；零第三方依赖 | 依赖图与唤醒逻辑易出竞态，**必须 TSan 验证** | 仅当"亲手理解任务系统"成为明确目标，且已过 V0.5；属范围控制中的暂缓项 |

### ECS 的备选

| 方案 | 优点 | 缺点 | 切换条件 |
| --- | --- | --- | --- |
| **自研稀疏集 ECS**（约 1000~2000 行） | 编译期与依赖完全可控；可裁剪到只留实际用到的特性 | 需自担边界 bug；提前投入工期 | V0.4 评估 EnTT 实际使用面后，若只用极少特性，经 ADR 决定切换 |
| 传统组件模式 / 纯 OOP 继承树 | 直观、上手快 | 组件内存离散、虚函数跳指针；继承树随实体种类膨胀 | 不采用（已由 ADR 前的方案文档排除） |

## 后果

### 正面

- 两项选型的文档表述**收敛为单一值**，各章节不再互相矛盾。
- 未采纳方案连同**切换条件**一并留档，日后要换有明确触发点，不靠记忆。
- 施工侧不再需要在开工前先做一次选型仲裁。

### 负面 / 必须承受的代价

- EnTT 的模板编译开销会体现在构建时间上（V0.4 起）。
- 若最终切到自研 ECS，V0.4 的评估本身要花时间 —— 这是显式接受的成本。

## 何时需要重新审视

1. enkits 无法表达管线所需的依赖语义（见上表切换条件）。
2. V0.4 的 EnTT 使用面评估结论指向自研。
3. 任一库的上游状态发生实质变化（停止维护、许可变更、大版本不兼容）。
