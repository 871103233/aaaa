# ADR 0033：大世界程序化内容放置与流式（地形感知规则 + 分块确定性 + 窗口增删）

- **状态**：已采纳（2026-10-07）
- **日期**：2026-10-07
- **相关**：ADR [0004](0004-hybrid-layered-world-representation.md) 层③（物件层）、
  [0024](0024-terrain-streaming-and-lod.md)（地表 tile 流式 + LOD 分环）、
  [0028](0028-world-families-and-static-asset-first.md)（静态资产优先）、
  [0029](0029-a-world-asset-enrichment-model-and-scatter.md)（模型形态 + 程序化散布）、
  [0005](0005-config-parsing.md)（配置非法即抛）
- **来源**：项目所有者 2026-10-07 设定**开发主线 = 大世界地图 + 静态物体摆放 / 创造**，并要求"开始开发缺失的能力"。
  缺失项由 `SKILL.md` 第五节新增的「逐部件归属判定表（山体 / 河流）」判定：
  **"崖壁 / 岩石 / 石林细节造型 = 物件层静态资产，按地形感知放置规则贴合散布"** —— 本 ADR 是这项能力的决策。
- **施工细则**：`docs/plans/v0.6.md`

## 背景

1. A 世界（10×10 km）落地后，**物件层内容只覆盖出生点**：`[[scatter]]` 是**以某点为圆心的圆域随机**
   （`PlanObjectScatter`，半径 80 格、10 条规则、132 点），
   **既无地形感知、也不会随玩家移动出现 / 消失** ⇒ 10 km 世界里 **99% 的地面没有任何程序化内容**。
2. `tech-plan-v2.0.md` §3.3 早已规定元素放置必须由**四项适配度判据**决定（**坡度阈值 / 高度带 / 生物群系 / 互斥半径**），
   参数来自配置；但**至今未实现**（A 的散射是无判据的圆域随机）。
3. 大世界是**窗口流式**（ADR 0024：`TerrainTileScheduler` 以玩家为中心常驻 `±R` tile）。
   内容若要"铺满大世界"，**必须与之同构**：内容按 **tile** 归属、随 tile 进入 / 离开而生成 / 移除，
   否则就得"开局把 10 km 全建好"——直接撞 CPU / draw call / 加载时间三重预算。
4. 硬约束（决定了不能怎么做）：
   - **无实例化 / HLOD**（ADR 0029 决策四.2）：每个物件 = 1 个 draw call + 1 个 Jolt 静态网体
     ⇒ **同时常驻的物件数必须受控**（全局总量可以很大，**窗口内的量**必须有界）。
   - **层③内容绝不写进地形场**（ADR 0004 硬约束 1）。
   - **分块确定性**（红线 7 / 15）：只看"当前 tile + 种子"即可重建，**不得**依赖全局激活点列表。
   - **不冻结画面**（SKILL 第四节）：生成 / 碰撞体构建 / 上传都必须分帧或下沉 worker。

## 决策

### 一、放置规则 = `tech-plan §3.3` 的四项判据，参数配置驱动

新增纯数据 `PlacementRule`：

| 判据（§3.3 原文） | 字段 | 语义 |
| --- | --- | --- |
| 坡度阈值 | `minSlopeDegrees` / `maxSlopeDegrees` | 由高度场梯度得到；超出区间不放置（**避免悬空与穿地**） |
| 高度带 | `minHeightBlocks` / `maxHeightBlocks` | 只落在允许的海拔区间内 |
| 生物群系 | `allowPlains` / `allowHills` / `allowMountains` | 复用 W3 的**地貌分区**（`LandformKind`）作为当前可用的"群系"口径 |
| 互斥半径 | `cellBlocks`（网格步长） | 抖动网格：每格至多 1 个、抖动 ≤ `0.25 × cell` ⇒ **最小间距 ≥ `0.5 × cell`**（可证明） |

规则**全部来自配置**（`[[scatter]]` 的可选字段，见决策五），**非法即抛**（ADR 0005）。

### 二、候选点 = **分块确定性**（tile 归属，红线 15）

新增纯函数 `PlanTileCandidates(rule, seed, TileCoord)`：

- 在**该 tile 的列范围**内铺**抖动网格**；每个格点由 `splitmix64(seed, tileX, tileZ, cellIx, cellIz)` 决定抖动与朝向；
- **一个格点只属于一个 tile**（格点完全落在 tile 内，不吃边界）⇒ **相邻 tile 永不重复计算同一点**，
  故"按 tile 生成 / 卸载"是**无状态**的：同一 tile 永远得到同一批点（**逐位可复现**）。
- **不采用**泊松盘采样：它需要**全局激活点列表**，与流式分块根本冲突（ADR 0029 备选表已记录同一取舍）。

### 三、流式 = 内容随 **tile 常驻窗口**增删（与 ADR 0024 同构）

- tile **进入常驻窗口** ⇒ 生成该 tile 的物件（先算候选点，再用**地形采样**过滤，最后建网格 + 碰撞体）；
- tile **离开常驻窗口** ⇒ **移除**该 tile 生成的物件（GPU 网格 + 物理体一并交还）；
- 生成 / 建造 / 上传**按帧预算切分**（预算队列），**禁止**在渲染帧内整批做完（SKILL 第四节）；
  预取环（ADR 0024 的 `prefetchTiles`）在**内容层同样生效** ⇒ 玩家看到之前就已生成。
- **窗口内的物件数有上界**（= 窗口 tile 数 × 每 tile 期望点数 × 命中率），**与世界总大小无关**。

> **实施细化（2026-10-07，C5 落地）**：常驻窗口半径 33 tile（= 4489 个 tile）若"每 tile 都生成"会撞 draw call 预算
> ⇒ 内容只生成在 **`kStreamedContentRadiusTiles = 8` tile（≈ 512 m，与 ADR 0024 的 **Ring 0** 同尺度）** 内。
> 该半径是**预算 / 画质旋钮**（不是新的分层口径）；要放开密度，先做**实例化 / HLOD**（ADR 0029 决策四）。
> 生成 / 移除为**主线程 + 每帧预算**（`kStreamedTilesPerFrame = 2`，成本落在"安装"段），**未新增线程契约**（沿用 P6 形态）；
> 槽位**只标记不缩短数组**（自由表复用）⇒ 其它系统持有的下标恒稳定，成本与世界总量无关。

### 四、内容复用既有物件层（零新通路）

放置结果直接进 `world/object/`（ADR 0004 层③ / ADR 0029 的 `Model` 形态与 `[[placement]]` 同一条路径）：
**渲染与碰撞同源**（同一份 `MeshData`）、**几何绝不写进地形场**、**底面 Y 由地表高度求解**（不悬空、不穿地）。

### 五、配置形态

`[[scatter]]` 增**可选**规则字段（缺省 = 不判据，**与引入本 ADR 之前逐位一致**）：

```toml
[[scatter]]
type   = "boulder"
center = [0.0, 0.0]      # 现有的圆域口径保留（"局部手工散布"仍用它）
radius = 80.0
count  = 6
seed   = 1009
```

新增 **`[[scatter_tiled]]`**（**流式 / 地形感知**形态）：

```toml
[[scatter_tiled]]
type              = "boulder"
seed              = 2001
cell_blocks       = 24.0      # 互斥：网格步长 ⇒ 最小间距 ≥ 12 格
max_slope_deg     = 42.0      # 坡度阈值
min_height_blocks = 0.0       # 高度带
max_height_blocks = 512.0
landforms         = ["hills", "mountains"]   # 地貌（当前"群系"口径）
```

### 六、本阶段明确不做（防蔓延；**均为已确认的降级**）

1. **不做实例化 / HLOD** ⇒ 密度是**预算参数**、窗口内数量受控、**不得全图铺开**（延续 ADR 0029 决策四.2）；
2. **不做逐模型贴图 / UV**（延续 ADR 0029 决策四.1）；
3. **不做真实生物群系**（当前只有 W3 的**地貌分区**；温度 / 湿度群系未实现 ⇒ 判据三先用 `LandformKind` 占位）；
4. **不做**采集 / 破坏 / 风动 / LOD 降面；
5. **不做**带设定语义的内容（建筑 / 宗门 / 遗迹 —— 须先由所有者给命名与世界观解释，SKILL 六.9）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **tile 归属的分块确定性抖动网格**（采纳） | 与流式天然同构；无状态、逐位可复现；不重叠可证明；红线 15 的正向做法 | 观感不如泊松盘自然；网格感需靠抖动与多规则叠加掩盖 | **采纳** |
| 泊松盘采样（Poisson Disk） | 观感最自然 | 需**全局激活点列表** ⇒ 与流式冲突（ADR 0029 已记录） | 不采纳 |
| 开局一次性把 10 km 全生成 | 实现最简 | 撞 CPU / draw call / 加载时间三重预算；与"不冻结画面"冲突 | 不采纳 |
| 只保留现有圆域散布、不做流式 | 零改动 | 大世界仍是空的（现状问题未解） | 不采纳 |
| 先做实例化 / HLOD 再做内容 | 可全图放开密度 | 属**表现与深度**、须另开 ADR；与"先把世界内容填起来"的阶段顺序相反 | 备选（**切换条件见下**） |

## 后果

### 正面

- 大世界从"出生点一小片"变为**随玩家移动持续出现的内容**，且**同时常驻量有界**；
- **零新通路**：复用 `ObjectLayer` / `Model` 形态 / 同源碰撞 / 地表高度落点求解；
- **可判定、可单测**：候选点与判据都是**纯函数**；
- **数据驱动**：密度 / 坡度 / 高度带 / 地貌全在配置里，调参只改 TOML。

### 负面 / 必须承受的代价

- **窗口边界会有内容"出现 / 消失"** —— 靠**预取环 + 分帧**把它藏在玩家视野外（沿用 ADR 0024 的口径）；
- **无实例化 ⇒ 密度受限**：窗口内物件数必须留在 draw call 预算（ADR 0024：≤ 6000 次/帧）与 Jolt 体量之内；
- **每个物件一次网格上传 + 一次形状构建** ⇒ 窗口移动时的成本必须分帧 / 下沉 worker（P6 已量过"形状构建"是热点）。

### 与既有决策的关系

- **补充** ADR 0029：其 `[[scatter]]`（圆域）**保留**（局部手工散布仍用它），本 ADR 新增**流式形态**，不取代；
- **不改** ADR 0024 的窗口 / 预取 / LOD 口径 —— 本 ADR **复用**它；
- **落实** `tech-plan-v2.0.md` §3.3 的四项判据与 `SKILL.md` §五「逐部件归属判定表」。

## 何时需要重新审视

1. **实例化 / HLOD 落地**（P4 解冻，或表现阶段）⇒ 放开密度上限，可"全图铺开"（切换条件：ADR 0029 决策四.2 解除）；
2. **真实生物群系（温度 / 湿度）实现** ⇒ 判据三由 `LandformKind` 换成真正的群系（改动面 = `PlacementRule` 的判据函数）；
   **部分落地（2026-10-07，C7）**：已实现**温度 / 湿度**两张 2D 噪声（`terrain.toml` 的 `[climate]`、`TerrainNoiseGenerator::TemperatureAt` / `HumidityAt`）
   并作为**气候区间判据**接入 `PlacementRule`（**与地貌判据并存**，非替换）；**具名生物群系分类**仍未做（避免代拟世界观命名）。
3. **需要"人工摆放 + 程序化填充"混合**（如"这片林子是我手摆的，别被程序化覆盖"）⇒ 需引入**排除区域**（`[[exclusion]]`），另开 ADR；
4. **需要视距 / 密度进一步提升** ⇒ 先做实例化（同上）。
