# ADR 0032：物件选择器与摆放模式（二级列表 + 幽灵预览 + 就地摆放与保存）

- 状态：**有效**（2026-10-06）
- 相关：[ADR 0004](0004-hybrid-layered-world-representation.md)（层③物件/建造）、
  [ADR 0013](0013-destructible-elements.md)（器物模型）、[ADR 0026](0026-premade-map-format-and-bake-tool.md)（预制与入库口径）、
  [ADR 0028](0028-world-families-and-static-asset-first.md)（静态资产优先 / 清单驱动）、
  [ADR 0030](0030-instance-save-slot.md)（存档原子替换与版本纪律）
- 落实：所有者 2026-10-06 需求 —— **"按下 F2 出现仓库选择 → 选模型 → 预览摆放 + 方向选择"**，
  并追加 **"含保存、一次交付"** 与 **"右键删除"**；形态经三轮问答冻结（见 `docs/plans/v0.5.md` §1.19）。

## 一、决策

1. **F2 = 开 / 关「物件选择器」**（**二级列表**：一级 = **仓库 / 类别**，二级 = 该类别下的物件类型）。
   面板为**模态**：打开即**释放鼠标捕获**、抑制玩法输入（口径与 ESC 系统面板 / V9 传送门菜单**同一套**）。
2. **类别是数据**：`ObjectType` 增**可选** `category`（值域 `vegetation / rock / prop / building / portal / misc`，
   **非法即抛**；缺省 `misc`）。一级列表顺序 = **配置中首次出现顺序**（确定性）；二级 = 同类别内**文件顺序**。
   **不按目录 / `kind` 猜分类**（显式字段才可校验、可判定）。
3. **确认后进入「摆放模式」**（关闭面板、回到游戏，但**接管部分输入**）：
   - 准星指向地面 ⇒ 落点显示**半透明幽灵预览**（**抖动淡出**：复用 `MeshRenderer::SetMeshOpacity`
     —— 它**保持不透明管线**、不引入 alpha 混合，故**不破坏深度排序**，是"贴脸穿模 / 幽灵预览"的业界标准解）；
   - **`Q` / `E` = 旋转**（步进 15°；`Shift` 吸附 90°）；**鼠标左键 = 放下**；**鼠标右键 = 删除**指向的已放置物件；
   - **`Esc` = 退出摆放模式**；**`F3` = 重复上次**（上次类型 + 朝向，直接进模式）；
   - **`F5` = 保存到可编辑层**（与面板内「保存」按钮等效）。
4. **模式内输入让位，模式外逐位不变**（符合 SKILL「已实现能力只允许配置项关闭，不得删除代码」）：
   - 摆放模式内：左键**不再**发光球、`E` **不再**触发传送门交互、`Esc` **先退模式**；
   - 摆放模式外：光球 / 交互 / `Esc` 系统面板**行为与从前完全一致**（不是删能力，是模式内让位）。
5. **编辑层 schema 扩展**（增量、向后兼容）：
   - `[[type]]` 增可选 `category`（见决策二）；
   - **新增 `[[remove]]`**（字段 `type` + `position`（平面 `[x, z]`）+ 可选 `tolerance`，缺省 0.5 格）——
     用于表达"删掉发布清单里的某个落点"；加载顺序 = **发布清单 → 应用 `[[remove]]` → 追加 `[[placement]]` → 散布**；
   - **不升** `ObjectTable::kSchemaVersion`（两处均为可选 / 新增数组，旧档仍合法）。
6. **保存 = 写 `objects_edit_file`**（该世界的**可编辑层**，`LevelManifest.objects_edit_file`）：
   - 只写**增量**：`[[type]]`（本层新增的类型）+ `[[placement]]`（本层新增落点）+ `[[remove]]`（本层删除项）
     + `[[scatter]]`（**保留**读入时的原样）；
   - **原子替换**（临时文件 + `rename`）+ `schema_version` + **未知版本拒绝**（口径同 [ADR 0030](0030-instance-save-slot.md)）；
   - **已知后果**：写盘是**覆盖式**的，`toml++` **不保留注释** ⇒ 游戏生成的编辑层**不带用户手写注释**（文件自带一行来源说明）。
7. **预览与最终摆放几何同源**：预览网格经**同一个** `buildLocalMesh` 生成 ⇒ 所见即所得；
   预览**不建碰撞体、不进物件槽表**（不参与剔除 / 支撑 / 破坏），只占一个独立网格句柄。
8. **选择器内的模型预览 = CPU 正交投影小图**（2026-10-06 追加，所有者需求"在选择模型的界面增加预览功能"）：
   面板右列显示当前选中类型的**小图**（`game/object_preview.hpp` 的纯函数 `BuildObjectPreview`：
   正交投影 + **顶点法线平均的背面剔除**（不依赖绕序）+ 固定光源**朗伯明暗** + **深度升序（画家算法）**，
   输出归一化到 `[0,1]²`）；**自动缓慢旋转**（`0.6 rad/s`）+ **可拖动转向**（拖动偏移记在
   `PaletteModel::previewYawRadians`）。**同源**：几何仍来自**同一个** `buildLocalMesh` ⇒ 与最终摆放一致。
   **零 GPU 资源、零渲染器改动**（不改 `MeshRenderer`）⇒ 与 SKILL「重活离开渲染帧」兼容：成本随**面数**（常数级），
   且只在**面板打开**时计算（用户动作绑定，不进玩法热路径）。
   **不做**「离屏渲染真缩略图」—— 见下方备选表与其切换条件。

## 二、备选方案与切换条件

| 备选 | 为什么不用（当前） | 何时改用 |
| --- | --- | --- |
| 全屏模态"建造 UI"（独立场景 / 网格吸附面板） | 超出本次需求；玩法态与编辑态耦合成本高 | 需要"整套建造系统 / 网格吸附 / 蓝图"时 |
| 拖拽 **gizmo**（3D 手柄）作为主要操作 | 依赖拾取 + 屏幕空间手柄 + 反投影，属**表现与深度**；本次先用键位旋转 | 需要精确摆放 / 对齐时 |
| 分类由 `kind` / 目录**推断** | 推断规则不可校验、易漂移；显式字段才"可判定" | 若类别数量爆炸到不便手写（届时用生成脚本） |
| 保存**写回发布清单** `objects_file` | 违反 [ADR 0028](0028-world-families-and-static-asset-first.md)"差异落在清单 + A 不入库"；发布清单应只读 | 若某世界明确允许就地编辑发布清单（须所有者裁定） |
| 保存**保留注释**（自写 TOML 发射器） | 需自研保注释序列化，成本高、易错 | 若"编辑层要长期手工维护 + 注释重要"成为明确诉求 |
| 删除仅限**本次新增**（不写 `[[remove]]`） | 无法删除发布清单 / 上一轮的落点，体验残缺 | 若 `[[remove]]` 匹配（类型 + 位置 + epsilon）在实测中误伤 |
| **离屏渲染「真缩略图」**（render-to-texture：独立小管线 + 小目标 + ImGui 纹理绑定，逐类型缓存） | **本阶段采纳的是 CPU 正交投影小图**（决策八）。真缩略图的观感更好（真材质 + 光照），但要：① 渲染器新增"渲到任意纹理"的公开 API（当前 `MeshRenderer::RenderFrame` **只输出到交换链**）；② 一条 LDR 输出的小管线 / 小目标（主管线的颜色目标格式固定为 `R16G16B16A16_FLOAT` + 色调映射通道）；③ ImGui 侧的纹理注册与生命周期；④ 资源创建纪律（SKILL 硬规则 4：不得在渲染热路径创建资源 ⇒ 需缓存 + 分帧） | ① 需要"一眼看出材质差异"（例如引入建筑 kit 后按材质区分构件）时；② 面板改为可停靠 / 常驻，预览需长期稳定刷新时；③ 内容量增大到 CPU 投影出现明显观感差距（多部件模型）时 |

## 三、后果

- **正面**：摆放从"写坐标"变为"选 → 看 → 放"，所见即所得；编辑结果**与发布清单分离**（可版本化、可回退）。
- **代价与登记**：
  - `E` 与 `Esc` 在模式内语义变化 ⇒ 必须在 `ui-inventory.md` 与 HUD 提示中**写清**（避免"按键行为不一致"的困惑）；
  - 预览要求每帧一次 `RaycastGround` + 一次 `SetMeshTransform`（**常数级**，不随世界总量增长）；
  - 保存**覆盖**编辑层文件（注释丢失，见决策六）；
  - `[[remove]]` 用"类型 + 平面位置 + epsilon"匹配 ⇒ **同类型同位置的两个落点无法区分**（登记为已知限制）；
  - **选择器预览（决策八）的已知限制**：CPU 投影只表达**形状与明暗**，**不表达材质 / 贴图**（真材质需离屏真缩略图，见备选表）；
    每帧重投影一次（面数级，仅在面板打开时）；**无 LOD**（多部件 / 高面数模型会有可感知开销，当前内容为 Kenney 低模）。
- **不改变**：分层与依赖方向、世界表示、破坏分级、发布清单只读口径、`ObjectLayer` 的确定性遍历顺序。

## 四、何时重新审视

1. 需要**网格吸附 / 对齐 / 蓝图（多物件组合）** ⇒ 评估引入 gizmo 与吸附（并把"编辑态"抽成独立模块）。
2. `[[remove]]` 的匹配在实测中**误伤 / 漏删** ⇒ 改为给落点分配**稳定 id**（发布清单落点编号）。
3. 编辑层需要**人工长期维护**且注释不可丢 ⇒ 换成保注释的序列化或改用"机器段 + 人工段"分离的两文件方案。
4. 出现"多人在线同步摆放"需求 ⇒ 属 V1.0 联机范围，届时按 [ADR 0028](0028-world-families-and-static-asset-first.md)「高风险点 1」单独定。
5. **选择器预览需要"看材质"**（而非只看形状）⇒ 按备选表切到**离屏渲染真缩略图**（前置 = 渲染器新增"渲到任意纹理"
   的公开 API + LDR 小管线 / 目标 + ImGui 纹理接线 + 逐类型缓存 / 分帧创建，须先落该渲染能力的 ADR）。
