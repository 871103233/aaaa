# ADR 0008：V0.1 尺寸、精度与性能预算口径

- **状态**：已采纳
- **日期**：2026-09-25
- **相关**：ADR 0004（分层混合世界）；ADR 0007（体积网格化）；`docs/tech-plan-v1.3.md` §1.3 / §4.1 / §4.4 / §7.1（**其中世界表示相关预算已被本 ADR 取代**）；`SKILL.md` 待收敛项 5
- **收敛**：`SKILL.md` 待收敛项 **5**（预算与精度口径重算）——本 ADR 落地后该项关闭
- **取代**：v1.3 中「区块 16×16×384 / Section 16³」「单区块光照 96 KB」「Draw Call ≤700@16 区块、≤1500@24 区块」「碰撞查询 3×3×3 方块」等**方块世界专属的尺寸与预算数字**

## 背景

ADR 0004 改变了世界表示，v1.3 的全部尺寸常量与预算数字随之失效。若不重算，施工者会继续引用
"96 KB 光照""≤700 draw call"这类已经根本不存在的指标，**性能验收会变成拿旧尺子量新房子**。

同时，前期讨论中暴露了一个量级事实，必须固化下来避免再次误判：

| 表示 | 数据量（32×32 水平面、地形厚度约 128 格） |
| --- | --- |
| 高度场（float32） | ≈ **4 KB** |
| 三维体积（33×33×129，int8） | ≈ **137 KB（约 34 倍）** |

## 决策

### 1. 尺寸与精度（冻结）

| 项 | 取值 | 说明 |
| --- | --- | --- |
| **地表 tile** | **64×64 列** | 高度场的最小加载 / 重网格 / 脏标记单位 |
| 地表高度精度 | **`int16`，1/16 格**（范围 ±2048 格） | 定点而非 `float`，保证确定性；单 tile ≈ **8 KB** |
| 世界垂直范围 | **0 ~ 512 格** | 够用且可控；扩容须提版本 |
| **可挖体积块** | **32³ 体素**（含 **33³** 采样，多一层边界共享） | 块与块必须共享边界采样（ADR 0004 硬约束 3） |
| 体积密度精度 | **`int8` 距离场**（±1 格范围近似） | 单块 ≈ **36 KB**（33³ × 1 B） |
| 地表网格顶点位置 | 块内**定点**坐标 | 世界定位仍用整数 / `double`（红线 6 不变） |
| 碰撞查询 | 由 **Jolt** 承担（`HeightFieldShape` / `MeshShape` / `CharacterVirtual`） | **"3×3×3 方块查询"口径作废** |

### 2. V0.1 预算（小场景：1~9 个地表 tile + 1 个体积块 + 胶囊体）

| 指标 | V0.1 目标 | 记录方式 |
| --- | --- | --- |
| 帧时间 | **1080p ≥ 60 FPS**（基线机：GTX 1660 / 同级） | Tracy，P50 / P95 / P99 |
| CPU 常驻内存 | **≤ 150 MB** | Tracy 内存面板 |
| VRAM 常驻 | **≤ 300 MB** | RenderDoc 资源统计 |
| Draw Call | **不设正式预算**，只记录实测值 | 理由见下 |

**为什么 Draw Call 不给数字**：大视距下的 draw call 预算取决于**地表 LOD 方案**（CDLOD / Geometry Clipmaps
以及合批策略），而 LOD 方案本身尚未收敛（`SKILL.md` 待收敛项 4）。
在 LOD 收敛前给出数字，等于凭空造一个日后必然要改的口径。**V0.1 只记录、不验收。**

### 3. 固定基准场景（性能对比的前提；按新方向修订 §7.1）

| 项目 | 固定值 |
| --- | --- |
| 世界种子 | `0x5EED0001` |
| 出生点 | 地表高度 +2，朝向 +Z |
| 相机 | 第三人称，FOV 70°，近 0.05，远 `viewDistance × 64` |
| 预热 | 全部 tile 达 `Ready` 后静置 **5 秒** |
| 采样 | 静止 10 秒 + 匀速直线前进 10 秒，各一条帧时间曲线 |
| 记录 | 帧时间 P50/P95/P99、draw call 峰值、常驻 CPU 内存、常驻 VRAM |
| 工具 | Tracy（CPU/GPU/内存）；RenderDoc 仅用于排查异常帧 |
| 场景约束 | 出生点周围 3×3 tile 内不放置随机结构，保证跨版本可比 |

**规则**：报告必须写明「基线配置 / tile 视距 / 是否启用 LOD / 是否含可挖体积」四项，缺一即不可比。

### 4. 逐条作废的旧口径（**不得再引用**）

- ~~区块 16×16×384、Section 16³、24 段~~ → 见上表。
- ~~单区块光照数据 96 KB~~ → **光照改为方向光 + 级联阴影，不再有逐方块光照数据**。
- ~~方块数据 8~20 KB/区块（palette 压缩）~~ → 该压缩方案已随方块表示作废。
- ~~Draw Call ≤700@16 区块 / ≤1500@24 区块~~ → 待 LOD 收敛后重给。
- ~~碰撞查询 3×3×3 个方块~~ → 由 Jolt 承担。
- ~~内存估算 2401 区块 / CPU 70~150 MB / VRAM 150~550 MB~~ → 该估算的推导前提（方块区块）已不成立。

## 备选方案与取舍

| 项 | 取此值 | 备选 | 取舍 |
| --- | --- | --- | --- |
| 地表 tile 尺寸 | **64×64** | 32×32：重网格更细粒度，但块数量与 draw call 翻倍；128×128：块数少，但单块重网格变重 | 64×64 在"脏标记粒度"与"块数量"之间取中 |
| 地表高度精度 | **int16 / 1/16 格** | float32：精度更高但体积翻倍且**破坏跨平台确定性**（与既有"确定性分两级"口径冲突） | 定点胜出 |
| 体积密度精度 | **int8** | uint8（仅密度无符号，无法表达内外距离）；int16（精度好但内存翻倍） | int8 起步，按重审条件升级 |
| 体积块尺寸 | **32³** | 16³：块数 8 倍、边界共享开销大；64³：单块重网格成本过高 | 32³ 为常见折中 |

## 后果

### 正面

- 所有性能与内存讨论重新有了**可对齐的尺子**，且区分了"有预算"与"只记录"两类指标。
- 尺寸与精度**冻结为单一口径**，写在 ADR 而非散落各处，避免第二次漂移。

### 负面 / 必须承受的代价

- `int8` 距离场的陡壁台阶感需要在实际观感确认后可能升级为 `int16`（内存翻倍）。
- V0.1 没有 draw call 预算，意味着**性能缺陷的发现会依赖人工看数据**，而非自动门禁。
- 基准场景改动后，**历史性能数据不可比**（故本 ADR 明确这是新起点）。

## 何时需要重新审视

1. **LOD 方案收敛时（待收敛项 4）** → 必须补上大视距下的 draw call 与内存预算，并把本 ADR 的"只记录"改为"有预算"。
2. **实测出现陡壁台阶感/薄壁粘连** → 评估密度精度升级到 `int16` 或改用更精确的距离场生成方式。
3. **世界垂直范围不够用** → 扩容须提版本并重算内存。
4. **单次笔刷重网格超出每帧预算** → 回到 ADR 0007 的重审条件 2。
