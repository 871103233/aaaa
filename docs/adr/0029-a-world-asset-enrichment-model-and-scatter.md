# ADR 0029：A 世界素材充实 —— 公共 CC0 素材 + 物件层"模型"形态 + 程序化散布

- **状态**：已采纳（2026-10-06）
- **日期**：2026-10-06
- **相关**：ADR [0028](0028-world-families-and-static-asset-first.md)（静态资产优先）/ [0004](0004-hybrid-layered-world-representation.md) 层③（物件层）/ [0005](0005-config-parsing.md)（配置非法即抛）/ [0013](0013-destructible-elements.md)（破坏分级）
- **来源**：项目所有者 2026-10-06 要求 **"在公共资源库寻找素材，充实 A 世界"**；动手前经三轮提问确认：① 本次范围 = **最小可玩版**（几何 + 现有地表材质着色）；② 内容 = **自然植被 + 岩石 / 巨石 + 水系点缀 + 中立小道具**（四类全选）；③ 素材来源 = **Kenney《Nature Kit》**（原选 Quaternius，因其官方渠道在本环境不可达而经确认改用）
- **施工细则**：`docs/plans/v0.5.md` §1.9

## 背景

A 世界（10×10 km）落地后**内容为空**：只有地形 + 2 个传送门 + 1 个土堆。ADR 0028 决策二要求"人工 / 内容用**静态资产**"，
而 `world/object/` 当时**只有程序化代形**（盒 / 椭球 / 锥 / 门环），没有任何"从文件载入模型"的通路 —— 即 **A 世界无法用美术资产填充**。

同时有两条硬约束决定了本项不可能一步做到位：

1. **渲染器没有"逐模型贴图 / UV"通路**：`MeshRenderer` 的网格管线片元阶段只采样**地表 4 槽材质数组**（草 / 土 / 岩 / 沙，世界坐标三平面），
   `MeshVertex` 也不含 UV ⇒ 下载来的模型**几何能显示、自带贴图显示不出来**（占位主角 `character_model.hpp` 亦有同一条已登记说明）。
2. **没有实例化 / HLOD**：当前**每个物件 = 1 个 draw call + 1 个 Jolt 静态网体**（`AddMesh`），
   A 世界是 10 km ⇒ 想"全图铺开"必然撞 draw call 预算（ADR 0024 修订后的 **≤ 6000 次/帧**）。

另有一条**来源可达性**的实测约束：**Quaternius 官方渠道（itch.io）在本环境不可达**（`无法连接到远程服务器`），
其 Cinevva 镜像虽可达但**无法批量检索文件名** ⇒ 无法脚本化取回。

## 决策

### 一、素材来源 = Kenney（CC0），沿用既有"资源不入库"口径

1. 取 **Kenney《Nature Kit》**（CC0 1.0，官方直链 **实测可达**），**整包 329 个 GLB 中选抽 12 个**低模自然物；
2. 落地沿用 T65 起的既有口径（**仓库只放脚本 + 校验和 + 台账**）：`tools/fetch_assets.ps1` 新增 **`modelzip` 模式**
   （下载整包 ZIP → 只抽选定 GLB，**名字大小写敏感、找不到即抛**）→ `assets/models/nature/`；`tools/assets.sha256` 逐项记录；
   `NOTICE.md`「美术资源台账」登记来源 / 作者 / 许可 / 采集日期 / SHA-256。

### 二、物件层新增"模型"形态（`ObjectAssetKind::Model`）

1. 配置：`model_file`（**仅 `model` 必填非空，其它形态必须为空**）+ `material_slot`（**仅 `model` 可给**，0 草 / 1 土 / 2 岩 / 3 沙，`-1` = 未指定 ⇒ 草）；
   越界 / 用于非 `model` **一律抛**（与 `target_world` 同口径，ADR 0005）；
2. 几何：纯函数 `BuildObjectMeshFromModel` —— 把 `Model` 的全部网格合并，**等比缩放"装进" `2*half_extent` 的盒**（各轴比例取最小 ⇒ **不拉伸**）、
   **底面贴 `y = 0`**、**水平居中**；空 / 退化模型返回**空网格**（不产生除零 / NaN）；
3. **关键设计：`half_extent` 对 `Model` = "目标包围盒"而非"约束"**。GLB 的建模单位与轴向各异 ⇒ 由配置统一给尺寸，
   使**落点 / 剔除包围盒 / 碰撞体**与程序化形态**共用同一套下游逻辑（零分叉）**；产物同样是 `vx::MeshData`
   ⇒ 渲染 / 物理（"谁画谁挡"同源）/ 视锥剔除 / 支撑探测**全部复用**，不新增第二条通路。

### 三、内容摆放 = 显式放置 + **程序化散布**（纯函数）

1. 新增配置段 **`[[scatter]]`**（`type` / `center` / `radius` / `count` / `seed`；非法即抛）；
2. 新增纯函数 **`PlanObjectScatter`**（`world/object/object_scatter.hpp`，header-only、无全局状态）：
   **分块抖动网格**（红线 15）+ **有界抖动**（偏移 ∈ `±0.25 × 步长` ⇒ **最小间距 ≥ 0.5 × 步长**，可证明、已单测）
   + 格点过多时用**确定性 Fisher–Yates 洗牌**取前 `count` 个（抖网格的**任意子集**都保持该间距与均匀性，故"恰好 `count` 个"且不偏向某一角）；
   抖动与朝向由 `splitmix64(seed, 格子索引)` 给 ⇒ **同种子逐位可复现**（红线 7）；
3. 竖直方向（底面 Y）**仍由地表高度求解**（与 `[[placement]]` 同口径）；落点无地表数据 ⇒ WARN 并跳过（不静默）。

### 四、本阶段明确不做（防蔓延；**均为已确认的降级**）

1. **不做逐模型贴图 / UV**（模型按**地表材质槽**着色：树 / 草 = 草槽、石 = 岩槽、木器 = 土槽）；
2. **不做实例化 / HLOD** ⇒ **数量必须受控**（A 上当前 **139 个物件**）、**不能全图铺开**；
3. **不做**采集 / 破坏 / LOD / 风动；
4. **不做**带**设定语义**的内容（建筑 / 宗门 / 遗迹）—— 那些须先由所有者给命名与世界观解释（SKILL 六.9）；
5. **本轮不摆放木桥** —— A 出生平台附近**无水体可跨**，摆了违反「世界内一致性」；登记待有河区域或 B / C 内容时补。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **Kenney《Nature Kit》**（采纳） | CC0；低模、游戏就绪、风格统一；**官方直链实测可达**；含 329 个 GLB，树 / 石 / 草花 / 营火 / 木栅齐备 | 与写实风不符（本阶段本就不出贴图，影响有限） | **采纳** |
| Quaternius（所有者原选） | 与占位主角同源；低模风格统一 | **官方渠道 itch.io 本环境不可达**；Cinevva 镜像无法批量检索文件名 ⇒ 不可脚本化 | 不采纳（**切换条件见下**） |
| Poly Haven 模型 | CC0 + 公开 API + CDN 直链，最易脚本化 | **写实扫描高模** ⇒ 与当前风格不符、对 10 km 世界更重 | 备选（表现阶段若改走写实风） |
| 只用程序化代形（不引外部素材） | 零依赖、零许可 | 达不到"用美术资产充实世界"的目标；形态单调 | 不采纳 |
| 手工逐条写 `[[placement]]` 坐标 | 无需新配置段与新代码 | 成片植被需几百条坐标 ⇒ 冗长易错、调参困难 | 不采纳（改用 `[[scatter]]`） |
| 泊松盘采样（Poisson Disk） | 观感更自然 | 需**全局激活点列表**，与流式分块根本冲突（见 `docs/learning-notes.md` A 节） | 不采纳（沿用红线 15 的分块抖动网格） |
| 先补"逐模型贴图 / 实例化"再做内容 | 外观最接近素材原样、可全图铺开 | 属**表现与深度**，与"先把世界建起来"的阶段顺序相反；工作量大、须另开 ADR | 备选（**表现阶段**，见下） |

## 后果

### 正面

- A 世界从"只有地形 + 2 门 + 1 土堆"变为**有植被 / 岩石 / 营地的世界**（139 个物件），代价小、可立即验收；
- **零分叉**：模型与程序化形态产出同一 `MeshData` ⇒ 既有渲染 / 碰撞 / 剔除 / 支撑探测全部复用，未引入第二条通路；
- **数据驱动 + 确定性**：尺寸 / 数量 / 半径 / 种子全在清单里，布局由纯函数给 ⇒ 可复现、可单测、调参只改 TOML；
- 素材口径与 T65 起一致（**资源不入库** + 脚本 + 校验和 + 台账），仓库不膨胀。

### 负面 / 必须承受的代价

- **贴图不出**：模型按地表材质槽着色 ⇒ 树 / 石能看出形体但**不是素材原色**；**这是本阶段用户可见的最大差距**；
- **数量受限**：无实例化 ⇒ draw call 与 Jolt 静态网体随实例数线性增长，**不能全图铺开**；
- **模型接入的已知限制**：`LoadModel` **不烘焙节点变换** ⇒ `BuildObjectMeshFromModel` 只适用**单节点 / 无变换**模型（Kenney 的 12 个即如此）；
- 加载期成本随物件数增长（当前 139 个实测**可忽略**：物件层耗时与引入前同量级）。

### 实测证据

- 素材：`fetch_assets.ps1 -Record` ⇒ 12 个 GLB + 校验和 30 项；既有资源哈希未变（可复现）；
- 冒烟（`build\v8_smoke.log`）：`放置 139 / 139（传送门 2、散布点 132、模型文件 12），类型表 14 项`、**0 条落到无地表数据**、
  首帧剔除 `物件 82/139 通过`、帧尖峰 **≤ 38 ms**（无 > 50 ms；主导项是既有的渲染提交瓶颈，本项未引入新尖峰类型）。

## 何时需要重新审视

1. **进入"表现与深度"阶段** ⇒ 补 **逐模型贴图 / UV**（须给 `MeshVertex` 加 UV 与逐网格材质绑定，另开 ADR）与 **实例化 / HLOD**
   —— 这两项是"全图铺开"的**前置**（切换条件：本 ADR 决策四第 1、2 条解除）。
   **已启动（2026-10-07）**：**实例化 / 远景 LOD 链**已解冻并立项 ⇒ 见 [ADR 0034](0034-object-instancing-and-hlod.md) 与 `docs/plans/v0.7.md`（决策四第 2 条**即将解除**）。
2. **需要写实风格**或**需要 Quaternius 的既有资产** ⇒ 重新评估来源（切换条件：官方渠道可达 **或** 找到可脚本化的 CC0 镜像）；
   改动面仅 `tools/fetch_assets.ps1` 的清单与台账，**代码不动**。
3. **需要带设定语义的内容**（建筑 / 宗门 / 遗迹）⇒ 先由所有者给命名与世界观解释（`docs/world-setting.md`），再按 ADR 0028 决策二走**静态资产 kit**。
4. **物件数量要上量**（> 数千）⇒ 实例化 / HLOD 成为**前置**，否则违背 ADR 0024 的 draw call 预算。
