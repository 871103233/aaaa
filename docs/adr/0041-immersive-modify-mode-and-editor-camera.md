# ADR 0041：沉浸式修改模式与编辑器相机（`F3` 直达 · 自由光标 · 镜头脱离角色 · UE5 口径）

- 状态：**有效**（2026-10-08）
- 相关：[ADR 0039](0039-three-interaction-modes-and-input-isolation.md)（三种交互模式；本 ADR **改写"修改模式"的形态**）、
  [ADR 0040](0040-input-context-stack-and-action-ownership-table.md)（输入上下文栈与归属表；本 ADR 的新动作**登记进该表**）、
  [ADR 0032](0032-object-palette-and-placement-mode.md)（摆放模式；本 ADR 把"重复上次"从热键改为面板按钮）、
  [ADR 0038](0038-construction-editor-and-runtime-separation.md)（编辑器分期；本项属 A 组建造交互的**可用性**收口）
- 落实：所有者 2026-10-08 需求 —— "① `F3` 进入修改模式，**固定镜头**、**光标自由移动**选择可见区域内任意物体、**隐藏角色**、**沉浸式**；
  ② 三个指示内容不够明显、大模型会挡住 ⇒ **随模型大小变化**、**放到一半高度**、**支持任意方向移动**、**旋转随光标移动**"；
  并裁定：**①②③④⑤ 全部采用业界标准做法**、**`F3` 让给修改模式**（「重复上次」改为 `F2` 面板按钮）、**镜头按甲派 UE5 口径**、**删除也按 UE5**。

## 一、背景

V0.11 / I4b 的"修改模式"是**游戏内准星**形态：鼠标被捕获、准星在屏幕正中、左键按手柄拖动。
所有者实测暴露三个**可用性缺陷**（`devlog` 2026-10-08 A7-Z1 条目）：

1. **入口难找**：只能在 `F2` 面板里点按钮（自由活动时零提示）⇒ 所有者"不明白怎么进入"。
2. **手柄不可见**：`drawGizmo` 上传 / 定位 / 染色都对，但三只手柄**从未加入 `frameHandles`** ⇒ 永不提交（A7-Z1 已修）。
3. **手柄不显眼 + 被大模型挡住**；且**只能沿两根轴直线移动**、旋转是"水平位移 × 系数"（不跟光标）。

## 二、决策

1. **`F3` = 修改模式开关**（**无面板、直达、进 / 出同一键**）。`F3` 原绑的「重复上次」**让位**，改为
   **`F2` 物件选择器里的按钮**（`PaletteRequest::Action::RepeatLast`）—— **能力不删、只换入口**（SKILL §五）。
   `F2` 面板里的「修改模式」按钮**保留**（同上；两条入口都走统一的 `enterModifyMode`）。
   - **模式互斥必须"完整"**（V0.11 / A8h 缺陷修复，2026-10-09）：进入一种模式**必须调对方的完整退出**
     （`enterModifyMode` → `exitPlacement()`；进建造 → `exitModifyMode()`）。**只把 `modifyMode` 置 false 不算退出**——
     会残留：**手柄未释放**、半途拖动未提交、**光标捕获未恢复**（从修改模式进建造时 `captureBeforePanel` 已是 `false`
     ⇒ 照它恢复会把光标**留在自由态**）。因此三条进建造路径（面板「进入摆放」/ `Enter` 确认 / 「重复上次」）
     **共用同一个守卫** `exitModifyBeforePlacement`（`game/main.cpp`），且 `enterPlacement` 收尾**恒锁定光标**（摆放 = 玩法态）。
2. **进入 = 沉浸式编辑观察态**（`enterModifyMode`），四条**可判定**的形态：
   - **释放鼠标捕获 ⇒ 自由光标**（可见、可点到任意像素）；
   - **相机脱离角色**（本模式内**不调用** `StepCharacter`，改用编辑器相机锚点 + `camera.SnapTo`）⇒ **镜头固定**；
   - **角色隐藏**（渲染提交列表里跳过主角网格；同时因未捕获鼠标，角色移动指令恒为零 ⇒ 角色也不动）；
   - **拾取按光标像素**（`ScreenPointToRay` 反投影），不再用屏幕正中准星。
   *「沉浸式」只落这四条可判定项，**不额外发明视觉特效***（SKILL：AI 不得代拟）。
   - **捕获由本模式独占**（V0.11 / A8 缺陷修复，2026-10-08）：**修改模式内必须跳过 `DecideMouseCapture` 捕获状态机**。
     该状态机的语义是"未捕获时点一下就重新捕获"，而本模式里**点左键选物件**是常规操作 ⇒ 若不跳过，
     玩家一点选物件鼠标就被重新捕获：**光标被锁住**（"光标不动"）、鼠标位移转而去转相机（"镜头动"）。
     ⇒ 规定：**`enterModifyMode` / `exitModifyMode` 是捕获的唯一职责方**（进模式释放、退模式恢复）；
     **本模式内不得有任何路径重新捕获**（同时把 `captureBeforePanel` 复位，使面板开合不会把捕获"恢复"回来）。
   - **屏幕提示的位置与可见性**（V0.11 / A8h + A8i，2026-10-09）：模式文案**画在右上角**（带半透明底色 + 同色边框），
     **不得画在屏幕正中**（正中会压住光标与拖拽路径，所有者实测"屏幕中心有字遮挡操作"）。
     **屏幕正中不放任何图标 / 准星**（A8i 修订）：本模式是**自由光标**（看到哪就点到哪）⇒ 正中十字既不是准星、
     也不指示拾取点，**已无实际含义**（所有者："修改模式的中心光标是不是已经没用了 … 去掉中心图标"）。
3. **编辑器相机 = 甲派（UE5 Level Editor 视口）口径**：**左键 = 选择 / 拖手柄**；**按住右键 = 环视**；**中键拖 = 平移**；
   **滚轮 = 推拉**；**右键 + `WASD` = 飞**（`Space` / `左Ctrl` = 升 / 降）；**`Delete` = 删选中物件**（走 I3 撤销栈）。
   - **右键的让位**：修改模式内右键原本是"删除指向物件" ⇒ 本 ADR 把它让给**环视**，删除改由 `Delete`（按**选中**而非指向）。
     **建造模式不变**（右键仍 = 删除指向物件）。
   - **左键专供编辑**：这是"自由光标拾取"能成立的前提（四家业界编辑器一致：相机操作挪到右键 / 中键 / Alt）。
   - **拖动"已选中物件"的本体 = 自由平移**（V0.11 / A8g 缺陷修复，2026-10-09）：左键**未落在任何手柄上**、
     但落在**当前已选中**的物件（成套建筑则**同一座**的任一构件）上 ⇒ 走**中心平面手柄同一条路径**（XZ 任意方向）。
     为什么必须有：中心平面手柄锚在**包围盒半高**，大模型 / 建筑会把它整个包住 ⇒ 玩家只点得到伸出模型的两支箭头
     （所有者实测"**还是只能两个方向移动**"）；而**本体不受遮挡影响**，也是 UE5 / Blender 视口左键的共同口径。
     - 配套闸：**无位移、无旋转 ⇒ 不提交**（`commitGizmoDrag` 开头按**吸附前**的草稿与锚点之差判定）——
       否则"只是单击本体"也会留下一笔编辑记录（对非本层物件甚至是 `[[remove]]` + `[[placement]]` 各一条）。
       **注意判据必须取吸附前的草稿**：拿吸附后的坐标比，会把"没动的单击"误判成位移（把物件吸到格点）。
4. **gizmo 形态**（`world/object/gizmo.hpp`）：
   - **锚点 = 物件（成套建筑则**整座**）包围盒的**中心（半高）** ⇒ 不再被大模型挡住、也不再埋在物件脚下；
   - **尺度 = 随模型大小**（`包围盒半径 × 1.4`，钳 `[0.6, 24]` 格）⇒ **手柄始终伸出模型之外**；
   - **新增中心平面手柄 `Plane`**：在 **XZ 水平面内任意方向**拖动（**优先**于轴线，中心区域不会被轴抢走）；
   - **拖动锚点取自"运行期权威"**（V0.11 / A8g 缺陷修复，2026-10-09）：**先查 `editLayerState`（可编辑层），再退回 `objects`**。
     为什么：`objects` 是**启动时**"发布清单 + 可编辑层"合并出的**快照，运行期不再更新**，而玩家改动只写 `editLayerState`
     ⇒ 若拿快照的 `def->x/z` 当建筑拖动锚点，**本层建筑**被就地移动后锚点仍是旧坐标，**一按手柄就弹回原位置**
     （所有者实测"**移动后，下次再移动时又回到了原位置**"）；且**移动 / 放置后新建**的建筑 id 只在本层，
     在快照里查不到 ⇒ 第二次拖动直接失败。见 `game/main.cpp` 的 `findBuildingDef`。
   - **拖动中的位姿必须"两条渲染路径都看得到"**（V0.11 / A8h 缺陷修复，2026-10-09）：静态物件走**实例化**渲染，
     其实例位姿取自 `slot.position` / `slot.yawDegrees`，**不看** `renderer.SetMeshTransform`
     ⇒ 只改后者则**拖动期间画面纹丝不动**、松手提交（销毁 + 重建槽位）才一次性看到结果
     （所有者实测"拖动黄色光圈旋转时模型没有跟随旋转，只有松手后才旋转"；**这条契约自 I4 起就没成立过**）。
     规定：拖动反馈的位姿由 **`gizmoDragPoseForSlot`** 提供（**单一真相**，与渲染反馈同一份公式），
     **实例收集与逐网格路径都查它**；且拖动中的槽位**跳过剔除**（`slot.bounds` 仍是拖动前的位置，照它剔除会误杀）。
   - **旋转按光标角位移**：`yaw = 按下时的 yaw +（当前极角 − 按下极角）`（`GizmoAngleDegrees` + `GizmoYawDeltaDegrees`），
     即"**跟着光标转**"；视线几乎与环平面平行时**退回**旧口径（水平位移 × 灵敏度）。
5. **引擎层新增能力**（"自由光标拾取"的前置，按 SKILL「新增引擎能力先登记」）：`InputMap` 增**绝对光标位置**
   （`SetMousePosition` / `MouseX` / `MouseY`）与**滚轮**（`AddMouseWheel` / `ConsumeWheel`）；平台层从
   `SDL_EVENT_MOUSE_MOTION` 的 `x,y` 与 `SDL_EVENT_MOUSE_WHEEL` 喂入。新增纯函数 `game/screen_ray.hpp`
   （`ScreenPointToRay`：屏幕像素 → 世界射线）。

## 三、备选方案与切换条件

| 备选 | 为什么不用（当前） | 何时改用 |
| --- | --- | --- |
| **相机完全锁死（不能转）** | 只能编辑当前屏幕上可见的东西——**背后的物件永远够不到**（所有者原话是"固定镜头"，但业界没有"锁死"这种做法） | 若所有者明确要"纯定格"编辑（则同时失去"选任意物体"的能力） |
| **gizmo 做"屏幕空间恒定尺寸"** | 需要给网格变换加 **scale**（当前 `MeshRenderer::SetMeshTransform` 只有 origin + rotation；`MeshTransformBlock` 的 `meshParams` 四个分量**已被 fade / morphStep / morph 区间占满**）⇒ 要改顶点着色器与变换块 | 出现"远处手柄太小、点不中"时（属后续增强，落点 `engine/render/`） |
| **中心手柄 = 屏幕平面（UE5 的"屏幕方块"原义）** | 会改动物件的 `y` ⇒ 造出**悬空物件**，与 ADR 0032 / I2 的"底面贴地、不悬空"契约冲突 | 引入"自由飞行物件 / 三维摆放"时（须先解除"不悬空"契约） |
| **右键保留"删除"、相机用别的键** | 违背甲派四家的共同口径（左键专供编辑、相机挪到右键 / 中键 / Alt）；且所有者已裁定按 UE5 | 不再改用 |
| **`F3` 保留"重复上次"、修改模式另找键** | 所有者明确要求"`F3` 进入修改模式" | 若需要恢复 `F3` 热键 → 「重复上次」改回热键（面板按钮可保留为双入口） |
| **`Delete` 删"光标指向"的物件** | UE5 的 `Delete` 删的是**选中**项；本模式的语义是"先选中再操作" | 若出现"想快速删多个而不想先点"的诉求 |

## 四、后果与已知取舍

- **正面**：入口从"两级面板"降到**一个键**；拾取从"屏幕正中"变成"**光标所在像素**"（编辑器式）；
  大模型不再挡手柄；移动从"两根轴"变成"**平面内任意方向**"（中心方块 **或 直接拖本体**，见决策 3）；旋转**跟着光标**；
  删除有独立键（不与相机抢右键）；**连续拖动稳定**（锚点取运行期权威 ⇒ 不再弹回原位，见决策 4）。
- **代价 / 已知限制（如实登记）**：
  1. **手柄尺寸不随相机距离恒定**（见备选表第 2 条）—— 只做到"随模型大小"；
  2. **`Delete` 只删"选中"**：没选中时按 `Delete` 无效果（先左键选中）；
  3. **修改模式内 `WASD` 的语义是"相机"**（须**按住右键**才飞）：因为鼠标未捕获 ⇒ 角色移动指令恒为零 ⇒ 原"移动"含义自然失效。
     这与 SKILL《三种模式与输入隔离》硬规则 5「移动 / 跳 / 冲刺 / 飞行 = 三模式共享**通用键**」**不冲突**——
     **键位仍共享、是"含义随模式而变"**（自由活动 / 建造 = 走角色；修改 = 开相机），故该硬规则**无需修改**（本 ADR 为其实施细则）；
  4. **编辑器相机按帧推进**（不是物理 / 角色逻辑，红线 11 不适用）：飞行速度用 `frameDeltaSeconds`，与 `UpdateAvoidance` 同口径；
  5. **相机避障仍生效**（`Evaluate` 的安全网）：自由相机若飞进地形内部，仍会沿视线朝锚点收缩。
  6. **"拖本体 = 自由平移"的边界**：只在左键**未命中任何手柄**时生效 ⇒ 若光标正好落在某支箭头的**拾取盒**上，
      仍按该轴拖动（先手柄、后本体；与"手柄优先"一致）。另：**单击**（按下即松开、无位移）**不产生任何编辑记录**。
   7. **拖动中的半透明反馈只对"逐网格路径"的物件生效**：实例化批次的不透明度是**整批**的（不能只淡出被拖的那一个）
      ⇒ 实例化物件在拖动中仍是不透明的（**位姿逐帧跟随不受影响**，见决策 4）。
- **不做 / 不影响**：不改世界表示、破坏分级、存档字节布局；**不删除**任何既有能力（`F2` 面板按钮 / 右键删除在建造模式 / 原 `F3` 逻辑全保留）。

## 五、验证（可检查判据）

1. **自动侧**：`tests/gizmo_test.cpp` 覆盖**平面手柄优先 / 外侧退回轴 / 尺度屏幕恒定 / 尺度受模型下限 / 钳位**；
   `tests/screen_ray_test.cpp` 覆盖**屏幕中心 = 相机前向 / 归一化 / 四角方向 / 往返自洽 / 退化入参**；
   `tests/input_context_test.cpp` 覆盖**新动作的归属**（相机与 `Delete` 仅修改模式；`F3` 为面板级热键）。
   `ctest` 全绿 + `check-banned-identifiers.ps1` 通过 + 构建零警告。
2. **人工侧（必须在真机上目视）**：① `F3` 一键进出修改模式；② 进入后**光标可见可动、角色消失、镜头不动**；
   ③ 光标点任意物件 ⇒ **选中**；④ 抓手柄**中心方块** ⇒ 平面内任意方向移动；⑤ 抓**环** ⇒ 朝向跟着光标转；
   ⑥ **右键按住**转视角、**中键**平移、**滚轮**推拉、**右键 + `WASD`** 飞；⑦ `Delete` 删掉选中物件且 `Ctrl+Z` 可撤销；
   ⑧ `F3` / `Esc` 退出后**角色、光标捕获、镜头跟随**全部恢复；⑨ `F2` 面板「重复上次」按钮可用（`F3` 不再触发它）。
3. **A8g 补充（2026-10-09）**：⑩ **直接拖物件 / 建筑的本体**（不抓手柄）⇒ **XZ 任意方向**平移（大模型被包住时这是唯一可达的入口）；
   ⑪ **同一物件 / 同一座建筑连续拖动多次** ⇒ 每次都从**当前位置**起拖（**不弹回原位**）；⑫ **单击本体**（按下即松开、不移动）
   ⇒ **不留编辑记录**（`F2` 面板的未保存计数不增加）。自动侧无新增单测（拖动逻辑在 `game/main.cpp` 的 lambda 内，
   现有 `gizmo` / `screen_ray` / `input_context` 三组单测**保持 851/851**）。
4. **A8h 补充（2026-10-09）**：⑬ 修改模式内按 `F2` ⇒「进入摆放」⇒ **手柄消失、光标被锁定**（不再"两种模式叠加"）；
   `Esc` / `F3` 在三种模式间切换 ⇒ **每次都干净**（进入方 = 另一方的完整退出）；⑭ 拖**黄环** ⇒ 模型**逐帧跟着转**
   （松手只是提交），拖**本体 / 中心方块** ⇒ **逐帧跟着移动**；⑮ 提示文字在**右上角**且有底色，屏幕**中心光标**
   在亮 / 暗背景上都清晰。

## 六、何时重新审视

- 出现"远处手柄点不中" ⇒ 做**屏幕空间恒定尺寸**（须给网格变换加 scale，见备选表）。
- 引入"三维自由摆放 / 悬空物件" ⇒ 中心手柄改回 UE5 的屏幕平面语义。
- 所有者要求"修改模式内也能走角色" ⇒ 需要另一套"相机脱离但角色可动"的形态（本 ADR 的 `SnapTo` 口径需重设计）。
