# ADR 0036：**室内变暗参数化**与**成套建筑的摆放**

  [0034](0034-object-instancing-and-hlod.md)（实例缓冲 = 逐实例数据的**唯一**通路）、

- **来源**：项目所有者 2026-10-07 四答 ——
  ① 室内变暗的调试开关 = **可调值**（`--interior-darkening=<0~1>`，非二元 on/off）；

- **后续（2026-10-07）**：其 §五的"①/③ 不放行"**已由 [ADR 0037](0037-world-state-save-v2-and-terrain-persistence.md) 解决** ——

  **决策五（首期只放地形之上、不裁地形）**直接冲突，且**地形改动没有持久化**（存档整块未开工）⇒ 本 ADR **不放行 ①/③**，
  并把"是否放行 / 是否连带做地形改动持久化 / 缺省模式取 ② 还是 ④"列为**待裁项**。

## 背景

1. **现状（V0.8 快照）**：室内变暗 = **写死在 `mesh.frag` 的常量** `kInteriorSkyVisibility = 0.45`；
   成套建筑只有 1 座（`spawn_hut`），**只能来自发布清单**，玩家不能在运行期摆放；
   可编辑层只放 `[[placement]]` / `[[remove]]`（单件），**没有 `[[building]]`**。
2. **缺口**：① 无法 A/B 对照（判据"室内亮度比室外低 ≥30%"要看读数才能定标）；
   ② 一座"账房"和一座"洞府"的室内明暗不能不同；③ 单件物件**没有围合体** ⇒ 室内变暗对它无意义
   （这正是"摆放成套建筑"是"逐建筑调参"前提的原因）。
3. **业界参照（点名）**：
   - 摆放单位 = **成套预制体**：**UE5 Place Actors / Level Instance**、**Unity Prefab 实例**、**Godot GridMap + 场景实例**；
   - 逐实例参数覆盖 = **UE5 Details 面板逐实例 override**、**Unity Prefab per-instance override**；
   - 落点处理 = **UE5 Landscape Spline / 地形平整合（flatten）**、**Unity Terrain "Place on Terrain"（贴合）**、
     **Valheim 建造（先校验地面平整，再允许放置）**；
   - 室内明暗参数化的参照 = **UE5 Post Process Volume / Lightmass 的逐空间参数**（本 ADR 只取"逐实例可覆盖"这一形态）。
4. **可判定判据（动手前立的 3A 基线）**：
   ① **关掉即等价**：`--interior-darkening=1.0` ⇒ 与"引入本参数之前"的同场景**逐位一致**；
   ② **不写字段即等价**：`[[building]]` 不写 `interior_darkening` ⇒ 与"只设全局值时"**逐位一致**；
   ③ **预览与最终同源**：整座预览与展开后的构件几何来自**同一个** `BuildKitPieceMesh`；
   ④ **保存往返逐字段一致**（[ADR 0032](0032-object-palette-and-placement-mode.md) 决策六口径）；
   ⑤ **模式外逐位不变**：不进入摆放模式时，输入 / 渲染 / 物件层行为与 V0.8 完全一致；
   ⑥ **确定性**（红线 7）：同配置 + 同操作序列 ⇒ 逐位同结果。

## 决策

### 一、R1 全局可调值 = `--interior-darkening=<0~1>`（缺省 **0.45**）

- **形态**：启动参数（与 `--object-instancing=on|off` / `--object-lod-distance=<格>` 同一种做法，
  SKILL §五「已实现能力只允许用配置项关闭，不得删除代码」）；取值 **闭区间 [0, 1]**。
  **`1.0` = 完全不调暗**（环境项乘 1.0 = **恒等** ⇒ 逐位退回"引入室内变暗之前"的行为）。
- **非法值即启动失败**（越界 / 非数 / 空值）：**不是 WARN + 回退**（本条与 `--object-instancing` 的静默回退口径**不同**，
  由所有者本次明确要求；依据 [ADR 0005](0005-config-parsing.md) 的"非法即抛"）。
- **承载**：`LightingUniform` **现成的空闲分量**（`sunColorLinear.a`，CPU 侧字段 `interiorDarkening`）——
  **不扩结构**（`sizeof(LightingUniform)` 不变 = 128 B）；`mesh.frag` 的 `computeSkyVisibility` 取该 uniform
  取代写死的 `kInteriorSkyVisibility`。
- **为什么不用新的 TOML 字段**：这是**调试 / 对照**开关，须"不改配置文件即可 A/B"（与既有旋钮同源）；
  配置化会引入"第二处默认值"，与单入口（`BuildLightingUniform`）口径冲突。

### 二、R2 逐建筑覆盖 = `[[building]].interior_darkening`（可选；缺省 **用全局值**）

- **数据形态**：`ObjectBuilding` 增 `float interiorDarkening`，**缺省 `-1` = 未给出（用全局值）**；
  显式给出时必须在 **[0, 1]**（非法即抛）。
- **承载**：实例缓冲里**已经空闲**的分量 `enclosureB.y`（见 `engine/render/instance_batch.hpp` 的
  `kInstancePoseBytes` 记录布局）⇒ **不加宽记录**（仍 96 B）。
  语义：`< 0` = 用全局值（`--interior-darkening`）；`[0, 1]` = 逐建筑覆盖。
- **不写字段 ⇒ 逐位一致**：`−1` 走全局值 ⇒ 与"只设全局值时"逐位相同（判据②）。
- **判据**：同一场景两座建筑设不同值 ⇒ 两处室内亮度**可分辨**。

### 三、R3 「可视化摆放模式」里的功能参数（作用域 = **B3 两者都要**）

- **预览态**（还没放下）调的是**待放值**：进摆放模式时先调好，放下即成型（写进该建筑记录的 `interior_darkening`）。
- **选中态**（准星指向已有建筑）调的是**该建筑的值**：立即生效（实例数据每帧重传 ⇒ 下一帧可见）。
- **入口**：**按键步进**（`[` / `]`，步进 0.05）+ **HUD 数值显示**（"实时可调"的可判定证据）。
  **不做滑条**：选择器面板（`F2`）进入摆放模式后即关闭，滑条放不进"摆放模式内"这一作用域；
  放进去就要么常驻面板（属"场景编辑器"暂缓项的不适当前置），要么在摆放模式里再开一个面板（另立界面）。
- **落盘**：`F5` 保存时，**玩家摆放的**建筑把值写进 `[[building]].interior_darkening`；
  对**发布清单 / 上一轮编辑层**里已有的建筑，写一条**覆盖记录** `[[building_darkening]]`（`id` + `interior_darkening`）
  —— 与 `[[remove]]` 同源（发布清单只读，差异落在可编辑层）。
- **不启动暂缓项**：这是**扩既有摆放模式**，**不是**启动 SKILL §五 的"场景编辑器"。

### 四、R4 摆放 / 删除**成套建筑**

- **选择器的单位**：`F2` 一级列表新增一个**游戏层合成的**类别 `building_set`（**不进** `ObjectType::category` 值域：
  它是"成套建筑"这个**另一种实体**的入口，不是类型表里的类别）。
  该类别下列出 `ObjectTable::buildings` 的 `id`（按文件顺序，确定性）。
- **识别口径（可判定、无歧义）**：解析期新增不变量 —— **`[[building]].id` 不得与任何 `[[type]].id` 相同**（非法即抛）
  ⇒ 游戏层按"先查类型、再查建筑"即可**无歧义**判定选择的单位。
- **展开 = 与加载期同一条装配路径**：把加载期的"成套建筑展开"抽成**同一个**函数（`placeBuildingSlots`）供
  加载期与摆放模式共用 ⇒ 渲染 / 碰撞 / 剔除 / 实例化 / 远景 LOD **零分叉**（[ADR 0035](0035-modular-building-kit-and-enterable-spaces.md) 决策三口径不变）。
- **预览 = 整座合并几何**：把建筑的全部构件各按"相对偏移 + 总朝向"变换后**合并成一个局部网格**
  （同源 `BuildKitPieceMesh` + `RotateMeshAboutY`）⇒ 幽灵预览显示**整座**（判据③）。
- **删除 = 按整座记账**：每个构件物件槽记录其**来源建筑 id**；右键命中任一构件 ⇒ **删除整座**。
  记账：**本层新增**的建筑直接从 `editLayerState.buildings` 删掉；**发布清单 / 上一轮**来的建筑写一条
  `[[remove_building]]`（**按建筑 id 精确匹配**，比 `[[remove]]` 的"类型 + 位置 + ε"更强，不再有"同类型同位置无法区分"的限制）。
- **落点处理 = 4 模式枚举**（`landing_mode`），**逐建筑记录、随保存落进可编辑层**：

  | 模式 | 配置串 | 做什么 | 是否改地形 | 本阶段 |
  | --- | --- | --- | --- | --- |
  | ① 顺手压平地形 | `flatten` | 把 footprint 内地形压平到锚点高度 | **是** | **不放行**（见 §五） |
  | ② 向下半埋 | `sink`（**交互摆放的缺省**） | 锚点整体下沉 `kBuildingSinkBlocks`（层高相对偏移不变） | 否 | **实现** |
  | ③ 悬空处填充 | `fill` | 建筑下方空隙填到地面 | **是** | **不放行**（见 §五） |
  | ④ 落地必须平整 | `flat_only` | footprint 内高差 ≤ `kBuildingFlatToleranceBlocks` 才允许放置，否则**拒绝 + HUD 提示** | 否 | **实现** |
  | （未给出） | 缺省 `unspecified` | **与 V0.8 完全一致**：锚点 = 地表高度，不下沉、不校验 | 否 | **实现**（保证"模式外逐位不变"） |

- **缺省（交互摆放）= ② 向下半埋**：**暂定，待所有者确认**（见 §五）。理由：它**不改地形**（不与 ADR 0035 决策五冲突）、
  且**永不拒绝放置**（摆放工具不应"点了没反应"）。若所有者改判取 ④，只需改**一处**默认值。
- **模式 ②/④ 的边界**：两者都**不碰地形场**（ADR 0004 硬约束 1 / ADR 0035 决策六不变），
  因此**不触发**流式地形重网格与碰撞重扫，也**不依赖**尚不存在的存档能力。

### 五、**①/③ 不放行**（待所有者裁定的留痕）

- **不放行的依据**：①/③ 会**改地形**（压平 / 填充）⇒ 与 [ADR 0035](0035-modular-building-kit-and-enterable-spaces.md)
  **决策五（首期只放地形之上、不裁地形）** 直接冲突；且地形改动**没有持久化**（存档整块未开工，
  见 `tech-plan-v2.0.md` §6 / §8 V0.3）⇒ **重启即丢失**，同时触发**流式地形重网格** + **碰撞体重扫**的连带成本。
- **不放行 ≠ 删除**：模式枚举里**保留** `flatten` / `fill` 两个取值与**全部文案**；解析遇到它们时**明确报错**
  （不静默回退），错误信息指向本 ADR。**能力一旦实现不得删除**（SKILL §五）。
- **待裁三问**（须所有者回答后才动）：① 是否放行 ①/③？② 若放行，是否**连带做地形改动持久化**
  （否则应明确登记"仅本次运行内有效"）？③ 交互摆放的**缺省模式**取 ② 还是 ④？
- **切换条件**：所有者裁定放行 ⇒ 另立 ADR 记录"地形改动是否持久化"，然后按本 ADR 的模式枚举补实现。

### 六、边界不变

- **不启动暂缓项**：仍**不做**场景编辑器 / gizmo / 网格吸附 / 撤销重做 / 多选框选（仍在
  [ADR 0032](0032-object-palette-and-placement-mode.md) §四 的"何时重新审视"）。
- **不做存档落盘**：本 ADR 只落**可编辑层**（`objects_edit_file`，[ADR 0032](0032-object-palette-and-placement-mode.md) 决策六口径），
  不触发 `.voxr` 世界状态存档（那是 V0.3 的范围）。
- **不进发布清单**：`objects_file` 仍是**只读**（[ADR 0028](0028-world-families-and-static-asset-first.md) 的"A 不入库"）。
- **层③几何绝不写进地形场**（ADR 0004 硬约束 1）；本 ADR 只扩**数据形态与装配 / 记账路径**。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **可调值 + 逐建筑覆盖 + 摆放成套建筑 + 落点 ②/④**（采纳） | 满足所有者四答；不改地形、不依赖存档；零分叉 | ①/③ 未放行（待裁）；观感仍是白模级 | **采纳** |
| 室内变暗**只做全局**（不做逐建筑） | 改动最小 | 与所有者粒度裁定 **C** 冲突（"账房 / 洞府"不能不同） | 不采纳 |
| 室内变暗**写进 TOML 配置**（而非启动参数） | 可持久化、可评审 | 对照调试须改文件 + 重启；引入第二处默认值 | 备选（若将来需要"按世界默认"） |
| 落点 ①/③**一起放行**（压平 / 填充地形） | 斜坡上也能放 | **冲突** ADR 0035 决策五；地形改动**重启即丢**；连带流式重网格 + 碰撞重扫 | **待裁**（须所有者裁定 + 可能另立 ADR） |
| 落点**嵌入地形（离线裁地形 + 留通道）** | 真正"陷进山体" | 需离线工具 + 重烘 tile（ADR 0035 备选表同一项） | 备选（切换条件同 ADR 0035 第 2 条） |
| 删除按**单件**（构件）而非整座 | 实现最省 | 与"摆放单位 = 成套建筑"**不对称**（放一座、删一件）⇒ 体验残缺 | 不采纳 |
| 删除用 `[[remove]]`（类型 + 位置 + ε）复用 | 不新增 schema | 构件是同类型多实例 ⇒ **无法区分是哪一座**；ε 匹配会误伤 | 不采纳（新增 `[[remove_building]]`，按 id 精确匹配） |
| 调参入口用 **ImGui 滑条**（常驻面板） | 直观 | 摆放模式内面板已关；常驻面板逼近"场景编辑器"暂缓项 | 备选（将来做建造 UI 时） |

## 后果

### 正面

- **能 A/B 对照**：`--interior-darkening=1.0` 与缺省构成两个读数点（V0.8 遗留的"室内亮度比 ≥30%"目视读数可据此闭环）；
- **逐建筑可不同**：一座建筑一个值，且**不扩实例记录**（复用空闲分量）；
- **摆放对称**：放一座、删一座、存一座（`[[building]]` 往返逐字段一致）；
- **零分叉**：构件仍走既有装配路径；预览与最终同源；
- **零地形副作用**：②/④ 不碰地形场 ⇒ 不触发重网格 / 重扫，不依赖存档。

### 负面 / 必须承受的代价

- **①/③ 未放行**（待裁）：斜坡上仍可能"悬空 / 半埋"（② 是"下沉半埋"，不是"贴合地形"）；
- **`[[remove]]` 的已知限制被新表覆盖**：删除成套建筑走 `[[remove_building]]`（按 id），
  单件仍走 `[[remove]]`（按类型 + 位置 + ε，限制不变）；
- **调参只有按键步进**（无滑条），取值粒度 0.05；
- **新增 3 张编辑层表**（`[[building]]` / `[[remove_building]]` / `[[building_darkening]]`）⇒ `ObjectTable` 的可编辑层 schema 面扩大；
- **不升 `ObjectTable::kSchemaVersion`**（三处均为**可选 / 新增数组**，旧档仍合法 —— 与 ADR 0032 决策五同口径）。

## 何时需要重新审视
