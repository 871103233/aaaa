# ADR 0005：配置解析采用 toml++（端口 `tomlplusplus`）

- **状态**：已采纳
- **日期**：2026-09-25
- **相关**：`SKILL.md` 待收敛项 1、唯一口径表；`docs/plans/v0.1.md` P2；ADR 0004（本 ADR 是它的直接后果）
- **收敛**：`SKILL.md` 待收敛项 **1**（配置解析方案）——本 ADR 落地后该项关闭

## 背景

ADR 0004 把世界表示改为分层混合后，`assets/blocks.toml`（方块注册表）与 `assets/textures/layers.toml`
（纹理数组层号表）**作废**，取而代之的是三类新配置：**材质表**（地表 splat 用哪些纹理、按什么高度/坡度混合）、
**可挖区域表**（见 ADR 0006）、**生成参数表**（噪声层、生物群系阈值、元素放置规则参数）。

而「用什么解析这些表」在方案 v1.3 与全部 ADR 中**都没有结论**，已被登记为待收敛项 1。
不收敛就直接施工，施工者会自选一个解析器 —— 这正是本仓库已经吃过一次的亏（见 ADR 0002 的背景）。

约束条件：

1. 配置必须**人可读可写**（要手改阈值、试参数），因此排除二进制格式；
2. 必须在**启动期一次性读入**，热路径只读内存结构（红线：热路径不分配、不抛异常）；
3. 解析失败必须**明确报错并中止启动**（启动期允许异常），不允许静默降级；
4. 尽量不引入新的构建负担（本项目的依赖已经很重：SDL3 + 可选的 Jolt/Assimp）。

## 决策

**配置格式统一为 TOML，解析器采用 `toml++`（vcpkg 端口 `tomlplusplus`，实测版本 `3.4.0#1`）。**

- **header-only、MIT**：零构建成本，不增加链接目标；
- 支持 C++17，与本项目唯一标准一致；
- 错误信息带**行号与列号**，配置写错时能直接定位（这是"手写解析器"最缺的一环）；
- 加载策略：**启动期**读取 `assets/config/*.toml`，一次性构建内存结构（`MaterialTable` / `GenerationParams` 等）；
  解析或校验失败即抛出并中止启动；**运行时热路径不触碰 toml++**。
- 与 ADR 0006 的配合：可挖区域表同为 TOML，只是加载得更早（在世界生成之前）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **toml++**（采纳） | 成熟、header-only、零构建成本、C++17、报错带行列号 | 引入一个第三方依赖；首次 configure 会多解析一个端口 | **采纳** |
| **手写极简 TOML 解析器**（只覆盖本项目用到的子集） | 零依赖、完全可控 | 需自担字符串/转义/数字/数组的边界 bug；**报错无法定位行号**；后续加字段就要改解析器 | 不采纳（值不上一个成熟库的维护成本） |
| **nlohmann/json（JSON 配置）** | 生态最广、header-only | **JSON 不支持注释**，配置表可读性显著变差；手写阈值/说明时体验差 | 不采纳 |
| **INI / 自定义 key=value** | 实现最省 | 表达不了嵌套数组（噪声层列表、区域列表），会退化成一堆重复键 | 不采纳 |
| **编译期常量代替配置文件** | 无解析、无运行时开销 | 改阈值就要重编译，与"数据驱动、便于试参数"的目标冲突 | 不采纳 |

## 后果

### 正面

- 配置格式**人可读、可注释**，试参数不必重编译。
- 解析失败有行列号，配置错误能被立刻发现而不是变成运行期的怪现象。
- `tomlplusplus` 是 header-only，**不动构建脚本的链接配置**，与现有 CMake 结构无摩擦。

### 负面 / 必须承受的代价

- 多一个第三方依赖，须同步 `NOTICE.md` 与 `docs/file-index.md`。
- `assets/config/*.toml` 需**带格式版本字段**并在加载时校验；配置结构变更时要有迁移或明确报错（见 ADR 0006 与 ADR 0008 的版本约定）。
- 配置表**不是**世界状态：玩家的挖掘结果另存（见 ADR 0006「与存档的关系」）。

## 何时需要重新审视

1. 若配置规模膨胀到需要**热重载**（改表即生效），需评估 toml++ 的重解析成本与线程安全（当前为启动期一次性加载）。
2. 若需要从**存档内**读取玩家自定义配置（而非仅从 `assets/`），需重新界定"配置"与"世界状态"的边界。
3. 若 toml++ 在上游停更且出现 C++ 标准适配问题，切换条件为：改用 `toml11` 或回到"手写子集解析器"（备选对比见上表）。
