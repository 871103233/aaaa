# ADR 0028：**世界族与实例切换 + 静态资产优先的空间表示**

- 状态：**有效**（2026-10-06 落盘）
- 取代：[`docs/plans/v0.4.md`](../plans/v0.4.md) 的 **W7-S3b①「Ring 0 体积壳随玩家流式」**（实测超预算，已回滚）
- 相关：[ADR 0004](0004-hybrid-layered-world-representation.md)（分层）、[ADR 0006](0006-diggable-region-marking.md)（可挖标记）、
  [ADR 0013](0013-destructible-elements.md)（破坏分级）、[ADR 0020](0020-dig-volume-vertical-band-and-dynamic-residency.md)（可挖窗口）、
  [ADR 0023](0023-world-representation-v2-hybrid-shell.md)（表示 v2）、[ADR 0024](0024-terrain-streaming-and-lod.md)（流式 + LOD）、
  [ADR 0025](0025-large-world-coordinate-precision.md)（坐标精度）、[ADR 0026](0026-premade-map-format-and-bake-tool.md)（预制与烘焙）

## 背景

项目所有者 2026-10-06 **重新规划需求**：

1. **10 km × 10 km 预制静态大世界**：绝大多数静态元素（建筑、植物）**不需要破坏**，**小部分可破坏**；
2. **≈1 km × 1 km 预制地图**：**部分元素可破坏**；
3. **按规范随机生成的临时地图**（**肉鸽**玩法）：**部分元素可破坏**；
4. **空间表示采用 AAA 方案**：**建筑、地宫、洞府、房间几乎全是静态资产；地形只管"地面与大尺度形体"**；
5. **性能优先**；地图可用**最简单的高度场**。

**触发**：`plans/v0.4.md` 的 W7-S3b① 试图用"全尺寸体积壳随玩家流式 + 逐块碰撞"实现"到处有真三维"，实测
（±8：4085 块 / 首帧冻结 1.05 s；±4：1457 块 / 安装 ≈10 ms/块、尖峰 35–230 ms）**不可接受** ⇒ 所有者裁定回滚，
并给出上面的新方向（**静态资产优先 + 高度场**）。

## 决策

### 一、世界族 + 实例抽象（`WorldInstance`）

当前世界为一个**实例**，三型：

| 型 | 数据来源 | 常驻 | 破坏 | 持久化 |
| --- | --- | --- | --- | --- |
| `Overworld`（大世界） | **离线烘焙**（预制，只读） | 窗口流式 + LOD | **标记区域（小）** | **是**（只存脏块） |
| `Instance_Premade`（预制小世界） | 离线烘焙 | 全量（≈1 km 很小） | 标记区域（中/大） | 按用途（剧情存 / 日常不存） |
| `Instance_Roguelike`（随机小世界） | **种子程序化生成** | 全量 | 标记区域（大） | **否**（退出即丢） |

- **切换（传送）= 世界切换**：卸载当前 → 加载 / 生成目标 → 重建玩家与相机；**必须有加载界面、不得冻结画面**（SKILL 第四节）。
- 差异**全部落在 `LevelManifest`（TOML）**：数据来源 / 常驻策略 / 破坏策略 / 存档策略 / 生成参数。
  引擎与游戏层**只有一条代码路径**（参照 UE5 World Partition / Data Layers、Unity Scene + Addressables）。

### 二、空间表示分流（**静态资产优先**）

| 表达对象 | 用什么 | 关键做法 |
| --- | --- | --- |
| 地面与大尺度形体（山川、丘陵、平原、水体） | **高度场**（首选；必要时体素） | 大世界**离线烘**（网格 + 碰撞 + HLOD） |
| **人工可进入空间**（建筑 / 地宫 / 洞府 / 房间 / 城镇 / 塔） | **静态资产（模块化 kit）** | 放在地形上或**嵌入地形**（放置时**离线裁开地形 + 留通道**）；超大室内做成**独立空间 / 实例** |
| 玩家要**挖穿 / 炸开**的部分 | **体素 + 破坏**（局部） | 必须由**可挖标记区域**限定作用域（ADR 0006 / 0020） |

⇒ **破坏是"元素属性"，不是"空间的表示方式"**（ADR 0013 三级：地形体量 / 固定器物 / 结构单元）。

### 三、性能口径（硬要求）

1. **大世界运行期不生成几何、不烘碰撞**：全部离线烘焙，运行期只"读盘 → 上传 → 剔除"。
2. **小世界（≤1 km）** 允许进入时生成，但必须 **worker + 分帧 + 进度可见**。
3. 破坏只发生在"**标记区域 ∩ 玩家窗口**"内（ADR 0020）。
4. 渲染侧沿用 **LOD 分环 + HLOD/合并 + 视锥/遮挡剔除**（ADR 0024）；大视距预算复核见该 ADR §四。

### 四、本里程碑（最小可玩，见 [`plans/v0.5.md`](../plans/v0.5.md)）

**A（大世界）+ B（预制 1 km）+ C（随机 1 km）+ A 上两个交互点（F → 加载界面 → 进入 B / C）
+ 三世界内可在"任意指定位置"摆放一个**可破坏土堆**（其余地形不可破坏）**。地形 = **高度场**。

**所有者 2026-10-06 追加裁定（本里程碑口径）**：

1. **土堆 = 物件层实体**（几何不可变 + 状态 `Intact` / `Broken`，ADR 0013 器物模型）⇒ **必须先补"物件层"能力**
   （ADR 0004 **层③「物件 / 建造」**：EnTT 实体 + 静态资产网格 + **预建碰撞** + 放置数据），故 `plans/v0.5.md` 增 **V0**。
2. **世界切换 = 进程内真切世界**（卸载当前 → 加载/生成目标 → 重建玩家与相机；**不是**重启进程）；
   加载界面复用现有加载分片管线 + 进度反馈。
3. **传送时序参照业界标准"地图/关卡切换加载"**：**UE5 Level Streaming + Loading Screen（MoviePlayer）/ Seamless Travel**、
   **Unity `SceneManager.LoadSceneAsync` + loading screen + 进度**、**Skyrim / Elden Ring 的 cell 切换（落点与朝向由目标 cell 的
   PlayerStart 决定）**。⇒ 本项目的口径：**目标世界的出生点由目标清单声明**（`spawn`），切换时**先把玩家状态与相机冻结到目标落点**，
   再在**持续出帧的加载界面**下完成加载（SKILL 第四节「不冻结画面」）。

**2026-10-06 追加（V3 落地；不改本 ADR 的决策）**：§四 首段原写"A 上两个交互点（`F` → 加载界面 → 进入 B / C）" ——
所有者当日明确改为**地图上的传送装置（门实体）**：A 放 **B / C 两个门**、B / C 各放一个**回 A 的门**，
**走到附近按 `E`** 触发（**不自动切换**；`F` 已被飞行模式开关占用，`E` 空闲）。**本 ADR 的决策不变**
（进程内真切世界 + 目标落点由目标清单声明）；仅**触发方式**由"交互点 + `F`"改为"门 + `E`"。详见
[`plans/v0.5.md`](../plans/v0.5.md) §1.8。

## 备选方案与取舍

| 备选 | 处置 |
| --- | --- |
| 用**地形体素**表达整栋建筑 / 地宫 | **否决**：美术不可控、运行期贵、LOD/流式难（W7-S3b① 实测教训） |
| **全可破坏**（Teardown 形态） | **否决**：与 PvP / 性能冲突（SKILL 高风险点 1） |
| 纯静态资产但**不裁地形** | **否决**：接缝 / 穿模；必须"嵌入 = 离线裁地形 + 留通道" |
| **50 km × 50 km** 大世界 | 面积 / 数据量 / 制作成本各 ×25 ⇒ **本阶段不启动**（登记为「后续阶段的明确目标」） |
| 大世界运行期生成 / 烘碰撞 | **否决**（实测尖峰）；离线烘焙是硬要求 |
| 大世界用"全尺寸体积壳"做真三维 | **被本 ADR 取代**（ADR 0024 的 Ring 0 = 512 m 体积壳口径作废，改写为"高度场 + 局部可挖区域"） |

## 后果

- **正面**：运行期轻（读盘 + 上传 + 剔除）；美术可控、AAA 品质；**破坏代价与"可破坏面积"成正比**（而非与近场面积成正比）。
- **负面 / 必须承受的代价**：
  1. 需要**新增"物件层"引擎能力**（静态资产实体 + 预建碰撞 + 实例化 / HLOD + 放置数据）—— **机制、渲染 / 物理接线与生命周期（失支撑掉落 / 按类型可破坏）均已落地**（V0 + V0b + V0c，2026-10-06：`world/object/object_layer.*`（类型表 / 放置清单 + EnTT `ObjectLayer`）+ `object_mesh.hpp`（程序化代形）+ `object_support.hpp`（支撑探测）+ `game/main.cpp` 接线，见 [`plans/v0.5.md`](../plans/v0.5.md) §3）；**kit 美术资产与实例化 / HLOD 仍待做**；
  2. 需要**世界切换管理器**（加载/卸载/生成 + 状态转移）；
  3. 需要**存档**（当前**未开始**）以支持"预制世界的持久化破坏"；
  4. 大世界的"真三维"收敛为**局部**（只有标记区域可挖穿），不再是"到处有洞穴"。
- **对既有 ADR 的影响**：ADR 0024 §二 的 Ring 0 体积壳口径**作废**（本 ADR 决策二取代）；ADR 0023 层②
  收敛为"**只在需要挖穿的标记区域内**使用"；ADR 0013 / 0020 / 0022 的破坏能力**保留并可分区启用**（不再是全局休眠）。

## 何时需要重新审视

1. 若需要"**整幅大世界任意挖掘**" ⇒ 回到体素路线并重估代价（新增 ADR）。
2. 若**静态资产 kit 的美术资源不可得** ⇒ 先用程序化代理体，但**不得**改用体素表达房间（本 ADR 决策二不变）。
3. 一旦启动 **50 km** ⇒ 重算预算（ADR 0024 §四）并新增 ADR。
