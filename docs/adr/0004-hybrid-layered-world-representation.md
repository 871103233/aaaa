# ADR 0004：世界表示改为分层混合（高度场地表 + 可挖体积 + 物件层）

- **状态**：已采纳
- **日期**：2026-09-25
- **相关**：`docs/tech-plan-v1.3.md` §4.1 / §4.4 / §4.5 / §4.6 / §8 / §9.2（**部分被本 ADR 取代**）；`docs/plans/v0.1.md`；`docs/adr/README.md`；`.trae/skills/voxel-engine-dev-standards/SKILL.md` 唯一口径表与待收敛项表
- **取代**：v1.3 中「体素 Section + 调色板 + 面剔除 + 贪婪网格化 + 体素光照 BFS + 自研 swept AABB 碰撞」这一组**世界表示与世界层模块**的子决策
- **仍然有效（未被取代）**：分层架构、SDL3_gpu 渲染后端（ADR 0001）、双格式 Shader（ADR 0002）、enkits 与 EnTT（ADR 0003）、C++17、大世界坐标精度口径、构建与 CI 体系、GoogleTest/CTest、Tracy/RenderDoc

## 背景

PoC 阶段结束后，需求被实质性澄清：目标**不是**"类 MC 的方块放置游戏"，而是：

1. 地图程序化生成各种元素，**按规则**"塞"进世界；
2. 玩家在**平滑表面**的地形上自由活动（**玩家看到的一定不能是方块**），可向下挖掘地面、堆建土堆；
3. 需要**洞穴**，并要求在**一定空间内**能自由三维挖掘，但**不需要**在全世界任意方向掏洞；
4. 需要**浮空内容**（程序化生成的浮空岛 / 遗迹 + 玩家自由搭建）与**可飞行的元素**；
5. 人物先用**胶囊体占位**，后续再接自由建模 / 公共资源库模型与骨骼动画。

对照 v1.3 的体素架构，出现三处错配与三处空缺：

- **表示错配**：Section + 调色板 + 面剔除 + 贪婪合并是为"可任意挖建的方块世界"设计的；而本需求要求可见表面平滑，方块外观不成立。
- **能力错配**：自研 swept AABB（3×3×3 方块查询）与体素天空光/方块光 BFS 都建立在"轴对齐方块格"上，平滑可变形地形不适用。
- **量级错配**：按 32×32 水平面、地形垂直厚度约 128 格估算 ——
  - 高度场数据 ≈ **4 KB**（float32，每列 1 个高度）；
  - 三维体素体积（33×33×129，8 bit）≈ **137 KB**，约为前者的 **34 倍**；
  - 网格化需遍历的格子数约为高度场顶点数（~1K）的**两个数量级**。
  而它换来的"全世界任意三维重塑"**并不是需求**（需求是"一定空间内可自由挖掘"）。
- **空缺**：无"浮空/建造层"、无第三人称相机、无模型与骨骼动画方案（v1.3 把 Assimp 排在 V0.5 且理由是"怪物模型"）。

## 决策

**世界表示为三层混合，并显式引入"可挖标记区域"：**

| 层 | 表示 | 负责 | 不负责 |
| --- | --- | --- | --- |
| ① 地表 | **高度场**（每列 1 个高度，int16 / float） | 挖坑、堆土、平整、陡坡、悬崖；材质按高度 + 坡度混合 | 悬垂、洞穴、悬空 |
| ② 可挖体积 | **有界 SDF 体积**，**仅存在于被标记区域内** | 洞穴与地下标记区域内的任意方向挖掘、竖井、隧道扩挖 | 地表整体高度（仍由 ① 管理） |
| ③ 物件 / 建造 | glTF 模型 + 简化碰撞体（EnTT 实体 + Jolt 刚体） | 浮空岛、遗迹、玩家搭建、树木岩石等元素 | **绝不写入地形场** |
| ④ 实体 | Jolt 动态刚体 / `CharacterVirtual` | 飞行元素、NPC、掉落物、玩家 | 地形表示 |

**四条硬约束**（本 ADR 的核心，后续方案与代码不得违反）：

1. **浮空物与建造物绝不写入地形场**——否则会在地表"打出柱子"。它们只作为实体 + 碰撞体存在。
2. **可挖范围由显式标记区域决定**，标记来源为"程序化规则 + 数据文件"两者结合；标记区域之外不可三维挖掘。
3. **可挖体积按固定网格对齐**，相邻体积共享边界采样 → 体积之间无接缝；体积与地表相接处由**体积接管该列高度**，这是层间过渡的唯一处理点。
4. **飞行元素不引入任何新的表示**，只是"在三维空间移动、与 ①②③ 做碰撞查询"的实体。

**随之确立的口径变更**（详见 `SKILL.md` 唯一口径表）：

- 地形网格化 → 「地表：高度场网格（LOD 方案待收敛）」+「可挖区域：局部等值面网格（算法待收敛）」；
- 材质与光照 → 地表**多纹理权重混合（splat）** + 方向光 + **级联阴影（CSM）**；物件用模型材质；
- 物理与角色 → **Jolt**：地表 `HeightFieldShape`（分块）+ 可挖体积 `MeshShape`（分块）+ 角色 `CharacterVirtual`（胶囊）；
- 作废资源 → `assets/blocks.toml`（方块注册表）、`assets/textures/layers.toml`（纹理数组层号分配表）；改为材质 / 生物群系 / 可挖区域等配置表；
- 存档 → 仍为「自定义二进制 + zstd，只存脏数据」，内容改为「高度场脏列 / 脏体积 / 物件与建造 / 实体状态」；
- 程序化生成 → 仍用 FastNoiseLite + 分块确定性（元素放置写成纯函数，沿用网格抖动思路）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **分层混合**（采纳） | 地表数据量最省（≈4 KB/单位）；LOD 有成熟方案；可挖范围可控；浮空与建造与地形解耦 | 需两套网格化与两套碰撞路径；层间过渡是主要风险点 | **采纳** |
| **全世界三维 SDF 体素** | 任意方向三维重塑、悬垂与洞穴天然支持 | 数据量约为高度场 34 倍；网格化遍历量高两个数量级；LOD 缝合是活跃难题；**能力远超需求** | 不采纳（过度设计） |
| **纯高度场（2.5D）** | 最省、最简单 | 无洞穴、无悬垂，不满足"洞穴内自由挖掘" | 不满足需求 |
| **多层高度场（每列 2~3 层）** | 比纯高度场多支持少量悬垂/浅洞，成本仅 2~3 倍 | 洞穴形态受限，无法在其内自由挖掘 | 备选（若 ② 成本失控可降级采用） |
| **三角网格雕刻**（移动顶点） | 无新数据结构 | 拓扑不可改（挖穿需重新三角化），大面积变形退化三角质量 | 不可行 |
| **窄带 SDF / 稀疏八叉树（SVDAG）** | 把三维体素内存压到 1/5~1/10 | 实现复杂度再上一个台阶 | 备选（若可挖范围显著扩大再评估） |

## 后果

### 正面

- 地表内存与网格化成本回到可接受量级，大视距主要靠高度场 LOD 解决。
- 浮空内容与玩家建造走物件系统，与地形表示解耦，不再倒逼地形表示升级。
- **复用面大**：构建 / CI / 门禁 / 规范体系、`engine/platform`、`engine/render` 薄封装与双格式 Shader、固定步长主循环、EnTT、enkits、**大世界坐标精度（int32/double + 相机相对渲染）**、分块流式加载与脏标记、只存脏数据的存档策略，全部保留。
- 已写下的世界层代码仅 `voxel/chunk/chunk_types.hpp` 与 6 个测试，**迁移成本处于最低点**。

### 负面 / 必须承受的代价

- **两套网格化路径** + **两套碰撞路径**，以及**层间过渡**（体积与地表相接处）——后者是主要风险点，处理不当会出现缝隙与穿模。
- 可挖体积的重网格成本高于方块贪婪合并，需异步 + 每帧预算上限。
- 世界层需要重写：v1.3 的 §4 全章、§7 部分行、§8 路线图、§9.2 目录结构作废；4 份 `references` 需重写；`docs/plans/v0.1.md` 原任务分解作废。
- 所有性能 / 内存预算数字（96 KB 光照、≤700 draw call、16×16×384 等）**失效**，须重算。

### 迁移期约束

- 新版方案（`docs/tech-plan-v2.0.md`）写完前，**不得据 v1.3 的世界表示章节施工**；涉及世界表示的裁决一律以本 ADR 与 `SKILL.md` 唯一口径表为准。
- 本 ADR 引入的待收敛项（配置解析、标记规则、体积网格化算法、地表 LOD 方案、预算与精度重算）已登记在 `SKILL.md`「待收敛项」表，须在各自时限前经 ADR 收敛。

## 何时需要重新审视

1. **"全世界任意方向三维重塑"成为核心玩法** → 重新评估全世界 SDF 体素或 SVDAG。
2. **可挖区域规模显著扩大**（例如整个地下层都可挖）→ 评估 SVDAG / 窄带 SDF，或改为稀疏分层体积。
3. **层间过渡成本失控**（缝隙、穿模长期无法收敛）→ 降级为多层高度场，或把洞穴改为独立网格空间（"洞穴作为关卡"路线）。
4. **地表 LOD 与可挖体积冲突**（在 LOD 区域开挖）→ 须重新界定"可挖范围"与"LOD 区域"的关系。
