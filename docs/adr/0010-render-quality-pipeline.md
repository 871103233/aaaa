# ADR 0010：渲染质量管线采用「HDR + 色调映射 → 光照与阴影 → PBR → MSAA 与细节」

- **状态**：已采纳
- **日期**：2026-09-26
- **相关**：`docs/plans/v0.1.md`（任务 T20~T23）；`tech-plan-v2.0.md` §4.3 / §4.4 / §4.5 / §7.2；[ADR 0008](0008-sizes-precision-budget.md)（尺寸与预算）、[ADR 0009](0009-terrain-material-pipeline.md)（材质贴图管线）
- **取代**：`tech-plan-v2.0.md` §4.4 中「光照 = 方向光 + CSM」的**笼统表述**——本 ADR 补全其**前置条件（HDR 与色调映射）**、**天空光与雾**、**着色模型（PBR）**与**抗锯齿**，并固定四者的**实施顺序**
- **范围授权**：本线属 SKILL 第五节「纯增强（后处理 / 光照 / 特效）」范畴，**默认不启动**；本条为**项目所有者于 2026-09-26 明确追加**的质量线，故获准进入当前阶段

## 背景

人工实测反馈：**「当前的地表材质感觉像是 20 年前的游戏质量」**，要求达到 3A 水准、表面"细腻圆润"。

诊断结论（**均有代码证据，且已核实**）：差距的主体**不在贴图分辨率**，而在**光照、色彩与抗锯齿**。

| # | 缺失项 | 证据 | 对观感的后果 |
| --- | --- | --- | --- |
| 1 | **没有阴影**（CSM = `未开始`） | `docs/engine-capabilities.md` §1.2 | 没有体积感，地形像"纸板"贴在地上 |
| 2 | **没有 HDR 与色调映射** | 全仓库检索 `sRGB` / `gamma` / `tonemap` / `exposure` → **0 命中** | 亮部一过 1.0 即死白截断、暗部无环境色；画面发灰发脏，没有动态范围 |
| 3 | **只有 Lambert 漫反射** | `assets/shaders/mesh.frag`：`o_color = albedo * (0.35 + 0.65 * diffuse)` | 所有表面都是哑光纸板；无高光、无粗糙度概念，岩石不可能"湿"或"硬" |
| 4 | **贴图仅 albedo + normal，且为单频噪声** | `world/terrain/material_textures.hpp`（albedo 为"单色细节"、法线由**一层**高度噪声求梯度） | 近看"糊 + 重复"：无粗糙度变化、无 AO、无宏观色变 |
| 5 | **没有抗锯齿** | `engine/render/mesh_renderer.cpp`：`multisample_state.sample_count = SDL_GPU_SAMPLECOUNT_1` | 边缘锯齿 + 远处高频地形**闪烁**——"旧"观感的一大半来自这里 |
| 6 | **没有雾 / 大气**（= `未开始`） | `docs/engine-capabilities.md` §1.2 | 远处几何硬边、没有纵深，大世界"空气感"为零 |

**同时明确一条否定结论（避免走错路）**：几何加密**不是**主因。3A 游戏地表普遍也是 1~2 米一个顶点，
靠**光照 + 法线贴图 + 抗锯齿**"骗"过眼睛；单纯把顶点间距从 1 格降到 1/4 格，只会把"宽带"变窄并抬高开销，不会产生"圆润"。

## 决策

**把观感拆成三件事分别解决：圆润 = 平滑法线 + 正确光照 + 抗锯齿；细腻 = 多尺度法线 + 粗糙度变化 + AO；不发灰 = HDR + 色调映射 + 线性空间。**

按**四个阶段、固定顺序**实施（**不得跳步**）：

1. **P0 —— HDR 管线（前置，必须先做）**
   渲染到离屏 HDR 目标（`R16G16B16A16_FLOAT` 颜色 + 深度）→ 后处理通道做**曝光 + ACES 近似色调映射 + sRGB 编码** → 输出到交换链。
   **理由**：没有 HDR 与色调映射，P1 / P2 的高光与阴影收益会被"亮部截断"直接吃掉——P0 是其余三步的**放大器**。
2. **P1 —— 光照与阴影**
   方向光（方向与颜色改为可配，不再写死在着色器里）+ **级联阴影（CSM）**；**半球天空光**（天空色 + 地面反弹色，给暗部以颜色而非死黑）；
   **指数高度雾**（雾色取自天空色，保证远景与天空融合）。
   **不在本次范围**：SSAO / HBAO、屏幕空间反射、体积光。
3. **P2 —— PBR 与材质四件套**
   Cook-Torrance（**GGX + Smith + Schlick**）；每层提供 **albedo / normal / roughness / AO** 四张贴图，并叠加**宏观变化（macro variation）**破平铺；
   `assets/config/materials.toml` 升 **`schema_version = 3`**（新增 roughness / AO / 宏观参数），仍经 `BuildMaterialUniform` 单入口投影（[ADR 0009](0009-terrain-material-pipeline.md) 的机制不变）。
   占位资源**继续程序生成**（项目所有者选择），但升级为**多尺度**（macro + micro 两层），后续可整体替换为美术 PBR 资源而**不改管线**。
4. **P3 —— 抗锯齿与近景细节**
   **MSAA 4×**（SDL3_gpu 的 sample count + resolve）；近景细节法线**多频叠加**（两层以上，消除"单一频率"的平感）。
5. **可观测性前置（与 P0 同步交付）**
   F1 面板必须能显示渲染开销（**Draw Call / 三角形数 / 纹理显存 / CPU 帧时间分解 / 各 pass GPU 时间**）。
   **理由**：本线每一步都在"变好看"的同时增加开销，没有开销数字就无法判断收益与代价，也无法满足 §7.2 的预算记账义务。

**参数归属**：光照方向 / 强度 / 颜色、雾密度与颜色、曝光值、MSAA 档位**一律进配置文件**（TOML），**禁止**在着色器里写死第二份（沿用 [ADR 0005](0005-config-parsing.md) 与 ADR 0009 的"单一事实来源"原则）。

## 备选方案与取舍

| 方案 | 视觉 | 性能 | 工程成本 | 结论 |
| --- | --- | --- | --- | --- |
| 维持现状（Lambert + 单频程序贴图 + 无 AA） | 差（"20 年前"） | 极低 | — | **不可交付**（SKILL 第七节：品质未达标） |
| **只升级贴图**（提高分辨率 / 换真美术资源） | 提升有限 | 中 | 低 | **不采纳**——光照与抗锯齿不变时，观感提升会被"死白截断 + 锯齿"压制；这正是本次提问的直觉误区 |
| **HDR → 光照 → PBR → AA 分阶段（本 ADR）** | 好 ~ 很好 | 中 | 中 | **采纳**（3A 主流基础栈） |
| 一次性上前向 + 全后处理栈（SSAO / SSR / Bloom / TAA） | 极好 | 高 | 高 | 后续（V0.5 大视距优化阶段评估） |
| 直接改**延迟渲染（deferred）** | 很好（多光源友好） | 中高（G-Buffer 带宽） | 高 | 后续（**切换条件**见下） |

**切换条件**：

- 几何量上升（可挖体积 + 物件层落地）后，前向 + MSAA 的**顶点与状态切换**成本上升 ⇒ 评估 **clustered forward** 或 **deferred**。
- 需要电影级近景 ⇒ 评估**视差遮蔽映射 / 置换**（属另一条线，须另开 ADR）。
- 帧率不达标且 MSAA 是主因 ⇒ 降级为**后处理 AA**（本 ADR 的 P3 允许此替换，但必须记录取舍）。

## 后果

### 正面

- 观感从"平"到"有质感"：**色调映射解决"灰"、阴影解决"没有体积"、PBR 解决"纸板"、MSAA 解决"锯齿"**——四者各治一症，可逐项验收。
- 光照与材质解耦：材质资源（含未来的美术 PBR 资源）只提供数据，**不再各自写一份光照**。
- 参数进配置后，**调参不需要重编 Shader**，可从 F1 面板与 TOML 双向核对。

### 负面 / 必须承受的代价

- **显存与带宽显著上升**（须单独记账）：
  - HDR 离屏目标：1080p `RGBA16F` ≈ **8.3 MB**（另加深度）；
  - MSAA 4×：颜色目标 ≈ **33 MB**（+ 深度目标，仅 P3 启用时）；
  - 阴影级联：**2~4 张** 2048² 深度图；
  - 材质贴图：程序生成由现 2.67 MB 升到**约 5 MB 级**（多 2 张图 + 多尺度）。
- **§7.2「VRAM 常驻 ≤ 300 MB」必须重新核算**；本线每落地一阶段，都要在 `engine-capabilities.md` 与 `tech-plan-v2.0.md` §7.2 补记账。
- **色调映射落地后，既有颜色常量需要重新校准**（材质 `tint`、清屏色、UI 主题的对比度）——这是一次性返工，属预期成本。
- 前向 + MSAA 在几何量上升后可能成为瓶颈（见"切换条件"）。

## 何时需要重新审视

1. **可挖体积（T8）与物件层落地后** ⇒ 评估 clustered forward / deferred。
2. **地表 LOD 收敛后**（SKILL 待收敛项 4）⇒ 与视距、阴影级联范围一起重算预算。
3. **帧率不达标**且 Tracy / F1 面板显示瓶颈在片元或带宽 ⇒ 按"切换条件"降级或换栈。

## 修订说明

- **2026-09-26（局部修订，不改方向）**：P3 的 **MSAA 颜色格式定为 `R16G16B16A16_FLOAT`**（由项目所有者选定）。
  **理由**：全浮点精度，暗部无色带风险；**代价**：4× 颜色目标约 **95 MB**（若改用 `R11G11B10_FLOAT`（4 B/px）则约 63 MB，省 32 MB 且写入带宽减半）。
  该选择已同步到 `tech-plan-v2.0.md` §7.2.1 与 `docs/plans/v0.1.md` 的 T23；
  **若日后显存或带宽成为瓶颈**，按本文"切换条件"降级为 `R11G11B10_FLOAT` 或**后处理 AA**（必须记录取舍）。
