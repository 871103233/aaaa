# ADR 0023：世界表示 v2 —— 宏高度场 + 预烘焙只读地表体积壳 + 水体层

- **状态**：已采纳（2026-10-05）
- **日期**：2026-10-05

## 背景

ADR 0004 把世界表示定为"高度场地表 + **仅存在于标记区域内的**有界 SDF 体积 + 物件层 + 实体"，并**明确否决**了"全世界三维 SDF 体素"（数据量约 34×、网格化遍历量高两个数量级、且当时判断为超出需求）。

现在需求把"真三维（洞穴 + 悬垂）"作为**大世界的组成部分**（而非"一小块可挖区"），并在 10km 尺度上要求它：

| 事实 | 现状 | 结论 |
| --- | --- | --- |
| 层① 地表 | 纯高度场，**无悬垂、无洞穴** | 无法表达真三维 |
| 层② 体积 | 只在中心 3×3 tile 的标记区内、地表下 16 格内、玩家窗口内（ADR 0020） | 无法覆盖 10km 全图 |
| 层③/④ | 未实现 | 不参与本阶段 |
| 破坏 | 已有完整子系统（T27~T56） | 本阶段**休眠**，不得删除 |

因此**不能**在现有层①/②的口径下满足需求，必须重新划定各层职责与覆盖范围。同时 ADR 0004 依然有效的一条核心判断是：**全图任意深度三维 SDF 体素的代价（数十 GB）在现有预算下不成立**。本 ADR 的全部取舍都建立在这条判断之上。

## 决策

### 一、三层职责与覆盖范围（v2）

| 层 | 表示 | 覆盖范围 | 本阶段读写 |
| --- | --- | --- | --- |
| ① 宏地形 | 高度场 tile（64×64 列、`int16` 1/16 格） | **全图 10km** | **只读** |
| ② 地表体积壳 | 贴着地表的**有界 SDF**（厚度 `T`）→ **离线烘焙为块网格** | **全图**（近场渲染与碰撞） | **只读** |
| ③ 水体 | 河道路径样条 + 静态水位 + 水面网格 | 河道 / 湖泊 | **只读** |
| ④ 实体 | Jolt 刚体 / `CharacterVirtual` | 玩家 | 动态 |

- 层② 由 ADR 0004 的"**仅标记区域内** + 可挖"扩展为"**全图地表壳** + **预烘焙** + **只读**"。
- **壳厚 `T` 与分环**见 [ADR 0024](0024-terrain-streaming-and-lod.md)：Ring 0（0–512 m）用体积壳全细节，其外改用高度场 LOD。
- **壳以下为实心岩**（`indestructible`，与 [ADR 0013](0013-destructible-elements.md) 自洽）；壳以上为空气。

### 二、因为本阶段只读 ⇒ 可以"离线烘焙成网格"

层② 在本阶段**不需要运行时编辑**，因此**不必在运行时持有 SDF**：由离线工具（[ADR 0026](0026-premade-map-format-and-bake-tool.md)）在生成期完成"SDF → Surface Nets 网格"（复用 [ADR 0007](0007-volume-meshing-algorithm.md)/[0019](0019-ambiguous-cell-vertex-splitting.md) 的同一套数学），运行时只做"读块 + 上传网格 + 建碰撞体"。

这与现有"可挖体积块"的差别仅在**数据来源与只读性**：网格化数学、碰撞体类型（Jolt `MeshShape`）、流式调度形态全部复用。

### 三、破坏子系统：**休眠保留，不删除**

- ADR 0013 / 0015~0018 / 0020 / 0022 与 `world/dig/` 全部代码**保留**；
- 本阶段**不实例化**可挖体积世界与倒塌运行时（不创建、不调度、不显示）；
- F1 面板必须显式标注"**破坏：已休眠**"，并在文档登记**切换条件**（需要运行时破坏时重新启用，层② 由只读转回可写）。

### 四、读取原则（与既有架构一致）

生成仍是**纯函数**（种子 + 整数坐标），离线烘焙亦必须确定性（同一版本 + 同一种子 ⇒ 逐位一致，红线 7）。浮空物/建造物仍走层③/④，**绝不写入地形场**（ADR 0004 硬约束 1）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **宏高度场 + 全图预烘焙只读体积壳 + 水体层**（采纳） | 近场真三维（洞穴/悬垂）可表达；远景靠高度场 LOD 廉价；运行时无需 SDF；复用既有网格化/碰撞/流式 | 壳厚以外无三维（悬垂淡出）；预制数据体积大 | **采纳** |
| 全图流式 SDF / SVDAG 体素 | 任意深度真三维 | 存储/带宽/生成/碰撞全重做；10km 下数十 GB 级 | 不采纳（代价远超当前需求与预算） |
| 高度场 + 洞穴实例（Valheim 形态） | 最省 | 悬垂/洞口只能在实例内，不是"全世界真三维" | 备选（若壳厚难以维持时的降级兜底） |
| 维持现状（1km + 标记区体积） | 零改动 | 不满足 10km 与真三维 | 不采纳 |

## 后果

### 正面

- 需求（真三维洞穴 + 悬垂）在**有界成本**内可表达：成本随"壳厚 × 视距窗口"增长，而不随世界总量增长。
- 大量既有资产可复用：Surface Nets、块格式、`MeshShape` 碰撞、流式调度骨架、材质管线。
- 破坏子系统完整保留 ⇒ 未来启用是"打开开关 + 层② 转可写"，不是重写。

### 负面 / 必须承受的代价

- **壳厚以外无悬垂/洞穴**：Ring 1/2 用高度场 LOD ⇒ 远处洞穴口与悬垂会消失（**登记为已知限制**，见 ADR 0024）。
- **预制数据体积大**：10km 全细节网格可能到 GB 级 ⇒ 必须分环存储 + 压缩 + 发行策略（ADR 0026）。
- **层② 从"可写"变"只读"**：本阶段不能挖；与产品目标"部分物体可破坏"的关系是**暂缓**，须在 `game-design.md` 登记并写明切换条件。

## 何时需要重新审视

1. **需要运行时破坏** ⇒ 层② 转回可写（回到 ADR 0020 的动态常驻 + 脏块保留路径），需另开 ADR 修订。
2. **需要"任意深度真三维"**（不止地表壳）⇒ 回到全图 SDF/SVDAG 评估（ADR 0004 重审条件 1）。
3. **壳厚 `T` 与 LOD 环距实测守不住预算或观感** ⇒ 修订 ADR 0024 的环参数或本 ADR 的壳厚。
4. **层间接管（ADR 0011/0012）在 LOD 区域出现接缝/穿模且长期不收敛** ⇒ 回到 ADR 0004 重审条件 4（"洞穴作为独立关卡"路线）。
