# ADR 0039：三种交互模式与输入隔离（自由活动 / 建造 / 修改）

- 状态：**有效**（2026-10-08）
- 相关：[ADR 0032](0032-object-palette-and-placement-mode.md)（物件选择器与摆放模式；本 ADR **扩展并细化**其决策四"模式内输入让位"）、
  [ADR 0035](0035-modular-building-kit-and-enterable-spaces.md)（建筑 kit）、
  [ADR 0038](0038-construction-editor-and-runtime-separation.md)（编辑器分期；首期 = **建造交互完善**）
- 落实：所有者 2026-10-08 需求 —— "将模式定义分为**自由活动模式、建造模式、修改模式**；进入修改模式 / 建造模式时**屏蔽左键的发光球功能**；
  将三种模式的**按键功能进行隔离区分**；**发光球是自由活动模式专属的功能**"；并先经"**评估合理性，合理则开发**"。
- 前置：V0.11 的 I4（gizmo）与 I4b（把"摆放 / 修改"拆成两种模式）已落地；本 ADR 把该拆分**升格为三模式契约**并补齐隔离硬规则。

## 一、决策

1. **三种模式（唯一定义，不得另起别名）**
   - **自由活动**（**默认**）：启动即此模式；建造 / 修改模式 `Esc` 退出后回到本模式。**左键 = 发射光球**（按住 = 连发）。
   - **建造**（即既有"摆放模式"）：`F2` 物件选择器 ⇒ 选类型 ⇒「进入摆放」/ `Enter` / `F3`。**左键 = 放下**当前单位。
   - **修改**：`F2` 物件选择器 ⇒「**修改模式**」按钮。**左键 = 点击已有物件 ⇒ 选中**（显示 gizmo）、按在手柄上 = 拖动改 transform。
2. **三模式互斥**：任一时刻**至多一种**；进入一种即退出另一种；`Esc` **逐级**退出（修改 / 建造 → 自由活动 → 系统面板）。
3. **光球是「自由活动」专属**：建造 / 修改模式内**屏蔽左键光球**（**含按住连发**）。
   实现落点 = **输入上下文归属表**：`game/input_context.hpp` 的 `OwnerOf(state, ActionId::Attack)` 在建造 / 修改上下文归
   `Build` / `Modify` ⇒ 自由活动（base）的发射路径**拿不到**该动作；退出模式后**逐位恢复**。
   *（2026-10-08 局部修订：初版落点写的是"`game/main.cpp` 的 `fireHeld` 必须同时排除两种模式"，
   该实现方式已由 [ADR 0040](0040-input-context-stack-and-action-ownership-table.md) **收敛为归属表**；契约不变。）*
4. **按键功能隔离**：模式专属键**只在该模式内生效**；其它模式内**消费边沿但不生效**（不留残余边沿）；
   **同键冲突必须显式让位**（已知：`E` = 建造模式"旋转" / 自由活动"传送门交互" ⇒ **建造与修改模式内 `E` 不触发交互**）。
5. **模式切换必须可见**：建造 = **幽灵预览 + HUD 横幅**；修改 = **屏幕中央指示器**（未选中 = 白十字 / 已选 = 绿十字 + 文案；
   ImGui 前景绘制，**零 GPU 资源**、不参与输入抑制；无 CJK 字体时回退纯 ASCII）。**禁止**"进了模式但看不出"。
6. **通用键不属于任何模式**（三模式共享）：移动 / 跳 / 冲刺 / 飞行、`F1`（调试面板）、`F2`（选择器）、`F5`（保存）、
   `Ctrl+Z` / `Ctrl+Y`（撤销 / 重做）、`Z` / `X` / `B`（摆放开关）、`Esc`（按第 2 条逐级顺序）。
7. **不得删除既有能力**（SKILL §五《已实现能力：只允许用配置项关闭》）：模式化只改变**"何时生效"**，
   **不得**删除任何模式的功能代码；需要关闭时用**配置项**。
8. **权威处**：**按键 ↔ 模式**完整矩阵 = [`docs/ui-inventory.md`](../ui-inventory.md)；**玩家要什么** = [`docs/game-design.md`](../game-design.md)（G12）；
   **不可违反的形态** = `SKILL.md`《三种模式与输入隔离》（本 ADR 与其保持一致，不复制全矩阵）。

## 二、依据（业界标准）

- **UE5**：视口左键默认 = **选择**（gizmo 只出现在**选中**对象上），放置靠从 *Place Actors / Content Browser* **拖入** ⇒ **"选择"与"放置"是两个工具**。
- **Unity**：Scene 工具栏 Move / Rotate（选择 + gizmo）与从 Project 拖预制体放置**分开**。
- **Godot**：拖入放置 vs 点击选择。
- **Valheim / Rust / 7 Days to Die**（玩家建造侧）：**建造模式（锤子）与常规分离**。
  ⇒ 共同口径 = **"放置"与"选择·修改"必须是不同的工具（模式）**，且修改模式内**点击选中**而非**悬停选中**
  （悬停选中会让 gizmo 在放置时不断弹出、并被左键误触 —— 本项目 V0.11 / I4 初版即此问题，由 I4b 拆开）。

## 三、后果与已知取舍

- **消除左键歧义**：三种模式下左键含义**唯一**、可预期；"按住左键没反应"一类反馈由**可见指示**兜底。
- **同键冲突有明确裁决口**：规则要求**点名**冲突键并规定谁让位，而不是依赖代码里"恰好先判定谁"。
- **已知取舍**（如实登记）：① `F3`（重复上次）在**任意模式**下都可**进入建造**（它是建造入口，非模式专属功能）；
  ② 修改模式的 gizmo 仍**无 Y 轴平移 / 无缩放**、移动落点**不做重叠校验**（见 [`docs/plans/v0.11.md`](../plans/v0.11.md) §5）。
- **不做 / 不影响**：不改世界表示、破坏分级（[ADR 0013](0013-destructible-elements.md)）与存档字节布局；**不新增**暂缓项。

## 四、验证（可检查判据）

1. **自由活动**：按住左键 ⇒ **连续发光球**。
2. **建造**：按住左键 ⇒ **只放下、不发光球**；按 `E` ⇒ **不打开传送门**。
3. **修改**：按住左键 ⇒ **只选中 / 拖动、不发光球**；按 `E` ⇒ **不打开传送门**；屏幕中央**指示器**出现（未选中白 / 已选绿），`Esc` 退出后**消失**。
4. 自动侧：`ctest` 全绿、`check-banned-identifiers.ps1` 通过、构建零警告（口径同 SKILL 第七节）。
