# ADR 0026：预制地图格式与离线烘焙工具

## 背景

需求为**预制地图**（而非每次运行时程序化生成），且世界为 10km×10km。按 [ADR 0024](0024-terrain-streaming-and-lod.md)，流式要求"**只读窗口那一块**"⇒ 地图数据必须**分块、可随机访问**。

若存成一个整体大 blob：要么整份读入（启动数分钟、内存爆），要么无法定位窗口 ⇒ 流式优势失效。因此格式设计是本需求能否成立的前提之一。

同时，本仓库既有约束必须遵守：

- 生成/烘焙必须**确定性**（红线 7；ADR 0004/0007 的"纯函数"口径）；
- 配置类文件带 `schema_version`，**非法即抛、不静默回退**（ADR 0005 口径）；
- 大体积美术资源"**不入库**"（`.gitignore` + 取回脚本 + 校验和 + 许可台账，见 `docs/file-index.md` 的 `assets/textures/`、`assets/models/` 行）。

## 决策

### 一、数据分层与块粒度

| 数据 | 块粒度 | 说明 |
| --- | --- | --- |
| 宏地形高度场 | 地表 tile（64×64 列、`int16` 1/16 格） | 与运行时 tile 同粒度（ADR 0008） |
| 地表体积壳网格 | **32³ 体素对齐**的块（与既有体积块同口径） | 离线由 SDF → Surface Nets 生成（ADR 0023） |
| 水体 | 按 tile 的河道路径 / 水位 / 水面网格 | 见 ADR 0027 |

### 二、文件结构

- **分块文件 + 索引**：文件头（魔数 + `schema_version` + 世界范围 + 块尺寸）+ 索引表（块坐标 → 偏移 / 长度）+ 数据段；
- **可随机访问**：给定块坐标可**O(1)**（或 O(log n)）定位并只读该块，不读整份；
- **压缩**：逐块 zstd（与既有存档口径一致）；
- **版本与校验**：`schema_version` 不匹配即拒绝加载（不静默回退）；可选的块级校验和。

### 三、离线烘焙工具（`tools/`，确定性）

- 输入：地图定义（种子 / 范围 / 群系与洞穴参数 / 河流样条定义）；
- 步骤：① 宏高度场（含山川/平原/丘陵分区）→ ② 地表体积壳 SDF（含悬垂、洞穴、河床）→ ③ Surface Nets 网格化 → ④ 水面/水位 → ⑤ 分块写盘 + 索引；
- **同一版本 + 同一输入 ⇒ 逐位一致**（可回归比对哈希）；
- 工具失败**即报错**，不产出半成品。

### 四、入库与发行

- 预制地图**数据文件的入库口径按尺寸分流**（2026-10-06 修订，取代原"一律不入库"）：
  **小世界预制（如 B）入库**（干净克隆即可玩，满足"写在程序里、何时访问都一样"）；**大世界（如 A）不入库**，
  与 `assets/textures/`、`assets/models/` 同口径 —— `tools/bake_premade_maps.ps1` 生成、`NOTICE.md` 台账登记来源与校验和；
- 地图的**可读定义**（种子、范围、群系参数、河流样条）可入库（小体积、可复现）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **分块 + 索引 + zstd**（采纳） | 支持 O(1) 随机访问；与流式天然契合；可增量重烘焙 | 需设计格式与工具 | **采纳** |
| 单一大文件顺序读 | 实现最简 | 无法只读窗口；启动/内存爆 | 不采纳 |
| 运行时代码程序化生成（不预制） | 无需存储与发行 | 与"预制地图"的需求相悖；生成 CPU 成本在运行时 | 不采纳（作为"只存差分"的混合形态保留为备选） |
| 直接存 SDF（不存网格） | 便于未来运行时破坏 | 运行时需在 worker 重网格化；内存/CPU 更高 | 备选（若未来启用破坏 ⇒ 回到存 SDF + 运行时网格化，见 ADR 0023 重审 1） |

## 后果

### 正面

- 流式的"只加载窗口"成立；启动不再与地图总量成正比。
- 地图内容可**离线**精细生成（不受运行时预算约束），运行期只做"读 + 上传"。

### 负面 / 必须承受的代价

- **磁盘与发行体积大** ⇒ 必须有压缩、分环（LOD 版本）与发行策略；干净克隆后需先跑生成 / 取回脚本。
- 地图更新需**重烘焙**（可增量，但仍是工具链负担）。
- 格式一旦冻结，新增字段须走 `schema_version` 迁移。

## 何时需要重新审视

1. **预制数据体积超出发行上限** ⇒ 改为"程序化生成 + 只存差分"，或进一步降低远场 LOD 版本。
2. **未来启用运行时破坏** ⇒ 需同时存 SDF 或把脏块落盘（ADR 0020 决策五的切换条件）。
3. **格块粒度与流式 / 碰撞实测不匹配** ⇒ 调整块尺寸（须与 ADR 0008 的尺寸口径一致）。
