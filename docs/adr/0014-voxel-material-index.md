# ADR 0014：体素级材质（可挖体积的材质索引）

- **状态**：已采纳（2026-09-27）
- **相关**：[ADR 0004](0004-hybrid-layered-world-representation.md)（分层混合世界）、[ADR 0007](0007-volume-meshing-algorithm.md)（体积网格化）、[ADR 0009](0009-terrain-material-pipeline.md)（地表材质：高度/坡度 splat）、[ADR 0013](0013-destructible-elements.md)（可破坏元素：坚固度）、`docs/game-design.md`（G12 / 能力清单）、`.trae/skills/voxel-engine-dev-standards/references/destructible-elements.md`

## 背景

两条**已确认的需求**共用同一个缺失的前置：

| 需求 | 出处 | 缺什么 |
| --- | --- | --- |
| ① 不同材质**抵抗伤害的能力不同**（泥土 3 / 岩石 5，逐格³ 抵消） | 项目所有者 2026-09-27；[ADR 0013](0013-destructible-elements.md) | 需要知道"**每个体素**是什么材质"才能查到它的坚固度 |
| ② **挖出的洞**应按"被切开的是什么材质"着色（当前洞底呈"草"= 绿色，与直觉不符） | 项目所有者 2026-09-27（人工实测第 7 轮） | 需要知道"**被切开的那个体素**是什么材质" |

现状：可挖体积只有 `int8` **密度**，**没有任何材质信息**；体积网格与地表**共用同一套 splat 规则**（`materials.toml` 的高度带 × 坡度带），于是洞底（y≈110、坡度 0）命中"草"⇒ 绿色。

## 决策

### 一、材质**按列派生、不落存储**（实现期修正）

- 材质 = "该列地表 splat 主槽位经表层 → 次表层映射后的结果"，即 `(worldX, worldZ) → 槽位` 的**纯函数**：
  体积侧由 `DigVolumeWorld::SampleMaterialSlot` 委托 `TerrainWorld::QueryDigMaterialSlot` 得到。
- **不引入每块 33³ 材质数组**：初稿曾计划存储（441 块约 +15.5 MB），但既然首期不做深度分层、且
  挖除不删材质、塌落不搬材质 ⇒ **任意高度的材质恒等于该列材质** ⇒ 存储是**冗余**的。
  这同时消除了"塌落要不要搬材质"这一整类一致性问题（不必再让 `DensityRegion` 携带材质）。
- **代价与切换条件**：一旦需要**深度分层**（浅土深岩）或**可编辑体素材质**（矿脉、多层岩层），
  纯函数不再成立，那时才引入存储（`VolumeBlock::material`）与相应的搬运规则 —— 属本 ADR 的**切换条件**。
- 仅**可挖体积**消费该材质；地表的着色仍按 ADR 0009 的逐像素 splat（不进体素）。

### 二、材质来源：**继承地表材质 + 表层→次表层映射**（项目所有者选定）

初始化（`InitFromHeightField`）时按列派生：

1. 取该列**地表的 splat 主槽位**（权重最大的层）作为该列体素的**基材质**；
2. **表层材质映射**：`grass` / `sand` 这类"只该出现在地表薄层"的槽位，在体积内映射为 **`dirt`**；`rock` / `dirt` 保持自身。⇒ **在草地上挖坑看到的是土，在山体（陡坡 ⇒ 岩）里挖洞看到的是岩** —— 与现实直觉一致；
3. 首期**不按深度再做分层**（不做"浅层土 / 深层岩"），记为后续项（见「后果」）。

### 三、网格与着色：顶点携带**材质槽位覆盖**

- `MeshVertex` 新增 `float material`（`kNoMaterialOverride = -1`）：**地表网格填 `-1`**（继续走 ADR 0009 的逐像素 splat），**体积网格填具体槽位**；
- Surface Nets 生成顶点时取该 cell **实体侧**（密度 < 0）各角材质的**众数**写入（跨材质的 cell 只产 1 个顶点，故取众数；全为"未指定"时回落 `-1`）；
- 顶点属性 `location 2` + 片元 `flat in`（离散属性不做插值，避免三角形内出现"槽位 1.7"这类中间值）；
- 片元遇到槽位 `>= 0` 时**直接令该槽位权重为 1**，否则照旧调用 `computeWeights()`；
- ⇒ 洞的内表面（壁与底）呈**被切开的材质**，不再出现"地下草地"。

### 四、与坚固度的关系

[ADR 0013](0013-destructible-elements.md) 的 `toughness` 由**该体素的材质槽位**查表得到：逐格³ 扣预算时读的是**同一个槽位**，无需第二份数据。

## 备选方案（已评估）

| 备选 | 未采纳的理由 |
| --- | --- |
| 不存材质，用几何规则**推导**洞内材质（例如按深度硬编码"浅土深岩"） | 无法表达"同一深度不同材质"（矿脉、岩层、不同岩性），也无法支撑 ADR 0013 的逐格坚固度 |
| **显式体素材质数据**（独立文件 + 生成规则，可做矿脉 / 多层岩层） | 最灵活，但需要新的数据通道、生成规则与美术约定；**项目所有者本次选择"继承地表材质"** ⇒ 记为后续项（见「后果」的切换条件） |
| 洞内表面**固定用岩** | 最省，但"挖草地也是岩"与"按被破坏物体的材质着色"的要求不符 |
| 把材质写进**密度**（编码进 `int8`） | 密度已用满且语义冲突（正负号承载实心/空），不可取 |

## 后果

- **正面**：一次投入同时解决"洞内外观"（T34）与"逐格坚固度"（T31）；洞内表面自然呈现被切开的材质。
- **代价与已知限制**：
  1. 常驻内存**零新增**（材质按列派生，不落存储；见 §一 的实现期修正）；
  2. 顶点格式需为材质槽位**增加一个字段**（地表网格填"未指定"）；
  3. 首期**不做深度分层** ⇒ 深部与浅部材质相同（要"浅土深岩 / 矿脉"须改用"显式体素材质数据"，见切换条件）；
  4. 体积**无存档** ⇒ 材质改动同样不跨会话（沿用已知限制）。
- **后续 / 切换条件**：
  - 需要**矿脉 / 多层岩层 / 不同岩性** ⇒ 切换到"显式体素材质数据"（另开 ADR）；
  - 需要**地表以下按深度分层** ⇒ 在 §二.3 的映射规则里加深度带（改配置即可，不必换表示）。
