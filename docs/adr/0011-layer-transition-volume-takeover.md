# ADR 0011：层间过渡 = 区域足迹内由可挖体积**接管**地表网格

- **状态**：已采纳
- **日期**：2026-09-27
- **相关**：ADR 0004（硬约束 3：「体积与地表相接处由**体积接管该列高度**，这是层间过渡的唯一处理点」）；ADR 0006（可挖区域标记）；ADR 0007（Surface Nets）；ADR 0008（尺寸与精度）；`docs/plans/v0.1.md` 的 T8
- **落地**：`world/terrain/terrain_mesher.*`（`ITerrainQuadFilter`）、`world/terrain/terrain_world.*`（`SetQuadFilter`）、`world/dig/dig_region.*`（`SkipQuad` 实现）、`world/dig/dig_volume.*`

## 背景

ADR 0004 把"层间过渡"点名为本方向**主要的风险点**，但只给了原则（"由体积接管该列高度"），
没有给可施工的做法。落地可挖体积（T8）时必须先回答：

**同一块地形，什么时候由地表高度场网格画、什么时候由体积等值面网格画？**

现实约束：

1. 地表是**高度场外壳**（每列 1 个高度，网格只连相邻列顶面 + 落差墙面），
   体积是**有界 SDF 等值面**（ADR 0007 的 Surface Nets）。两者**都能**表示"地面"，也都**不能**无缝地表示对方：
   - 高度场无法表达悬垂与横向洞穴（这正是体积存在的理由）；
   - 体积只在被标记区域内存在（ADR 0004 硬约束 2），区域外没有数据。
2. 两侧在**未挖状态下表示同一个表面**：体积密度由高度场推导（`d = y − 地表高度`），
   故体积表面与地表网格在平面地形上**逐点重合**（见 `dig_volume.hpp` 的初始化口径）。
3. 一旦重叠绘制，两个表面共面 ⇒ z-fighting / 闪烁，必须先决定"谁来画"。
4. 接缝无法通过"把四边形切开"（mesh clipping）彻底消除——那需要把高度场网格沿区域边界**重新三角化**，
   成本与错误率都显著高于 V0.1 的收益（挖洞是本轮目标，不是几何缝合）。

## 决策

**在可挖区域内，地表网格让位：凡是"四角全部落在可挖区域内"的地表四边形，地表网格化时直接不发射，
由体积等值面接管这一片可见表面。**

具体口径（三条一起才成立，缺一会退化为"缝"或"闪"）：

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | **逐四边形判定，且要求四角全部可挖**（`DigRegionTable::IsDiggable(x, 高度, z)` 对四个角都成立） | 只要求"任一角在区域内"会让地表网格在边界处**少画一圈**，而体积表面恰好也差那一圈 ⇒ **漏空**（能看穿地形）。要求"四角全部"则边界那一圈仍由地表绘制 ⇒ 至多**共面重叠**，不会漏空 |
| 2 | 判定接口为 `ITerrainQuadFilter`（声明在地表网格化侧），由 `DigRegionTable` 实现 | 依赖方向保持 `dig → terrain`：地表网格化**不认识**"可挖区域"这个概念，只认识"这个四边形要不要跳过" |
| 3 | 体积的密度采样在**区域外回退到同一套高度场公式**（`DigVolumeWorld::TerrainDerivedDensity`） | 区域边界处体积表面与地表表面**同源连续**；否则体积会在边界凭空长出一面墙 |

**为什么不是"按爆炸球体在洞口处打洞"（只在被挖到的地方删除地表四边形）**：那样地表网格的洞是
"按四边形整格判定的台阶状边界"，与体积的球面腔壁**不可能对上** ⇒ 洞口一圈出现可见裂缝，
而且裂缝正好在玩家盯着看的位置。区域足迹交接虽然把不一致摊到"区域边界"，
但边界可以选在**玩家不细看的位置**（本次配置即把区域边界放在离山体 4 格以外的平地上），
且不一致量级只有 **SN 的平滑误差**（平面地形上为 0，曲面处约 ≤0.5 体素）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **区域足迹交接**（采纳） | 实现最小、判定纯函数可测、平面地形上零误差、不会漏空 | 区域边界存在**一圈共面重叠**（可能在极端视角下轻微 z-fighting）；区域内的地表被 SN 平滑（棱角变圆，ADR 0007 的固有代价） | **采纳** |
| 按挖除球体删除地表四边形 | 改动局限在"被挖到的位置" | 洞的四边形台阶边界与球面腔壁对不上 ⇒ **洞口一圈裂缝**（正在看的位置） | 不采纳 |
| 沿区域边界**裁剪**地表网格（mesh clipping） | 理论上无缝 | 需要把地表网格按区域边界重新三角化（含顶点插值与索引重建），实现与测试成本高，且与本轮目标（能挖洞）无关 | 备选（若重叠观感不可接受再评估） |
| 区域内**完全不做地表**（当作不存在） | 最简单 | 区域外没有体积数据 ⇒ 区域外无地表、无碰撞、无高度查询 | 不采纳 |
| 体积表面**偏移一个小 ε** 避让地表 | 一行改动 | 破坏"未挖状态下两表面同源重合"的前提，会让洞口边缘出现可见台阶 | 不采纳 |

## 后果

### 正面

- 可挖区域的可见表面**只有一个来源**（体积），挖洞时不会与地表网格打架：
  **洞是真三维洞体**（横向洞穴、悬垂都能表达），这是纯高度场做不到的。
- 判定是**纯函数**（四角采样），可单测；地表网格化的默认路径（不设置过滤器）与旧版**逐位一致**。
- 与 ADR 0006 的分层结构天然对齐：区域由标记决定 ⇒ "哪里交给体积"是**世界定义的函数**，不是运行期状态。

### 负面 / 必须承受的代价

- **区域边界有一圈共面重叠**：在平面地形上两者逐点重合，深度比较相等时先画者胜（管线为
  `COMPAREOP_LESS`），通常不会闪烁；但浮点插值差异在极端视角下可能造成细线闪烁。
  **缓解方式**：把区域边界选在玩家不细看的位置（本次配置边界距山体 4 格、距出生点 32 格）。
- **区域内的地表被 SN 平滑**：陡壁棱角被磨圆（ADR 0007 已登记的代价）；平面地形上无误差。
- **区域内的地表碰撞仍是原地表高度场**（T8 本轮未做体积 `MeshShape`）：视觉已交给体积，碰撞没有 ⇒
  **洞口可见但走不进去**。这是本轮显式登记的降级（见阶段计划 T8 的"不做"清单），不是本 ADR 的取舍。
- 区域边界处的**高度场数据在内侧不再被渲染**（仅碰撞使用）：数据与视觉暂时不一致，
  待体积碰撞接入后由"体积接管该列"彻底取代（ADR 0004 硬约束 3 的完整形态）。

## 何时需要重新审视

1. **体积碰撞（Jolt `MeshShape`）接入时** ⇒ 必须把"区域内高度场采样"一并处理（打洞或改由体积接管），
   否则会出现"看得见洞、走不进去"。
2. **区域边界共面重叠在人工验收中被判定为可见缺陷** ⇒ 评估「沿边界裁剪地表网格」或"区域内地面完全不绘制"。
3. **可挖区域规模显著扩大**（接近整个地下层）⇒ 回到 ADR 0004 的重审条件 2，评估 SVDAG 等方案；
   届时应改用"地表 LOD 与体积的边界缝合"路线，而非本 ADR 的足迹交接。
4. **地表 LOD 落地时** ⇒ LOD 层与体积接管的交接需要重新界定（ADR 0004 重审条件 4 的延续）。
