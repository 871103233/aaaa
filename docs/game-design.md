# 游戏设计（本项目要做的游戏）

> **性质**：本仓库的**内容基线文档**之一（见 `.trae/skills/voxel-engine-dev-standards/SKILL.md` 第六节）。
> **层面**：**游戏层** —— 这里写"**我们要做哪款游戏、要求什么**"，与"引擎能做什么"分开。
> 引擎的通用能力见 [引擎能力与产出范围](engine-capabilities.md)；世界背景见 [世界观设定](world-setting.md)；
> NPC 见 [NPC 行为逻辑](npc-behavior.md)。
> **维护义务**：任何一次改动**新增、修改或移除游戏需求 / 玩法规则 / 阶段范围**，必须**同一次提交内**更新本文件。
> 未实现的需求**先占位**（状态 `未开始`），不得留白。

## 1. 这是一款什么游戏

**修仙题材的开放大世界游戏**（当前阶段的全部需求见 §2）。

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 题材 | **修仙大世界** | 项目所有者确认（2026-09-25） |
| 视角 / 控制 | 第三人称，玩家控制自己的角色 | 同上；引擎侧已有第三人称相机与胶囊角色 |
| 世界尺度 | **大世界**（尚未给具体数值） | 待补：具体尺度过大或过小都会影响流式与 LOD 参数 |
| 商业模式 / 平台 | 待补 | 待项目所有者提供 |

## 2. 当前阶段的全部需求（所有者已确认）

> 这是**当前阶段**的范围。每行都必须是可判定的；未实现的写 `未开始`，不得空着。

### 2.1 世界生成（三种并存的要求）

| # | 需求 | 状态 | 实现方式 / 落点 | 备注 |
| --- | --- | --- | --- | --- |
| G1 | **每次进入世界都随机生成**（同一种子可复现，不同种子世界不同） | **已实现** | 种子 + 整数坐标的**纯函数**生成（`world/generation/`） | 随机即可复现：换种子即是新世界 |
| G2 | **可对必备元素进行定义**（声明"这个世界必须有 X"） | **未开始** | 尚无实现 | 需要一份**世界需求清单**（必备元素 + 出现条件），先生成需求再生成世界；格式与规则**待定** |
| G3 | **可预设固定地图**（手工地图，用于测试 / 剧情） | **已实现** | `assets/maps/<name>.toml`（种子 / 范围 / 出生点 / 地形编辑区）；示例 `assets/maps/test_range.toml` | 手工编辑域：flatten / raise / carve |

### 2.2 玩家能力

| # | 需求 | 状态 | 实现方式 / 落点 | 备注 |
| --- | --- | --- | --- | --- |
| G4 | **能跑** | **已实现** | 走 / 冲刺（`game/`，胶囊控制器） | — |
| G5 | **能飞** | **部分实现** | 飞行模式开关（`game/`） | 当前是"可直接操控升降"的测试设施；**是否作为正式玩法（灵力 / 御剑等）尚未定**，待世界设定确认 |
| G6 | **能破坏地形** | **部分实现** | 球笔刷挖 / 堆 + 脏 tile 重网格（`world/dig/`） | 可改地形高度；**三维挖掘（洞穴、横向掏洞）未实现** |
| G7 | **能在大世界里收集东西** | **未开始** | 尚无实现 | 需要：可收集物（物品定义）、拾取交互、背包 / 持有；物品系统整体未建 |
| G8 | **视角控制**：以水平面为基准**上下各看近 90°**（规格 **±89°**，留 1° 防退化矩阵）；**鼠标锁定**（相对鼠标模式，光标隐藏、位移持续输入、不会移出窗口） | **已实现** | 平台层相对鼠标模式（失焦自动释放）+ `game/` 捕获状态机（`Esc` 释放 / 点击重捕获）+ 相机俯仰钳制 | 俯仰上限**不得取正好 90°**（视线与上方向平行会让 `lookAt` 得 NaN，见 B2）；重捕获的那次点击**不得**同时触发挥/堆 |
| G9 | **系统面板与设置**：`Esc` 打开面板，含**显示模式（窗口 / 全屏）**、窗口下的**分辨率选择**、**音量 0–100**、**退出游戏**；设置须持久化（下次启动仍生效） | **已实现** | `game/system_panel.*`（面板）+ `engine/platform/settings.*`（设置与落盘）+ `engine/platform/window.*`（显示模式 / 分辨率 / 事件转发）+ `game/gameplay_input.hpp`（输入抑制） | **控件标签即行为契约**，见 [ui-inventory.md](ui-inventory.md)；**音量仍为"部分实现"**（生效路径已接通、当前无音源 ⇒ 听不到）；ImGui 默认字体无 CJK 字形 ⇒ 控件用中英双语标签 |
| G10 | **世界边界**：地图边缘必须有**不可穿越的边界**（空气墙），避免玩家掉出世界；边界由**地图范围自动推导**，对**测试地图与所有随机地图**一致生效 | **已实现** | `world/terrain/world_bounds.*`（由 tile 范围推导边界与墙位）+ `engine/physics/`（`AddStaticBox` 静态盒体）+ `game/out_of_bounds.hpp`（出界救援） | 墙按设计**完全不可见**；另配"掉出世界救援"（飞行越界后坠落送回出生点，余量 16 格），因为墙挡不住飞行 |

| G11 | **画面质量达到 3A 观感**：地表与物体表面**细腻圆润**、不发灰、有立体感与材质感（人工实测反馈"像 20 年前的游戏"） | **未开始** | 由 [ADR 0010](adr/0010-render-quality-pipeline.md) 定义的四阶段质量线承担：HDR + 色调映射（T20）→ 光照与阴影（T21）→ PBR 与材质四件套（T22）→ MSAA 与细节（T23）；判据采集靠 F1 面板性能数据（T24） | 该线属"纯增强"范畴，**由项目所有者于 2026-09-26 明确追加授权**；观感**必须人工目视验收**（SKILL 第七节），不以色带 / 阴影 / 高光 / 锯齿的可判定现象替代 |

### 2.3 主角与 NPC 能力清单（能力 · 状态 · 参数 · 落点）

> **为什么单列一节**：玩法能力会随阶段不断增加（跑 / 飞 / 破坏地形 / 收集 / 战斗……），
> 且**主角与 NPC 共用同一套底层能力**。这一节是**唯一的能力清单**，新增或改动任何能力都必须在此登记（见 SKILL 第六节六.7）。

**主角能力**

| 能力 | 状态 | 参数（当前值 / 来源） | 落点 |
| --- | --- | --- | --- |
| 走 / 冲刺 | **已实现** | 冲刺 20 格/秒；重力 24、跳跃初速 7.20（= 身高 60%）、最大坡度 50°、自动上台阶 1.0 格（`engine/physics/`） | `game/character_movement.hpp`、`engine/physics/` |
| 飞 | **部分实现** | 测试设施（`F` 开关、`Space` 升 / 左 `Ctrl` 降）；**正式形态（灵力 / 御剑等）待世界设定确认** | `game/main.cpp` |
| 破坏地形 | **部分实现** | **平整填平 / 削平**（`Level`，向目标高度平滑收敛）+ **平滑爆破**（`Crater`，坑体 + 外环、边界一阶连续）+ 球笔刷挖 / 堆；参数表 `assets/config/brush.toml`（半径 6 格 / 速率 6 格-秒 / 坑深 6 / 坑半径 8 / 外环 2）；**三维挖掘（洞穴 / 悬垂）未实现**，待 T8 体积破坏 | `world/dig/terrain_brush.*`、`assets/config/brush.toml`、`game/main.cpp` |
| 收集物品 | **未开始** | 缺：物品定义、拾取交互、背包 / 持有 | 待登记 |
| NPC 能力（复用同一套） | **未开始** | 与主角共用移动 / 地形改造底层能力；**是否允许 NPC 改造地形、以何种规则**待 NPC 阶段确认 | 见 [npc-behavior.md](npc-behavior.md) |

**通用约定**

- **能力清单里的每一条都必须可判定**（有参数或可观察现象），不得只写"支持 X"。
- **主角与 NPC 的能力差异**（数值、感知、权限）在 NPC 阶段写明；底层能力不各写一套。

## 5. 登记规则

1. **先登记后动手**：任何新玩法需求先在 §2 补一行（状态 `未开始`），再实现，完成后回填。
2. **可判定**：每行的"实现方式 / 落点"必须具体到模块或文件；写"用某个系统实现"这类空话视为未填。
3. **不写"A 或 B"**：涉及技术选型的（如物品系统怎么存、飞行的实现方式），候选与理由写 **ADR**。
4. **不虚构设定**：主角身份、境界体系、门派、地名一律来自项目所有者，未提供就标 `待补`。
5. **需求与引擎能力联动**：需求若依赖引擎缺失的能力，必须同时在 `engine-capabilities.md` 占一行，
   并在阶段计划里给出实现任务。

## 6. 待项目所有者确认的问题

> 回答后整理进上表，并在此标记已答。

1. **世界尺度**：一个世界大约多大（多少平方公里 / 多少 tile）？是单一大陆还是多区域？
2. **随机程度**：每次随机生成时，哪些东西必须保持稳定（如"一定有某类地貌"）？→ 对应 G2。
3. **必备元素清单**：`G2` 具体要声明哪些内容？（至少举 2~3 个例子，如"每张地图必须有一条河""必须有可采集的灵石"）
4. **飞行的定位**：是开局即可自由飞，还是需要条件（境界 / 道具）？→ 决定 G5 的做法与手感
5. **收集物范围**：`G7` 要收集什么（资源 / 装备 / 功法 / 材料）？收集后如何使用？
6. **主角设定**：身份、境界体系、成长方式（是否由项目所有者提供，或需要一起设计？）
