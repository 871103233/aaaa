## 1. 技术约束（已确定，不属待定）

- NPC 的动态实体一律为 **ECS Entity（EnTT）**：位置、朝向、状态、目标等为组件；**地形不进 ECS**（红线 1）。
- 行为逻辑**跑在固定步长**里（1/60，`engine/core/fixed_step.hpp`），**不得**依赖渲染帧率；
  渲染插值系数 `alpha` 只能用于渲染，**不得**回写行为状态（红线 11）。
- `world/` 不得直接调用平台 API；NPC 需要的时间、随机、IO 一律经引擎核心层。
- 随机必须是**确定性**的（种子 + 整数坐标 / 显式 RNG 状态），不得用 `rand()` 与全局时间（红线：分块确定性）。
- 大量 NPC 的更新**不得阻塞主线程**：须走任务系统（enkits）分帧 / 分片更新，具体预算见 SKILL 第四节。
- 寻路与感知查询的是**当前世界表示**：地表高度场 + （将来的）可挖体积 + 物件层，
  查询接口形态与 `ITerrainQuery` 同源思路（引擎层定义契约、世界层实现）。

## 3. 登记规则

1. **先登记后动手**：写 NPC 代码前，先在第 2 节把对应行从 `待补` 更新为初步结论；

3. **与内容能力表联动**：NPC 相关内容的实现状态改动，同时更新 `docs/content-capabilities.md` §2.4。
4. **与世界设定联动**：NPC 的种族、文明、语言等来源自 `docs/world-setting.md`，不在本文件重写。
