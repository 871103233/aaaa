**A4. 交互修订（所有者 2026-10-08）：把「摆放」与「修改」拆成两种模式**

> **来源（所有者 2026-10-08）**："当前摆放和修改操作逻辑存在冲突，将**修改模式**在 `F2` 面板中单独做一个按钮入口，
> 修改模式时在屏幕中间显示一个**光标指示器**，点击已存在的物体时**选中**进入调整的相关逻辑。"
> **真伪判定 = 确认交互冲突**（I4 引入）：ADR 0032 决策四要求"模式内左键 = **放下**"，而 I4 又定义"左键**按在手柄上 = 拖动**"
> 且"选中 = **准星指向**" ⇒ 摆放时准星扫过既有物件就弹 gizmo、按在手柄上的左键不再放下（"左键放"不再无条件成立）。
> **业界标准（点名）**：UE5（视口左键 = **选择**，放置靠拖入；gizmo 只出现在选中对象上）/ Unity（Move·Rotate 与拖预制体放置分开）/
> Valheim·Rust（**建造模式与常规分离**）⇒ 共同口径 = **"摆放"与"选择·修改"是两种工具（模式）**，且修改模式内**点击选中**而非悬停选中。
> **结论：方案合理、与业界一致 ⇒ 实施**（gizmo 能力代码全保留，只改**触发方式**）。

### 动手前评价（A6 输入上下文栈；先评价再动手 / 3A 基线；2026-10-08）

- **范围**：把**按键隔离**从"散落手写判断"收敛为**一张权威表 + 一个纯函数路由**（`PlayerInput` 的输入层重构）。
  **只做**：归属表 / 上下文 / `Esc` 栈弹出 / `suppression` 走上下文 / 文档与 DoD。
  **不做**：不改键位绑定（`InputMap` 的 `BindKey` 一行不动）、不改世界表示 / 破坏分级 / 存档、不改 `MouseCapture` 捕获状态机（见下）、
  不引入运行期可配置的"动作重绑定"（属后续增强）、不动面板内控件（`PaletteConfirm` / 面板按钮由面板自身处理）。
- **业界标准做法（点名）**：① **UE5 Enhanced Input** 的 **Input Mapping Context + Priority**（`Push`/`Pop` 上下文、高优先级**消费并阻断**低优先级）；
  ② **Unity Input System** 的 **Action Map 的 `Enable()` / `Disable()`**（互斥集合 + 只启用当前模式那张图）；
  ③ **Godot `InputMap`** 的 action + 代码层 gate；以及各 3A 通用的 **模态 UI 栈**（`Esc` 统一 = 弹栈顶）与
  **分层穿透**（base 层承载移动 / 视角，overlay 只覆写它要用的动作）。三者共同口径 = **"分层 + 优先级 + 消费 / 阻断"**，本项**采纳**。
- **本项目的 3A 基线形态（可判定判据）**：
  ① **任一时刻只有一个"游戏玩法上下文"生效**（自由活动 / 建造 / 修改**互斥**，SKILL 硬规则 2 由**结构**保证，不靠逐处 `xxMode=false`）；
  ② **光球仅自由活动**：`OwnerOf(Attack)` 在建造 = `Build`、修改 = `Modify` ⇒ 自由活动的发射路径**结构上拿不到**该动作（**A5 那类遗漏不可能复现**）；
  ③ **移动 / 飞行 / 视角在三种模式下逐位同源**（表里均为 `Free` = 穿透复用，**每帧只算一次 `command`**，性能不退化）；
  ④ **模态面板 ⇒ 玩法输入全量阻断**（`Blocked`），**面板级热键**（`F1` / `F2` / `F5` / `Ctrl+Z`·`Y` / `Z`·`X`·`B` / `Esc`）仍生效（`AlwaysOn`）；
  ⑤ **表 ↔ `ui-inventory` 矩阵逐格一致**（DoD 勾选项 + 单测钉死）。
- **是否降级**：**不降级**（完整实现）。**三处口径取舍（如实登记，非降级）**：
  ① **模态面板合并为一个上下文值 `Modal`** —— 系统面板 / 传送门菜单 / 物件选择器**当前**对玩法输入的隔离行为**完全相同**（全量抑制），
  故不拆三个值；若将来某个面板需要"只抑制一部分"，`InputContextState` 已保留三个独立布尔，拆分成本低；
  ② **`ModifyDrag` 单列一个上下文** —— 只为表达"拖动手柄期间鼠标位移归 gizmo、**不转相机**"这一条运行时子状态（否则又要退回手写布尔）；
  ③ **`PaletteConfirm`（`Enter`）与面板按钮不走路由表** —— 它们是**面板内部**的确认 / 控件语义（`ObjectPaletteOpen()` 自门控），
  不属于"玩法 / 模式"的隔离契约。
- **分帧 / 不冻结**：路由 = **O(1) 查表 + 栈深 ≤ 2**（编译期常量表、零分配、无字符串）⇒ 热路径**不退化**；
  `command` / `aimDirection` 仍**每帧一次**供全部固定步复用。**无新增重活**。
- **世界内一致性**：纯输入层重构，**不引入玩法语义**（三种模式的语义在 A5 已定，本项只改"判定在哪写"）⇒ 不涉及 `world-setting.md` 登记。
- **与捕获状态机的边界**：`MouseCapture`（`mouseCaptured` / `fireSuppressUntilRelease` / `captureBeforePanel`）是**物理层**（光标是否锁定），
  本栈是**逻辑层**（动作归谁）—— 两者**正交、不合并**（合并会把既有纯函数状态机弄脏）。

### 动手前评价（I4 gizmo；先评价再动手 / 3A 基线；2026-10-08）

- **范围**：**选中（准星指向 / 粘性）已有物件 → 拖动手柄改 transform** —— 平移仅 **X / Z**（`y` 由地表高度决定）、旋转仅**绕 Y（yaw）**；
  对象 = **单件 + 成套建筑**；提交走 I3 撤销栈（`MoveObject` / `MoveBuilding`）。
  **不做**：Y 轴平移（会导致悬空，违反 I2 契约）、缩放手柄、多选 / 框选（G6）、gizmo 吸附到顶点 / 插槽。
- **业界标准做法（点名）**：① **UE5 Editor** 的**世界轴 gizmo**（`GEditor->...`，选中 actor 后拖轴平移 / 拖环旋转）；② **Unity Editor** 的
  **Move / Rotate Gizmo**（W / E 切换，轴与环手柄）；③ **Godot Editor** 的 `Node3D` 平移 / 旋转 gizmo。三者共同口径 =
  **"选中对象上叠一组世界轴手柄；按在手柄上拖动改 transform；按在地面走原工具"**，**采纳**。
- **本项目的 3A 基线形态（可判定判据）**：① 进入摆放模式并**指向**已放置物件 ⇒ 手柄**可见**（X 红 / Z 蓝 / 环黄）；
  ② 左键**按在手柄上并拖动** ⇒ 物件沿该轴移动 / 绕 Y 旋转，**松开提交**；③ 提交后**可 `Ctrl+Z` 撤销**（回原位）与 `Ctrl+Y` 重做；
  ④ **退出摆放模式 ⇒ 手柄不再绘制**（且释放手柄网格）；⑤ **不制造 > 3 ms 单帧**（每帧成本 = 常数级：3 次矩阵 + 常数次 `SetMeshTransform`）。
- **是否降级**：**不降级**。两处**口径取舍（如实登记，非降级）**：
  ① **Y 轴不做** —— 平移 `y` 由地表高度求解是既有契约（I2 拒放悬空），给出 Y 轴会造出自相矛盾的"悬空物件"；
  ② **旋转环几何取"扁平环"**（非圆管）—— 拾取判据（环带）与视觉**逐字对应**，代价是正侧视时环看起来偏细（观感项）。
- **分帧 / 不冻结**：拖动每帧 = 3 次 `SetMeshTransform` + 常数次槽位位姿更新（被移动对象的槽位数，建筑 = 其构件数，几十以内）；
  提交 = 销毁 + 重建该对象的槽位（与右键删除 / 摆放同量级）⇒ 当帧做，**无新增重活**；物理体**仅在提交时**重建（拖动中不碰物理）。
- **世界内一致性**：拖动**只改水平位置与朝向**，`y` 重新按新落点取地表高度 ⇒ 与"底面贴地 / 不悬空"一致；
  撤销"移动过的建筑"时其**旧的变暗覆盖**按原下标回插（不留悬挂覆盖）。不引入新的世界观解释 ⇒ 不涉及 `world-setting.md`。
