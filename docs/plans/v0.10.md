### S2 动手前评价（先评价再动手 / 3A 基线）

- **范围**：只做**地形侧**的差量采集 / 叠加 + 与 `.voxr` 的落盘往返（含单测）。
  **不做**：流式卸载耦合、延迟 flush、worker 异步、游戏层接线、落点 ①/③（分别是 S4 / S5）。
- **业界标准做法（点名）**：① **Minecraft Anvil** —— 只保存**被修改过**的区块（dirty 标记 + 保存；未改动靠种子重建），
  与本项目红线 4 同源；② **UE5 Landscape Edit Layer / World Partition** —— 地形改动以**层 / patch** 为单位保存，
  只写被改动的部分；③ **Unity `TerrainData`** —— 只写 heightmap 的**改动区域**。本项目按 ADR 0037 已收敛为
  **逐列 `i16` 差量**（比 patch 更省），**采纳**，不降级。
- **可判定判据**：ADR 0037 判据②「改 3 列 ⇒ 文件里只有这 3 条 entry、未改动 tile 不出现」+ 判据①「读回后高度逐位一致」；
  另加「共享边界列不裂缝」（红线 12）。
- **是否降级**：**不降级**。唯一妥协 = 差量基准用**纯函数重算生成结果**（而非驻留一份 pristine 快照），
  省掉 ~8 KB/tile 的常驻内存；代价是 flush 时对**脏 tile**（数量少）重算一次 —— 属「不矛盾的更优做法」，非降级。
- **世界内一致性**：S2 是引擎 / 存档能力，不引入玩法语义 ⇒ 不涉及 `world-setting.md` 登记。
- **已知边界（登记为遗留）**：非法编辑发生在 **tile 边界列**且**拥有该列的 tile 未常驻**时，
  该列在冻结格式（列号 0..4095 = 本 tile 拥有的 64²）里**无法表示** ⇒ 不落盘。
  当前流式窗口以玩家为中心（半径约 1 km），笔刷必在窗口深处 ⇒ **实际不可达**；切换条件见 §3「阻塞 / 未决」。

### S4 + S3 动手前评价（先评价再动手 / 3A 基线）

- **范围**（所有者 2026-10-07 选定"S4 先接高度场"，并追加"开始开发 s3 和 s4 内容"）：
  先做 **S4（地形差量端到端落盘 / 读档 / 异步 flush）**，再把 **S3（脏体积块）**接进同一通路。
  **不做**：S5 落点 ①/③、S6 世界定义哈希（`generatorVersion` / `digRegionContentHash` 先写 0 占位并在读档时提示）、
  多存档槽 / 槽位 UI、玩家状态存档、实体状态。
- **业界标准做法（点名）**：① **Minecraft Anvil** —— 区块脏则**保存**、未改动靠种子重建（与本项目红线 4 同源）；
  ② **UE5 World Partition / Landscape Edit Layer** —— 改动层**异步写盘**、写盘不阻塞游戏线程；
  ③ **Unity `TerrainData` 异步保存 + 原子替换**；④ 容器形态沿用本项目 **ADR 0026**（已实测）。
  本阶段**采纳**，不降级。
- **可判定判据**：① 「挖坑 → 退出 → 重启 ⇒ 坑仍在」（端到端）；② 卸载脏 tile **不丢改动**；
  ③ flush 期间**无 > 50 ms 单帧**、主线程无磁盘等待；④ 关掉开关（`--world-save=off`）⇒ 与引入前**逐位一致**；
  ⑤ 未知 / 不匹配档（种子 / 半径 / 版本）⇒ **拒绝并提示**，不静默误读。
- **是否降级**：**不降级**。一处口径澄清（见下），非降级。
- **口径澄清（ADR 0037 决策四 vs 决策五）（须写进 ADR）**：决策四说"**未写的脏单元不得卸载**"，
  决策五说"**主线程绝不阻塞在磁盘**"。两者在"卸载前必须完成写盘"这一字面读法下冲突。落地方案 =
  **卸载前先把差量**采集进会话（内存记账，改动**已离开该单元**、不会丢），**随后按预算异步写盘** ——
  既满足"不静默丢改动"（决策四的**目的**），也满足"主线程不阻塞磁盘"（决策五 / SKILL §四）。
  这不是放宽，而是取两条决策的**交集**；已在 ADR 0037 增补说明。
- **世界内一致性**：本项是引擎 / 存档能力，不引入玩法语义 ⇒ 不涉及 `world-setting.md`。

### S5 动手前评价（先评价再动手 / 3A 基线；2026-10-07）

- **范围**：放行 `landing_mode = "flatten"` / `"fill"`，并在**摆放成套建筑时**按 footprint 把地形改到锚点高度；
  改完走**既有**脏 tile → 延后重网格 → 碰撞重扫（`PendingDestruction`），地形改动天然经 S2/S4 **落盘 / 读档**。
  **不做**：缺省落点仍为 **② 向下半埋**（ADR 0037 决策八未改判）；不做"嵌入地形（离线裁地形 + 留通道）"；
  不做收口小项 C1~C5；**作者配置的建筑**（发布清单里直接写 `flatten`/`fill`）在加载期不重复压平 —— 其地形由
  `.voxr` 差量恢复（玩家摆放的即此路径）；纯作者固定建筑用 ①③ 的情形登记为遗留。
- **业界标准做法（点名）**：① **UE5 Landscape** 的 *Flatten* 工具 + **Landscape Edit Layer**（把地形改到目标高度、
  改动按层记录）；② **Valheim / Rust / 7 Days to Die** 的建筑地基（放置时按 footprint 压平 / 填平地面使地基贴合）；
  ③ **Unity Terrain `SetHeights`** 的区域写入。三者都是"**按 footprint 矩形把高度场改到目标高度**"，**采纳**。
- **本项目的 3A 基线形态（可判定判据）**：地基贴合 = footprint 内高差 ≤ 0.05 格、建筑与地面**无缝无穿模**、
  **改完即持久**（重启后地面仍平、建筑仍在）、**footprint 之外地形逐列不变**。
- **是否降级**：**不降级**。唯一取舍 = 平整形状取**矩形纯函数**（精确"只改 footprint 内"）而非复用圆形笔刷
