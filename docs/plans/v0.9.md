## 2. 需求（**记录，不实现**）

### R1 全局可调值（引擎 / 渲染层）

- **要什么**：`--interior-darkening=<0~1>`（缺省 **0.45**）；`1.0` = **完全不调暗** ⇒ 逐位退回旧行为（等价于"关"）。
- **为什么**：现状 0.45 **写死在 shader**，无法 A/B 对照，也**无法调**（判据"室内亮度比室外低 ≥30%"要看读数才能定标）。
- **口径**：与既有 `--object-instancing=on|off` / `--object-lod-distance=<格>` 同一种做法
  （SKILL「已实现能力只允许用配置项关闭，不得删除代码」）；**非法值（越界 / 非数）⇒ 启动失败**（不静默，ADR 0005）。
- **落点（预期）**：`LightingUniform` 的**空闲填充位**（现成的 4 个 `*Unused`，**不扩结构**）→ `mesh.frag` 取 uniform 取代常量。
- **判据**：`--interior-darkening=1.0` 与"引入本参数之前"的**同场景逐位一致**（可判定）。

### R2 逐建筑参数（内容 / 数据层）

- **要什么**：`[[building]]` 增可选字段 `interior_darkening`（缺省 = **取全局值**）；每座建筑可不同。
- **为什么**：一座"账房"和一座"洞府"的室内明暗不必相同；也是 R3 的**数据载体**。
- **口径**：仍为**逐实例**数据 —— 放进实例缓冲里**已经空闲**的分量（`enclosureB.y`，见
  [instance_batch.hpp](../../engine/render/instance_batch.hpp) 的 `kInstancePoseBytes` 记录布局）⇒ **不加宽记录**。
- **判据**：同一场景两座建筑设不同值 ⇒ 两处室内亮度**可分辨**；不写该字段 ⇒ 与只设全局值时**逐位一致**。

### R3 「可视化摆放模式」里的功能参数（游戏 / UI 层）

- **要什么**：在 `F2` 摆放模式里把「室内变暗」**当成一个可调参数**就地调、就地看：
  至少包含 ① 一个**实时可调**的入口（滑条 / 按键步进）② 调整结果**随保存落进可编辑层**（`F5`）。
- **为什么**：调参必须"所见即所得"，否则只能改配置 + 重启（与 ADR 0032 决策八"同源预览"同一诉求）。
- **范围提醒**：**不启动"场景编辑器"暂缓项** —— 这是**扩既有摆放模式**，不引入新的编辑器形态。

### R4 摆放**成套建筑**（游戏 / UI 层）

- **要什么**：在 `F2` 摆放模式里能摆放 / 删除 **`[[building]]`**（而不只是单件 `[[placement]]`）。
- **为什么**：这是 R2 / R3 真正"能用"的前提 —— **单件物件没有围合体**，室内变暗对它无意义；
  只有摆放**成套建筑**才谈得上"给这座建筑设室内变暗"。
- **已知难点（记录，待设计）**：放置单位从"一件"变成"一套" ⇒ 需要新的**预览形态**（幽灵预览要显示整座）、
  **落点校验**（模数吸附 / 与地形的贴合）、**删除与记账**（可编辑层目前只有 `[[remove]]` 的"类型 + 平面位置"匹配口径）、
  以及**保存格式**（`[[building]]` 进可编辑层的 schema 影响面）。
