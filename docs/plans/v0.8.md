### 2.1 施工细则要点（硬约束）

- **零分叉**：构件**必须**复用 `objectLayer.Place` + `addObjectSlot`（渲染 / 碰撞 / 剔除 / 实例化的**唯一**装配路径），
  不得为建筑另开一条几何通路。
- **堆叠只能来自成套声明**：逐件 `[[placement]]` 的 `y` 一律按地表求解 ⇒ 层高由 `[[building]].pieces[].offset.y` 给出。
- **可进入性 = 可判定不变量**：门洞净高（`2*half_extent.y > 2.2`）与洞口无几何**两处**都必须在解析期 / 几何侧成立。
- **资源创建不得发生在渲染帧**（SKILL 硬规则 4）：实例缓冲容量创建时定死；围合体只是**逐实例数据**（每帧一次上传里的字段）。
- **超容量不静默**：实例数超容量 ⇒ 截断 + `WARN`（既有 `UploadInstances` 口径不变）。
- **双格式 Shader**（ADR 0002）：4 个 vert + `mesh.frag` 必须经 `glslc → SDL_shadercross` 产出 **SPIR-V + DXIL**。
- **varyings 必须三处同址**：`mesh.frag` 新增 `location 4/5` ⇒ **所有**与它配对的 vert（`mesh.vert` / `mesh_instanced.vert` /
  `mesh_skinned.vert`）都要输出；漏一处 ⇒ **管线创建失败**（本次已实测撞到，见 §3 踩坑）。

### 2.2 3A 基线三问（动手前三问）

1. **业界参照（点名）**：**UE5 Modular Building Kit + Grid Snapping**、**Unity ProBuilder**、**Godot GridMap**（模数化构件拼接）；
   室内明暗 = **UE5 Lightmass / Volumetric Lightmap**、**Unity Lightmap + Light Probes**；超大室内 = **Skyrim / Elden Ring 的 load door**。
2. **本项目 3A 基线形态（可判定）**：① **可进入**（洞口内无几何 + 净高 ≥ 2.2 格）；② **无缝嵌入**（模数整除 ⇒ 接缝错位 = 0）；
   ③ **室内变暗**（同材质室内亮度比室外低 ≥ 30%）；④ **性能**（构件 draw call 增量 ≤ 类型数）；⑤ **持久化**（配置可加载可校验）；
   ⑥ **确定性**（同配置逐位可复现）。
3. **是否降级**：**有，且已确认**（所有者 2026-10-07 四答）：美术 = **程序化代理体**（非正式 kit）；
   结合 = **只放地形之上**（不裁地形）；室内变暗 = **解析式围合体近似**（非逐顶点烘焙）。切换条件写在 ADR 0035「何时需要重新审视」。

### 2.3 世界内一致性

- **真实世界**：kit 构件是**低矮、规则、可进入**的人工结构（4×4 格、3.3 格层高），尺度与角色（高 1.8 格）自洽；
  门洞净高 2.2 格（余量 0.4 格）；地板 / 墙 / 屋顶成体系，**不出现"墙悬在半空 / 屋顶压在地面"**（层高由相对偏移给出）。
- **修仙世界（`world-setting.md`）**：本阶段引入的是**通用人工建筑**（无名的小屋），**未引入任何新设定**：
  小屋**未命名**、**未解释来历**（§3 的门 / 建筑命名口径仍待所有者提供）。⇒ **无需** `world-setting.md` 改动；
  若将来把 `spawn_hut` 变成"剧情地标"，须先由所有者给命名与语义（SKILL 六.9）。

## 3. 当前进度

- **已完成**：P1~P4；**K1~K6 全部落地**（2026-10-07）。
- **进行中**：无。
- **下一步**：评审 V0.8 结果；按本文件「阻塞 / 未决」与 `docs/devlog.md` 的遗留推进（人工目视验收 / 嵌入地形 / 正式 kit）。
- **实测（2026-10-07，`--world=world_a --auto-test --manual-test=hut_enterable`，debug，`build/v08_enclosure.log`）**：
  - 成套建筑：**1 座、展开 6 个构件（跳过 0）、其中 1 座带围合体代理**；
  - 物件实例化：**10 类型 / 132 物件 → 14 类型 / 138 物件**（多出的 4 个类型 = 4 个 kit 构件类；
    它们因"含围合体的组不受阈值限制"例外进入实例化）；
  - draw call：**2240 → 2235**（首帧）/ **2249 → 2243**（流式对账完成后）⇒ **零回归**（构件数少，改走实例化后略降）；
  - 类型原型 **18/18**；物件层就绪「放置 145 / 139 个物件（…成套建筑构件 6 个），类型表 18 项」。
- **踩坑（本次撞到并已修）**：`mesh.frag` 新增 `location 4/5` 后，**漏改 `mesh_skinned.vert`** ⇒
  蒙皮主通道管线创建失败（`0x80070057`）、启动即 `ERROR`。**教训**：改 `mesh.frag` 的输入契约必须**先枚举全部配对 vert**
  （`grep` 使用 `mesh.frag` 的管线），再一次性改齐。
- **阻塞 / 未决**：
  1. **室内变暗的目视验收须人工**：缺 = "同材质室内亮度比室外低 ≥ 30%"的**屏上读数**；为什么 = 本环境无法向前台窗口注入输入 / 截图；
     切换条件 = 所有者目视（或后续阶段引入离屏截图设施）。
  2. **嵌入地形未做**（首期只放地形之上）：缺 = 地宫 / 洞府 / 半地穴；为什么 = 需**离线裁地形工具**（ADR 0026 的 `voxel_bake` 同类），
     且要处理与流式地形（ADR 0024）的接缝；切换条件 = 出现"建筑必须陷进地形"的需求。
  3. **正式美术 kit 未接入**：缺 = 像样的外观；为什么 = 前置（逐模型贴图 / UV）尚未做（ADR 0034 已登记的同一缺口）；
     切换条件 = 进入表现与深度阶段，或所有者选定 CC0 近风格 kit。
  4. **室内变暗是解析式近似**：缺 = 逐面精确的明暗；为什么 = 共享原型无法逐实例烘焙；切换条件见 ADR 0035「何时需要重新审视」第 1 条。
  5. **建筑不可玩家自建 / 不持久化**：缺 = "我自己盖房子并保存"；为什么 = ADR 0032 的可编辑层目前只放 `[[placement]]` / `[[remove]]`；
     切换条件 = 出现该需求时把 `[[building]]` 纳入可编辑层与保存器。
  6. **多套 kit / 院落级蓝图 / 地宫 / 洞府未做**：缺 = 内容多样性；切换条件 = 需要更复杂的可进入空间时（沿用本阶段的数据形态，扩配置即可）。
