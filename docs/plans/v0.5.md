### 1.5 **V0c 施工细则（物件生命周期：失支撑掉落 + 可破坏）**（2026-10-06）

- **来源（缺陷 + 所有者裁定）**：人工实测报告"在地上挖坑后物件**不掉落、不破坏**"。真伪判定：
  ① **不掉落 = 确认是缺陷**（违「世界内一致性」：承重/地基被破坏 ⇒ 上部不得**悬空不动**）；
  ② **不破坏 = 已登记**（V6）。所有者裁定：**掉落按 A（失支撑 ⇒ 转动态刚体）**；
  **破坏按 C（按类型分流）**，并**做成配置项**，**分别创建实例**供人工测试。
- **范围**：① **失支撑 ⇒ 静态体转动态刚体**（掉落；复用既有 Jolt 动态凸包路径，非新物理系统）；
  ② **爆炸命中** ⇒ `destructible_enabled && type.destructible` ⇒ **摧毁消失**；否则 ⇒ **只被炸飞 / 掉落，不破坏**；
  ③ **配置项**：`objects.toml` 增 `destructible_enabled`（全局开关，缺省 `true`；按 SKILL「已实现能力只允许配置项关闭」）；
  ④ **测试实例**：放置清单增一对"可破坏 / 不可破坏"对照实例。
  **明确不做（本步）**：物件**破坏状态持久化**（存档未开始）、**凹形物件的多凸包**（`ConvexHullDesc` 会填平凹形，当前三形态皆凸）、
  物件的**联网同步**、按伤害预算的**多段血条**（当前 `prop_damage_threshold = 0` ⇒ 单发命中即破，与破坏表一致）。
- **顺序**：0.1 配置项（`ObjectTable.destructibleEnabled` + `objects.toml` + 测试实例）→ 0.2 支撑探测纯函数（`object_support.hpp`）→
  0.3 `game/main.cpp` 接线（支撑检查 → 转动态 → 每帧同步位姿；爆炸 → 摧毁 / 炸飞）→ 0.4 单测 → 0.5 文档同步。
- **落点**：`world/object/object_layer.{hpp,cpp}`、**新增** `world/object/object_support.hpp`、`assets/config/objects.toml`、
  `game/main.cpp`、`tests/object_layer_test.cpp`、**新增** `tests/object_support_test.cpp`、`tests/CMakeLists.txt`、
  `docs/engine-capabilities.md`、`docs/file-index.md`、`docs/game-design.md`、`docs/devlog.md`。
- **验收判据（可判定）**：① 炸掉物件**脚下**的地面 ⇒ 物件**掉下去**并停在新地面（不再悬空）；
  ② `destructible_enabled = true` 时爆炸命中土堆 / 木箱 ⇒ **消失**（网格 + 碰撞体一并移除），石块**不消失**（只被炸飞）；
  ③ `destructible_enabled = false` 时 ⇒ **任何物件都不消失**（只被炸飞）；
  ④ 配置非法（`destructible_enabled` 非布尔）⇒ **启动失败**；⑤ 构建零警告 + `ctest` 全绿 + 门禁 0 违规。
- **3A 基线三问**：
  1. **业界参照**：**7 Days to Die**（结构完整性 SI：失支撑方块塌落）、**Space Engineers**（失支撑网格转**动态刚体**）、
     **Teardown / Fortnite**（失支撑即倒塌）、**Minecraft 重力方块**（最简：失支撑即下落）；破坏分流参照 **R6S / BF 的局部破坏**。
  2. **本项目 3A 基线形态（可判定）**：失支撑 = **确定性判据**（底面若干探测点全为空 ⇒ 无支撑）⇒ 转 `AddDynamicConvexHull`
     （与 ADR 0015/0017 的"失支撑 ⇒ 动态刚体"**同一口径**，不引入第二套物理）；破坏 = **按类型 + 全局开关**、
     **数据驱动**（`destructible` / `destructible_enabled`），不是硬编码。
  3. **是否降级**：**有**（所有者已确认）——① 不作**破坏状态持久化**（存档未开始）；② 无**凹形多凸包**；
     ③ 无**多段血条**（单发即破）；④ 支撑检查为**固定探测点 + 固定间隔**（非连续接触求解）。
     **切换条件**：存档启动 ⇒ 持久化；出现凹形物件 ⇒ 多凸包；需要"打几下才破" ⇒ 接伤害预算。
- **世界内一致性**：**真实世界** —— 地基被挖 ⇒ 物件**必须落下**（不得悬空）；被炸 ⇒ 可破坏者**消失**、不可破坏者**被炸飞**。
  **修仙世界** —— 仍为**临时占位内容**，**不引入新设定**（"此物为何可破坏 / 被毁后如何"待所有者提供，见 `world-setting.md` §3）。

- **尺寸发现（先报告，再改计划）**：`game/main.cpp` **3701 行**，其中**世界级局部状态 40+ 个**

### 1.2 V6 口径（**已由所有者裁定，2026-10-06**）

| 项 | 裁定 |
| --- | --- |
| 「土堆」表示 | **物件层实体**（几何不可变 + 状态 `Intact` / `Broken`，[ADR 0013](../adr/0013-destructible-elements.md) 器物模型）⇒ **本阶段必须先补「物件层」能力** ⇒ 新增任务 **V0** |
| 世界切换实现 | **进程内真切世界**（卸载 → 加载/生成 → 重建玩家与相机；**不是**重启进程）；加载界面复用现有加载分片管线 + 进度 |
| 传送时序（业界口径） | 参照 **UE5 Level Streaming + Loading Screen / Seamless Travel**、**Unity `LoadSceneAsync` + 进度**、**Skyrim / Elden Ring 的 cell 切换**：**目标落点由目标清单的 `spawn` 声明**；切换时在**持续出帧的加载界面**下完成（不冻结画面） |
| 摆放触发方式 | 暂定：**指向地面按 `G` 放置**（可在调试面板切换）；尺寸暂定 **半径 ~2 格 / 高 ~1.5 格**（实现前可一并调整） |
