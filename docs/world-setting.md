# 世界观设定

> **性质**：本仓库的**内容基线文档**之一（见 `.trae/skills/voxel-engine-dev-standards/SKILL.md` 第六节）。
> **状态**：**未开发（占位）** —— 尚无任何设定内容。
> **维护义务**：一旦开始涉及世界背景（题材、地理、种族、历史、命名……），必须**同一次提交内**更新本文件；
> 缺失的条目写 `待补`，**不许留白、不许由 AI 代拟**。**本文件缺失时必须先建立，再动手。**

## 0. 最重要的一条规则

> **本文件的内容必须来自项目所有者的设定。**
> AI **不得**自行编造世界观——不得虚构地名、种族、历史事件、神话、语言或文化细节。
> AI 在本文件里只做三件事：**（1）搭结构；（2）把已有设定整理成条目；（3）把缺失项标为 `待补` 并提问。**
> 若某项设定与生成规则或玩法参数有关，AI 只能**指出关联**，不能替所有者决定取值。

## 0.1 已确认的世界级需求（所有者已给出，2026-09-25）

> 这些是**对世界本身的要求**（玩法层），实现方式与进度见 [游戏设计](game-design.md) §2。此处只记录设定事实。

| 项 | 结论 | 是否影响生成规则 |
| --- | --- | --- |
| 题材 | **修仙大世界**（放开世界） | 是——宗门、洞府、灵脉、秘境等元素都要有对应的生成规则（具体清单待补） |
| 世界生成方式 | **每次进入世界都随机生成**（同一世界种子可复现） | 是——一切内容必须由种子 + 整数坐标的纯函数决定 |
| 世界可变性 | **可对必备元素进行定义**（声明"这个世界必须有 X"） | 是——这是 G2 的设定输入，须落到配置 |
| 手工地图 | **可预设固定地图**（用于测试 / 剧情） | 是——手工地图可能覆盖随机生成结果（当前实现为地形编辑区） |
| 玩家能力 | 能在大世界**收集东西、能飞、能跑、能破坏地形** | 是——飞行与地形破坏是否受境界 / 灵力限制，属设定层，待补 |

## 2. 登记规则

1. **先登记后动手**：任何设定一旦确定，先写入本文件（结论 + 依据 + 是否影响玩法），再动代码或资源。
2. **AI 不得代拟**：AI 只能提问、搭结构、整理。发现缺失就写 `待补` 并明确列出"需要项目确认的问题"。
3. **影响玩法的设定必须落地为配置**：只写在本文件里、未进入 `assets/config/` 或阶段计划的设定，
   视为**未生效**——代码不会知道它。
4. **与技术文档分工**：本文件写"世界是什么"；技术选型与理由写 ADR；任务顺序与验收写阶段计划；
   内容范围与实现状态写 `docs/content-capabilities.md`。

## 3. 待项目确认的问题（AI 提问区）

> 由项目所有者逐条回答后，将答案整理进 §1，并在此处标记已答。
> 已答：**题材 = 修仙大世界**（2026-09-25，见 §0.1）。

1. **修仙体系的细分**：是否有确定的境界划分（名称与数量）、灵根 / 灵脉 / 灵气等设定？
2. **宗派与势力**：是否已有门派、家族、散修等势力设定？是否需要在世界中生成它们的据点？
3. **地理与命名**：是否已有地名（大陆 / 区域 / 秘境）？命名偏好（古风 / 简白 / 自造词）？
4. **必备元素清单**：`G2` 要声明哪些"世界必须有"的内容？（如"每张图必须有一条灵脉""必须有可采集的灵石"）
5. **飞行的设定依据**：飞行是修为能力、御剑、还是法宝？是否需要条件才能飞？
6. **可破坏地形的边界**：破坏地形是否有代价或限制（灵力消耗 / 只能破坏特定材质）？（**实现侧已备好两类旋钮供设定落值**：材质的 `toughness`（坚固度）与弹丸的 `damage`（伤害）——见 [ADR 0013](adr/0013-destructible-elements.md)；例如"凡铁不可破 / 灵石极脆"可用 `toughness` 表达）
7. **哪些设定只影响文案**（不进配置、不影响生成），避免把纯背景设定误做成规则。
8. **被破坏之物的修仙侧后果**（2026-09-27 新增，来源：SKILL「世界内一致性」审查 —— 给山挖洞连带到此）：山体 / 地面被灵力打穿、挖空之后，在设定上会怎样？是否有**渗灵、灵气外泄、山势受损、异象**等表现？是否有**自愈 / 复原**的规则？
9. **建筑与结构的承重规则是否被法术改写**（2026-09-27 新增，同一来源 —— 当支撑物缺失时应塌陷连带到此）：修仙世界的**宗门建筑 / 洞府 / 护山大阵**是纯物理承重，还是靠**阵法 / 禁制**维持？被破坏后是"按真实世界那样塌"，还是"阵法先破、再塌"，或"有护持则暂时不塌"？倒塌是否伴随**灵气波动 / 尘土异象**？（器物已按「**可破坏 / 不可破坏**」+「破坏状态」建模，见 [ADR 0013](adr/0013-destructible-elements.md)；本题决定这些开关的**设定含义**）
