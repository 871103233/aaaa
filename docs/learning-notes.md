## A. 技术选型名词

### 体素（Voxel）

- 一句话定义：把三维空间切成规则小立方体来表示世界，可类比"3D 像素"。
- 在本项目里是什么 / 为什么需要：世界由体素堆成，可放置与破坏。选它的根本理由是**规则网格**——能用数组存、能用整数坐标寻址，因此能比任意几何体做激进得多的优化。
- 易错点或关键取舍：别把"体素"等同于"方块游戏"。体素是**数据结构选择**，方块外观只是它的表现。

### 区块（Chunk）

- 一句话定义：世界的固定大小切片，是**加载 / 渲染 / 存储的最小单位**。
- 在本项目里是什么 / 为什么需要：本方案为 16×384×16。流式加载、脏标记、序列化全部以区块为单位。
- 易错点或关键取舍：区块是**数据归属单位**，不是渲染单位，也不该是锁单位。

### Section（子区块 / 垂直分段）

- 一句话定义：区块在垂直方向再切成的 16³ 小段（16×384×16 → 24 个 Section）。
- 在本项目里是什么 / 为什么需要：全空气的 Section 可以**不存、不网格化、不上传**，省下大量内存与带宽。
- 易错点或关键取舍：贪婪网格化的作用域**只到单个 Section**（顶点位置用 uint8 存 0~16）。

### 调色板压缩（Palette）+ 位打包

- 一句话定义：一个 Section 内通常只有少数几种方块，于是存一张"去重后的方块 ID 列表"（调色板），每个方块只存调色板下标，位数按调色板大小动态决定（4~8 bit）。
- 在本项目里是什么 / 为什么需要：把每方块 4 字节压到 0.5~1 字节，是单区块内存降到 8~20 KB 的关键。
- 易错点或关键取舍：调色板变化时需重新打包；读方块多一层间接寻址。

### 面剔除（Face Culling）

- 一句话定义：只为"邻居是空气或透明方块"的那些面生成几何。
- 在本项目里是什么 / 为什么需要：地下实心区域内部的面对面玩家不可见。效果是把单区块面数从最高 6 万降到几百~几千。
- 易错点或关键取舍：**必须跨区块取邻居方块**——区块边界面的可见性依赖邻居数据。

### 贪婪网格化（Greedy Meshing）

- 一句话定义：把同材质、同朝向、同光照的相邻面**合并成一个大四边形**。
- 在本项目里是什么 / 为什么需要：在面剔除基础上再压 3~10 倍。
- 易错点或关键取舍：① 作用域只到单 Section；② 合并判据必须含 4 个角的**光照与 AO**（AO 是逐顶点量，不同就不能合）。

### 视锥剔除 / 遮挡剔除

- 一句话定义：视锥剔除 = 跳过相机视野外的区块；遮挡剔除 = 跳过**被其它几何挡住**的区块。
- 在本项目里是什么 / 为什么需要：视距越大越必要；洞穴场景尤其依赖遮挡剔除。
- 易错点或关键取舍：视锥剔除便宜、遮挡剔除昂贵，后者要谨慎实现并配 Tracy 数据。

### 纹理图集（Atlas）vs 纹理数组（Texture Array）

- 一句话定义：图集是把所有纹理拼成一张大图；数组是每张纹理独立成"一层"，采样时用层号索引。
- 在本项目里是什么 / 为什么需要：**本项目选数组**。图集在开启 mipmap 时相邻 tile 会互相**渗色**（低级别 mip 把邻居颜色混进来），需要留 gutter 补丁；数组天然没有这个接缝问题。
- 相关：ADR 0001、`references/meshing-and-render.md`

### Draw Call

- 一句话定义：CPU 向 GPU 提交一次绘制命令。
- 在本项目里是什么 / 为什么需要：每次提交都有开销，数量过多时 CPU 成为瓶颈。目标 ≤700/帧 @16 区块、≤1500/帧 @24 区块。
- 易错点或关键取舍：压缩它靠**合并网格**，不是减少三角形数量。

### LOD / Impostor

- 一句话定义：LOD = 远处区块用低精度网格；Impostor = 超远距离直接用一张贴图替代实体方块。
- 易错点或关键取舍：相邻不同 LOD 之间会出现**裂缝**，需要缝合策略。

### 噪声：Perlin / Simplex / Worley

- 一句话定义：给定坐标返回连续随机值的函数，用来程序化生成地形。
- 在本项目里是什么 / 为什么需要：2D 噪声叠成高度图；3D 噪声挖洞穴；2D 温度 + 湿度映射生物群系。库选 **FastNoiseLite**（轻量 header-only）。
- 易错点或关键取舍：它是 **float 实现** → 只能保证"同一构建内确定性"，跨编译器 / 平台可能有差异。

### 网格抖动（Chunked Jittered Grid）vs 泊松盘采样（Poisson Disk）

- 一句话定义：网格抖动 = 把世界切成格子、每格按种子随机放一个点；泊松盘 = 保证任意两点有最小距离。
- 在本项目里是什么 / 为什么需要：**本项目选网格抖动**。泊松盘观感更自然，但需要**全局激活点列表**，与"走到哪生成到哪"的流式分块根本冲突——它做不到"只看当前区块即可重建"。
- 相关：`references/chunk-and-streaming.md`

### 天空光 / 方块光 / BFS 传播

- 一句话定义：天空光从世界顶部向下传播、遇不透明方块停止；方块光（火把、岩浆）向四周传播、每格衰减 1 级；两者都用广度优先（BFS）逐格扩散。
- 在本项目里是什么 / 为什么需要：必须**增量更新**——只在区块加载或方块改动时传播变化部分，不能每帧全场景重算。
- 易错点或关键取舍：光会**跨越区块边界**传播；邻居加载 / 卸载时须能越界重传，否则出现黑边。

### AO（环境光遮蔽，Ambient Occlusion）

- 一句话定义：角落因被邻接方块遮挡而自然变暗。
- 在本项目里是什么 / 为什么需要：原版 MC 的观感很大一部分来自它，成本低、收益大。
- 易错点或关键取舍：**逐顶点量**，会破坏贪婪合并的等价条件，因此合并判据必须包含它。

### swept AABB / 子步进（Sub-stepping）/ 自动上台阶

- 一句话定义：swept AABB 把移动视为一段位移、检测它与方块 AABB 的**扫掠相交**；子步进把每帧位移拆成若干小步推进；自动上台阶在遇到 1 格坎时自动抬升。
- 在本项目里是什么 / 为什么需要：只为玩家包围盒周围 **3×3×3 个方块**做查询，是纯整数索引，比通用物理引擎快上百倍。
- 易错点或关键取舍：不要靠"把碰撞盒缩小 20%"改善手感——那会让玩家看起来悬空，且能从缝隙掉下去。

### 固定时间步长（Fixed Timestep）

- 一句话定义：逻辑与物理用恒定的 dt 更新，渲染侧做插值。
- 在本项目里是什么 / 为什么需要：可变 dt 会让物理行为随帧率变化，直接破坏确定性。

### 相机相对渲染（Origin Rebasing）

- 一句话定义：世界坐标用整数（int32 / int64），渲染时把"世界原点"动态搬到相机附近。
- 在本项目里是什么 / 为什么需要：float 只有 24 位有效位，离原点约 2²⁴ 格后精度不足 1 格，画面会抖。
- 易错点或关键取舍：所有位置一律整数，float 只用于渲染与插值等相对量。

### Job System / 依赖计数 / DAG

- 一句话定义：能表达任务间依赖关系的调度器。
- 在本项目里是什么 / 为什么需要：异步区块管线是一张**有依赖的图**（生成 → 邻居就绪 → 光照 → 网格化 → 上传），朴素线程池表达不了"等 4 个邻居都完成再网格化"。**本项目已采用 enkits**（vcpkg 端口名 `enkits`，注意无连字符）；备选 Taskflow 与自研无锁池的取舍见 ADR 0003。

### ECS（Entity-Component-System）

- 一句话定义：用"实体 + 组件 + 系统"组合代替继承的数据驱动架构。
- 在本项目里是什么 / 为什么需要：**体素场景里 ECS 只服务少量动态实体**（怪物、掉落物）。方块不是 Entity，区块顶多算一个。
- 易错点或关键取舍：别把 ECS 当性能银弹，它不是体素性能的主要杠杆。
- 本项目实现：**EnTT**（vcpkg 端口 `entt`，起步）；自研稀疏集为备选，切换条件见 ADR 0003。

### RHI（Render Hardware Interface）

- 一句话定义：把不同图形 API（Vulkan / D3D12 / Metal）包成统一接口。
- 在本项目里是什么 / 为什么需要：选 **SDL3_gpu** 直接充当这一层，避免自己写多后端。
- 易错点或关键取舍：抽象不能泄漏某个 API 的语义，否则换后端就返工。

### SPIR-V / DXIL / GLSL / HLSL

- 一句话定义：GLSL / HLSL 是人写的高级着色器语言；SPIR-V 是 Vulkan 用的中间字节码；DXIL 是 D3D12 用的字节码。
- 在本项目里是什么 / 为什么需要：**Shader 格式与渲染后端强耦合**——Vulkan 只吃 SPIR-V，D3D12 只吃 DXIL。所以构建期同时产出两种，运行时按设备能力选。
- 相关：本文件 D 区「双格式 Shader 管线」

### 区域文件（Region File）

- 一句话定义：把 32×32 个区块合并存进一个文件（如原版 MC 的 `.mca`）。
- 在本项目里是什么 / 为什么需要：避免"每区块一个小文件"造成文件数爆炸与读放大。本项目格式为 `.voxr`。

### zstd

- 一句话定义：现代高速压缩库。
- 在本项目里是什么 / 为什么需要：区块二进制存档要体积小、解压快；比 gzip 更快、比 LZ4 压得更狠。

### 单写者 + 不可变快照

- 一句话定义：一个区块同时只由一个 Worker 构建，构建完成后整体替换指针发布，主线程只读已发布版本。
- 在本项目里是什么 / 为什么需要：避免对区块加粗粒度锁——那会把主线程拖垮。
- 易错点或关键取舍：不能让主线程"边构建边读"。

### MDI（Multi-Draw Indirect）

- 一句话定义：一次命令提交多组绘制（绘制参数放缓冲区间接寻址），大幅削减 CPU 提交开销。
- 在本项目里是什么 / 为什么需要：**备选方案**，仅在确实需要把 Draw Call 压到"几百"时才启用。

### LFS（Git Large File Storage）

- 一句话定义：Git 的大文件扩展——仓库里存指针文件，实体另存。
- 在本项目里是什么 / 为什么需要：`.gitattributes` 已为 png / jpg / ogg / wav / fbx / glb 声明 LFS。

### 分层混合世界（Layered Hybrid World）

- 一句话定义：把"世界"拆成几层不同的表示，各管一段，而不是用**一种**表示硬扛全部需求。
- 在本项目里是什么 / 为什么需要：**本项目采用**（见 [ADR 0004](adr/0004-hybrid-layered-world-representation.md)）——① 高度场地表 ② 可挖标记区域内的有界 SDF 体积 ③ 物件/建造层 ④ 实体。选它的理由是"全世界三维体素"虽能力最强，但数据量约为高度场的 34 倍、网格化遍历量高两个数量级，而"全世界任意三维重塑"**并不是需求**。
- 易错点或关键取舍：**浮空物与建造物绝不能写进地形场**（会在地表打出柱子）；层与层的交界处（洞口、天坑）必须共享采样或做过渡，否则出现裂缝与穿模。

### 高度场（Heightfield）

- 一句话定义：用"每个水平格子一个高度值"表示地形（2.5D），表面由三角网格平滑渲染。
- 在本项目里是什么 / 为什么需要：地表的表示。数据量极小（32×32 单位约 4 KB），挖坑/堆土/平整就是改高度值；LOD 有成熟工业方案（Geometry Clipmaps、CDLOD），这是它相对体素的最大优势。
- 易错点或关键取舍：**不能表达悬垂、洞穴、隧道**（每列只有一个高度）。所以洞穴与地下三维挖掘必须交给 ② 的可挖体积。

### 有符号距离场（SDF）与等值面网格化

- 一句话定义：SDF = 每个三维格点存"到表面的带符号距离"（负=内部、正=外部、0=表面）；等值面网格化（Marching Cubes 系）把这张场抽成三角网格，因此**数据是格子、看到的却是平滑曲面**。
- 在本项目里是什么 / 为什么需要：可挖体积的表示。它正是"代码层面一个个格子、玩家看到平滑表面"的实现方式。
- 易错点或关键取舍：① 三种算法的取舍——**Surface Nets**（每格最多 1 顶点、顶点连续变化，LOD 过渡天然平滑，实现最简）／**Marching Cubes**（最成熟但顶点位置会跳变，LOD 缝合难）／**Dual Contouring**（能保留锐利棱角，需 QEF 求解）；② 密度精度（8 bit 省一半内存，但陡坡会出现台阶感与 alias）；③ 网格化作用域必须分块，且相邻块要共享边界采样，否则出现接缝。

### 多纹理权重混合（Splat Map）

- 一句话定义：地表不贴单张纹理，而是按"高度 / 坡度 / 生物群系"算出多种纹理的混合权重，在着色器里加权混合。
- 在本项目里是什么 / 为什么需要：替代方块世界的"纹理数组 + 层号"方案；陡坡露岩、平地草土过渡，都靠它。
- 易错点或关键取舍：权重必须归一化，否则亮度随层数漂移；纹理层数要按硬件采样上限控制。

### 级联阴影贴图（CSM，Cascaded Shadow Maps）

- 一句话定义：把相机视锥按距离切成若干段，每段用一张分辨率合适的阴影贴图，让近处清晰、远处不糊。
- 在本项目里是什么 / 为什么需要：替代方块世界的"天空光/方块光 BFS 逐格传播"。平滑大世界 + 方向光必须靠 CSM，否则阴影要么糊要么开销爆炸。
- 易错点或关键取舍：级联之间会有缝合缝与闪烁，需要随相机做 texel 对齐。

## B. 开发流程与工程用语

### PoC（Proof of Concept，概念验证）

- 一句话定义：正式开发前，用**最小、可丢弃**的实验回答"某个关键假设是否成立"。
- 在本项目里是什么 / 为什么需要：有些假设错了就要改架构，代价极大。本项目 #1 验证 SDL3_gpu 后端可用性、#2 验证 Shader 工具链格式——**正是 #2 推翻了"只编 SPIR-V"的假设**。
- 易错点或关键取舍：PoC 的目的是**回答问题**，不是交付功能；允许粗糙、用完即弃。
- 相关：[devlog.md](devlog.md) 2026-09-25 第 5 条

### CI（Continuous Integration，持续集成）

- 一句话定义：每次推送代码，服务器**自动**跑一遍"检查 → 构建 → 测试"，用红 / 绿灯反馈。
- 在本项目里是什么 / 为什么需要：`.github/workflows/ci.yml`，三步：门禁 → 构建（Win Debug/Release + Linux ASAN/TSan）→ 测试；红灯不合并。
- 易错点或关键取舍：本地环境没装齐时，CI 往往是**唯一**的验证通道。

### 门禁（Gate）

- 一句话定义：用机器执行的**规范检查**，通常作为 CI 第一步，失败即终止。
- 在本项目里是什么 / 为什么需要：`check-banned-identifiers.ps1` 扫描源码里被禁的写法。它把"禁止项"从"依赖人记住"变成"构建直接失败"。

### DoD（Definition of Done，完成定义）

- 一句话定义：一个任务算"做完"的检查清单。
- 在本项目里是什么 / 为什么需要：开发规范第七节的 15 项自检。

### 阶段计划（Plan）

- 一句话定义：一份写清"这个阶段做哪些任务、按什么顺序、做到什么算完、现在到哪了"的活文档。
- 在本项目里是什么 / 为什么需要：放在 `docs/plans/<阶段>.md`（如 `docs/plans/v0.1.md`），是**第 4 份常驻文档**，也是交接包的第 3 份。规范要求「任何一次任务下发，动手前必须先把任务写进计划（范围 / 顺序 / 落点 / 验收）」，目的是让接手者（人或大模型）**只读这一份文件就能开工**，不必靠反推 devlog 猜下一步。
- 易错点或关键取舍：① 它是**活文档**，每完成一步就要勾选并更新「当前进度 / 下一步」，与代码**同一次提交**；② 它**不写技术结论**，选型与理由只引用方案 / ADR，否则又造出第二个事实来源；③ 阶段闭环后**冻结不回改**，新阶段新建文件；④ 「下一步」必须可执行、可验收，写"继续优化"等于没写。

### vcpkg host 依赖（`"host": true`）

- 一句话定义：把某个依赖标记为"只在**构建机**上需要"，vcpkg 用 host triplet 构建它，并把它提供的可执行工具暴露给构建系统。
- 在本项目里是什么 / 为什么需要：`glslc`（`shaderc` 端口）与 `shadercross`（`sdl3-shadercross` 端口）是**构建期工具**，不是链接进产物的库。写成 `{ "name": "shaderc", "host": true }` 后，`cmake/Shaders.cmake` 的 `find_program` 能找到它们，开发机与 CI 都不必手工配 `PATH`。
- 易错点或关键取舍：写成普通字符串（`"shaderc"`）会被当作**目标平台库**处理，不保证工具可见。另：host 依赖会传递地带出其依赖的特性——`sdl3-shadercross` 会拉入 `sdl3[vulkan]`、`directx-dxc`、`glslang`、`spirv-cross`，首次 configure 明显变慢（不是卡住）。
- 相关：`vcpkg.json`、`cmake/Shaders.cmake`、`references/build-and-tests.md` §1

### 警告即错误（/W4 + /WX）

- 一句话定义：把编译警告当错误处理，任何警告都让构建失败。
- 在本项目里是什么 / 为什么需要：C++ 的警告常是真 bug 的预兆，攒着只会越来越多。

### 回归（Regression）

- 一句话定义：原本正常的功能因新改动而坏掉。
- 在本项目里是什么 / 为什么需要：CI + 单元测试的主要目的就是拦住它。

### 确定性（Determinism）

- 一句话定义：同样的输入必然得到同样的输出。
- 在本项目里是什么 / 为什么需要：分**两级**——「同一构建内确定性」（单机可依赖）与「跨平台确定性」（联机 / 共享种子才需要，须改用整数哈希噪声）。

## D. 本项目专属概念

### 区块状态机与跨区块唯一判据

> ⚠ **已被 ADR 0004 取代（迁移期）**：本条目描述的是方块世界下的"区块 / Section"状态机，其尺寸常量与判据载体
> 随世界表示改为**分层混合**而作废。**"邻居就绪才可网格化"这一原则仍然成立**，但作用域将改为
> 「地表 tile / 可挖体积块」——详见 [ADR 0004](adr/0004-hybrid-layered-world-representation.md)。

- **一句话定义**：给每个区块贴一个"走到哪一步了"的标签，并规定"满足什么条件才允许开始算网格"。
- **在本项目里是什么 / 为什么需要**：
  - 状态**只能单向推进，不得跳级**：`Empty → Generating → Generated → Lit → Meshed → Ready`
  - `Empty` 占位 → `Generating` 后台填方块 → `Generated` 方块就绪（邻居可查询）→ `Lit` 光照完成（含跨边界）→ `Meshed` 要画的面算完 → `Ready` 已上传 GPU，可渲染与碰撞查询。
  - **唯一判据 `can_build_mesh`**（`voxel/chunk/chunk_types.hpp`）：**自身 ≥ `Generated`，且 4 个水平邻居均 ≥ `Lit`**，才允许进入 `Meshed`。
  - 为什么必须等邻居：**一个面要不要画，取决于邻居方块是什么**。区块边界处邻居未就绪时，面剔除判断不完整，视觉上就是边界上一条闪烁的裂缝。
  - 为什么强调"唯一"：条件若散落在十几处代码里各写一遍，早晚有人写漏一处，且极难排查。收进一个函数即**单一事实来源**，所有网格化路径都必须经过它，不得绕过。
- **易错点或关键取舍**：
  - 光照也必须跨边界，不只是网格；邻居加载 / 卸载时要能重新传播，否则出现黑边。
  - **"邻居中途卸载"是最容易被遗漏的情形。**
  - 自身处于 `Empty` / `Generating` 时绝不能开始网格化。
- **相关**：`references/chunk-and-streaming.md`（§2 状态机、§3 邻居依赖）、`tests/chunk_state_test.cpp`

### 双格式 Shader 管线

- **一句话定义**：同一份 GLSL 源码在**构建期产出两种**字节码（SPIR-V 与 DXIL），运行时按当前图形后端加载对应的那一种。
- **在本项目里是什么 / 为什么需要**：
  - Shader = 跑在显卡上的小程序（本项目用 GLSL 写）。**Shader 格式与图形后端强耦合**：Vulkan 只接受 SPIR-V，Direct3D 12 只接受 DXIL，喂错直接崩溃。
  - 而 SDL3_gpu 会自动挑选后端（**Windows 上默认 D3D12**，有可用 Vulkan 的机器才走 Vulkan），因此只备一种格式必然有一类机器跑不起来。
  - 链路为**两段式**：`triangle.vert (GLSL) --glslc--> .spv (SPIR-V) --shadercross--> .dxil (DXIL)`
  - 运行时用 `SDL_GetGPUShaderFormats()` 询问设备需要哪种，再决定加载 `.spv` 还是 `.dxil`。
- **易错点或关键取舍**：
  - **`shadercross` 不认 GLSL**（输入仅支持 SPIR-V / HLSL），所以必须"先 `glslc` 再 `shadercross`"，无法一步到位。
  - 需要 `glslc`（shaderc 端口）与 `shadercross`（sdl3-shadercross 端口）**两个**工具；二者已作为 **host 依赖**写入 `vcpkg.json`，随 `cmake --preset` 自动装入。缺工具时构建只警告不阻断，代价是**运行时才失败**。
  - 不要再写成"只编 SPIR-V"——这是已被实测推翻的旧结论（见 [devlog.md](devlog.md) 2026-09-25 第 4 条）。
- **相关**：ADR [0002-shader-dual-format-pipeline.md](adr/0002-shader-dual-format-pipeline.md)、`cmake/Shaders.cmake`、`engine/render/triangle_renderer.cpp`、`references/meshing-and-render.md` §6

### 世界定义 vs 世界状态

- **一句话定义**：**世界定义**是"这个世界本来长什么样"（种子、生成规则、可挖区域标记、配置表），**世界状态**是"玩家把它改成了什么样"（挖掉的土、堆起的堆、放置的物件、实体位置）。
- **在本项目里是什么 / 为什么需要**：这条区分决定**什么要落盘**。世界定义**不落盘**（可由种子 + 数据文件重建，只需记版本与哈希）；世界状态**必须落盘**，且只存脏数据（见 ADR 0006 与 `references/save-and-serialization.md`）。重建顺序固定为：**标记 → 生成初始密度/高度 → 叠加玩家改动**。
- **易错点或关键取舍**：**把可挖区域标记写进地形场或密度场**是典型错误——那会让"标记"变成世界状态，既污染生成结果又让存档无谓膨胀。标记是**输入**，不是结果。
- **相关**：ADR 0004、ADR 0006、`docs/tech-plan-v2.0.md` §2

### 固定步长累加器与动作状态输入

- **一句话定义**：固定步长累加器 = 把"帧间隔"攒起来、每满一个固定 `dt`（本项目 1/60 s）就推进一次逻辑，并限制单帧最多补 5 步；动作状态输入 = 把按键/鼠标原始事件在**每帧采样一次**后变成"动作"，上层只问"这个动作是否按住 / 是否本帧按下"。
- **在本项目里是什么 / 为什么需要**：两者共同保证**逻辑与帧率解耦**：前者让物理与角色手感不随帧率漂移（可变 `dt` 会改变跳跃高度与隧穿判定），后者保证同一帧内多个逻辑步**不会重复消费同一次点击**（否则点一下会挖两次）。
- **易错点或关键取舍**：① 插值系数（alpha）只用于渲染，**绝不能回写进逻辑状态**；② 单帧补步必须封顶，否则卡顿后会陷入"越补越慢"的死亡螺旋；③ 上层（`world/`、`game/`）**不得直接读 SDL 事件队列**。
- **相关**：`engine/core/fixed_step.hpp`、`engine/input/input_map.hpp`、`references/gameplay-v0.1.md`、ADR 0008

### Jolt `CharacterVirtual`：台阶上不去的真正原因

- **一句话定义**：`CharacterVirtual` 是 Jolt 提供的"角色控制器"——用形状扫掠 + 自带逻辑处理移动，而不是给胶囊挂刚体。
- **在本项目里是什么 / 为什么需要**：角色胶囊用手感优先的控制器（走 / 冲刺 / 跳 / 上坡 / 自动上台阶），地形碰撞用 `HeightFieldShape` 逐 tile 生成并在挖掘后重建。
- **易错点或关键取舍**：低速逼近台阶时中心过不去棱，**`mWalkStairsMinStepForward` 必须大于胶囊半径**（本项目取 `1.5 × 半径`）；`mWalkStairsStepUp` 需略大于台阶高（`+0.05` 余量）。另外 **vcpkg 的 `joltphysics` 5.6.0 未开 `JPH_DOUBLE_PRECISION`（`RVec3` = `Vec3`，单精度）**，与"世界定位用 `int`/`double`"的红线在大坐标上冲突 → 已登记为**待收敛项 7**。
- **相关**：`engine/physics/physics_world.*`、`world/terrain/terrain_collision.*`、`docs/plans/v0.1.md` T7

### vcpkg 的 ImGui 端口把后端编进了库本体

- **一句话定义**：vcpkg 的 `imgui` 端口会按所开特性**把后端源码一起编成 `imgui.lib`**。
- **在本项目里是什么 / 为什么需要**：开了 `sdl3-binding` + `sdlgpu3-binding` 后，`imgui_impl_sdl3.h` / `imgui_impl_sdlgpu3.h` 已随端口安装，**无需**再把后端 `.cpp` 加进自己的目标，只需 `find_package(imgui CONFIG REQUIRED)` + 链接 `imgui::imgui`。
- **易错点或关键取舍**：ImGui 需在每帧 `NewFrame` **之前**收到平台事件（`ImGui_ImplSDL3_ProcessEvent`）才能交互。本项目 `Window::pump_events` 独占事件队列且不外露，因此当前面板是**只读展示**（可用 F1 开关，不可拖动）——要交互须在平台层加事件外露钩子。
- **相关**：`game/debug_overlay.*`、`world/streaming` 无关；`docs/plans/v0.1.md` T9

## E. 疑难问答

### Q1 为什么 D3D12 要 DXIL，而 Vulkan 要 SPIR-V？

两者是不同厂商体系的着色器中间表示：D3D12 只接受微软的 DXIL，Vulkan 只接受 Khronos 的 SPIR-V。SDL3_gpu 会按选中后端要求对应格式，喂错就直接断言失败。**本机没有可用 Vulkan，SDL 落在 D3D12，所以只产 SPIR-V 必然崩。**

### Q2 为什么方块碰撞不能用 Jolt / Bullet 这类通用物理引擎？

通用引擎为"任意凸体 + 大量动态物体"设计，走宽相 + 窄相 + 形状查询。而体素碰撞只需查玩家 AABB 周围的 3×3×3 个方块，是纯整数索引查询，能快上百倍。通用物理留给怪物、掉落物这类动态刚体。

### Q3 为什么只存"脏区块"？

世界由种子确定性生成，未修改的区块走到哪儿都能原样重建，只有玩家改过的必须落盘。这从根本上避免了"无限世界撑爆硬盘"。

### Q4 为什么世界坐标不能用 float？

float 只有 24 位有效位，离原点约 2²⁴ 格后精度不足 1 格，画面会抖。故世界坐标用整数，渲染时改用相机相对坐标。

### Q5 为什么贪婪合并的作用域只能到单个 Section？

顶点位置用 uint8 存相对坐标（0~16），表示不了跨 Section 的更大范围。

### Q6 `VCPKG_ROOT` 为什么会被"改掉"？

VS 的开发者环境脚本（`vcvars` / `Enter-VsDevShell`）会把它设成 VS 自带的 vcpkg。**必须在加载 VS 环境之后再设置 `VCPKG_ROOT`**，否则 Presets 指向错误的 vcpkg 实例，并连带产生 `Ninja not found` / `CMAKE_CXX_COMPILER not set` 之类的**级联误报**。

### Q7 CI 为什么会"0 job"？

GitHub 对**无效的 workflow 文件**（或 Actions 启动前置条件不满足）会创建一个结论为 `failure`、但**没有任何 job** 的运行，且 `created_at` / `updated_at` / `run_started_at` 三个时间戳完全相同。这表明失败发生在**启动阶段**，不是构建失败。

### Q8 `.ps1` 为什么必须写成纯 ASCII？

Windows PowerShell 5.1 读取无 BOM 的 UTF-8 文件时会按本地代码页（中文环境为 GBK）解码，某些中文字节会解出 `\`，把字符串的收尾引号转义掉，导致整个文件语法崩溃。CI 脚本用纯 ASCII 即可规避。**注意：这是编码问题，不是行尾问题——LF 行尾的 `.ps1` 在 PowerShell 5.1 下完全正常。**

### Q9 装了 clang 为什么还不能编译？

Windows 上 clang 只是编译器前端，仍需要 Windows SDK 的头文件 / 库与 MSVC STL。所以 VS Build Tools 不可跳过；clang 当前的价值在 clang-format / clang-tidy。

### Q10 winget 的 portable 安装为什么失败？

winget 会在 `%LOCALAPPDATA%\Microsoft\WinGet\Links` 下创建符号链接，该目录缺失时报 `create_symlink: The system cannot find the file specified`。补建该目录即可，或直接手动解压到自定义目录（本项目 Ninja / sccache 就是这么装的）。

### Q11 为什么规范里要强调"正向写法优先"，而不是直接列禁止项？

处理"禁止 X"时需要先表征 X 再取反，长上下文里这一步容易丢失；同时解释性文字会把 X 这个名词注入上下文，反而提高它被采用的可能。所以规则尽量写成"必须执行 Y"，把禁令集中到**可机械执行的门禁脚本**里。

### Q12 "常驻文档"为什么值得单独立规矩？

因为知识有三种不同的去处，混在一起会同时变差：**概念**（是什么）→ 学习笔记；**过程**（做了什么、为什么、验证）→ 开发记录；**决策**（选了什么、备选、切换条件）→ 方案文档 / ADR。分开写之后，三者各自可检索、可维护，也不会互相覆盖。
