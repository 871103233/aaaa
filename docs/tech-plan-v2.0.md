## §1 目标与范围

### 1.1 核心目标

| 目标 | 说明 |
| --- | --- |
| 程序化开放世界 | 由**种子 + 规则**生成地形、生物群系、元素与洞穴 |
| 平滑可见表面 | 玩家**看到并行走的表面是平滑曲面**，**不得**出现方块外观 |
| 地表可改造 | 在高度场地表上**挖坑**与**堆土** |
| 洞穴与限定三维挖掘 | 存在洞穴；在**显式标记的可挖区域内**可自由三维挖掘 |
| 浮空与建造（后置） | 程序化浮空岛 / 遗迹与玩家搭建归**物件层** |
| 飞行元素 | 在三维空间自由移动的实体 |
| 角色占位 | 角色先以**胶囊体**表示；人物模型与骨骼动画后置 |

### 1.2 范围控制

范围控制的**权威表格**见 [SKILL.md](../.trae/skills/voxel-engine-dev-standards/SKILL.md) 第五节「范围控制」。总原则：引擎不为"未来第二款游戏"提前抽象；每阶段只交付一个可运行、可观察的目标。在本方向下，**人物模型与骨骼动画**同样后置（当前以胶囊体占位）。

### 1.3 目标硬件基线

沿用 `tech-plan-v1.3.md` §1.3：性能验收必须在**基线配置**（GTX 1660 / 6 GB 显存同级、1920×1080 @ 60 FPS）上测；推荐配置数据仅作参考。**视距档位**改用本版 §7 的 tile 视距口径。

## §2 世界表示

> 决策见 [ADR 0004](adr/0004-hybrid-layered-world-representation.md)。本节只列**必须遵守的形态与硬约束**，不展开理由与备选。

### 2.1 四层

| 层 | 表示 | 负责 | 不负责 |
| --- | --- | --- | --- |
| ① 地表 | **高度场**（每列 1 个高度，`int16` / 1/16 格） | 挖坑、堆土、平整、陡坡、悬崖；材质按高度与坡度混合 | 悬垂、洞穴、悬空 |
| ② 可挖体积 | **有界 SDF 体积**（`int8` 距离场），**仅存在于被标记区域内** | 洞穴与地下标记区域内的任意方向挖掘、竖井、隧道扩挖 | 地表整体高度（由 ① 管理） |
| ③ 物件 / 建造 | 模型 + 简化碰撞体（EnTT 实体 + Jolt 刚体） | 浮空岛、遗迹、玩家搭建、树木岩石等元素 | **绝不写入地形场** |
| ④ 实体 | Jolt 动态刚体与 `CharacterVirtual` | 飞行元素、NPC、掉落物、玩家 | 地形表示 |

**禁止**：把地形写成方块；把层 ③ 的内容写进任何地形场数据。

### 2.2 四条硬约束

1. **浮空物与建造物绝不写入地形场** —— 否则会在地表"打出柱子"；它们只作为实体 + 碰撞体存在。
2. **可挖范围由显式标记区域决定**，标记来源为「程序化规则 + 数据文件」两者结合，见 [ADR 0006](adr/0006-diggable-region-marking.md)；标记区域之外不可三维挖掘。
3. **可挖体积按固定网格对齐**，相邻体积共享边界采样；体积与地表相接处由**体积接管该列高度** —— 这是层间过渡的**唯一**处理点。
4. **飞行元素不引入任何新的表示**，只是"在三维空间移动、与 ①②③ 做碰撞查询"的实体。

### 2.3 世界定义与世界状态的边界

- 可挖标记 = **世界定义的输入**，不是世界状态；**禁止**写进地形场，也**禁止**写进体积密度场（见 [ADR 0006](adr/0006-diggable-region-marking.md)）。
- 玩家的挖掘结果 = **世界状态**。重建顺序固定为：**标记 → 生成初始密度 → 叠加玩家改动**。

## §3 生成与元素放置

### 3.1 噪声基础

噪声库为 **FastNoiseLite**（沿用 v1.3 §4.2）。2D 噪声叠加出地表高度；3D 噪声出洞穴与可挖候选区；2D 温度与湿度出生物群系，且**与高度图解耦**。

### 3.2 分块确定性（硬约束）

- 所有生成逻辑**必须是纯函数**：输入 = **全局种子 + 整数坐标**，输出只由输入决定。
- **禁止**依赖 `rand()`、时间、线程调度顺序、容器迭代顺序（红线 7）。生成路径**禁止**开启会影响浮点结果的激进优化（如 `-ffast-math`）。
- **同一构建内确定性是必要条件**：同一可执行文件 + 同一种子 → 结果一致；未修改区域**不落盘**，按需重建。
- 子系统种子由全局 64-bit 种子派生（`splitmix64` / `xxhash`），避免噪声之间耦合。
- 元素与结构放置沿用**分块确定性网格抖动**思路：只看"当前 tile 坐标 + 种子"即可重建（红线 15）。

### 3.3 元素放置规则（适配度判据）

每个候选元素**必须**由可复现的适配度判据决定是否放置，判据至少覆盖四项：

| 判据 | 说明 |
| --- | --- |
| 坡度阈值 | 由高度场梯度得到；超过阈值的坡面不放置（避免悬空与穿地） |
| 高度带 | 只落在允许的海拔区间内 |
| 生物群系 | 只落在允许的生物群系内 |
| 互斥半径 | 相邻元素之间的最小间距，**禁止**生成重叠 |

- 判据参数一律来自**生成参数表**（TOML，见 [ADR 0005](adr/0005-config-parsing.md)），**禁止**硬编码在生成代码里。
- 元素是**物件层**内容（层 ③），放置结果**不得**写进地形场。

### 3.4 可挖区域标记

- 标记 = **程序化规则与数据文件叠加**，顺序固定：先算程序化规则，后由数据文件按 `priority` 覆盖。一行摘要，细节见 [ADR 0006](adr/0006-diggable-region-marking.md)。
- 数据文件为 `assets/config/dig_regions.toml`，随世界定义一起版本化；运行期按**固定网格对齐单元**缓存，可丢弃、可重建。
- **禁止**把标记写进地形场与体积密度场。

## §4 网格化与材质

### 4.1 地表：高度场网格

- 地表由高度场直接网格化为**平滑曲面**；**禁止**生成方块外观。
- **法线由高度场梯度计算**并写入顶点属性；**禁止**在片元阶段用面法线近似。
- 网格化与重网格以**地表 tile**（64×64 列，[ADR 0008](adr/0008-sizes-precision-budget.md)）为单位；相邻 tile 边界**必须几何连续**，**禁止**出现裂缝。
- 顶点位置以**块内定点坐标**存储；世界定位用整数与 `double`（红线 6）。
- 地表 LOD 方案与接缝策略**尚未收敛**（§0.3 / SKILL 待收敛项 #4）；收敛前**不得**据任何候选方案施工。

### 4.2 可挖体积：局部等值面网格

- 网格化算法为 **Naive Surface Nets**，密度为 **`int8` 距离场**，块为 **32³ 体素（33³ 采样）**。一行摘要，理由与备选见 [ADR 0007](adr/0007-volume-meshing-algorithm.md)；尺寸与精度见 [ADR 0008](adr/0008-sizes-precision-budget.md)。
- 密度语义：`d < 0` 为实心、`d > 0` 为空、`0` 为表面。
- 网格化**作用域 = 单块**；读取邻块边界采样，**块边界必须共享采样值**，**禁止**各自独立生成（ADR 0004 硬约束 3）。
- 法线由**密度场梯度**计算，写入顶点属性。

### 4.3 材质：多纹理权重混合（splat）

- 地表材质 = **多纹理权重混合**，权重由**高度与坡度**决定；材质表为 TOML（[ADR 0005](adr/0005-config-parsing.md)）。
- 纹理采样**必须**使用纹理数组（多层 GPU 纹理）；**禁止**使用纹理图集（低 mip 层会渗色）。
- 材质参数口径见 [ADR 0009](adr/0009-terrain-material-pipeline.md)：权重**逐像素**在片元着色器重算（窄带 `smoothstep`），层贴图为 albedo + 法线，参数经 `BuildMaterialUniform` 单入口投影。
- PBR 四件套（albedo / normal / roughness / AO）与宏观变化见 [ADR 0010](adr/0010-render-quality-pipeline.md) P2（**未开始**）。
- 物件层材质 = 模型自带材质，**不参与**地表 splat。

### 4.4 光照与色彩

**实施顺序固定为四步且不得跳步**（[ADR 0010](adr/0010-render-quality-pipeline.md)）：

1. **P0**：HDR 离屏目标 + 曝光 + ACES 近似色调映射 + sRGB 编码；
2. **P1**：方向光（可配）+ **级联阴影（CSM）** + 半球天空光 + 指数高度雾；
3. **P2**：PBR（GGX / Smith / Schlick）+ roughness / AO；
4. **P3**：MSAA 4× 与多频细节法线。

**禁止**在未接入 HDR 与色调映射的情况下先做 P2 / P3：亮部截断会吃掉全部增益。
**禁止**引入逐方块光照与光照 BFS：本方向下不存在逐方块光照数据（[ADR 0008](adr/0008-sizes-precision-budget.md) §4）。

### 4.5 渲染通道与坐标精度

- 不透明通道为主通道；alpha cutout 与半透明各自独立通道，半透明**必须按距离排序**。
- **主通道渲染到 HDR 离屏目标**，再经后处理通道（色调映射 + 编码）写入交换链（ADR 0010 P0）。
- 世界坐标定位用整数与 `double`；上传 GPU 前做**相机相对偏移**转 `float`。
- 遮挡剔除方案**尚未收敛**（§0.3 / SKILL 待收敛项 #6）。

## §5 物理与角色

### 5.1 选型：Jolt Physics

- 物理库为 **Jolt Physics**（vcpkg 端口 `joltphysics`）。一行摘要，理由与口径变更见 [ADR 0004](adr/0004-hybrid-layered-world-representation.md)，尺寸见 [ADR 0008](adr/0008-sizes-precision-budget.md)。
- 地形：**每个地表 tile 一个 `HeightFieldShape`**。
- 可挖体积：**每个体积块一个 `MeshShape`**（由 §4.2 产出的网格生成）。
- 角色：**`CharacterVirtual`**，碰撞体为**胶囊**。
- 动态实体：Jolt 动态刚体。
- **作废**：自研 swept AABB 与「3×3×3 方块碰撞查询」。

### 5.2 主循环与时间步

- 逻辑与物理以**固定 `dt = 1/60 s`** 推进，用累加器承接帧间余量；渲染侧用插值系数平滑显示。
- **单帧最多补 5 步**，超出部分丢弃，防止卡顿后陷入死亡螺旋。
- 时间源用 SDL3 高精度单调计时（`SDL_GetPerformanceCounter`）。
- **禁止**把可变帧间隔直接传进物理与角色更新；插值系数只用于渲染，**不得**回写逻辑状态（红线 11）。

### 5.3 飞行元素与建造物

- 飞行元素是**实体**（层 ④），不引入新的表示（§2.2 约束 4）。
- 建造物是**实体 + 碰撞体**（层 ③），**禁止**写入地形场（§2.2 约束 1）。

## §6 存档

### 6.1 原则（沿用）

存档格式一律为**自定义二进制 + zstd 压缩**；**只存脏数据**；**必须带 `version` + 迁移函数 + 迁移测试**；主线程**不得**阻塞在磁盘 IO；文本格式仅用于 `level.dat` 这类元数据。

### 6.2 v2 内容模型

只落盘以下四类脏数据：

| 类别 | 内容 |
| --- | --- |
| 高度场脏列 | 被挖坑、堆土、平整改动过的地表列（相对生成结果的差异） |
| 脏体积块 | 在可挖区域内被改动过的体积块密度数据 |
| 物件与建造 | 放置的物件与玩家建造（实体 + 变换 + 碰撞体描述） |
| 实体状态 | 需要持久化的动态实体状态 |

### 6.3 世界定义一致性

- 存档记录可挖区域表（`dig_regions.toml`）的 `schema_version` 与**内容哈希**；不匹配时**提示**，**禁止**静默迁移（见 [ADR 0006](adr/0006-diggable-region-marking.md)）。
- 重建顺序固定为：**标记 → 生成初始密度 → 叠加玩家改动**。

### 6.4 待定

`.voxr` v2 的**精确字节布局待定**，须在**首次存档实现前**冻结（登记见 §0.3）；执行细则见 `../.trae/skills/voxel-engine-dev-standards/references/save-and-serialization.md`。

## §7 尺寸精度与预算

> 决策见 [ADR 0008](adr/0008-sizes-precision-budget.md)。本节只列**冻结口径**与**验收规则**。

### 7.1 尺寸与精度（冻结）

| 项 | 取值 |
| --- | --- |
| 地表 tile | **64×64 列** |
| 地表高度精度 | **`int16`，1/16 格**（范围 ±2048 格） |
| 世界垂直范围 | **0 ~ 512 格** |
| 可挖体积块 | **32³ 体素**（含 **33³** 采样，多一层边界共享） |
| 体积密度精度 | **`int8` 距离场** |
| 地表网格顶点位置 | **块内定点坐标** |
| 碰撞查询 | 由 **Jolt** 承担 |

### 7.2 V0.1 预算（小场景）

| 指标 | V0.1 目标 | 记录方式 |
| --- | --- | --- |
| 帧时间 | **1080p ≥ 60 FPS**（基线机 GTX 1660 同级） | Tracy，P50 / P95 / P99 |
| CPU 常驻内存 | **≤ 150 MB** | Tracy 内存面板 |
| VRAM 常驻 | **≤ 300 MB** | RenderDoc 资源统计 |
| Draw Call | **只记录、不验收** | 见 §7.3 |

> **渲染质量线（ADR 0010）的显存增量**：HDR 离屏目标、MSAA 目标、阴影级联、多通道材质贴图**必须单独记账**；上表 VRAM 口径在 ADR 0010 各阶段落地后**重新核算**（SKILL 待收敛项 #10）。

### 7.3 只记录、不验收的项

- **Draw Call**：长视距下的预算取决于地表 LOD 方案，而 LOD **尚未收敛**（§0.3 / SKILL 待收敛项 #4）。收敛前**只记录实测值**。
- **长视距内存**：同理随 LOD 变化，收敛前**只记录**。
- **验收规则**：LOD 收敛前，**不得**把 Draw Call 与长视距内存列为验收判据（[ADR 0008](adr/0008-sizes-precision-budget.md) §2）；任何性能报告**必须**写明「基线配置 / tile 视距 / 是否启用 LOD / 是否含可挖体积」四项，缺一即不可比。

### 7.4 固定基准场景

沿用 [ADR 0008](adr/0008-sizes-precision-budget.md) §3 的基准场景（世界种子、出生点、第三人称相机参数、预热与采样协议、场景约束）。

### 7.5 不得再引用的旧口径

旧方块世界专属的尺寸与预算（区块尺寸、Section 尺寸、逐方块光照数据量、旧 Draw Call 档位、方块碰撞查询范围）**一律作废**；**禁止**在任何文档、源码注释与性能报告中作为现行指标引用。完整作废清单见 [ADR 0008](adr/0008-sizes-precision-budget.md) §4。

## §8 分阶段路线图 V0.1 ~ V1.0

> 原则：每阶段交付一个**可运行、可观察**的目标，**不在 V0.1 就做超大世界**。
> 阶段验收的权威判据在本章；**当前阶段**的任务分解、顺序与进度见 [docs/plans/v0.1.md](plans/v0.1.md)。

### V0.1 最小闭环：平滑地形 + 可挖可堆 + 胶囊体活动

**阶段目标**：验证"**平滑地形 + 可挖可堆 + 胶囊体自由活动**"这条主链路 —— 一个能挖能堆的平滑地形块，外加一个与地表相通的洞穴体积。

- **世界层**：地表高度场 tile（数据布局 + 多层噪声生成 + 平滑网格化 + 法线）；笔刷挖掘 / 堆建 + 局部重网格；最小可挖体积（局部 SDF + 等值面网格化 + 与地表相接的洞口过渡）。
- **地表材质**：多纹理权重混合（按高度与坡度）。
- **角色与相机**：Jolt `HeightFieldShape` 地形碰撞 + `CharacterVirtual` 胶囊（走 / 跳 / 上坡 / 上台阶）；第三人称相机（含避障）。
- **引擎与调试**：固定步长主循环、动作状态输入层、网格渲染路径、Dear ImGui 调试面板。
- **工具链**：CMake + SDL3（SDL3_gpu 渲染）+ GLM + stb + toml++ + Jolt + ImGui；Shader 经 `glslc` → SDL_shadercross 离线编译为双格式（[ADR 0002](adr/0002-shader-dual-format-pipeline.md)）。

**验收判据**（与 `docs/plans/v0.1.md` §4 一致；该文件为进度侧权威，本表为方向侧权威）：

| 维度 | 可观察现象 |
| --- | --- |
| 平滑地表 | 目视无方块外观；相邻 tile 边界几何连续无裂缝 |
| 地表可挖可堆 | 坑 / 土堆 / 平整生效；操作后 **≤ 1 帧**可见更新 |
| 可挖体积 | 体积内可任意方向挖掘；**与地表相接处无裂缝、无穿模** |
| 角色移动 | 走 / 跳 / 上坡 / 上台阶不穿地形 |
| 第三人称相机 | 可跟随且不穿地形 |
| 调试设施 | 面板可随时开关且不崩溃 |
| 工程门禁 | 一键构建 + 零警告 + 测试与门禁全绿 |
| 性能与内存 | **只记录**（§7.3），不设验收数字 |

**明确不做（防范围蔓延）**：全世界三维体素；程序化浮空岛 / 遗迹与玩家自由搭建（本阶段只做飞行元素）；人物模型与骨骼动画；LOD、遮挡剔除、存档落盘、粒子与音频。

### V0.2 流式加载与体积扩展

- 地表 tile 流式加载：以玩家为中心按 **tile 距离**加载与卸载；优先级与卸载策略见 `../.trae/skills/voxel-engine-dev-standards/references/chunk-and-streaming.md`。
- 任务系统（enkits）+ 后台生成与网格化；**邻居边界采样就绪后**才可网格化。
- 多体积块：体积块之间边界共享采样；体积块集合按标记区域调度。
- 接入 **Tracy** 与 **GoogleTest + CTest**；从本阶段起用数据而非感觉驱动优化。
- 里程碑：朝一个方向持续行走，地形与体积持续生成，无空洞、无明显卡顿。

### V0.3 生成系统与持久化

- 多层噪声叠加：高度与生物群系；生成参数全部来自 TOML。
- 元素放置规则：坡度阈值、高度带、生物群系、互斥半径（§3.3）。
- 洞穴程序化规则 + `dig_regions.toml` 数据文件叠加（[ADR 0006](adr/0006-diggable-region-marking.md)）。
- 存档落盘：按 §6.2 的 v2 内容模型只存脏数据，并配套版本迁移（字节布局须在实现前冻结，§0.3）。
- 里程碑：新档可由种子复现，玩家改动可持久化。

### V0.4 玩法与动态实体

- Jolt 动态刚体：掉落物与可推动物体；飞行元素（层 ④）。
- 物件层起步：树木与岩石等元素的放置与渲染（Entity + 碰撞体）。
- 基础 HUD 与物品栏（Dear ImGui）。
- 里程碑：可以挖、可以捡、可以逛的探索原型。

### V0.5 大视距与优化

- **前置**：地表 LOD 方案（待收敛项 #4）与遮挡剔除（待收敛项 #6）**必须在开工前经 ADR 收敛**。
- 地表 LOD 与接缝策略、遮挡剔除、视锥体裁剪。
- 拉高 tile 视距；**在 LOD 收敛后**补足大视距 Draw Call 与内存预算，并把 §7.3 的"只记录"改为"有预算"。
- 粒子与音频；简单 AI。
- 里程碑：大视距下稳定运行。

### V1.0 正式版（后续持续）

- 多人联机（GameNetworkingSockets）；脚本绑定（Lua + sol2）。
- 完整生存系统。
- 浮空岛 / 遗迹与玩家建造完善。
- **人物模型与骨骼动画**（此时评估引入 Assimp）。
- 渲染后端下沉（仅在超出 SDL3_gpu 能力时）。

### 9.3 质量保障与测试清单

- 沿用 v1.3 §9.3：CI 门禁、ASAN / TSan 互斥配置、clang-format / clang-tidy、commit 规范、**红灯不合并**。
- **必须有的四类测试**（取代 v1.3 §9.3 的旧清单）：
  1. **生成确定性**：同种子 + 同整数坐标 → 输出一致；
  2. **边界与共享采样**：相邻地表 tile 边界几何连续无裂缝；相邻体积块边界采样一致；
  3. **标记合并语义**：程序化规则与数据文件按 `priority` 覆盖的结果可复现（[ADR 0006](adr/0006-diggable-region-marking.md)）；
  4. **存档往返与迁移**：序列化往返逐字段一致；旧档能被新版本正确读出。
- **调试设施**：Dear ImGui 面板（帧时间、玩家坐标、笔刷半径、已加载 tile 与体积块数）；**不得**成为世界层热路径的一部分。
