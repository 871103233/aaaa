# 并发与任务系统

涉及后台线程 / 异步区块管线 / GPU 上传的改动，**本文件全部适用**。

## 1. 线程角色（严格划分，不得越界）

| 角色 | 允许做的事 | 禁止做的事 |
| --- | --- | --- |
| 主 / 渲染线程 | 窗口、输入、相机、GPU 提交、碰撞查询 | 阻塞式 IO、区块生成、网格化 |
| Worker（N 个） | 生成、光照传播、网格构建 | **调用任何图形 API** |
| IO 线程（1 个） | 脏区块读写、存档 | 阻塞 Worker |

图形上下文只能在创建它的线程使用 ⇒ **只有渲染线程能调用 GPU**。

## 2. 任务系统

- **任务调度一律使用 enkits**（vcpkg 端口名 `enkits`；现成任务图库，原生支持依赖计数与工作窃取，零自研成本）。备选方案与切换条件见 `docs/adr/0003-task-scheduler-and-ecs.md`，本文件不重复。
- **线程与停止语义**：用 `std::thread` + 停止标志，或交给任务库的线程池（语言标准见主文件「编码约定」）。
- 线程依赖与停机的**选型理由、不采用的做法**见 ADR 0003 —— 本文件只写"如何正确使用"。

### 2.1 与 Jolt 的时序（易踩坑）

- Jolt 已在 **V0.2（T7）** 引入并承担地表高度场 / 体积三角网 / 角色胶囊；**任务系统（enkits）与之各管一段**，互不调度。
- **评估把 Jolt 的 JobSystem 桥接到同一线程池的时间点**：当"两侧线程数之和明显超出核数、或出现互相等待"时再评估 —— 当前（V0.3）未桥接。

### 2.2 本项目已落地的启用形态（V0.3 / T81；决策见 [ADR 0022](../../../../docs/adr/0022-volume-build-worker-pipeline.md)）

- **enkits 的接入点只有一处**：`engine/core/task_scheduler.*` 是**薄封装**（**pimpl 把 enkiTS 类型挡在公共头之外** ⇒ 换库不改调用方）；
  业务侧只用 `Submit` / `WaitFor` / `WaitForAll`，不得直接 `#include <enkiTS/...>` 到 `world/` 与 `game/`。
- **任务粒度 = 一个可挖体积块**（`world/streaming/volume_build_pipeline.*`）：worker 只跑 `BuildBlockFromInput`（**纯函数**），
  即"填密度 + 等值面网格化"，**主线程**只做"采快照 + 收包 + GPU 上传"。
- **快照必须提交时采**：`BlockBuildInput` 在提交前由主线程填好（含**邻块已写入的壳层采样**）⇒ worker 只读、不碰世界状态（本文件 §5）。
- **上传严格留渲染线程**：SDL_gpu 命令缓冲单线程 ⇒ 禁止把 GPU 上传挪进 worker；worker 只回传 CPU 侧结果。
- **结果晚 1~N 帧可见**：主线程每帧最多安装固定数量（`kVolumeBuildsInstalledPerFrame`），**允许"新块晚几帧就位"**，但**不允许冻结画面**。
- **失败降级**：线程池不可用时**回落同步构建 + `WARN`**（结果不变，只是尖峰回到从前）；**不得静默**。
- **确定性**：同一块在同步 / 异步两条路径上的结果必须**逐位一致**（红线 7 / 9）⇒ 必须有"两条路径逐值比较"的单测钉住。
- **生命周期**：任务池必须**先于**它服务的使用者构造（后建先毁），否则 worker 可能读已释放的快照。

## 3. 区块异步管线（五阶段）

1. **生成**（后台）：按种子填充方块数据。
2. **光照**（后台）：BFS 传播，注意跨区块边界。
3. **网格**（后台）：贪婪网格化，产出顶点 / 索引缓冲**上传包**。
4. **上传**（**必须渲染线程**）：`SDL_UploadToGPUBuffer` 上传到 GPU。
5. **卸载**（后台）：序列化脏区块到磁盘，释放内存。

## 4. 依赖调度（关键）

- 网格构建**必须等所有邻居区块生成并完成光照**（邻居达 `Lit`）才能处理边界面。
- 实现方式：生成时若邻居未就绪，把自己加入邻居的"待通知列表"；邻居就绪后再触发本区块的网格任务。
- 任务图必须能表达"自身生成完成 + 4 邻居光照完成 → 网格化"这类依赖计数语义。

## 5. 数据竞争规避：单写者 + 不可变快照

- Worker **独占**构建一个区块；构建完成后以**原子指针整体发布**新版本。
- 主线程只引用"已发布"的**不可变快照**；**禁止对区块加粗粒度锁**；旧版本在所有引用释放后回收。
- **禁止跨线程直接改同一 Chunk**。
- 双缓冲：主线程读"当前版本"网格，后台构建"新版本"，上传完成后原子交换。
- 异步任务持有区块时用引用计数 / 句柄保证生命周期，避免卸载与在跑任务互相悬垂。

## 6. 验证要求

- **Windows（MSVC）**：用 ASAN。MSVC **不支持 TSan**。
- **Linux / Clang**：额外启用 **TSan** 跑竞争检测。
- **ASAN 与 TSan 互斥**，必须拆成两套 CI 配置分别运行。
- 新增或修改并发逻辑后，必须在 TSan 配置下跑一遍再提交。

## 7. 提交前自检

- [ ] 主线程帧内无生成 / 网格 / IO / 阻塞等待
- [ ] Worker 未触碰任何图形 API
- [ ] 区块数据发布走原子指针，无粗粒度锁、无跨线程直改
- [ ] 任务依赖（邻居就绪）已正确处理，含邻居中途卸载的情形
- [ ] TSan 配置下无报告
