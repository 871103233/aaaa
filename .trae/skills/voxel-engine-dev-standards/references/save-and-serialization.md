# 存档与序列化

涉及区块落盘 / 读档 / 版本兼容的改动，**本文件全部适用**。

## 1. 格式定稿

- **存档格式一律为「自定义二进制 + zstd 压缩」**：区块数据本质是"固定布局字节数组 + 压缩"，自写序列化只需几十行、零模板膨胀、格式完全可控且无第三方依赖。
- 文本格式（JSON / XML）仅用于 `level.dat` 这类人可读的元数据；区块存档一律用二进制（文本体积大、读写慢几十上百倍）。

## 2. 区域文件布局（参照 MC `.mca`）

每个 `.voxr` 文件存 **32×32 个区块**（避免单文件无限增长导致读写卡顿）：

```
[头部] 1024 个区块位置表（offset + size）  ← 支持随机读
[数据] 每个区块独立 zstd 压缩：
        方块数据(Section+palette) + 光照数据 + palette + BlockEntity 列表
```

- 压缩前单区块约 10~50 KB，压缩后通常 < 5 KB。
- **压缩库用 zstd**（比 zlib 快 3~5 倍、压缩率更好；单文件 amalgamation 可直接 vendoring）。
- 文件与区块头部必须含 `magic`、`version`、区块坐标、校验和。

## 3. 版本迁移（强制，红线之一）

- `.voxr` 区块与 `level.dat` 头部**必须含 `version` 字段**。
- **任何字段或布局变更都必须配套：**
  1. 迁移函数（旧格式 → 新格式）；
  2. 迁移测试（"旧档能被新版本正确读出"）。
- 不做迁移 = 玩家存档静默损坏，属**红线违规**。

## 4. 写入安全

- **原子替换**：写临时文件 → `rename` 覆盖，防止进程崩溃导致存档损坏。
- **延迟批量写盘**：脏区块每 5~10 秒 flush 一次；玩家退出前强制 flush。

## 5. 读取策略

- 内存 **LRU 缓存**已读区块，避免同一区块重复读盘。
- **纯异步 IO**：`std::thread` + 停止标志，或统一交给任务系统线程池（语言标准限制见主文件第三节）。
- **主线程永远不阻塞在磁盘**。

## 6. 元数据

- 单独写 `level.dat`（JSON 或简单二进制）：种子、玩家位置、**生成版本号**、存档版本号。

## 7. 与其他模块的耦合

- 只落盘**脏区块**（玩家修改过）；未修改区块靠种子确定性重建。
- 跨区块结构（树 / 村庄）若跨越边界，须记录"结构影响范围"，避免重建时残缺或重复。
- `BlockEntity` 必须随区块一起序列化与反序列化。

## 8. 提交前自检

- [ ] 格式头部含 magic + version + 校验和
- [ ] 字段 / 布局有变更时，已配套迁移函数与迁移测试
- [ ] 写盘为原子替换（临时文件 + rename）
- [ ] 读写走异步，主线程无阻塞
- [ ] 序列化往返测试通过（写 → 读 → 逐字段一致）
