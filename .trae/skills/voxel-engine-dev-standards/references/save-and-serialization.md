# 存档与序列化

涉及落盘、读档与版本迁移的改动读本文件。**格式原则已定稿；`.voxr` v2 的精确字节布局待定**（§3）。
**红线条款见主文件第一节红线表**；本文件只写"怎么落地"。世界表示与脏数据粒度见方案 §2 / §6 与 ADR 0004 / ADR 0006 / ADR 0008。

## 1. 格式定稿（原则层，不可动摇）

- **存档格式一律为「自定义二进制 + zstd 压缩」**：世界状态本质是"固定布局字节数组 + 压缩"，自写序列化零模板膨胀、格式完全可控。
- **只存脏数据**（红线 4）：未修改的地表与体积靠**种子确定性重建**，**禁止**把未修改数据落盘。
- 文本格式（TOML / JSON）**仅**用于 `level.dat` 这类人可读的元数据；世界状态一律用二进制。
- 文件头**必须**含 `magic`、`version`、坐标与校验和。
- IO **必须**异步，**主线程永远不阻塞在磁盘**（红线 2）。

## 2. v2 内容模型

只落盘以下四类脏数据：

| 类别 | 内容 | 粒度 |
| --- | --- | --- |
| **高度场脏列** | 被挖坑、堆土、平整改动过的地表列（相对生成结果的差异） | 列；按地表 tile 组织 |
| **脏体积块** | 在可挖区域内被改动过的体积块密度数据 | 单体积块（32³） |
| **物件与建造** | 放置的物件与玩家建造（实体 + 变换 + 碰撞体描述） | 单对象 |
| **实体状态** | 需要持久化的动态实体状态 | 单实体 |

- **禁止**把物件与建造写进地形场再存档（ADR 0004 硬约束 1）；它们作为**实体记录**独立存储。
- **禁止**把可挖区域标记写进存档当作世界状态；标记是**世界定义的输入**（见 §5）。
- 高度场脏列**必须**存"相对生成结果的差异"，而非整列绝对值，以保证生成算法升级后仍可叠加。

## 3. 精确字节布局（**待定**）

- `.voxr` **v2 的精确字节布局尚未冻结**，登记为方案 §0.3 待定项 3；**须在首次存档实现前**定稿并写入本节。
- 定稿前：
  - **禁止**按任何草案实现读写代码；
  - **禁止**产出真实的落盘文件作为兼容性基准；
  - 可以先实现的内存结构与往返测试**不得**依赖具体字节顺序与字段宽度。
- 区域文件的**组织原则**已定：按地表 tile 集合分文件，避免单文件无限增长；文件头含位置表以支持随机读。
- 定稿后的**规则**：字段顺序与宽度一经冻结，任何变更都必须提升 `version` 并配套迁移函数与迁移测试。

## 4. 版本迁移（强制，红线之一）

- 存档文件头与 `level.dat` **必须**含 `version` 字段（红线 8）。
- **任何字段与布局变更都必须配套：**
  1. 迁移函数（旧格式 → 新格式）；
  2. 迁移测试（"旧档能被新版本正确读出"）。
- 不做迁移 = 玩家存档静默损坏，属**红线违规**。
- 生成算法版本（`generatorVersion`）**必须**与存档版本分开记录：它决定"未修改数据重建后是否仍与原档一致"。

## 5. 世界定义一致性（ADR 0006）

- 存档**必须**记录可挖区域表（`dig_regions.toml`）的 `schema_version` 与**内容哈希**。
- 加载时哈希不匹配：**必须提示用户**，**禁止**静默迁移（ADR 0006）。
- 重建顺序固定为：**标记 → 生成初始密度 → 叠加玩家改动**；**禁止**颠倒顺序。

## 6. 写入安全

- **原子替换**：写临时文件 → `rename` 覆盖，防止进程崩溃导致存档损坏。
- **延迟批量写盘**：脏数据每 5~10 秒 flush 一次；玩家退出前**强制** flush。
- 写盘失败**必须**上报并按红线 2 的异步路径重试，**禁止**在主线程重试。

## 7. 读取策略

- 内存 **LRU 缓存**已读单元，避免同一单元重复读盘。
- **纯异步 IO**：IO 任务必须走后台线程执行（线程归属见 `concurrency.md`）；**不使用 C++20 的 `std::jthread`**（语言标准见主文件第三节）。
- **主线程永远不阻塞在磁盘**。

## 8. 元数据

单独写 `level.dat`（文本格式，见 §1）：世界种子、玩家位置、`generatorVersion`、存档 `version`、可挖区域表的 `schema_version` 与内容哈希。

## 9. 与其他模块的耦合

- 只落盘**脏数据**；未修改单元靠种子确定性重建（见 `chunk-and-streaming.md` §4）。
- 卸载单元前**必须**先完成脏数据落盘（见 `chunk-and-streaming.md` §8）。
- 存档**不得**包含任何"必须由生成逻辑推导出来"的冗余数据。
