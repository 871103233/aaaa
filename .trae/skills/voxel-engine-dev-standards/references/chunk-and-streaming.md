# 区块、生成、流式加载、体素光照

读取本文件后，本任务相关的区块规则**全部适用**。红线条款见主文件第一节。

## 1. 数据布局

- 区块水平尺寸固定 **16×16**，高度 **384**（可扩到 512）。
- 区块内部切分为 **16×16×16 的 Section**——存储 / 网格构建 / 光照的**最小单元**。
- Section 内方块 ID 用**调色板（Palette）+ 位打包**：
  - `vector<BlockId>` 存本 Section 出现过的方块；每方块 4~8 bit 索引到调色板。
  - **全空气 Section 用 `nullptr` 标记**，不分配内存、不网格化、不上传、不落盘。
- 方块属性（透明 / 固体 / 纹理坐标 / 硬度 / 发光 / 摩擦）统一存全局 `BlockRegistry`，启动时一次性构建，**不随方块重复存储**。
- `BlockEntity`（箱子 / 熔炉 / 告示牌 / 漏斗）单独挂在 Chunk 上的 `unordered_map<BlockPos, BlockEntity*>`，每 Chunk 通常个位数，必须参与序列化。

**内存红线**：单区块方块数据目标 8~20 KB；光照未压缩为 96 KB（`16×16×384 × 1 B`，2 nibble/block），估算不得按 48 KB。

## 2. 区块状态机（禁止跳步）

```
Empty → Generating → Generated → Lit → Meshed → Ready
```

| 状态 | 含义 |
| --- | --- |
| `Generating` | 后台按种子填充方块数组 |
| `Generated` | 方块数据就绪，可参与邻居判断与结构生成 |
| `Lit` | 天空光 / 方块光已在**本区块及跨界处**传播完成 |
| `Meshed` | 可见面 / 贪婪网格构建完成 |
| `Ready` | 网格已上传 GPU，可进入渲染与碰撞查询 |

## 3. 邻居依赖（硬规则）

- 进入 `Meshed` 的前置：自身达 `Generated`，且 **4 个水平邻居（启用垂直邻居时为 6 个）均达 `Lit`**，否则边界面可见性判断不完整。
- 邻居区块**修改 / 加载 / 卸载**时，必须把本区块标脏 → 重跑光照传播 → 重新网格化。
- 光照 BFS **必须能跨区块边界**；邻居未就绪时暂挂，邻居就绪后续传。
- 碰撞与渲染查询**必须跨区块**取方块，禁止只查当前区块。
- 跨区块结构（树、村庄）生成时记录"结构影响范围"，避免重建时残缺或重复。

**红线**：区块未等邻居就建网格 = 返工。

## 4. 程序化生成

- 噪声：FastNoiseLite，2D 叠加出高度图；3D 出洞穴 / 矿脉 / 含水层；2D 温度 + 湿度出 Biome，**与高度图解耦**（避免山顶出现沙漠）。
- 结构生成用**分块确定性网格抖动（Chunked Jittered Grid）**：
  1. 世界按"结构单元格"划网格（如村庄 32×32 区块一格）；
  2. 每格用 `hash(seed, gridX, gridZ)` 决定是否生成及格内 jitter 偏移；
  3. 该格对应区块生成时确定性算出结构位置；
  4. 跨区块大结构由"主区块"生成，邻居读取结果。
- **结构生成一律用分块确定性网格抖动（Chunked Jittered Grid）**。理由：它满足"只看当前区块 + 种子即可确定性重建"这一硬约束，而这是流式加载的前提；需要全局状态才能保证分布的方案不满足该约束。

## 5. 确定性与种子

- 所有子系统种子由全局 **64-bit 种子派生**（`splitmix64` / `xxhash`），避免噪声间耦合。
- **同一构建内确定性（必要）**：生成逻辑禁止依赖 `rand()`、时间、线程调度顺序、容器迭代顺序。未修改区块无需存盘。
- **跨平台 / 跨版本确定性（仅联机或共享种子需要）**：FastNoiseLite 是 **float 实现**，不同编译器 / FMA 收缩 / 优化等级下可能不同。**不得承诺"跨平台永远一致"**；若需联机，改用**整数哈希噪声**。
- 生成路径禁止开启会影响浮点结果的激进优化（如 `-ffast-math`）。

## 6. 流式加载

- 以玩家为中心，按曼哈顿 / 切比雪夫距离维护 `(2*viewDistance+1)^2` 个区块；超出则卸载。
- 加载优先级：玩家当前列 → 面向方向前方 → 其他已加载区（保证面前不出现空洞）。
- 五阶段异步管线：生成 → 光照 → 网格 → **上传（必须渲染线程）** → 卸载。
  线程角色划分与任务依赖调度须严格按并发约定执行。
- 双缓冲区块数据：主线程只读"当前版本"网格，后台构建"新版本"，上传完成后原子指针交换。

## 7. 体素光照

- 每方块 2 个 nibble（共 1 字节）：高 4 位天空光、低 4 位方块光；跟随 Section 压缩存储。
- 天空光自顶部向下传播，遇不透明方块停止；方块光（火把 14 / 岩浆 15 / 萤石 15）向 6 邻域 BFS，每格衰减 1。
- **BFS 增量更新**：以被改变的光源 / 被移除遮挡的位置为起点传播，**禁止每帧全量重算**。
- 顶点颜色打包：光照打在顶点色 RGB（天空光与方块光取 max 乘全局亮度曲线），Shader 内与纹理采样相乘。
- **光照重网格问题**：光照进顶点色 ⇒ 每次光照变化需重建网格。这是 MC 经典性能热点，须把**脏标记限制到 Section 粒度**，禁止整 Chunk 重建。
- **AO（V0.5 启用）**：逐顶点计算 0~3 打在顶点 Alpha。**其合并判据必须在 V0.2 的贪婪网格阶段就以"恒为 0"预埋**，否则开启 AO 时会破坏贪婪合并或产生错误 AO。

## 8. 本引用相关测试

- 生成确定性：同种子 → 逐方块同输出。
- 光照 BFS 跨界正确性（邻块未加载 / 加载 / 卸载三种情形）。
- Section 全空气不分配内存、不产出网格。
