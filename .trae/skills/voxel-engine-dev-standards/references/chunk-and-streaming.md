# 地表 tile、可挖体积块的流式加载与生成

涉及世界生成、流式加载、脏标记与卸载时读本文件。**红线条款见主文件第一节红线表**，本节只写"怎么落地"。
内部网格化规则见 `meshing-and-render.md`；线程与任务系统细节见 `concurrency.md`；存档细节见 `save-and-serialization.md`。

## 1. 加载单元与数据布局

本方向下**不存在方块与 Section**。加载与脏标记只有两种单元：

| 单元 | 尺寸 | 数据 | 权威 |
| --- | --- | --- | --- |
| **地表 tile** | **64×64 列** | 高度场：每列 `int16`（1/16 格，范围 ±2048 格），单 tile ≈ **8 KB** | ADR 0008 |
| **可挖体积块** | **32³ 体素**（含 **33³** 采样） | `int8` 距离场，单块 ≈ **36 KB** | ADR 0007 / ADR 0008 |

- 体积块**只在被标记的可挖区域内存在**（ADR 0004 硬约束 2）；未标记区域**不得**分配体积块。
- 33³ 采样比 32³ 多出的一层是**边界共享层**：它必须写成邻块对应位置的实际采样值，**禁止**按本块数据自行外推。
- 高度场用**定点**而非 `float`，保证跨平台确定性一致。
- **内存口径**：本文件不设内存数字上限；预算与"只记录 / 有预算"的区分见方案 §7 与 ADR 0008。

## 2. 加载单元状态机（禁止跳步）

```
Empty → Generating → Generated → Meshed → Ready
```

| 状态 | 含义 |
| --- | --- |
| `Empty` | 已列入加载范围，尚未分配数据 |
| `Generating` | 后台按**纯函数**填充高度列（地表）与密度值（体积） |
| `Generated` | 数据就绪，可供**邻居采样**与元素放置规则查询 |
| `Meshed` | 网格构建完成（高度场网格 / 等值面网格） |
| `Ready` | 网格已上传 GPU，可进入渲染与物理查询 |

- 地表 tile 与体积块**各持一套状态**，判据相同。
- 状态推进由加载器单点驱动；**禁止**由多个执行者并发改写同一单元的状态。

## 3. 邻居边界就绪（硬规则）

进入 `Meshed` 的前置条件：

- 地表 tile：自身达 `Generated`，且**参与边界采样的 4 个水平邻 tile 均达 `Generated`**（否则边界几何无法连续）。
- 体积块：自身达 `Generated`，且**参与边界共享采样的 6 个邻块均达 `Generated`**（33³ 采样含各个面的外层）。

规则：

- 邻单元**加载、修改、卸载**时，**必须**把本单元标脏并重跑网格化（红线 12）。
- 渲染与物理查询**必须跨单元取值**，**禁止**只查当前单元。
- **层间过渡**：体积与地表相接处由**体积接管该列高度**（ADR 0004 硬约束 3）。相接列的**地表网格与体积网格必须在同一批更新中重建**，否则会出现缝隙与穿模。

## 4. 生成确定性（硬约束）

- 生成逻辑**必须是纯函数**：输入 = `(全局种子, 整数坐标)`，输出只由输入决定（红线 7）。
- **禁止**依赖 `rand()`、时间、线程调度顺序、容器迭代顺序。
- 元素与结构放置沿用**分块确定性网格抖动**：只看"当前 tile 坐标 + 种子"即可重建（红线 15）。
- 子系统种子由全局 64-bit 种子派生（`splitmix64` / `xxhash`），避免噪声之间耦合。
- 生成路径**禁止**开启会影响浮点结果的激进优化（如 `-ffast-math`）。
- 同一构建内确定性是**必要条件**：同一可执行文件 + 同一种子 → 结果一致；未修改单元**不落盘**，按需重建。

## 5. 流式加载

- 以玩家为中心，按 **tile 距离**维护加载范围；超出范围的单元**逐出**。
- 加载优先级：玩家当前 tile → 面向方向前方 → 其余已加载区（保证玩家面前不出现空洞）。
- 管线（阶段顺序固定）：**生成 → 网格化 → 上传（渲染线程）→ 卸载**。
- **禁止**在主线程同步执行生成、网格化与文件 IO（红线 2）；主线程只做渲染、输入、相机与查询。
- 发布方式：按红线 9，采用**单写者构建 + 不可变快照 + 原子指针发布**；**禁止**对单元加粗粒度锁读写。

## 6. 后台线程角色

| 角色 | 职责 | 禁止 |
| --- | --- | --- |
| 生成线程 | 按种子计算高度列 / 密度值 | 触碰 GPU 与文件句柄 |
| 网格化线程 | 地表高度场网格、体积等值面网格 | 上传 GPU |
| IO 线程 | 读盘、脏数据落盘、压缩 | 阻塞主线程 |
| 渲染线程 | **唯一**可调用图形 API 的线程；执行 GPU 上传 | 执行生成与网格化 |

- 任务依赖用 enkits 的 `TaskSet` prerequisites 显式表达："自身 `Generated` + 边界邻居 `Generated` → 网格化"。
- 每帧网格化任务量**必须有上限**，防止单次大笔刷阻塞帧。

## 7. 脏标记粒度与重网格

- 地表改动**脏标记到 tile**；体积改动**脏标记到体积块**；**禁止**整世界重网格化。
- 一次改动的边界跨越多个单元时：**按单元去重**，每个受影响单元只重网格一次。
- 地表重网格时，与改动列相邻的 tile **必须**一并纳入边界重算。
- 体积重网格时，与改动块共享边界采样的邻块**必须**一并纳入。
- 物件层（层 ③）的放置与玩家建造**不触发地形重网格**：它们绝不写入地形场（ADR 0004 硬约束 1）。

## 8. 卸载

卸载顺序固定，**禁止**跳步：

1. 标记为 `Empty` 候选，停止下发新的网格化任务；
2. **仅脏数据**落盘（见 `save-and-serialization.md`）；
3. 释放 GPU 资源（顶点 / 索引缓冲）；
4. 释放 CPU 数据。

- 玩家周围保护半径内的单元**禁止**卸载。
- 卸载**不得**改变生成结果：卸载后再加载，未修改部分必须与首次生成逐值一致。

## 9. 本引用相关测试

- **生成确定性**：同种子 + 同坐标 → 逐值同输出。
- **邻居就绪**：邻单元未达 `Generated` 时不得进入 `Meshed`。
- **边界连续**：相邻 tile 拼接处几何连续无裂缝；相邻体积块边界采样一致。
- **脏标记粒度**：单次改动的重网格单元数等于受影响单元数，未受影响单元保持不变。
- **卸载往返**：卸载后重新加载，未修改数据与首次生成逐值一致。
